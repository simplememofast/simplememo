Use Templater
Run templates and set up daily notes

Templater is a plug-in that executes variables and functions in a note and puts the results into the body. First, manually insert the 1 sheet, and then proceed to the settings when creating daily notes. Here, we checked the state where the variable remains and the result after setting with the same template.

Prepare the Templater and distinguish the notation

The official installation guide says to search for “Templater” in Obsidian Community plugins and install it. In this test, we placed the official 2.25.1 release files in an isolated Vault and enabled the plugin in Settings. If your Obsidian or Templater version differs, check the screen names and behavior in your own environment.

Template's Template folder location, specify Templates in the example. The command starts with <% and ends with %>. tp.file.title is the title of the target note, and tp.date.now("YYYY-MM-DD HH:mm") is an example of using the date and time of execution. Do not confuse the journaling template, which is written by hand, and the {{date}} notation of core Templates.

If you want to check the replacement and saving results of the title and date and time of the core templates, please also refer to Markdown template collection that actually inserts and re-displays all 10 types.

Templater is a plug-in that can also execute JavaScript and system commands. THE OFFICIAL README GUIDES YOU TO USE CODE THAT YOU CAN UNDERSTAND FROM A RELIABLE SOURCE. In the short example of this article, we do not use external communication, user script, or system commands.

First, insert the template into the current note

The original text of Templates/Simple.md used for verification is as follows. The English memo part is a fictional content for verification that does not include personal information.

# <% tp.file.title %>

created: <% tp.date.now("YYYY-MM-DD HH:mm") %>
result: templater-simple-expanded

## Capture
- Sample thought from isolated verification.
  1. Prepare Templates/Simple.md and open the inserted note.
  2. In the command palette, select Templater: Open insert template modal, then choose Simple from the list.
  3. Check the inserted heading and date. In this Normal note, tp.file.title is deployed to Normal, and the time formula is deployed to 2026-09-30 10:46.

result: templater-simple-expanded is a fixed character in the original text. The fact that this line is visible is not used to determine success. Check if <% … %> has been replaced with the actual value. The date and time are UTC in this Linux environment, and 19:46 in Japan time.

Replace templates in the active file, which expands Templater commands already pasted into the note, is a separate operation. A recovery example for daily notes appears in a later section.

Run Templater in the new daily note

First, I tried to configure the core Daily notes to include the template body and handle the Templater command in the body. The Templates/Daily.md used is the following original text.

# Daily <% tp.date.now("YYYY-MM-DD") %>

note-title: <% tp.file.title %>
result: templater-daily-expanded

What to check when the template does not apply?

It is divided between cases where the note body is not included and when only the Templater expression of the body remains. In this OFF note, the text itself was included. Even if you turn on Trigger and reopen the same existing note with the Daily notes command, the saved content SHA256 matches before and after, and the expression remains.

Run Templater: Replace templates in the active file with the existing note open, and I was able to expand the date and title expression. In the notes containing the record, check the contents and the code of the template, try it with a copy, and then operate. This is the result of this condition. It has not been generalized to other routes, such as the setting to open the Daily note at startup.

Frequently Asked Questions

If I save the Templater template, will it be executed automatically?
It is not automatically applied to all notes just by saving. Use "Templater: Open insert template modal" to put the saved template into the current note. The processing when creating a new file is another setting called "Trigger Templater on new file creation".
Do I also need Folder templates in Daily Note?
In this confirmation, Templates/Daily.md was specified in the core Daily notes, the Trigger of the Templater was ON, and the Template matching mode was None, and the command in the new date note was deployed. None is a setting that does not automatically assign templates, but the Templateter command already in the new body is processed.
If I turn on the Trigger, will the existing daily note be fixed?
In this test, reopening a note created with the trigger OFF through the Daily notes command after turning the trigger ON did not change its saved content. In that same note, “Templater: Replace templates in the active file” expanded the unprocessed commands. These results apply to the tested configuration; opening the daily note at startup and batch processing were not tested.
Can I use the same procedure on iPhone?
Templater 2.25.1's official manifest is not a desktop-only setting, but only the Linux version of Obsidian 1.13.7 is confirmed for actual operation this time. The iPhone screen, template deployment, inter-terminal synchronization, and input from SimpleMemo have not been verified. The trigger setting screen also shows the settings to be enabled for each terminal.

Verification environment and the scope of use for this article

  • Actual operation: Linux isolation Vault, Obsidian 1.13.7, Templater 2.25.1. Operate the setting screen and check the creation and deployment of notes with the commands registered in the app. For manual insertion, I selected a template from the list of GUIs.
  • Daily note comparison:2026 year 9 month 30 days 10:49~10:50 UTC (19:49~19:50 JST). Compare OFF and ON+None saving Markdown with the same template, storage destination, and date format. We also confirmed the reopening of the existing OFF note and the restoration by explicit Replace.
  • Official original: Check the distribution file, manifest, and official docs/source of 2.25.1. The minimum Obsidian version of manifest is 1.13.0. This is not a guarantee of the operation of all versions and terminals.
  • Unverified: iPhone/Android/Mac, Obsidian closed state and external file creation, daily note at startup, synchronization, SimpleMemo linkage, speed, audio quality, Siri, Watch.

This Linux desktop operation is not confirmed on the iOS Simulator or iPhone actual machine. It is described as a result of actual operation only to the extent indicated by the fictional memo and saved Markdown shown in the image.
