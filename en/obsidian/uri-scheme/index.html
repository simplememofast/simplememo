obsidian:// URI Scheme Complete Guide — All Actions and Pitfalls

obsidian:// is a URI for opening, creating, and searching Obsidian notes from another app or launcher. First, select the action that suits the purpose and encode each value URI. The additional text can start with the example of new+append=true, which has been confirmed to be saved this time.

If you want to enter the text and copy the URI, also refer to free URI generator that separates syntax and fixed Linux observations.

This page organizes 7 sections and 38 action-specific parameter entries, combining the 6 actions in the official documentation with a separate section for Hook. It maps these to 58 recorded inputs passed to Obsidian 1.13.7 on Linux. Inputs that produced no result are included so that documented behavior and actual save destinations can be read separately.

Confirmed range:Local Vault for authors, official Linux app 1.13.7, English UI, isolated Xorg screen. I passed the URI to the executable file and checked the operation after the app received it. OS association from browser links, physical iPhone, iOS shortcut, SimpleMemo, synchronization have not been verified. 58 does not mean the warranty of all values, all combinations, and all terminals.

Choose action by purpose

The basic form is as follows. Place the parameter after ? and connect multiple items with &. & in the value is converted to %26 because it is not treated as a demarkation.

obsidian://action?param1=value&param2=value

Encode both the # of the body and the # of the heading as a value

The official text explains that the blank should be %20 and the slash should be %2F. In I:N1, which converted the author text mixed with Japanese, line breaks, and # & ? + % / = by value, the saved Markdown matched the input. If you convert the entire URL at once, the separator will also change, so the values of vault, file, and content will be treated individually .

const vault = encodeURIComponent('練習Vault');
const file = encodeURIComponent('ノート/日本語 メモ');
const content = encodeURIComponent('本文 # & ? + % / =\n二行目');
const uri = `obsidian://new?vault=${vault}&file=${file}&content=${content}`;

The above is a code for explaining how to assemble. It does not include the execution of saving to the notebook on the terminal. Practice Vault and replace the save destination with your name.

The second half fell in the input that left the raw #

In I:W1, only the # within content was left unencoded. Only the opening sentence was saved; the rest of the text was absent from the file. This observation is not evidence that Obsidian deleted text on its own. It is the result of input that mixed URI delimiters with values.

Separe new creations, add notes, and overwrites

name of new is the new note name, and the storage destination is left to the "Default location for new notes" of Obsidian. file is a value that includes the storage destination from the Vault route. The official states that file takes precedence over name, and I:N2 also saved it to the file specified destination. In S:N01, only name is stored in a pre-set default folder.

obsidian://new?vault=Practice&file=Inbox%2FURI-test&content=Hello%20World

If you want to leave the existing text and add it, pass append=true. I:N3 retained the existing text and added it. overwrite=true is specified to replace the existing text, and there is a separate original text/stored record in I:N5. The official statement says "overwrite only if append is not set", and it was added in both specifications of S:N03. There is no need to mix overwriting specifications with daily text additions.

obsidian://new?vault=Practice&file=Inbox%2FURI-test&content=Another%20line&append=true

silent=true's I:N4 maintained the displayed notes while creating a saved file. clipboard=true's S:C01/C02/C03 saves the author text of the dedicated screen to new/daily/unique. The clipboard text was saved in S:C04, which also passed content at the same time. This set of priority results cannot be extended to all forms of all terminals.

Daily notes and proper name notes also check plug-ins and storage destinations

It is officially stated that daily requires Daily notes, and unique requires a Unique note creator core plug-in. The first time I:D1/U1 could not create a file and left the failure record as it was. In another later plan, we prepared a storage folder for a real author and observed I:D2 to create a daily file from the index and I:U2 to create a proper name file. We do not determine that this assumption change is the only cause of failure.

obsidian://daily?vault=Practice&content=Daily%20entry
obsidian://unique?vault=Practice&content=Unique%20entry

The archived official text states that daily accepts the same parameters as new. However, in S:D01/D02/D03, the destinations specified by name, file and path were not created; the content was appended to 日次/2026-09-30.md in the Daily notes settings instead. These observations support using new for a new note with a specified name and daily for input to a daily note, while checking the actual file to confirm the final save destination.

S:D04 was saved daily while maintaining the index display in silent. S:D05 retained the original text by specifying both append and overwrite, but since daily without a flag was also added, the contribution of append alone and the operation of overwrite alone have not been confirmed.

paneType to select the display destination

For open/new/daily/unique, we recorded the 12 inputs involving paneType=tab, split and window (S:P01〜P12). The official documentation marks window as desktop-only. We inspected the actual main tab, tab groups and separate pop-out windows, and saved screenshots. Because metadata for closed windows remains, success was not judged solely by the global leaf count.

x-success・x-error confirms receipt at the return address

The official explains that the return to x-success includes name (no extension), url (obsidian URI), and desktop file (file URI). It is different between the success of saving and the fact that the caller has received the return. S:X01/X02/X03 observed the storage of the note, but there was no reception in the author's localhost HTTP recipient. The prepared BROWSER adapter has not been executed, and the OS and caller handoff have not been confirmed.

The official documentation states that hook-get-address for Hook returns to x-success when supplied; otherwise, it copies the current note’s Markdown link to the clipboard. In S:K01, the author’s clipboard sentinel remained unchanged, and S:X04 received no callback. Hook itself was not run. With the nonexistent Vault in S:X05, the actual “Vault not found” dialog appeared, but no x-error was received. We do not interpret an error dialog as callback success or as proof of a product defect affecting all callbacks.

How do you write Japanese, spaces, and #?

URI-encode each value separately. A space becomes %20, # becomes %23, and / becomes %2F. Encode the # used for a heading or block reference within the file value as well. In our example with a raw # left in the content, everything from that # onward was not saved.
