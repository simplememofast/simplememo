Moving to Obsidian from Notion/Evernote/Apple Notes

What is more likely to trouble after migration is the appearance of attachments, links, and text rather than the number of notes. We actually imported the HTML ZIP of Notion and the ENEX of Evernote with the official Importer and compared the original data with the saved Markdown.

Verification date: 2026 year 9 month 30 (UTC) · Linux version Obsidian 1.13.7 · Importer 3.1.9

Separe the number that can be imported and the shape that is not left

We saved 4 notes and 5 images from Notion, and 3 notes from Evernote. However, Notion’s collapsed sections and paragraph indentation did not retain their original form. We did not test an actual Apple Notes import on Linux.

Input is a test fixture in the fixed commit of the official repository. This is not the data that the author actually exported from his Notion/Evernote account. In this article, this small example shows what remains and what to rework.

Check the importer version and storage address on the practice Vault

First, prepare the Vault for empty practice and look at the output in a few notes. The introduction of Obsidian and the creation of Vault are covered in the parent guide for download and installation.

  1. Enable Importer in Settings → Community plugins. The actual screen of this example is Importer v3.1.9.
  2. Open the Command palette with Ctrl+P and select Importer: Import notes.
  3. Select the format of the migration source and check the input file and Output folder. I will also read the preview before execution.
  4. Select Start import, then separately check the counts of notes, attachments, and failed items shown on completion and the files saved in Vault.

In this initial preparation, the official release main.js, manifest.json, and styles.css were manually deployed to the isolated Vault, and after activation, it was operated with the actual GUI. This is not a verification introduced by clicking Browse → Install in Community plugins. It has not been verified that the same result will be obtained in the version other than the selected 3.1.9.

Obsidian and Installer's actual version screen

Notion passes the ZIP of HTML to File import

This version of Notion has two routes. This time, I chose File import. The screen says "no token or Internet connection required" and "no database is retained". The migration of the Notion account's database and formula is a separate route, and this verification is not performed.

  1. After selecting Notion, choose File import. The actual screen asked for an export in HTML format. For your own migration, prepare the files using the official export instructions.
  2. Select the ZIP using Choose file. In the test, we selected the official fixture notion-testspace.zip in the operating system’s file picker. The structure, with 1 additional ZIP files inside the outer ZIP, could be imported directly.
  3. Check Folders to import and Continue. This time, we proceeded in the initial state of selecting all the targets.
  4. Output folder was Notion, Attach location was Vault folder, Save parent pages in subfolders was ON. This is an example of an empty Vault without an existing notebook. Update overwriting and conflict processing have not been verified.
  5. On the next screen, we left Save Notion ID on, Single line breaks off, and no template selected. We read the Preview and clicked Start import 1 time.

The parent page is Notion/Notion-Testspace/Notion-Testspace.md, and the child page is under the same subordinate. Attachment Tests is also in the folder of the same name. The 3 links in the parent text uniquely correspond to the corresponding child notes of this Vault.

Evernote selects ENEX and compares the indending of the code

  1. Open the Importer again from the Command palette and select Evernote (.enex). The actual screen showed the ENEX export for each notebook.
  2. Choose files. In this example, the official fixture code-block-indentation.enex was passed on the OS file selection screen.
  3. The Output folder was Evernote, Attachment location was Vault folder, and no template was selected. We chose Continue, read the Preview, and clicked Start import 1 time.
  4. The completion display is 3 imported / 0 attachments / 0 failed. The 3 notebook was created in the Evernote/code-block-indentation/ of the storage destination.

The blank example retains 4 and 8 infolds and blank lines. The NBSP example has changed to a normal blank space, but the indenances of 4 and 8 are the same. Strings including backslash, *, and _ also remained as characters in the code block.

Confirmation and FAQ before and after migration

Which import method do you choose in Notion?
This test used Notion → File import. Notion account is a separate route that uses a token and network communication; we did not run it. The actual File import screen states that it does not preserve databases. Complete migration of databases and formulas is outside the scope of these results.
Do you want to decompress the ZIP of Notion first?
This official fixture contains 1 ZIP files inside an outer ZIP, which we could select directly with Choose file. The 4 HTML files with IDs became notes; index.html, which had no ID, did not. This does not prove that every ZIP structure will import successfully.
If 0 failed, does it look the same as the original?
It is not necessarily the same. In this example, the contents of the fold are expanded to a normal headline list, and paragraphs with indends become normal paragraphs. 0 failed is a display of the number of processing cases. Check the appearance, attachment, and link separately.
Why do links to Notion headings and blocks become page links?
This time, the original HTML has a block ID in the display string, but there is no anchor in href, and the output was [[Formatting Tests]]. The position lost in the original export will not be restored by the Importer alone. Look at both export and output before migration.
Is the indendent of the Evernote code left?
In this ENEX 3 example, 4 and 8 spaces, blank lines, and backslashes and symbols inside code were preserved. Non-breaking spaces became ordinary spaces, and the indentation of 4 and 8 spaces matched. This did not test attachments, every format, or every note.
Can Apple Notes also be imported in this environment?
The pinned source checks for the macOS desktop environment. Because our test environment was Linux, we did not try actually importing Apple Notes. These results cannot establish success or complete migration on a Mac.

Confirmation scope and official documents

  • Linux version Obsidian/Installer 1.13.7, Importer v3.1.9 real screen. The official release assets 3 were activated from the GUI with the quarantine Vault that was manually placed.
  • Notion File import and Evernote ENEX are executed from the actual OS file selection and Start import each 1 times. The saved 7 note, 5 local image, and finite text, link, and layout examples were compared with the original fixture.
  • Open the attached note of Notion and the blank code note of Evernote again from the file list in the same startup to confirm the bytes match. Restarting the app and reopening has not been verified.
  • The PNGs, input fixtures, and saved Markdown retain their original bytes. Helper code was used for preparation and reading; plugin API did not substitute for the import operation or output-file generation.

The error in the prepared profile ID, the failure of waiting for the selector to be clicked, and the fact that only the first Return in the file selection was not closed. The actual selection was confirmed with the Open button on the OS screen. The app exited 0 with a real wait after GUI Close, and Xorg was SIGTERM to the ownership process and actually wait 0. The controller is exited 1 in the Xlib termination process at the end, and it is not a normal termination of the whole. Details will be summarized in verification record.

Not tested: exporting from a real account; Notion account/API, databases, and formulas; running Apple Notes; all metadata or layouts; arbitrary large datasets; other operating systems; iOS; Sync; SimpleMemo; or effects on speed, safety, and productivity.
