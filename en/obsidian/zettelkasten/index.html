How to start Zettelkasten with Obsidian?

Write an idea in the body of the note and start by leaving the relevant reasons and internal links together. In this example, prepare a temporary note and a note of two ideas, and add a link with a reason. Finally, make sure to make an index and proceed to two notes from there.

Here, we treat Zettelkasten as a small exercise to rewrite ideas on a notebook basis and leave related articles and links. For the entrance to collect thoughts, go to Zetterkasten and email memo guide. This article is an example of the operation of connecting notes in Obsidian.

1. Prepare the textA temporary memo and two notes that summarize thoughts
2. Leave a relatedA sentence of reason and an internal link to another note
3. Trace and confirmIndex, link, backlink, graph

The note name, number, and text are examples made by the author to show this procedure. It is not taken from actual research, reading materials, or user operation records.

1. Prepare the text in a small storage room

When trying, use a practice vault that does not contain personal information. There is no need to move existing notes. If it's your first storage, you can check the storage destination and the actual file first.

The first to prepare in this example is the following three. I will add an index later. The titles 20260930-01 and 20260930-02 are numbers given by the author for distinction.

Saved file nameRole in this example
仮メモ.mdTwo short notes about the stage of writing down and the stage of thinking about the relationship
20260930-01 入力と整理を分ける.mdAn example of rewriting an idea in your own words
20260930-02 関係に理由を添える.mdAn example of a reason to refer to another note

All three existed on the first screen, and 3 nodes and lines 0 were displayed in the graph. There is a difference between having a text and a link to another note.

The author prepared the first three notes as Markdown files before starting. The following link reason and index text were entered into the actual Obsidian editor and saved. The scope of using auxiliary API to adjust the display of the configuration window and the right sidebar and read the saved status is described in the verification record at the end.

2. Write the relevant reason before the link

Open 20260930-01 入力と整理を分ける and write the heading of ## 関連 and the reason for proceeding to the note of 02 at the end. The link is in the form of [[ノート名]] and is matched to the name that is actually saved.

Below is the saved Markdown of 01 after adding the link. The contents of the original are posted as they are, including empty lines.

# 入力と整理を分ける

この例では、思いつきを仮メモに置き、あとで一つの考えを一つのノートに書き直す。

書き留める段階と、整理する段階を分ける運用案として扱う。
## 関連

整理の段階で関連の理由も書く例として、[[20260930-02 関係に理由を添える]]を参照する。

Rather than simply lining up the links, you can leave the entrance to the text when reviewing if you leave "what to open to check" in one sentence. In this example, 02 is referred to as "an example of writing related reasons at the organization stage".

If you want to arrange short sentences and reference notes as cards, you can also refer to examples of leaving connection labels in Canvas.

The graph immediately after the addition was 3 node, line 1. There is a line between 01 and 02, and the temporary memo remains isolated. I also checked to switch to the read view with Ctrl＋E and click the link to move to 02.

3. Trace notes from the index

Next, create a new notebook with Ctrl＋N, name it 索引 and save it. Fill in this small set of themes and the entrance to the two notebooks. The contents of this storage are as follows.

# 索引

この例で扱うテーマは、メモを書く段階と、関連を残す段階を分けること。

- [[20260930-01 入力と整理を分ける]] — 書き留める内容と整理する内容を分ける例。
- [[20260930-02 関係に理由を添える]] — 関連ノートへ進む理由を添える例。

After reopening the index, I checked that the text had not changed, and clicked on the link in the order of index → 01 → 02 in the read view. In the backlink of 02, two reference sources, 01 and index, were displayed, and I was able to click on the context of the reference source to return to 01.

The index is an author-created example that provides an entry point back to this topic. We did not test rules for collecting every note in the vault here or an automatic generation system. To combine it with project folders and working notes, see the small PARA implementation example.

Check the changes in the graph in three stages

In this English UI, I opened the command palette with Ctrl＋P and selected Graph view: Open graph view. Check the actual screen of each stage with a saved note.

The last graph was 4 node, line 3. The added node is the index, and the added line is the two links filled in from the index to 01 and 02. Temporary notes do not have links to other notes until the end and remain isolated.

The three sheets are in the order in which the operation was carried out in one verification on the same day. The position of the point changes with the automatic layout of the graph, so it is not used as an indicator to compare the position and the size of the spread. I checked the actual file, the result of the internal link resolution, and the correspondence of the display node and line.

The display conditions have been fixed with Search blanks, Tags OFF, Attachments OFF, Existing files only OFF, and Orphans ON. There were no unresolved internal links in this vault. The graph shows the structure of this link, and does not measure the correctness of the sentence, the depth of learning, or the improvement of knowledge or productivity.

Search, isolated notes, color coding, and operations to change the depth of local graphs can be found in Example of a graph view that narrows down the display range.

Check when the line or link cannot be found

  1. View the current storage and actual files. Check if you have opened a separate vault with the same name and if you have the intended Markdown.
  2. Open the link to the text. See if the inside of [[...]] matches the name and path of the target note. If you have a note with the same name, please check the open text.
  3. See the display conditions of the graph. Check the settings of Orphans to narrow down such as Search and display isolated notes. It is not necessarily the same as this display condition.
  4. Reread the reason for the link in the text. It is not only aimed at increasing the number of lines, but it is a sentence of which idea you want to proceed to with that link.

This checklist is a procedure to check in your own vault. This time, it is not the result of trying all unresolved links, notes of the same name, and all combinations after switching filters. For operations and display settings, please also refer to internal link and official description of graph views.

Frequently Asked Questions

Do I need a dedicated plug-in for Zettelkasten?
In this small example, we used the core functions of Obsidian 1.13.7's internal link, graph view, and backlink. No community plug-ins have been added. Please make sure that the necessary core functions are valid in your environment.
Do I need to attach a note ID like 20260930-01?
This number is an example chosen by the author to distinguish the notes for verification. This is not an ID automatically added by Obsidian. In this article, we do not compare the numbering methods. First of all, I use it as an example of choosing the link and naming it correctly, leaving a reason related to the text.
If there is no line on the graph, is the note not saved?
On the first screen this time, there is a saved 3 notebook, and the line of the link is 0. The existence of notes and the links that connect notes to each other are different. When checking the save, open the actual note and also check the text of the Markdown.
What do the lines in the graph represent?
In this display setting, lines were displayed between notes connected by an internal link. I don't know why the line alone is related or whether there is any basis for the explanation. In the example, write the reason just before the link so that you can read the body of the note found from the graph.
