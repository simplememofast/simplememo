Select the display range and return to the text

Use the graph view in Obsidian
Narrow the view and check connections

After opening the graph, select the range of notes you want to see first. I checked the search by folder tag, the display of isolated notes, the color group, and the depth of the local graph in a small author-created vault.

Author: SimpleMemo Developer · Confirmation of actual operation: 2026 10 month 1 (Japan time) · Linux version Obsidian 1.13.7

Choose the whole and nearby notes according to the range you want to see

Use the global graph to search for the entire library, and select the depth of the local graph to view the surroundings of the open note. The color group is a display that identifies the notes that meet the selected conditions. Open the note to confirm that the text and internal links have been saved.

The note name, text, and tag in the example were created by the author. It is not taken from the actual records of research and life, or from the user's storage. The display position is a layout, not a value that indicates the time required or the degree of understanding.

The first six files were prepared before the app was launched, and only the seventh one was created with the actual editor. " #研究 is written in the three notes and additional notes in the "Research" folder, and #生活 is written in the second notebook of life.

The first conditions for global graphs are Search files blanks, Tags OFF, Attachments OFF, Existing files only OFF, Orphans ON. There were no unresolved links. In the future comparison, only the described search, Orphans, and color groups are switched.

1. Add notes and compare the saved content with the graph

Open Open graph view from the left ribbon. At first, it was six notes and three links. Next, I made an "additional memo" with Ctrl＋N and entered the name and text into the actual editor. The saved full text is the following 92 bytes.

# 追加メモ

GUIで追加する著者作成ノートです。 [[研究/入口]]

#研究

When I waited for automatic saving and opened the graph, it became seven notes and four links. One more from the additional memo to the 研究/ entrance increased, and the saved Markdown and the internal link resolution results also matched.

The configuration panel covers some nodes. The number of these two images is a value that has been confirmed by reading the node name and link endpoint from the actual Graph renderer. It is not a counting method that shows all the circles in the image. The image is preserved as it is.

Finally, I reopened the additional notes from the file list and read the text and tags. When adding, after re-displaying, and after the end of the app normally, the saved Markdown had the same content.

2. Choose a different range for folders and tags

Enter a search string in Filters → Search files in Graph settings. path:"研究/" selects notes within a folder; tag:#研究 selects notes containing a tag. The observed results differed as follows.

The additional note is at the vault root, so it does not match the path condition for the 研究 folder. It does match the tag condition because it has #研究. We left Tags off in this test and did not test displaying tags themselves as nodes.

When you finish narrowing down, empty the Search files. This time, when the search candidate overlapped with the operation, I closed it with Esc and then clicked the next switch. The folder name and tag name will be adjusted to your saved content.

3. If you also want to see isolated notes, turn on Orphans

With the search string empty, if you turn off Orphans of Filters>, 孤立.md disappears and becomes six notes and four links. When I returned to ON, I returned to the Seven Notes and Four Links, including 孤立.md. Both link endpoints are the same.

In this example, the saved orphan note had no internal links, so toggling the setting changed which notes were shown. If a note is missing, check separately whether its body is saved and which search and display conditions the graph currently uses. Unresolved links and every combination of filters were not tested.

4. Identify notes that match the conditions by color group

Groups → New group, and entered path:"研究/" in the first and tag:#生活 in the second. Click on the color circle of the group and change the first one to RGB 30 / 140 / 220 (#1e8cdc) on the Linux color selection screen. The second assigned color was #d6ad5c.

The three notes in the 研究 folder appeared blue, and the two notes with the life tag appeared gold. The additional note at the vault root and 孤立.md matched neither condition, so they received no group color. We also checked the node names and colors; the overall total remained seven notes and four links.

The original image shows the actual color picker. We used the existing X11 mouse and keyboard helpers for GUI input; we did not set the color through the app’s API or by assigning DOM values. Overlapping or reordered color groups, other colors, and other operating systems’ color pickers were not tested.

5 Select a nearby note by the depth of the local graph

Open 研究/入口.md from the file list and select More options → Open linked view → Open local graph in the note. The Filters of the local graph have a Depth slider. The conditions for this time are Incoming links ON, Outgoing links ON, and Neighbor links OFF.

Both images are originals captured after choosing the settings and closing the panel. They record depths 1 and 2 for the entry note. Opening a different note also changes the scope of the linked local graph. Depths 3–5 and other combinations of Incoming/Outgoing/Neighbor links were not tested.

Frequently Asked Questions

What do you check when you can't see a note in the graph?
In this example, the target has changed with the search string of Search files and the ON/OFF of Orphans. Open the target note to check the saved contents, empty the search string, and turn on Orphans if you also want to check isolated notes. You can also check conditions such as Tags, Attachments, and Existing files only in the official help. I haven't tried all the combinations of settings.
What is the difference between global graphs and local graphs?
The global graph targets the entire notebook in the vault, and the local graph targets the area leading to the open note. In this entrance note, Incoming links and Outgoing links were turned on, Neighbor links were turned off, and 3 note and 2 link with depth 1, and 4 note and 3 link with depth 2. No other connected components or isolated notes were included.
Is it the same operation to switch Tags and tag: search?
In the official help, Tags is the toggle for displaying tags in the graph. A tag: search filters notes containing a specified tag. In this test, Tags remained OFF while tag:#研究 displayed 4 notes. Displaying tags themselves as nodes was not tested in this example.
If there are more nodes and lines, can you judge that you have high knowledge and productivity?
What we confirmed in this article is the structural difference due to the saved notes, internal links, and specified display conditions. The correctness of knowledge, depth of understanding, productivity and speed are not measured. The exercise of checking the reason for the link in this text is introduced in the Zettelkasten notes and the link practice guide.
