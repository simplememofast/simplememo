노트의 값을 정렬하여 목록에 연결

Obsidian의 프로퍼티 활용
frontmatter에서 목록으로

상태, 수치, 체크, 날짜, 태그를 노트에 저장하고, Dataview에서 조건에 맞는 기록을 표시합니다. 가상의 세 가지를 사용한 실제 GUI 조작과 저장 Markdown을 확인한 입문입니다.

저자: SimpleMemo Developer · 실제 기기 확인: 2026년 10월 1일(일본 시간) · Obsidian 1.13.7 / Linux

이 페이지의 내용

01속성은 노트 앞에 있는 YAML을 다루는 UI↗02이름, 형식, 값을 순서대로 정합니다↗03저장한 frontmatter를 확인합니다↗

속성은 노트 앞의 YAML을 다루는 UI

Properties에 입력한 이름과 값은 노트 앞의 frontmatter에 저장됩니다. 예를 들어 status: 進行中을 정렬해 두면 Dataview의 WHERE 조건에서 “진행 중” 노트를 선택할 수 있습니다. 본문에 쓴 일반적인 문장과는 취급이 다릅니다.

우선, 무엇을 비교하고 싶은지 결정하고 소수의 항목을 사용합니다. 이 예에서는 상태를 status, 우선순위를 priority, 완료를 done, 기한을 due, 분류를 tags로 했습니다. 저자 작성의 허구 기록이며, 이용자의 데이터가 아닙니다.

GUI로 입력저장 YAMLTABLE・LIST변경 및 결과연습용 원본

이름, 형식, 값을 순서대로 정합니다

  1. 노트를 열고, Add property 또는 공식 Ctrl/Cmd+;에서 항목을 추가합니다. 실제 기기 예에서는 Add property를 클릭하여 priority을 추가했습니다.
  2. 항목명 옆에 있는 형식 아이콘을 누른 뒤, Property type을 열어 형식을 선택합니다. 실제 기기에서는 Number를 선택하고 3을 입력하여 저장했습니다.
  3. 기존 status은 Text를 선택하고, “미시작”에서 “진행 중”으로 변경했습니다. 체크, Date 입력, Tags 입력도 실제 UI에서 변경하고, 저장된 YAML에 반영되는 것을 확인했습니다.
  4. Tags는 문자만 입력하고 끝내지 않으며, 포커스된 입력으로 Enter 키를 눌러 확정합니다. 이번 보조 작업도 한 번 확정하지 못하고, 다시 Enter와 포커스 이동으로 저장을 확인했습니다.
이름이 예시의 형식과 값실기에서 수행한 일
상태Text / 進行中텍스트 선택, 未着手→進行中
우선순위번호 / 3항목 추가, Number 선택, 3 입력
일했습니다Checkbox / true 또는 falsefalse→true→false、마지막에 true
만기Date / 2026-10-0310월1일→10월3일
태그태그 / 검증, 속성속성을 추가하고 확정

공식 자료에서는 같은 이름의 형식이 보관함 전체에 공통됩니다. 다른 의미의 값에 같은 이름을 재사용하기 전에, 타입과 용도를 확인합니다. List와 Date & time 등, 여기서 다루지 않은 형식은 이번 동작 확인에 포함되지 않습니다.

저장한 frontmatter를 확인합니다

아래는 조사 A의 마지막 저장 전체 텍스트, 211 bytes입니다. GUI에서 done을 true로 변경한 후의 상태이며, 본문을 포함하여 원본 Markdown과 동일한 내용입니다.

조사 A의 저장 Markdown 전체 텍스트 보기
---
status: 進行中
tags:
  - 検証
  - プロパティ
done: true
due: 2026-10-03
priority: 3
---

# 調査A

著者が検証用に作成した架空の記録です。顧客データではありません。

공식 자료에서는 frontmatter가 파일 시작을 ---으로 둘러싸고, 名前: 値의 YAML 형식으로 기술합니다. 속성 이름은 하나의 노트 내에서 중복되지 않습니다. 이 예제의 숫자 3와 체크 true는 각각 숫자와 boolean으로 저장되어 있습니다. Date는 이 값을 저장한 확인이며, 모든 날짜 형식이나 입력의 정확성을 검증한 결과가 아닙니다.

같은 값을 TABLE과 LIST 조건으로 설정합니다

실기에서는 공식 Dataview 안정 릴리스의 세 파일을 격리된 보관함에 사전에 복사하고, 실제 신뢰 확인으로 플러그인을 활성화했습니다. 이는 Browse/Install 화면 조작을 검증한 기록이 아닙니다. 플러그인은 제3자 코드를 실행하기 때문에 배포원 및 이용 조건을 확인하고 선택합니다.

릴리스명은 0.5.70이며, 배포 매니페스트와 실제 화면 표시 버전은 0.5.68이었습니다. 필요한 Obsidian 최소 버전은 manifest상의 0.13.11이며, 실제로 실행한 Obsidian은 1.13.7입니다. DataviewJS 설정은 false이며, 다음 DQL을 실제 편집기에 입력하고 Reading view에 표시했습니다.

폴더명 記録, 항목명, 상태 문자열을 일치시킵니다. 조사 A/B는 진행 중이며, C는 완료되었습니다.

# Properties接続検証

著者が作成した架空の3件だけを表示します。

## 進行中の表

```dataview
TABLE status AS "状態", priority AS "優先度", done AS "完了", due AS "期限"
FROM "記録"
WHERE status = "進行中"
SORT file.name ASC
```

## 未完了の一覧

```dataview
LIST
FROM "記録"
WHERE done = false
SORT file.name ASC
```

## 保留の該当なし

```dataview
LIST
FROM "記録"
WHERE status = "保留"
SORT file.name ASC
```

TABLE은 진행 중인 두 건을 표에, LIST는 done가 false인 노트를 목록에 표시합니다. 마지막 리스트는 보류된 노트를 선택하고, 대상이 없는 경우 실제 표시도 확인했습니다. DQL의 모든 기능, 인라인 필드, DataviewJS는 여기서 시도하지 않았습니다.

완료 체크를 변경하면, 미완료 목록이 2건에서 1건으로 변환됩니다

조건조사 A의 done=falseGUI에서 done=true로 변경한 후
status = 進行中의 TABLE조사 A·B / 2건조사 A·B / 2건. A의 완료값 true를 표시
done = false의 LIST조사 A·C / 2건조사 C / 1건
status = 보류 중인 리스트해당 없음해당 없음

변경 전의 TABLE 두 건은 실제 Reading DOM으로 확인했지만, 그때의 PNG는 표에서 아래로 스크롤되어 있었습니다. 위의 변경 후 PNG에서는 표 두 건과 미완료 목록 한 건이 표시됩니다. 표시 위치나 이미지를 다시 만들어 교체하지 않았습니다.

파일 목록에서 조사 A와 목록 노트를 다시 열어, 저장된 Markdown의 바이트와 SHA256이 동일한지도 확인했습니다. 같은 앱이 실행 중인 상태에서 재표시된 것은 앱 전체의 재시작이나 다른 기기의 확인이 아닙니다. 이번 조건에서 값이 표시에 반영된 결과, 작업 속도와 생산성이 상승한다는 인과관계는 측정하지 않았습니다.

최종 상태의 네 파일을 저장합니다

실기에서 저장한 원본 Markdown의 바이트를 그대로 복사한 파일입니다. 조사 A의 done은 true입니다. 다음 구성에서 쿼리의 FROM과 폴더 이름을 맞추고 있습니다. 독자의 보관함에서의 수집은 아직 검증되지 않았습니다.

保管庫/
  一覧.md
  記録/
    調査A.md
    調査B.md
    調査C.md
보관함 내의 상대 경로보존 원본

記録/調査B.md調査B.md을 저장(152 바이트)
記録/調査C.md調査C.md을 저장(150 바이트)

세 기록의 초기 내용은 검증 전에 직접 작성하고 있습니다. 조사 A의 항목 변경 및 목록 노트에 대한 쿼리 입력은 GUI 작업의 범위입니다. B/C를 GUI에서 처음부터 만든 기록으로 만들지 않습니다.

자주 묻는 질문

Obsidian의 프로퍼티와 frontmatter는 다른 데이터인가요?
프로퍼티는 노트의 구조화된 값을 조작하는 UI이며, 값은 파일 시작에 있는 YAML frontmatter로 저장됩니다. 이번 실기에서는 status, tags, done, due, priority를 GUI에서 조작하고, 저장된 Markdown 값과 대조했습니다.
속성의 타입을 노트별로 설정합니까?
공식 자료에서는 동일한 프로퍼티 이름에 보관함 전체에서 동일한 유형이 사용됩니다. 이름 옆에 있는 형식 아이콘에서 Property type을 열어 형식을 선택합니다. 이번 실기에서는 priority에 Number를 선택하여 3을 저장했습니다. 모든 형식 및 날짜 입력에 대한 검증을 수행한 것은 아닙니다.
Dataview에서 속성을 목록화하는 기본 형태는 무엇입니까?
dataview 코드 블록에 TABLE 또는 LIST, FROM 및 WHERE를 씁니다. 이번 세 건에서는 FROM "記録"으로 폴더를 대상으로 했으며, status = "進行中"의 TABLE은 두 건, done = false의 LIST는 완료 체크 변경 전 두 건, 변경 후에 한 건이었습니다.
다운로드한 예는 어떤 상태인가요?
GUI에서 조사 A의 done을 true로 변경한 후 저장된 원본입니다. 記録 폴더 내부에 조사 A·B·C, 동일한 보관함 바로 아래에 一覧.md을 배치하는 구성을 보여줍니다. 이번 실기 결과는 TABLE 두 건이며, 미완료 리스트는 조사 C 한 건, 보류는 해당되지 않았습니다. 독자의 보관함으로의 가져오기 및 별도 환경의 동작은 아직 검증되지 않았습니다.

공식 자료와, 이 실기 확인 범위

GUI 확인의 UTC 날짜는 2026년 9월 30일이며, 일본 시간은 2026년 10월 1일입니다. 실제 화면, 저장된 원본, 고정 소스, 보조 수정, 종료 기록의 부족은 검증 기록에 정리합니다. 종료 Close는 전송했지만, 기록기의 종료 순서에 따라 Obsidian의 종료 코드는 아직 기록되지 않았습니다.

  • 확인됨：Linux Obsidian 1.13.7, 다섯 가지 유형의 유한 GUI 작업, 저장 YAML, DQL 세 조건의 실제 읽기 표시, 값 변경 및 재표시, 동일한 시작 중 저장 일치.
  • 공식 설명：Properties의 저장 형식·형식 공유, Dataview의 frontmatter/QUERY/TABLE/LIST/WHERE를 고정 자료로 확인합니다.
  • 미확인：전형·전 입력 검증, 플러그인 보안 감사, 전체 DQL/JS, 앱 재시작, iOS, 동기화, SimpleMemo 연동, 대보관함·속도·생산성.
