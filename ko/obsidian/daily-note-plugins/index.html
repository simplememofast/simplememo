Obsidian · 일일 및 주간 노트

데일리 노트를 강화하는 플러그인 — Calendar/Periodic Notes

날짜와 주 번호를 기준으로, 되돌아보고 싶은 노트를 여는 입구를 준비합니다. Calendar와 Periodic Notes를 결합하여 일지와 주간지를 생성·저장하고, 동일한 앱 내에서 다시 열 수 있는 사례입니다.

검증일: 2026년 9월 30일 (UTC) · Linux 버전 Obsidian 1.13.7

두 역할을 나누면 설정하기 쉽습니다

Calendar는 “언제 노트를 열지”의 입구이며, Periodic Notes는 “어디로, 어떤 이름과 본문으로 만들지” 설정입니다. 이번에는 일일 2026-09-30과 주간 2026-W40를 만들고, 템플릿 본문에 저자 확인문을 추가하여 저장했습니다.

Obsidian 표준의 Daily notes와 iPhone에서 일지에 메모를 추가하는 루트는 데일리 노트의 부모 기사에서 다루고 있습니다. 이 문서는 데스크톱의 캘린더 조작 및 일일·주간 설정으로 좁힙니다.

기능역할이 예에서 확인한 범위
코어 일일 노트Obsidian 표준 일일 노트 기능.실제 GUI로 활성화합니다. 표준 기능만을 사용한 일일 생성과는 별도로, 아래 두 가지를 결합했습니다.
캘리더 1.5.10날짜와 주 번호를 기준으로 노트로 이동하는 사이드바.날짜 30, 주 번호 40, 작성 확인, 전월과 당월 이동.
주기 노트 0.0.17Daily/Weekly의 저장 대상, 서식, 템플릿.일지와 주간지 설정, 실제 작성 본문, 저장, 동일한 앱 내에서 다시 열기.

여기서 사용한 버전은 공식 비베타 태그에서 선택한 Calendar 1.5.10과 Periodic Notes 0.0.17입니다. 최신·현재의 권장 버전이나 다른 버전에서 동일한 결과가 된다는 것을 보장하는 기록이 아닙니다. 조작한 UI 버전도 아래 원본 화면에서 확인하고 있습니다.

검증한 버전을 준비하고, 활성화합니다

이 예제에서는 공식 릴리스 파일을 격리한 저자 Vault에 수동으로 배치하고, 이후의 활성화 및 작업을 GUI에서 수행했습니다. Community plugins의 Browse → Install을 클릭하여 도입한 검증이 아닙니다.

  1. 연습용 Vault에 빈 日誌, 週誌, テンプレート 폴더를 준비합니다. 이 예시의 입력은 아래의 Markdown을 사용하고 있습니다.
  2. Calendar 1.5.10의 공식 릴리스와, Periodic Notes 0.0.17의 공식 릴리스에서 이 예에서 사용한 파일을 확인할 수 있습니다. 수동 배치의 구성은 아래에 표시됩니다.
  3. Settings → Core plugins에서 Daily notes를 켭니다. 이번 작업에서는 Command palette도 ON이며, Quick switcher는 ON 상태를 확인했습니다.
  4. 제가 직접 준비한 Vault의 Trust를 확인한 후, Settings → Community plugins에서 Period Notes와 Calendar를 켭니다. 아래 원본 화면은 이 두 개를 실제로 활성화한 후의 표시입니다.
  5. 오른쪽 사이드바를 열고, Calendar 탭을 선택합니다. Backlinks와 같은 별도의 탭을 그대로 두면 날짜 화면이 보이지 않습니다.

일지와 주간지의 저장처를 미리 정렬합니다

Settings → Periodic Notes에서 Daily Notes와 Weekly Notes를 켜고, 다음 값을 입력합니다. 폴더와 템플릿은 미리 Vault 내에 준비합니다. 이번 설정 입력은 실제 GUI의 표시와 저장 JSON을 대조했습니다.

Settings → Calendar에서는 Show week number와 Confirm before creating new note를 ON으로 설정했습니다. 이번 주 시작일은 Locale default(Sunday)이며, 앱의 로케일은 en, 환경의 시간대는 UTC입니다. 모든 주 경계와 로케일 조합을 검증한 결과가 아닙니다.

우선했을 때 확인 및 FAQ

Calendar와 Periodic Notes는 둘 다 필요합니까?
날짜를 선택하는 입력과 일일·주간 노트 설정을 결합하고 싶을 때, 이 예시의 두 가지를 사용합니다. Calendar는 캘린더의 입구이며, Periodic Notes는 Daily/Weekly의 폴더·서식·템플릿을 설정하는 측입니다. 일일 기본 설정을 알고 싶으시면, 부모 기사의 데일리 노트 해설부터 시작하실 수 있습니다.
주 번호가 표시되지 않을 때는?
이번 Calendar1.5.10에서는 Settings의 Calendar에 있는 Show week number를 ON으로 설정하면 왼쪽 끝에 주 번호 열이 표시되었습니다. 오른쪽 사이드바를 여는 것만으로는 Backlinks와 같은 별도의 탭이 선택되어 있을 수 있으므로, Calendar 탭을 선택하십시오.
날짜를 클릭해도 본문으로 이동할 수 없을 때는?
이번에는 New Daily Note와 New Weekly Note의 생성 확인이 메인 화면이 아니라 열려 있던 Settings의 별도 창에 표시되었습니다. 양쪽 화면을 확인하고, 대상 파일명을 확인한 뒤, 해당 확인 화면의 Create를 선택합니다. 확인 전에 같은 날짜를 여러 번 눌렀을 때의 결과는 검증되지 않았습니다.
주차의 형식은 YYYY와 gggg 중 어느 것인가요?
이 고정 예제에서 사용한 값은 gggg-[W]ww이며, 2026-09-30 환경에서는 2026-W40를 생성했습니다. 주의 연도를 나타내는 서식과 날짜의 연도는 경계에서 일치하지 않을 수 있으므로, 형식을 섞지 않고, 앱의 주 시작일과 로케일도 확인합니다. 모든 연경계·로케일·타임존 결과는 아직 검증되지 않았습니다.
템플릿 변수와 Templater도 사용하고 계십니까?
일일 입력에는 Obsidian의 네이티브 {{date:YYYY-MM-DD}}를 사용했으며, 실제 작성에서 2026-09-30로의 교체를 확인했습니다. 주차는 저자의 정적인 본문입니다. Templater, JavaScript, 임의의 변수 및 모든 형식 토큰의 실행은 이 예에 포함되지 않습니다.
iPhone, SimpleMemo, 동기화에서도 동일하게 동작합니까?
실제 조작을 확인한 사람은 Linux 버전 Obsidian1.13.7의 저자 Vault입니다. iOS, Android, 기타 OS, Obsidian Sync, SimpleMemo와의 연동, 기기 간 동기화, 속도·생산성·유입 효과는 이 기록에서 검증하지 않았습니다. iPhone에서 일지에 추가할 루트는 다른 데일리 노트 기사를 참조하십시오.

실제 확인한 범위와 공식 자료

  • 공식 Linux 버전 Obsidian 1.13.7/Installer 1.13.7, 영어 UI. Calendar 1.5.10/Periodic Notes 0.0.17의 실제 버전 표시.
  • 저자 Vault에서 실제 GUI 설정, 일일 및 주간 각각 하나의 생성 확인·본문·저장·동일한 앱 내 재오픈. 월 이동은 다른 고정 시도로 확인했습니다.
  • 플러그인의 공식 릴리스 자산은 수동으로 배치됩니다. 보조 코드는 초기 환경 준비와 상태·저장 파일의 읽기, 원본 복사에 사용했습니다. 노트의 생성·편집·저장·재오픈을 API로 대체하고 있지 않습니다.
  • 공개하는 PNG와 Markdown은 원본 파일의 바이트를 유지하고 있습니다. iOS, 기타 OS, SimpleMemo, Sync, 전체 날짜·주·월·시간·시간대, 생산성·유입에 대한 효과는 아직 검증되지 않았습니다.

준비 단계의 시작 정지, 베타 버전 화면과 저장 설정 불일치, 숨김 탭 클릭, 별도 창 확인 화면을 놓친 실패는 원래 실패로 남겨두고 있습니다. 이 기사 작성·저장 예시는 별도의 고정 시도에 기반합니다. Ctrl+O에서는 Quick switcher 화면을 확인할 수 없었으며, 동일한 저장 대상 파일 목록에서 실제 클릭으로 처음으로 다시 열었습니다. 상세와 원본 파일의 대응은 검증 기록에 정리합니다.
