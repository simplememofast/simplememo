Obsidian의 Markdown은 CommonMark와 동일합니까?
공식 자료는 CommonMark, GitHub Flavored Markdown, LaTeX와 Obsidian 고유의 확장을 결합한다고 설명하고 있습니다. CommonMark0.31.2와 고정된 공식 Help를 기반으로 표준·확장 형식을 구분하고, 실제 기기의 원본 화면과 대응하고 있습니다. 전체 규격에 적합하거나 다른 앱의 모든 대응을 시험한 결과가 아닙니다.
내부 링크와 임베드를 어떻게 구분합니까?
[[노트]]는 wikilink、![[ 노트]]는 삽입의 기본 형태입니다. 제목은 #, 블록은 #^id를 붙입니다. 추가 예에서는 Markdown 형식의 노트·제목·블록 임베드도 표시했습니다. 한편, 참조 형식의 relative 링크는 실제 클릭 시 Cannot open location이 되었기 때문에 wikilink의 도착 결과와 별도로 게시하고 있습니다.
이 목록은 모든 표기법에 대한 완전한 동작 증명입니까?
고정된 11 자료의 114 섹션을 색인으로 하여, 기본 35·보충 26·추가 13, 총 74의 유한한 저자 예시를 대응하고 있습니다. Callout은 정식형 13와 alias14·fallback·custom의 29 값을 표시했습니다. 59 문맥 행은 중복을 포함하는 자료 인덱스이며, 테스트 수가 아닙니다. 전체 문법, 전체 Mermaid/LaTeX, 임의의 CSS, NUL, 전체 코덱 및 각 디바이스의 동작은 검증되지 않았습니다.
연습용 파일은 실제로 사용한 원본인가요?
GUI에서 저장한 구 13 노트와 추가 13 노트, 참조·첨부·Base·CSS의 저자 fixture를 원본 바이트 그대로 저장할 수 있습니다. 전체 41 원본의 ZIP은 상대 경로를 유지한 새로운 포장입니다. 구 25 원본 ZIP도 보존하고 있습니다. CSS는 .obsidian/snippets에 배치했으며, 실제 GUI에서는 CSS snippets 페이지의 Reload와 toggle을 사용했습니다. loopbackURL의 서버는 종료되었으며, 다른 환경의 독자 가져오기는 아직 검증되지 않았습니다.
