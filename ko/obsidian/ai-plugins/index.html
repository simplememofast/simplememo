선택하기 전에 보는 것은 모델·문맥·색인·추가 기능

“로컬 대응”이라는 한 단어만으로는 플러그인 전체의 전송 대상이 정해지지 않습니다. 모델에 전달되는 노트의 발췌, 인덱스를 만드는 위치, 웹 검색 및 문서 변환 서비스, 진단·업데이트 확인을 구분하여 확인합니다.

  1. 모델프로바이더·엔드포인트·에이전트
  2. 참조하는 문맥선택문·발췌·템플릿
  3. 색인·검색로컬인지 다른 서버인지
  4. 추가 기능웹·문서 변환·진단·업데이트

이 도표는 공식 자료를 읽기 위한 정리입니다. 실제 통신 기록이 아닙니다. 비교는 고정된 자료와 소스 확인이며, 설정 화면 조작 및 실제 요청·제공자의 운영 감사는 포함되지 않습니다.

먼저 아래 표에서 사용할 기능의 경로를 확인해 주세요. 표에 있는 「소스」는 코드에서 읽을 수 있는 상수와 분기를 의미하고, 「제공자 설명」은 README 및 가이드의 기재를 나타냅니다.

Copilot：모델을 선택해도, 추가 기능의 경로는 별도로 남습니다

고정 버전 가이드는 hosted·Cloud BYOK·Local BYOK·opencode·Claude·Codex의 처리 대상을 구분하고 있습니다. 예를 들어 Local BYOK 모델이 local endpoint라는 설명이라도, 사용하는 스킬이나 project context에 따라 다른 서비스가 관련될 수 있습니다. Q03

노트의 참조와 Miyo의 인덱스를 구분

자료에는 에이전트가 노트를 읽고, 필요한 부분을 선택 모델의 프롬프트에 넣는 설명이 있습니다. Agent Chat을 열기만 해도 Vault 전체를 업로드하는 동작은 설명되지 않았습니다. Miyo는 로컬 연결과 원격 서버 연결이 있으며, 색인 및 검색 대상을 별도로 선택합니다. 검색으로 찾은 발췌는 모델의 맥락에도 들어갑니다. Local의 인덱스를 사용하는 것만으로는 발췌가 모델 provider에 전달되지 않는다고 말할 수 없습니다. Q03 / Q05

문서 처리도 일률적이지 않습니다. 자료상, Agent Chat의 Miyo 처리는 로컬 CLI를 사용하고, Quick Chat은 연결된 Miyo 서비스를 사용하며, remote인 경우 해당 서버에서 처리합니다. Web·YouTube·binary 파일을 사용하는 saved project context는 hosted project service를 사용할 경우가 있으며, Miyo의 선택과는 별개의 경로입니다. Q03

Self-Host Mode를 통신 차단 보증으로 하지 않음

가이드는 Self-Host Mode에서도 cloud가 비활성화되지 않는다는 것을 명시하고 있습니다. 선택한 Claude·Codex·클라우드 모델 및 검색 provider 등으로 보내는 경로는 남아 있습니다. 사용하고자 하는 기능과 허용되는 처리 대상이 일치하는지 기능별로 확인하기 위한 설정입니다. Q04

키의 getter, 초기 상수, 진단 방침은 각각의 근거에 따라 읽습니다

확인한 KeychainService의 범위는 app.secretStorage의 유무를 확인하고, 없을 경우 오류를 발생시킵니다. 실제로 키를 저장한 결과나 OS 암호화를 검증한 기록이 아닙니다. enableMiyo=false, enableMiyoSearchSkill=false, activeBackend=opencode, debugFullFrames=true는 소스 내 초기값이며, 이전된 설정이나 리더의 GUI 값을 표시하지 않습니다. Q07 / Q08 / Q09

README는 호스팅된 요청의 무작위 UUID와 독자가 선택하여 업로드하는 진단 ZIP을 설명합니다. ZIP의 60일 후 삭제, hosted request의 일시 처리·비보유·비학습은 제공자가 설명하는 방침입니다. 여기서 백엔드 운영을 감사한 것이 아닙니다. debugFullFrames=true만으로 진단 ZIP이 자동으로 전송된다고 판단할 수 없습니다. Q02

Smart Connections: 로컬 임베딩에 대한 설명과 전체 통신의 유무를 구분합니다

README는 내장 로컬 모델이 Vault를 색인하며 API 키가 필요하지 않다고 설명합니다. 관련 노트를 찾는 방식에 대한 안내로 볼 수 있지만, 이번 비교에서는 모델을 실행하거나 실제 색인 과정과 네트워크 통신을 관찰하지 않았습니다. README의 ‘private’, ‘offline’, 모바일 관련 설명도 제공자의 주장으로 취급합니다. Q10 / Q11

한편, 자체 src/main.js에는 initialize 후 업데이트 확인에서 GitHub latest-release로 GET을 예약하는 코드가 있습니다. 첫 번째 사용자의 StoryModal에는 smartconnections.app의 URL이 전달됩니다. 이는 통신과 관련된 코드 경로 확인입니다. StoryModal의 구현은 종속 측에 있으며, 실제로 URL이 로드되었는지, 어떤 payload가 전달되는지는 확인되지 않았습니다. Q12 / Q13

model・settings・HTTP 등 일부는 Smart Environment/jsbrains 관련 외부 패키지를 참조하고 있습니다. 이 범위만으로는 “모든 기능이 기기 내에 있다”, “텔레메트리가 없다”, “노트가 반드시 전송된다”고 단정할 수 없습니다. 로컬 인덱스 설명, 업데이트 확인 코드, 미확인 의존성·실통신을 구분하면 추가로 조사 대상을 알 수 있습니다. Q14

Text Generator：문맥 후보와 키 저장 분기를 확인합니다

클립보드를 가져올 수 있는 설정과 실제 프롬프트는 별도

고정 버전의 초기 설정에는 includeClipboard=true이 있으며, context builder는 그 값이 true이면 clipboard를 가져올 수 있는 분기를 가지고 있습니다. 한편, 인용한 초기 템플릿에 있는 것은 title, starredBlocks, tg_selection이며, 클립보드 플레이스홀더가 아닙니다. Q15 / Q17

template, frontmatter, context options, 선택 범위에 따라 해결되는 값이 달라집니다. 사용 가능한 값 목록과 실제 요청에 들어간 값을 동일한 것으로 취급하지 마십시오. 이 코드 확인은 “clipboard가 반드시 전송된다”, “Vault 전체가 항상 전송된다”는 결과가 아닙니다. Q17 / Q18

plain key 열의 빈 문자는 암호화의 증거가 되지 않습니다

초기값은 encrypt_keys=false입니다. 저장 시 plain key 필드를 비우는 처리와 별도의 secret 관련 필드를 준비하는 처리가 있습니다. getEncryptedKey은 암호화를 사용할 수 없거나 encrypt_keys가 비활성화된 경우, 고정 프리픽스와 입력 키를 연결한 값을 반환합니다. 필드 이름에 encrypted/hashed가 포함되어 있더라도, 그것만으로는 암호화된 바이트라고 판단할 수 없습니다. Q15 / Q19 / Q20 / Q21 / Q22

키를 입력하지 않았기 때문에 실제 저장 내용 및 이 단말기의 safeStorage 동작은 확인되지 않았습니다. 키가 포함된 설정 파일이나 진단 기록을 공유하기 전에, plain 필드뿐만 아니라 저장되는 다른 값에도 주목해야 합니다.

초기 provider와 로컬 대응을 구분하여 선택합니다

소스의 초기 공급자는 OpenAI Chat (Langchain)이며, 엔드포인트는 https://api.openai.com/v1입니다. Ollama provider는 설정한 basePath를 수신하는 구현이 있습니다. Local 지원 provider가 있다는 사실만으로는 다른 기능의 처리 대상이나 전체 통신이 없다는 것이 증명되는 것은 아닙니다. Q15 / Q23 / Q24

첨가된 request, automatic suggestions, slash suggestions, JavaScript 실행은 인용한 초기값에서 OFF입니다. 이것들도 현재 GUI의 실제 측정값이 아닙니다. 사용할 템플릿과 저장된 설정을 자신의 환경에서 확인해 주세요. Q15 / Q16

설정을 변경한 후의 상태는 이 표에서 실제 측정한 결과가 아닙니다. 자신의 노트를 사용하기 전에, 어떤 기능을 사용하고 어떤 데이터를 허용 대상에 전달할지 결정하기 위한 읽는 방법으로 사용하십시오.

자주 묻는 질문

로컬 모델을 선택하면 플러그인이 전혀 통신되지 않나요?
모델의 처리 대상과 인덱스·웹 검색·문서 변환·업데이트 확인은 별개의 경로입니다. Copilot의 자료는 추가 기능의 경로를 구분하고, Smart Connections의 자체 코드에는 GitHub 업데이트 확인 GET이 있습니다. 이번 자료 확인에서는 전체 기능이 통신되지 않는 것이나 실제 전송 내용을 확인하지 않았습니다.
Smart Connections는 노트를 외부로 전송합니까?
고정판 README는 임베딩 로컬 모델을 사용하여 임베딩과 인덱스를 만든다고 설명하고 있습니다. 이는 제공자의 설명입니다. 자체 소스에 업데이트 확인 및 최초 안내인 URL이 있으며, 모델·설정 등은 일부가 외부에 의존하고 있습니다. 실제 노트 전송 및 전체 통신의 유무는 이 비교에서 측정하지 않습니다.
Text Generator의 includeClipboard=true는 클립보드를 반드시 전송한다는 의미입니까?
소스에서는 해당 설정이 true일 때 context builder가 클립보드를 가져올 수 있는 분기점이 있습니다. 한편, 게재된 초기 템플릿은 title, starredBlocks, tg_selection을 사용하며, clipboard 지정은 없습니다. 사용 가능한 값과 실제로 구성된 요청의 내용은 다릅니다. 실제 payload는 측정되지 않았습니다.
저장 데이터의 api_key가 비어 있다면, 키가 암호화되어 있습니까?
빈 키 필드만으로는 판단할 수 없습니다. Text Generator 0.8.7에서는 plain key 필드를 비우는 저장 처리와 별도의 저장 필드가 있으며, 암호화를 사용할 수 없거나 encrypt_keys가 무효인 경우 고정 프리픽스와 입력 키를 반환하는 분기점이 있습니다. 실제 키 저장 및 플랫폼 암호화 동작은 시도하지 않았습니다.
