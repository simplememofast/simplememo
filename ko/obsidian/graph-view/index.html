Obsidian / 그래프 뷰

표시 범위를 선택하고 본문으로 돌아갑니다

Obsidian의 그래프 뷰를 사용하여
표시 범위를 좁혀 연결을 확인합니다

그래프를 열면, 보고 싶은 노트의 범위를 먼저 선택합니다. 폴더 태그에 의한 검색, 고립된 노트 표시, 색상 그룹, 로컬 그래프의 깊이를 작은 저자 제작 보관함에서 확인했습니다.

저자: SimpleMemo Developer · 실제 작업 확인: 2026년 10월 1일(일본 시간) · Linux 버전 Obsidian 1.13.7

이 페이지의 내용

01보고 싶은 범위에 맞추어 전체와 가까운 노트를 선택합니다↗02이 예시의 저장 내용 및 표시 조건↗031. 노트를 추가하고 저장 내용과 그래프를 비교합니다↗

보고 싶은 범위에 맞춰 전체와 가까운 노트를 선택합니다

보관함 전체를 볼 때는 전역 그래프로 검색을 사용하고, 열린 노트 주변을 볼 때는 로컬 그래프의 깊이를 선택합니다. 색 그룹은 선택한 조건에 맞는 노트를 구분하는 표시입니다. 본문 및 내부 링크가 저장되어 있는지는 노트를 열어 확인합니다.

노트 추가 전후폴더와 태그고립 노트색 그룹로컬의 깊이연습용 파일

예시의 노트명·문장·태그는 저자가 만든 것입니다. 연구 및 생활의 실제 기록은 이용자의 보관함에서 채취한 것이 아닙니다. 표시 위치는 레이아웃이며, 소요 시간이나 이해 정도를 나타내는 값이 아닙니다.

카드를 직접 배열하여 관계를 나타내는 절차는 Canvas에서 생성·연결·이동·재표시하는 예시를 참조하십시오.

이 예시의 저장 내용 및 표시 조건

처음에 여섯 개의 Markdown을 준비했습니다。「 '연구'의 세 노트는 입구→가설→검증이며, '생활'의 두 노트는 쇼핑→식사와 내부 링크로 연결되고, 고립된 노트에는 다른 노트에 대한 링크가 없습니다. 두 개의 연결 성분과 하나의 고립된 노트를 구분할 수 있는 연습용 구성입니다.

研究/入口.md → 研究/仮説.md → 研究/検証.md
生活/買い物.md → 生活/食事.md
孤立.md

後からGUIで追加: 追加メモ.md → 研究/入口.md

첫 번째 여섯 개 파일은 앱 실행 전에 준비하고, 일곱 번째 파일만 실제 편집기로 만들었습니다. '연구' 폴더의 세 노트와 추가 메모에는 #研究을, 생활의 두 노트에는 #生活을 적어 두었습니다.

글로벌 그래프의 초기 조건은 Search files 공란, Tags OFF, Attachments OFF, Existing files only OFF, Orphans ON입니다. 해결되지 않은 링크는 없었습니다. 이후 비교에서는 설명한 검색·Orphans·색상 그룹만 전환했습니다.

1. 노트를 추가하고, 저장 내용과 그래프를 비교합니다

왼쪽 리본에서 Open graph view를 엽니다. 처음에는 6노트·3링크였습니다. 다음으로 Ctrl＋N에서 “추가 메모”를 만들고, 이름과 본문을 실제 편집기에 입력했습니다. 저장한 전체 텍스트는 다음 92 바이트입니다.

# 追加メモ

GUIで追加する著者作成ノートです。 [[研究/入口]]

#研究

자동 저장을 기다렸다가 그래프를 열면 일곱 노트·네 링크가 되었습니다. 추가 메모에서 研究/ 입력으로의 하나가 증가했으며, 저장된 Markdown과 내부 링크의 해결 결과도 일치했습니다.

설정 패널이 일부 노드를 덮고 있습니다. 이 두 이미지의 건수는 실제 Graph 렌더러에서 노드 이름과 링크 끝점을 읽어 확인한 값입니다. 이미지 안에 모든 원을 볼 수 있다는 계산 방법은 아닙니다. 이미지는 그대로 보존하고 있습니다.

마지막으로 파일 목록에서 추가 메모를 다시 열어 본문과 태그를 읽었습니다. 추가 시·재표시 후·앱 정상 종료 후의 저장 Markdown은 동일한 내용이었습니다.

2. 폴더와 태그에서 서로 다른 범위를 선택합니다

Graph settings의 Filters → Search files에 검색 문자열을 입력합니다. 폴더 내의 노트를 선택하는 예는 path:"研究/"이며, 태그가 포함된 노트를 선택하는 예는 tag:#研究입니다. 이번 결과는 다음과 같이 달랐습니다.

입력한 조건대상 노트확인한 구조
path:"研究/"研究 폴더의 입구·가설·검증3노트 / 2링크
tag:#研究위의 세 노트와 보관함 바로 아래에 있는 추가 메모4노트 / 3링크
검색 문자열을 비우기이번 일곱 노트 전부7노트 / 4링크

추가 메모는 보관함 바로 아래에 있기 때문에 研究 폴더의 통과 조건에 포함되지 않습니다. #研究을 가지고 있기 때문에 태그 조건에 포함됩니다. 여기에서는 태그 전환을 OFF 상태로 유지하고, 태그 자체를 노드로 표시하는 작업은 시도하지 않았습니다.

필터링을 마칠 때는 Search files를 비워 둡니다. 이번에 검색 후보가 작업과 겹쳤을 때는 Esc으로 닫은 후 다음 전환을 클릭했습니다. 폴더 이름과 태그 이름은 자신의 저장 내용에 맞춥니다.

3. 고립된 노트도 보려면 Orphans를 ON으로 설정하십시오

검색 문자열을 비워 둔 상태에서 Filters의 Orphans를 OFF하면 孤立.md이 사라지고, 6노트·4링크가 되었습니다. ON으로 되돌리면, 孤立.md을 포함한 7노트·4링크로 돌아갔습니다. 두 경우 모두 링크 끝점은 동일합니다.

이 예에서는 저장된 고립된 노트에 내부 링크가 없었기 때문에 전환 시 표시 대상이 변경되었습니다. 노트가 보이지 않을 때는 본문이 저장되어 있는지 현재 그래프의 검색·표시 조건을 각각 확인합니다. 미해결 링크와 모든 필터 조합을 시도한 결과가 아닙니다.

4. 색 그룹으로 조건에 맞는 노트를 구별하기

Groups → New group에서 그룹을 추가하고, 첫 번째에 path:"研究/"을, 두 번째에 tag:#生活을 입력했습니다. 그룹의 색상 원을 클릭하고, Linux 색상 선택 화면에서 첫 번째를 RGB 30 / 140 / 220(#1e8cdc)로 변경하고 있습니다. 두 번째 할당 색상은 #d6ad5c였습니다.

研究 폴더의 세 노트는 파란색이고, 생활 태그의 두 노트는 금색이 되었습니다. 보관함 바로 아래에 있는 추가 메모와 孤立.md은 이 두 조건에 해당하지 않으므로, 그룹 색상이 적용되지 않았습니다. 노드명·색상의 읽기도 대조했으며, 전체의 일곱 노트와 네 개의 링크는 변하지 않았습니다.

원본 이미지는 실제 색상 선택 화면이며, GUI 입력에는 기존의 X11 마우스·키보드 보조를 사용했습니다. 앱 API 및 DOM의 값 대입에서 색상을 설정하지 않았습니다. 색 그룹의 중복, 정렬, 다른 색상 및 OS 선택 화면은 시도하지 않았습니다.

5. 로컬 그래프의 깊이에서 가까운 노트를 선택합니다

파일 목록에서 研究/入口.md을 열고, 노트의 More options → Open linked view → Open local graph를 선택했습니다. 로컬 그래프의 Filters에는 깊이 슬라이더가 있습니다. 이번 조건은 Incoming links ON, Outgoing links ON, Neighbor links OFF입니다.

깊이입구 주변에 포함된 노트확인한 구조
1입구, 입구에서 참조하는 가설, 입구를 참조하는 추가 메모3노트 / 2링크
2위에 가설에서 참조하는 검증이 추가됩니다4노트 / 3링크

Depth를 실제 슬라이더 조작으로 1에서 2로 변경하고, 노드명과 링크 엔드포인트를 확인했습니다. 생활의 두 노트와 孤立.md는 입구에 연결되지 않았기 때문에 이 두 깊이에 들어가지 못했습니다.

두 이미지는 설정을 선택한 후 패널을 닫고 촬영한 원본 이미지입니다. 입구를 대상으로 한 깊이 1·2의 기록입니다. 다른 노트를 열면, 링크된 로컬 그래프의 대상도 변경됩니다. 깊이 3~5 및 Incoming/Outgoing/Neighbor links의 다른 조합은 시도하지 않았습니다.

연습용 일곱 개의 Markdown을 다운로드합니다

일곱 파일은 GUI 추가 후 저장한 Markdown 원본과 동일한 바이트입니다. ZIP은 이 기사 준비 시 만든 배포용 패키지이며, 일곱 개의 본문과 상대 경로를 유지하고 있습니다. 개별 다운로드에서는 표의 폴더 이름과 파일 이름을 함께 배치합니다.

7개의 파일을 한 번에 저장합니다(ZIP)

보관함 내의 상대 경로원 Markdown
孤立.md孤立.md을 저장
生活/買い物.md買い物.md을 저장
生活/食事.md食事.md을 저장
研究/仮説.md仮説.md을 저장
研究/入口.md入口.md을 저장
研究/検証.md検証.md을 저장
追加メモ.md追加メモ.md을 저장

ZIP을 확장한 일곱 파일의 상대 경로와 본문인 SHA256을 원본과 대조했습니다. 독자 측에서의 ZIP 가져오기, 다른 보관함에 배치, 공개 서버에서의 배송은 실제 애플리케이션 검증에 포함되지 않습니다.

자주 묻는 질문

그래프에 노트가 보이지 않을 때, 무엇을 확인합니까?
이번 예에서는 Search files의 검색 문자열과 Orphans의 ON/OFF에 따라 대상이 변경되었습니다. 대상 노트를 열어 저장 내용을 확인하고, 검색 문자열을 비우며, 고립된 노트도 확인하려면 Orphans를 ON으로 설정하십시오. 태그, 첨부 파일, 기존 파일만 해당 등의 조건도 공식 도움말에서 확인할 수 있습니다. 모든 설정의 조합을 시도하지 않았습니다.
글로벌 그래프와 로컬 그래프는 어떻게 다릅니까?
글로벌 그래프는 저장소의 노트 전체를 대상으로 하고, 로컬 그래프는 열린 노트와 연결되는 범위를 대상으로 합니다. 이번 입구 노트에서는 Incoming links와 Outgoing links를 ON으로, Neighbor links를 OFF로 설정했으며, 깊이 1에서 3 노트·2 링크, 깊이 2에서 4 노트·3 링크였습니다. 다른 연결 성분이나 고립 노트는 포함되지 않았습니다.
Tags 전환과 tag: 검색은 같은 작업인가요?
공식 도움말의 Tags는 태그를 그래프에 표시하기 위한 전환입니다. Tag: 검색은 지정한 태그를 포함하는 노트를 좁혀 검색합니다. 이번에 태그는 꺼 둔 채로, tag:#研究으로 4 노트를 표시했습니다. 태그 자체를 노드로 표시하는 작업은 이 예에서 시도하지 않았습니다.
노드와 선이 많다면, 지식과 생산성이 높다고 판단할 수 있습니까?
이 기사에서 확인한 것은 저장된 노트, 내부 링크, 지정한 표시 조건에 따른 구조 차이입니다. 지식의 정확성, 이해의 깊이, 생산성 및 속도는 측정하지 않습니다. 본문에서 링크의 이유를 확인하는 연습은 Zettelkasten의 노트와 링크 실천 가이드에서 소개하고 있습니다.

검증 환경 및 확인 범위

  • 실제 앱:Linux 버전 Obsidian 1.13.7, 설치 프로그램 1.13.7. 커뮤니티 플러그인 없이, 저자가 만든 작은 일본어 보관함.
  • 실 GUI：그래프 열기, 노트 새로 만들기·입력·저장, 검색 입력, Orphans 전환, 그룹 생성 및 색상 선택, 파일 목록 및 메뉴에서 로컬 그래프 열기, Depth 슬라이더, 재표시, General 설정, 정상 종료.
  • 보조:초기 6 Markdown을 실행하기 전에 준비하고, 저장 파일·내부 링크 해결 결과·렌더러의 노드명·선수·색상·설정을 읽어들였습니다. 노트 추가 및 표시 조건 변경은 실제 GUI입니다.
  • 이미지:실제 화면의 원본 PNG를 가공하지 않고 게재합니다. 설정 패널 및 좁은 표시 영역이 일부 노드를 덮는 기록이 있으며, 건수는 명시된 API 판독값으로 대조하고 있습니다.
  • 미검증：iOS/Android/Windows/macOS、Sync、SimpleMemo 연동、별도 기기、대형 보관함、모든 검색·표시 설정、속도、학습·생산성、유입 효과。

실제 작업의 날짜는 2026년 10월 1일(일본 시간)이며, 기록된 UTC 날짜는 2026년 9월 30일입니다. 원본 읽기 기록 및 보조 코드 수정, 저장 파일·원본 이미지의 대응은 검증 기록에 정리합니다.

공식 설명 확인처

  • Obsidian 공식 도움말: Graph view — Filters, Groups, Local Graph에 대한 설명.
  • Obsidian 공식 도움말: Search — path:와 tag:에 대한 설명.

고정된 공식 소스 설명과 이 Linux에서의 제한된 실제 작업을 구분하고 있습니다. 공식 설명에 있는 모든 기능을 실제로 시험해 본 결과가 아닙니다. 본 사이트는 독립 앱 “SimpleMemo”을 소개하는 개발자 사이트이며, Obsidian 공식 기사(문서)가 아닙니다.
