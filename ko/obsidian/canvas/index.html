작은 카드로 저장 내용까지 확인합니다

Obsidian의 Canvas를 사용하는
카드를 배열하고, 선에 이름을 붙입니다

빈 캔버스를 만들고, 짧은 문장 두 장과 기존 노트 한 장을 배치하여 선과 라벨을 저장하는 연습입니다. Linux 버전의 실제 화면과 저장 파일을 사용하여 카드 이동 및 다시 열기까지 확인했습니다.

저자: SimpleMemo Developer · 실제 작업 확인: 2026년 10월 1일(일본 시간) · Linux 버전 Obsidian 1.13.7

문장을 놓기, 노트를 참조하기, 선으로 연결하기

Canvas는 텍스트 카드와 노트 카드를 평면에 배치하는 Obsidian의 코어 플러그인입니다. 우선 세 장만 배열하고, 두 장을 선으로 연결한 뒤, 그 관계를 라벨에 남깁니다. 본문과 참조하는 노트가 저장되어 있는지도 확인하겠습니다.

새로 생성카드를 놓으십시오선과 라벨카드 이동저장 및 재표시연습용 파일

카드의 문장과 참고 메모는 저자가 작성한 짧은 문장입니다. 실제 이용자의 기록이 아닙니다. 도표의 배열은 수동으로 배치한 것이며, 지식의 정확성이나 생산성을 측정한 결과가 아닙니다.

1. 명령 팔레트에서 빈 캔버스를 생성합니다

이번 환경에서는 Canvas와 명령 팔레트를 활성화했습니다. Ctrl＋P에서 명령 팔레트를 열고, Canvas: Create new canvas를 선택합니다. 왼쪽 파일 목록에 있는 이름은 Untitled.canvas이었습니다. 빈 상태로 저장한 원본 파일은 {}의 2 바이트입니다.

앞으로 배치할 카드의 문장은 허구의 관찰 및 확인 안내입니다. 참조용 資料/参照メモ.md은 앱 실행 전에 준비했습니다. 카드를 추가하는 작업은 실제 Canvas에서 수행하고 있습니다.

2. 짧은 문장 두 장과 기존 노트 한 장을 놓으십시오

Canvas의 빈 공간을 더블 클릭하고 텍스트를 입력합니다. 다른 빈 공간에서도 같은 작업을 수행하여 두 개의 텍스트 카드를 만들었습니다. 저장한 전체 텍스트는 다음과 같습니다.

텍스트 카드 A

# 観察カード

著者作成の短文を並べます。

텍스트 카드 B

# 次の確認

参照メモを開いて本文を確認します。

다음으로, 파일 목록의 資料/参照メモ.md을 Canvas로 드래그합니다. 세 번째는 그 Markdown을 참조하는 파일 카드입니다. 이번 저장 데이터에서는 두 장이 type: text이고, 한 장이 type: file이 되었습니다.

짧은 문장 카드의 높이는 60이며, 전체를 한 번에 표시하지 않습니다. 이미지 카드 내부에는 스크롤바가 있으며, 보이는 부분이 다릅니다. 카드 내 표시만으로 전체를 판단하지 않고, 본문 및 저장 내용도 확인합니다.

3. 두 장을 연결하고, 선에 “本文を確認”이라고 씁니다

  1. 관찰 카드의 오른쪽 끝에 포인터를 놓고, 나타나는 원에서 다음 확인 카드의 왼쪽 끝으로 드래그합니다.
  2. 만든 선을 더블 클릭합니다.
  3. 本文を確認를 입력하고, Esc에서 라벨 편집을 마칩니다.

저장된 연결은 관찰 카드의 오른쪽에서 다음 확인 카드의 왼쪽으로 이동하며, 라벨은 本文を確認입니다. 세 번째 참조 메모에는 이 예에서 선을 연결하고 있지 않습니다. 이미지에서도 두 장 사이의 라벨과 참조 메모 본문을 확인할 수 있습니다.

4. 카드를 선택하고 내부를 드래그하여 위치를 변경합니다

참조 메모의 파일 카드를 선택하고, 내부에서 드래그하여 이동했습니다. 첫 번째 작업에서는 경계를 파악하고, 의도치 않게 크기를 바꾸어 버렸습니다. 그 상태를 기록한 후, Ctrl＋Z으로 되돌리고 내부를 다시 드래그하고 있습니다.

최종 저장 데이터에서는 파일 카드의 좌표만 x=-32, y=61에서 x=-160, y=-60로 변경되었으며, 400×400의 크기, 참조 대상, ID는 동일했습니다. 다른 두 개의 본문과 연결의 의미도 동일합니다.

이것은 한 장의 내부 드래그를 확인한 기록입니다. 크기 변경 기능을 일괄적으로 검증한 작업이 아닙니다. 좌표는 저장 내용의 비교이며, 소요 시간이나 효율을 나타내는 값이 아닙니다.

5. 저장하고, 다른 노트에서 Canvas를 다시 엽니다

Ctrl＋S으로 저장하고, 파일 목록에서 다른 Markdown을 열었으며, 그 후 Untitled.canvas로 돌아갔습니다. 저장된 세 장의 카드·한 연결·라벨을 확인하고 있습니다.

이동 후·재표시 후·앱 종료 후의 Canvas 원본은 모두 612 바이트에서 SHA256과 일치했습니다. 한편, Canvas의 표시 위치와 텍스트 카드 내의 스크롤 위치가 변경되었습니다. 저장 파일의 일치와 화면 표시가 완전히 동일한 것은 별개의 확인입니다.

이번에는 같은 앱의 프로세스 내에서 다시 열었습니다. 앱 전체를 종료하고 재시동한 후의 복원, 다른 기기나 동기화는 시도하지 않았습니다. 마지막으로 General 설정에서 app/installer 1.13.7을 실제로 표시하고, 내 앱과 표시용 프로세스를 정상적으로 종료했습니다.

연습용 Canvas와 참조 메모를 저장합니다

다음 두 파일은 실제 작업 후에 저장한 원본과 동일한 bytes입니다. Canvas가 참조하는 資料/参照メモ.md의 상대 경로도 유지합니다. 개별적으로 저장하는 경우에는 동일한 보관함 내에서 다음 배치에 맞춥니다.

Untitled.canvasUntitled.canvas을 저장(612 바이트)

두 파일을 한 번에 저장합니다(ZIP)

ZIP은 기사 준비 시 만든 새로운 배포용 패키지이며, 두 파일의 본문과 상대 경로를 유지합니다. 전개 후의 패스·SHA256을 원본과 대조했습니다. 독자 측에서의 가져오기, 별도의 보관함, 공개 서버에서의 배송은 아직 검증되지 않았습니다.

자주 묻는 질문

Canvas의 텍스트 카드와 노트 카드는 어떻게 다릅니까?
이번 텍스트 카드의 문장은 .canvas 내의 text 필드에 저장되어 있으며, 노트의 카드는 파일 필드에서 資料/参照メモ.md을 참조하고 있습니다. 텍스트 카드를 다른 Markdown으로 변환하는 작업이나 백링크 동작은 시도해 보지 않았습니다.
카드끼리 연결하고 선에 이름을 붙이려면 어떻게 해야 하나요?
카드의 가장자리에 포인터를 놓고, 나타난 원을 다른 카드로 드래그합니다. 선을 더블 클릭하고 라벨을 입력한 뒤 Esc로 편집을 완료합니다. 이번에는 두 개의 텍스트 카드를 연결하여 本文を確認이라는 라벨을 저장했습니다.
다운로드한 Canvas에는 참조 메모도 필요합니까?
이 예시의 파일 카드는 資料/参照メモ.md이라는 상대 경로를 참조하고 있습니다. Untitled.canvas뿐만 아니라 동일한 보관함 내의 資料 폴더에 参照メモ.md을 배치하는 구성입니다. 두 파일의 원래 상대 경로를 유지하는 ZIP도 준비했습니다. 독자 측의 가져오기와 다른 보관함은 아직 검증되지 않았습니다.
저장한 Canvas를 다시 열면 화면도 완전히 동일해지나요?
이번에 같은 앱 내에서 다른 노트로 이동하여 Canvas를 다시 열면, 저장한 612 bytes와 SHA256이 일치했습니다. 한편, 화면 표시 위치와 텍스트 카드 내 스크롤 위치가 변경되었습니다. 앱 전체를 재시동한 후, 다른 기기, 동기화, 속도 및 생산성을 확인하지 않았습니다.

검증 환경 및 확인 범위

  • 환경：Linux 버전 Obsidian 1.13.7, 설치 프로그램 1.13.7, 커뮤니티 플러그인 없음. 저자가 만든 작은 일본어 보관함.
  • 실제 GUI:명령 선택, 새 Canvas, 텍스트 입력, 파일 목록에서 드래그, 연결 및 라벨, Undo와 내부 드래그, 저장, 별도 노트를 통한 재표시, General 설정, 정상 종료.
  • 보조:초기 Markdown의 준비, 원본 파일 저장, readonly의 Canvas 데이터·active view·DOM 위치 읽기. 카드 생성·연결·이동을 앱 API에서 수행하지 않았습니다.
  • 원본 이미지:실제 화면의 PNG를 가공하지 않고 게재합니다. 단문 카드의 전체 텍스트는 한 번에 보이지 않으며, 재표시 시의 표시 위치도 동일하지 않습니다.
  • 미검증:그룹, 색상, 이미지·음성·웹 삽입, 변환, 전체 크기 변경, 전체 앱 재시작, 대형 Canvas, 정식 JSON Canvas 규격 적합, iOS/Android/Windows/macOS, Sync, SimpleMemo, 속도·생산성·유입 효과.

실제 작업은 2026년 10월 1일(일본 시간)이며, 기록 UTC는 2026년 9월 30일입니다. 초기 준비 실패와 복원, 원본 이미지·저장 파일의 대응은 검증 기록에 정리합니다.

공식 설명 확인처

  • Obsidian 공식 도움말: Canvas — 새로 만들기, 카드, 연결, 라벨, 이동에 대한 설명. 커밋을 고정하고 확인했습니다.

공식 설명에는 이 예시에서 시도하지 않은 기능도 포함되어 있습니다. 본 사이트는 독립 앱 “SimpleMemo”의 개발자 사이트이며, Obsidian 공식 기사(문서)가 아닙니다.
