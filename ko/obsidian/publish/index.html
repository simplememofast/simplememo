Obsidian / Publish와 대체

공개 서비스와 생성·배포 역할을 선택합니다

Quartz와 배포 대상을 비교합니다

호스팅을 맡길지, 생성물을 직접 관리할지

Publish는 노트를 웹에 공개하는 공식 호스팅 서비스입니다. Quartz는 Markdown에서 사이트를 생성하는 도구이며, 생성물의 배포 대상을 별도로 선택합니다. GitHub Pages는 그 배포 대상 중 하나입니다. Quartz와 GitHub Pages를 결합할 경우, 생성과 배포의 두 가지 역할을 다룹니다.

공개하고 싶은 노트를 선택하고, 사이트 호스팅을 서비스에 맡기고 싶으시면 Publish 조건을 확인하십시오. 명령 실행이나 설정 변경, 배포 대상 관리를 직접 할 수 있는 경우에는 Quartz와 같은 정적 생성을 작은 노트에서 시도합니다. 저장한 노트를 웹에 공개할 필요가 없으면, 공개용 추가 서비스를 선택하기 전에 목적을 정합니다.

역할 비교요금 확인실내 빌드 입력생성 절차화면과 링크연습용 파일

Publish・Quartz・GitHub Pages에서 담당 범위가 다릅니다

선택지역할과 자신이 해야 할 일이번 확인
Obsidian Publish공식 클라우드 호스팅. 계정과 Publish 계약을 준비하고, 공개할 노트와 사이트를 관리합니다.공식 Introduction/Set up을 고정 소스에서 확인하십시오. 계약·Publish 실제 조작·실제 공개는 아직 수행되지 않았습니다.
석자Markdown 등에서 사이트를 생성하는 도구. Node/npm, 설정, 입력 파일, 생성물을 직접 처리합니다.v4 브랜치의 고정 커밋, package 4.5.2에서 실제 npm ci·로컬 빌드·브라우저 표시.
GitHub 페이지리포지토리에서 정적 사이트를 배포하는 서비스. 리포지토리, 공개 원본·워크플로우, 공개/비공개 및 플랜 조건을 관리합니다.공식 자료를 고정 소스로 확인합니다. 신규 리포지토리 생성·설정·배포·실배포는 아직 수행되지 않았습니다.

이 표는 모든 기능을 비교하는 순위가 아닙니다. Quartz로 빌드할 수 있었다는 것이 Published와 동일한 서비스 기능이나 GitHub Pages에서의 배포 성공을 의미하지 않습니다.

요금은 계약·배포 대상·운용을 구분하여 확인합니다

Publish의 현재 금액은 이번 환경에서는 재확인되지 않았습니다. 최신 금액과 연간·월간 결제 청구 기간은 Obsidian 공식 요금에서 확인해 주세요. 이 실제 빌드의 성공으로 인해 Publish가 무료가 된다는 결과를 얻지 못했습니다.

고정한 Quartz 소스는 MIT 라이선스였습니다. 이는 소프트웨어 이용 조건이며, 배포 대상, 고유 도메인, 업데이트 작업까지 비용이 일괄적으로 0이 되는 조건이 아닙니다. 이번 실행 비용도 알 수 없습니다.

고정된 GitHub 공식 자료는 GitHub Free와 조직용 GitHub Free에서는 공개 리포지토리에서 Pages를 이용할 수 있으며, Pro/Team/Enterprise 조건에서는 공개·비공개 리포지토리를 지원한다고 안내하고 있습니다. 실제로 선택하는 계정의 플랜, 공개 범위, 제한 및 계약 조건을 확인합니다. 이번에도 계정 및 호스팅 설정을 변경하지 않았습니다.

기존 요금 목록은 2026년 9월 9일에 공식 표시를 확인한 기사입니다. 이번에는 이를 현행 요금의 독립 확인으로 처리하지 않고, 최신 구매 조건은 공식 확인이 필요한 정보로 구분합니다. Publish와 기기 간 동기화의 Sync도 별도의 서비스입니다.

작은 세 개의 노트와 첨부 파일로 생성을 확인합니다

이용자의 보관함이 아니라, 저자가 만든 가상의 일본어 Markdown 3건과 SVG 1건을 직접 준비했습니다. Frontmatter의 title/tags/날짜, wiki 링크, 첨부 파일이 대상입니다. 날짜는 fixture 내의 고정값이며, 웹 공개일이 아닙니다.

고정 소스를 전개하고, 의존성 및 설정을 확인하여 빌드합니다

  1. 공식 Quartz의 v4 브랜치를 확인하고, commit d25a6eabf96751ffca56f8a8139272def7a65041의 소스 아카이브를 scratch 내에 배포했습니다.
  2. README, MIT 라이선스, package.json, package-lock.json, CLI의 빌드 처리를 확인했습니다. 패키지 버전은 4.5.2이며, 필요 버전은 Node 22 이상·npm 10.9.2 이상입니다. 실제 환경은 Node 24.19.0·npm 11.9.0였습니다.
  3. 고정된 lockfile로 npm ci을 실행했습니다. 491 패키지가 설치되고, 0를 exit합니다. Lockfile의 597 entries는 지원 OS 등의 의존성도 포함하는 기록이며, 설치 표시 건수와 동일한 의미가 아닙니다. 원본 lockfile의 바이트는 변하지 않았습니다.
  4. 개인 설정을 변경하고, 세 개의 노트를 대상으로 Quartz CLI로 생성했습니다. 설정 변경 및 최초 실패에 대해 다음에 설명하겠습니다.

실행한 명령의 형식은 다음과 같습니다. 예시의 입출력 폴더는 자신이 준비한 위치를 지정합니다.

npm ci --no-audit --no-fund
node quartz/bootstrap-cli.mjs build   --directory /path/to/fixture   --output /path/to/generated   --concurrency 1

실행 로그에는 scratch 내의 절대 경로와 격리된 npm 캐시 지정이 남아 있습니다. 여기서 제시한 path는 설명용 대체입니다. Audit를 생략한 명령으로 의존성 보안 감사를 통과했다는 의미는 아닙니다. 이 문서는 공개 서버에 대한 배포 절차를 수행한 기록이 아닙니다.

수식첫 번째는 표준 Latex가 외부 KaTeX CSS/JS를 요구했으며, 환경 측에서 차단되었습니다. 수식이 없는 동일한 fixture에서 사용되지 않은 Latex를 비활성화하고 다시 빌드했습니다.

두 번의 빌드는 모두 0을 exit하고, 각 20 파일을 생성했습니다. 첫 번째 생성물과 실패한 브라우저 기록을 남기고, 설정 변경 후 생성물을 다른 폴더에서 확인하고 있습니다. 표준 Quartz가 외부 통신을 하지 않는다는 결론이나 수식 호환성에 대해서는 확장하지 않습니다.

생성한 HTML, 위키 링크, 첨부 파일을 실제로 엽니다

로컬 서버에서 생성물을 열고, 320/390/768/1440 px의 네 가지 폭을 확인했습니다. Title·일본어 본문·검증 태그·SVG를 읽고, 입구→확인→참고→입구를 각 폭으로 실제로 클릭했습니다. 총 12 클릭에 대한 제한된 확인입니다.

생성 HTML 3건, CSS, JS 2건, contentIndex, SVG 총 8건은 localhost의 실제 HTTP 응답과 생성 원본의 bytes/SHA256이 일치했습니다. 첨부된 SVG도 입력 원본과 동일한 내용입니다. 설정 변경 후의 사폭에서는 가로가 튀어나와 해당 페이지의 console/page/resource 오류가 없었습니다.

이미지 내의 그래프와 백링크 위젯이 표시되고 있지만, 그 모든 기능은 테스트하지 않았습니다. Fixture 안에 본문 제목도 작성했기 때문에 Quartz 측의 기사 제목과 겹쳐 표시됩니다. 현행 요금 확인, SEO 성능, 대형 Vault, 웹 공개의 증명으로 계산되지 않습니다.

자주 묻는 질문

Obsidian의 노트를 웹에 공개하려면 Publish 계약이 필수인가요?
Publish를 사용하려면, 공식 안내에서는 Obsidian 계정과 유효한 Publish 계약이 필요합니다. 다른 방법으로는 Quartz에서 Markdown에서 생성한 사이트를 직접 선택한 배포 대상에 배치하는 구성이 있습니다. 이번에는 Quartz의 로컬 생성까지 확인했으며, Publish 계약이나 외부 배포는 시도하지 않았습니다.
Quartz와 GitHub Pages는 같은 종류의 서비스인가요?
Quartz는 Markdown을 HTML·CSS·JavaScript 등으로 변환하는 도구이며, GitHub Pages는 리포지토리에서 정적 사이트를 배포하는 서비스입니다. Quartz로 만든 생성물을 GitHub Pages 등에 배치하는 구성입니다. GitHub Pages에 대한 설정·배포·실전 배포는 이번에 진행하지 않았습니다.
Publish 및 대체 방법의 비용은 어디에서 확인하면 될까요?
Publish의 최신 금액 및 청구 기간은 공식 요금 페이지에서 확인합니다. 이번 환경에서는 현재 요금 페이지를 다시 가져올 수 없으며, 현재 금액은 확인되지 않았습니다. Quartz의 고정 소스는 MIT 라이선스였지만, 배포 대상, 도메인, 운영 비용은 별도로 확인하겠습니다. GitHub Pages의 공개·비공개 리포지토리 플랜 조건도 공식 자료를 참조합니다.
이번 Quartz 확인만으로 웹 공개와 모든 기능의 호환성을 판단할 수 있습니까?
판단할 수 없습니다. 세 개의 저자가 만든 Markdown과 하나의 SVG에 대해 고정 커밋의 로컬 빌드, 네 화면 너비, 내부 링크 및 생성 파일을 확인했습니다. 미사용 Latex와 임의 OG 생성을 비활성화하는 등 설정 변경이 있습니다. 수식, 대형 보관함, 전체 Obsidian 기능, 외부 전송, 동기화, SimpleMemo 연동, 속도와 생산성은 아직 검증되지 않았습니다.

고정 소스와 확인된 범위

실제 빌드·브라우저 확인의 UTC 날짜는 2026년 9월 30일이며, 일본 시간은 2026년 10월 1일입니다. Node/npm/Quartz의 실판, source/lock, 설정 차이, 최초 실패, 보존 원본은 검증 기록에 정리합니다. 초기 브라우저의 언어 기대값 오류와 실패 JSON 건에 대한 덮어쓰기 누락도 명시하고 있습니다.

  • 실행 확인：개인 CLI의 npm ci와 두 빌드, 설정 변경 후의 로컬 사방·내부 링크·첨부·HTTP 원본 대조. 실제 Obsidian GUI 입력은 수행하지 않았습니다.
  • 공식 설명：Publish introduction/setup, Quartz source/docs, GitHub Pages 역할·플랜 조건을 고정 커밋으로 확인합니다.
  • 미확인:Publish 현재 금액·계약·실제 조작, GitHub Pages/다른 배포처의 배포 및 배송, 수식·임의의 Quartz OG·전체 기능, iOS/Sync/SimpleMemo, 전체 환경·속도·생산성·유입 효과.
