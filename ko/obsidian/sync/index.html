Obsidian 동기화 방법 비교

Obsidian을여러 기기에서동기화하는4의 방법

보관함은 특별한 형식이 없으며, 단지 Markdown 폴더일 뿐입니다. 따라서 동기화 방법은 Obsidian 자체에 얽매이지 않고, iCloud Drive와 같은 OS 표준 동기화, 유료 공식 Obsidian Sync, Git과 같은 버전 관리, Syncthing과 같은 자체 호스트형 동기화 도구까지 자유롭게 선택할 수 있습니다. 여기에서는 4 방식을 비용·지원 OS·컨플랙트 시 동작을 비교하고, Git와 Syncthing은 실제로 2대의 오프라인 편집을 충돌시켜 파손 방식을 확인했습니다.

한 마디로 말하면

Apple 제품만으로 완결한다면 iCloud Drive(기본으로 작동하며 추가 비용이 없습니다)이면 충분합니다. Windows/Android도 마찬가지이며, 공식 버전 기록이나 지원이 필요하시면 Obsidian Sync(유료). Git에 익숙하고 변경 기록도 커밋으로 남기고 싶다면 Git(무료·설정 필요). 클라우드 사업자를 거치지 않고 무료로 동기화하고 싶다면Syncthing(무료·설정 필요). iPhone·iPad는 공식적으로 지원되지 않습니다). 실측해 본 차이는 “충돌(경쟁 편집)이 발생했을 때 깨지는 방식”이며, Git은 노트 본문에 충돌 마커가 직접 삽입되어 수동 해결이 필요하고, Syncthing은 자동으로 한쪽을 남겨두고 다른 하나를 별도의 파일로 저장합니다.

iPhone에서음성으로 말하고 Obsidian에 남기는최단 방법은 4 방식의 비교(플러인 없이 절차 포함)에 정리했습니다.

4개의 동기화 방법

모두 “보관함 폴더의 내용을 여러 기기에서 정렬한다”는 동일한 작업을 수행하지만, 구조가 다릅니다.

☁️ iCloud 드라이브
Apple 순정 파일 동기화. 보관함 폴더를 iCloud Drive에 넣기만 하면, Mac/iPhone/iPad 사이를 추가 설정 없이 맞출 수 있습니다. Windows/Android/Linux에는 도착하지 않습니다.설정 절차는 별도 페이지에 정리하고 있습니다.
🔄 Obsidian Sync（공식·유료）
Obsidian 개발자가 제공하는 공식 서비스. E2E 암호화·버전 히스토리 기능을 갖추고 있으며, 모든 플랫폼에 대응합니다. 요금은별도 기사에서 실측 완료에서,Standard/Plus 어느 것이 필요한지도 별도의 페이지에서 정리하고 있습니다.
🌿 Git
저장소를 Git 리포지토리로 취급하고, 커밋·푸시·풀로 동기화하는 방식입니다. 커뮤니티 플러그인(Obsidian Git 등)을 사용하면 자동화도 할 수 있습니다. 모든 변경 사항이 기록으로 남는 반면, 갈등 해결에는 Git 지식이 필요합니다.
🔁 Syncthing
오픈소스 자체 호스트형 파일 동기화. 클라우드 사업자를 거치지 않고 단말기 간에 직접(P2P) 동기화합니다. 무료로, PC(Windows·Mac·Linux)용 공식 버전이 있습니다. Android는 공식 앱 개발이 끝난 후, 커뮤니티 버전(Syncthing-Fork)을 사용합니다. iPhone·iPad는 Obsidian의 공식 도움말에서 “공식에 비지원”으로 처리되어, 타사 앱(Synctrain 등)으로 회피하는 형태입니다. 각 기기에 앱을 삽입하여 페어링하는 번거로움도 있습니다.

파손 방식을 비교하기 — 실제로 충돌을 일으켜 보았습니다

동기 방식에 대한 카탈로그적인 비교는 자주 보이지만, 「동시에 2대로 편집하면 실제로 어떻게 되는지」까지 손을 움직여 확인한 기사는 많지 않습니다. 여기에서는 이 검증 환경(Ubuntu 24.04·GitHub Actions)에서 Git과 Syncthing을 실제로 설정하고, 2대의 단말기를 모방한 폴더에 오프라인에서 별도의 1 행을 추가한 후 동기화를 재개했습니다 iCloud Drive와 Obsidian Sync는 이 환경에 macOS/iOS이 없기 때문에 실제 기기로 재현할 수 없으며, 공식 도움말에 기재된 내용에 근거하고 있습니다.

실측 — Git

노트 본문에 충돌 마커가 그대로 삽입됩니다

중앙 리포지토리를 1으로 만들고, 2의 클론을 각각 별개의 단말기로 비유했습니다. 양쪽을 모두 “오프라인” 상태로 유지한 상태에서 같은 노트의 끝에 다른 1 행을 추가하고 커밋한 뒤 차례대로 푸시하고 있습니다. 

# デバイスAを先にpush → 成功
$ git push origin master
   ba48c62..f0be52e  master -> master

# デバイスBをpush → 拒否される
$ git push origin master
 ! [rejected]  master -> master (fetch first)

# デバイスBがpull（マージを試み、衝突）
$ git pull origin master --no-rebase
Auto-merging Daily Notes/2026-08-26.md
CONFLICT (content): Merge conflict in Daily Notes/2026-08-26.md

# ノートの中身（Obsidianで開くとこのまま見える）
# 2026-08-26

- 08:00 起床
<<<<<<< HEAD
- 09:15 買い物メモ
=======
- 09:00 会議メモ
>>>>>>> f0be52e...

데이터는 손실되지 않습니다하지만, 충돌 마커가 포함된 상태의 노트가 그대로 Obsidian으로 열립니다. 무심코 읽으면 자신의 글이라고 오독될 수 있으며, 해결을 위해서는 <<<<<<< / ======= / >>>>>>>의 의미를 이해한 뒤 수동으로 편집하고 다시 커밋해야 합니다. Obsidian Git과 같은 플러그인을 사용하고 있더라도, 이 최종 충돌 해결은 Git에 대한 지식이 필요한 작업입니다.

실측 — Syncthing

한쪽은 남겨두고, 다른 쪽은 다른 파일로 후퇴합니다

같은 절차(apt를 통해 설치한 Syncthing v1.27.2을 2 인스턴스로 실행하고, 로컬 TCP에서 직접 페어링) 시도하면 Git과는 전혀 다른 방식으로 손상되었습니다. 

# 同期再開後のvault-a
Daily Notes/2026-08-26.md
Daily Notes/2026-08-26.sync-conflict-20260825-212901-P2RW67Y.md

# 2026-08-26.md（採用された側）
# 2026-08-26

- 08:00 起床
- 09:15 買い物メモ（デバイスBで追記）

# 2026-08-26.sync-conflict-....md（退避された側）
# 2026-08-26

- 08:00 起床
- 09:00 会議メモ（デバイスAで追記）

Syncthing은 자동으로 어느 하나를 원래 파일명 그대로 유지하고, 다른 하나는 *.sync-conflict-日時-デバイスID.md이라는 별 다른 노트로 저장합니다. 본문에 마커가 섞이지 않으며, Git 지식도 필요하지 않습니다. 단자동으로 병합되지 않습니다 때문에, 대피된 노트를 눈치채지 못하고 방치하면 동일한 주제의 메모가 2개의 파일로 분리된 상태로 남게 됩니다. 보관창고 검색 결과에 익숙하지 않은 파일명이 늘어나는 점은 운영상의 노이즈가 될 수 있습니다.

공식 정보·미검증 — iCloud Drive

Apple 공식 도움말에는 번호가 매겨진 중복 파일이 있습니다

Apple 공식 Mac 도움말은 iCloud Drive에서 문서 버전이 충돌할 경우, 충돌 해결 대화 상자에서 각 버전을 선택하여 유지할 수 있으며, 여러 버전을 유지할 경우 “Seven Wonders”, “Seven Wonders 2”와 같이 끝에 번호가 붙은 파일명으로 남는다고 설명하고 있습니다. 단, 이 대화 상자는 Apple의 문서 버전 API에 대응하는 앱(Pages 등)용 동작이며, Obsidian과 같이 파일 시스템에 직접 읽고 쓰는 앱에서 동일한 대화 상자가 나타나는 것은 아닙니다 이 환경에는 macOS/iOS이 없으며, Obsidian+iCloud Drive에서 실제 기기 검증을 수행하지 못했습니다.

기존 기사「데일리 노트에 들어가지 않음」장에서 다룬 동기 지연(쓰기는 즉시라도 반영까지 수초에서 수십 초가 걸립니다)은 이 경쟁과는 다른 현상입니다. 두 가지를 모두 알고 있으면, iCloud를 통한 트러블을 분리하는 것이 빨라집니다.

공식 정보·미검증 — Obsidian Sync

경쟁 해결 알고리즘은 비공개입니다. 믿을 수 있는 것은 Version History

공식 도움말(obsidian.md/help/sync, 2026년 8월 26일 취득)에는 동시 편집 시 어느 버전을 채택할지에 대한 구체적인 알고리즘 기재가 보이지 않았습니다. 한편, 「Obsidian Sync를 Dropbox·Google Drive·OneDrive 등 다른 클라우드 스토리지와 함께 사용할 경우 동기화 충돌(sync conflicts)이 발생할 우려가 있으므로 보관함을 백업해 주시기 바랍니다라는 공식 주의 사항이 있으며, Obsidian Sync에도 경쟁이라는 개념 자체가 존재합니다. 복구 수단으로 명시된 것은 Version History 기능이며, 노트 단위로 과거 버전을 목록에서 선택하여 복원할 수 있습니다. 보유 기간은 Standard 플랜에서 1개월, Plus 플랜에서 12개월이며, 첨부 파일은 플랜에 관계없이 2주입니다.

이 환경에서는 결제가 필요하기 때문에 Obsidian Sync 계정을 만들 수 없으며, 실제 경쟁 재현을 할 수 없습니다.

공통의 교훈

4 방식 중, 실측할 수 있었던 Git·Syncthing은 모두데이터를 잃지 않았습니다. 분해 방식의 차이는 “마커가 본문에 섞이는지”와 “다른 파일로 분열되는가”이며, 두 경우 모두 깨지 못하면 조용히 방치됩니다라는 점은 공통됩니다. 1의 보관함을 여러 동기화 방식으로 이중 동기화하지 않는 것(Obsidian 공식이 명시적으로 주의하고 있는 점도 이 점)이 가장 확실한 예방책입니다.

선택 방법의 기준

🍎 Apple 제품만으로 사용
iCloud Drive만으로 충분합니다. 이미 켜져 있어 추가 비용이나 설정이 필요하지 않습니다.
🖥️ Windows/Android도 다시
공식 지원과 버전 이력을 기술 지식 없이 얻고 싶다면 Obsidian Sync. 무료로 괜찮다면 Syncthing이 경쟁자입니다.
🌿 Git에 익숙합니다
보관함의 변화 자체를 커밋 기록으로 남기고 싶다면 Git. 갈등 해결을 스스로 할 수 있는 것이 전제입니다.
🔒 클라우드 사업자를 이용하고 싶지 않습니다
4 중, 단말기 간에 직접 동기화되는 것은 Syncthing뿐입니다. 무료이지만, iPhone·iPad는 Obsidian의 공식 도움말에서 “공식적으로는 지원되지 않습니다”로 처리되어 각 단말기의 설정도 직접 진행합니다.

어떤 동기화 방식이든, 보관함은 단지 폴더에 불과합니다

동기화 방식을 어느 것으로 할지는 보관함 폴더의 “정리 방법”을 결정하는 것뿐입니다. SimpleMemo는 전송한 메모를 자신에게 보내는 메일에 남기면서, iCloud Drive에 있는 보관함 폴더의 데일리 노트에 직접 추가합니다. iCloud Drive와 동기화된 보관함을 대상으로 하며, Git 및 Syncthing만으로 운영되는(iCloud Drive를 거치지 않는) 보관함 폴더는 현재 시점에서는 대상에서 제외됩니다.

어떤 동기화 방식이든, 도착지는 동일한 폴더

다운로드는 무료입니다. iCloud Drive에서 보관함 폴더를 한 번 선택하기만 하면 설정이 완료됩니다.

PC 사용자는 스마트폰으로 읽어야 합니다

자주 묻는 질문

결국 어느 것을 선택하면 좋을까요?
Apple 제품만으로 사용한다면, 이미 켜져 있는 iCloud Drive가 가장 번거롭지 않습니다. Windows/Android도 사용하시거나, 버전 이력 및 지원을 공식적으로 원하신다면 유료 Obsidian Sync를 사용하십시오. Git에 익숙하고, 커밋 기록으로 보관함의 변경도 남기고 싶다면 Git. 무료로 클라우드 사업자를 이용하고 싶지 않다면 Syncthing입니다(iPhone·iPad는 Obsidian의 공식 도움말에서 “공식적으로는 지원되지 않음”으로 처리됩니다).
Obsidian Sync를 사용하지 않고 여러 기기에서 동기화할 수 있습니까?
할 수 있습니다. 보관함은 특별한 형식을 갖지 않은 단순한 Markdown 파일의 집합이므로, iCloud Drive·Dropbox·Google Drive 등 OS 표준 파일 동기화와 Git 및 Syncthing과 같은 범용 동기화 도구를 그대로 사용할 수 있습니다. Obsidian Sync는 동기화 방법의 선택지 중 하나이며, 필수는 아닙니다.
동시에 2대에서 편집하면 어떻게 됩니까?
방식에 따라 파손 방식이 다릅니다. 본 기사에서 실제 측정한 결과, Git은 동일한 파일에 충돌 마커(<<<<<<)가 직접 기록되어 수동으로 해결해야 했습니다. Syncthing은 자동으로 한쪽을 채택하고, 다른 한쪽은 “sync-conflict”라는 별도 파일로 저장하여 데이터 손실이 없었습니다. iCloud Drive와 Obsidian Sync는 이 환경(Linux·macOS/iOS 없음)에서는 실제 기기 검증을 할 수 없습니다.
여러 동기화 방법을 동시에 사용해도 될까요?
Obsidian 공식 도움말은 Obsidian Sync를 Dropbox·Google Drive·OneDrive 등 다른 클라우드 스토리지와 함께 사용할 경우 동기화 충돌(sync conflicts)이 발생한다고 하여 보관함 백업을 권장하고 있습니다. 이중 동기화 메커니즘을 같은 폴더에 겹쳐 놓는 것은 피하고, 1개의 보관함에는 1개의 동기화 방법에만 머무르는 것이 안전합니다.
Obsidian Sync에서 실수로 덮어쓰면 원래대로 되돌릴 수 있습니까?
공식 도움말에 따르면, Version History 기능을 통해 노트별 과거 버전을 조회·복원할 수 있습니다. 보유 기간은 Standard 플랜에서 1개월, Plus 플랜에서 12개월이며, 첨부 파일은 2주입니다(2026년 8월 26일에 공식 도움말에서 확인). 복원은 파일을 선택하고 “Open version history”에서 수행합니다.
검증 환경 및 검증 범위

검증일: 2026년 8월 26일 / 환경: Linux 데스크톱(Ubuntu 24.04·GitHub Actions 실행 환경). 실측(이 세션에서 실제로 실행하여 확인): Git 2.x — 중앙 저장소 1개와 2개의 클론에서 오프라인 동시 편집→push 거부→pull 시 병합 충돌→본문에 충돌 마커 삽입까지 재현. Syncthing v1.27.2(apt를 통해 설치) — 로컬 TCP에서 직접 페어링한 2 인스턴스 간에 동일한 시나리오를 재현하고, sync-conflict-*.md 파일 생성을 확인합니다. 공식 정보에 기반한 기재(미검증): Obsidian Sync의 버전 이력 보유 기간·다른 클라우드와 함께 사용할 때 주의사항(obsidian.md/help/sync를 본 세션에서 직접 획득·2026년 8월 26일), iCloud Drive상의 문서 충돌 시 번호가 매겨진 파일명(Apple 공식 Mac 도움말), Syncthing의 지원 단말기(obsidian.md/help/sync-notes와 Syncthing 문서·2026년 10월 1일 확인). 이 환경에서 검증하지 못한 점: iCloud Drive와 Obsidian의 조합에서 실제 경쟁 동작(macOS/iOS가 없음), Obsidian Sync에서의 실제 경쟁 재현(유료 서비스이므로 미계약). Obsidian의 버전 및 각 도구의 동작은 향후 변경될 가능성이 있으므로, 최신 정보는 각 공식 사이트에서 확인해 주시기 바랍니다.
