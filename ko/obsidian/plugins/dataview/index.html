Dataview는 무엇을 하는 플러그인인가요?

보관함(Vault)를 데이터베이스처럼 검색할 수 있게 하는 플러그인입니다. 노트의 frontmatter와 인라인 필드에 작성한 메타데이터를 DQL·인라인식·DataviewJS·인라인JS식이라는 4 방식으로 처리할 수 있습니다. DQL의 출력 형식은 LIST·TABLE·TASK·CALENDAR이며, DataviewJS와 동일한 분류가 아닙니다. 공식 다운로드 수 데이터(2026년 8월 22일 획득)에서는 4805635건으로 3위였습니다(레지스트리 등록 총수는 6,840개이지만, 순위는 이와는 다른 파일의 다운로드 수 데이터 내에서의 순위입니다).

다운로드 통계의 업데이트 일시만으로는 개발 지속·중지 및 현재 동작을 판단할 수 없습니다. 아래 수치와 버전은 2026년 8월 22일의 획득 기록이며, 현재값이 아닙니다.

4개의 쿼리 모드 — 공식 README 샘플에서

공식 README는 DQL·인라인식·DataviewJS·인라인 JS식의 4개의 작성 방식을 구분하고 있습니다. DQL 내의 출력 형식은 LIST(목록), TABLE(표), TASK(작업), CALENDAR(날짜 캘린더)입니다. 다음 README 예는 이번에도 실제 기기에서 실행하지 않았습니다.

1. DQL（데이터뷰 쿼리 언어）

SQL과 유사한 전용 표기법. 기본적인 용도에 적합합니다. 

```dataview
TABLE file.name AS "File", rating AS "Rating" FROM #book
```
2. 인라인식

본문에 삽입되어 미리보기에서 평가됩니다. 

We are on page `= this.file.name`.
3. DataviewJS

JavaScript API를 완전히 활용할 수 있는 가장 강력한 모드. 

```dataviewjs
dv.taskList(dv.pages().file.tasks.where(t => !t.completed));
```
4. 인라인 JS식

인라인식 JavaScript 버전. 원하는 JS를 그 자리에서 실행할 수 있습니다. 

This page was last modified at `$= dv.current().file.mtime`.

데이터 입력 측은 2 종류입니다. 노트 앞에 있는 YAML frontmatter(---로 둘러싸기) 또는 본문에 “フィールド名:: 値”라고 쓰는 인라인 필드에서, 두 경우 모두 Dataview가 읽어 쿼리의 대상이 됩니다. 입력 UI와 저장 YAML에서 실제 쿼리로 연결하는 예는, 속성을 변경하고 Dataview의 목록이 바뀌는 실제 기기 예에서 확인할 수 있습니다. 

---
alias: "document"
last-reviewed: 2021-08-17
thoughts:
  rating: 8
  reviewable: false
---
Basic Field:: Value
**Bold Field**:: Nice!
You can also write [field:: inline fields]; multiple [field2:: on the same line].

DataviewJS의 보안에 관한 주의

공식 README에서

DataviewJS는 강력하기 때문에 다른 Obsidian 플러그인과 동일한 권한으로 작동합니다. 즉, 파일의 재작성·생성·삭제 및 네트워크 통신도 가능합니다. 자신이 작성한 코드나 내용을 이해하고 신뢰할 수 있는 배포 원본 스크립트만 사용하는 것이 공식적으로 권장됩니다. 한편, 일반적인 Dataview 쿼리(DQL)는 샌드박스화되어 있어 저장소에 변경을 가할 수 없습니다(그로 한할 수 있는 것이 제한됩니다).

쿼리를 작성하기 전에, 먼저 1 행을 남길 위치를 결정합니다

Dataview는 보관함에 있는 노트와 메타데이터를 검색·집계합니다. 입력한 메모를 SimpleMemo에서 남기는 경우, 연동을 켜고, 접근 가능한 폴더와 저장 대상을 설정하여 쓰기 테스트를 확인합니다. 날짜 노트 또는 고정 인박스를 선택할 수 있습니다. 메일 도착과 노트 저장은 별도로 확인하시고, Dataview용 필드를 자동으로 생성하는 기능과는 구분해 주세요.

쿼리의 대상이 되는 1 행을 먼저 생성합니다

입력한 메모의 저장 대상과 연동 조건을 확인한 후에 사용할 수 있습니다. 다운로드는 무료입니다.

PC 사용자는 스마트폰으로 읽어야 합니다

자주 묻는 질문

Dataview는 무엇을 하는 플러그인인가요?
보관함(Vault)를 데이터베이스처럼 검색할 수 있게 하는 플러그인입니다. 노트의 frontmatter와 인라인 필드에 작성한 메타데이터를 DQL·인라인식·DataviewJS·인라인JS식이라는 4의 작성 방식으로 처리할 수 있습니다. DQL의 출력 형식은 LIST·TABLE·TASK·CALENDAR이며, DataviewJS와 동일한 분류가 아닙니다.
Dataview는 얼마나 사용되고 있습니까?
Obsidian 공식 다운로드 수 데이터를 2026년 8월 22일에 직접 획득한 결과, 4805635건이며, 그 데이터 중에서3위였습니다（1위 Excalidraw·2위Templater）。 참고로 “등록 플러그인 6,840개”는 레지스트리 목록의 건수이며, 순위를 계산한 다운로드 수 데이터와는 별개의 파일입니다.
Dataview는 지금도 개발되고 있습니까?
이 페이지의 2026년 8월 22일의 통계·판 획득 기록만으로는 현재 개발 상황을 판단할 수 없습니다. 통계의 업데이트 일시는 코드의 업데이트 일시와 별개입니다. 공식 릴리스와 변경 내역을 확인하시고, 사용하시는 Obsidian 버전으로 시도해 주세요. 이번 수정에서는 현행 버전을 설치하고 동작을 확인하지 않았습니다.
Dataview의 기본적인 작성 방법은?
노트의 frontmatter(YAML) 또는 본문에 “필드명:: 값” 형태로 작성하는 인라인 필드에 메타데이터를 추가합니다. 그 위에dataview코드 블록에 표시 형식과 조건을 작성합니다. 예를 들어 LIST·TABLE에서는 노트를, TASK에서는 노트 내의 작업을 표시할 수 있습니다.
DataviewJS는 안전하게 사용할 수 있습니까?
공식 README에 따르면, DataviewJS는 다른 Obsidian 플러그인과 동일한 권한으로 동작하므로 파일의 재작성·삭제 및 네트워크 통신이 가능합니다. 직접 작성한 코드나 신뢰할 수 있는 배포원의 스크립트만 사용하는 것이 권장됩니다. 일반적인 DQL 쿼리는 샌드박스화되어 있어 보관함에 기록할 수 없습니다.
검증 환경 및 검증 범위

2026년9월30일에 공식 README와 Query Types에 대한 설명을 다시 읽고, 작성 방식과 출력 형식의 분류를 수정했습니다. 다운로드 수·등록 수·당시 버전은 2026년 8월 22일의 획득 기록을 유지하고 있으며, 이번에는 다시 가져오지 않았습니다. Dataview 설치, 쿼리 실행, 현행 버전 호환성, SimpleMemo에서의 입력 및 다른 기기 동기화는 이번 실기 검증에 포함되지 않습니다.
