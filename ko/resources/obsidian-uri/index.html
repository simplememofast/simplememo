무료·계정 불필요

Obsidian용 URL을 입력하여 만듭니다.

iPhone의 단축키 등으로 사용할 obsidian:// URI를 만들 수 있습니다. 노트 열기·새로 만들기·일일 노트 열기 작업을 지원합니다. URL만 만들면 Obsidian 설치는 필요하지 않습니다.

iPhone으로 일일 노트에 추가하기만 하면, Obsidian 표준의 “Capture to Daily Note” 단축키도 사용할 수 있습니다. 이 도구는 URI가 필요한 다른 앱이나 런처와 연동하는 경우를 위한 것입니다. Obsidian 공식 iOS 가이드에서 표준 기능을 확인해 주세요.

기존 new의 append/silent는 노출 플래그입니다. append=true 등과 같은 고정 관측과는 별도의 입력이며, 구문만 취급합니다. 일차의 append 단독 효과는 분리되지 않았기 때문에, 이 화면의 daily 생성에서는 append을 생략합니다. 순수 API의 기존 출력은 유지하고 있습니다.

Obsidian에 표시되는 보관함 이름을 입력합니다. 이름에 공백이나 일본어가 있더라도 인코딩합니다.

보관함의 경로로부터의 상대 경로. 예: Inbox.md 또는 Ideas/Inbox.md.

여기에 넣은 본문은 생성 URI에 고정됩니다. URL을 공유하면 상대방도 본문을 볼 수 있으므로, 비밀 내용은 넣지 말아 주세요.

입력 내용은 이 브라우저 내에서 URL로 변환됩니다. 저장·전송·분석 이벤트에 본문을 추가하지 않습니다.

생성한 URI

    생성한 query의 읽기 되돌림
    

    이 화면에서는 URI를 실행하지 않으며, 보관함도 변경하지 않습니다. 복사한 URI를 사용할 때는 먼저 테스트용 노트에서 시험해 보시고, 저장 결과를 Obsidian으로 확인해 주세요.
    

    

    


    어떤 작업을 선택하시겠습니까?
    

    작업할 수 있는 일확인하기
    

    new지정한 노트를 생성합니다. 추가를 선택하면 기존 노트가 있는 경우 끝에 추가합니다.기존 노트에 본문을 추가하고 싶을 경우에만 “추가”를 선택하십시오. 이 도구는 덮어쓰기 URI를 만들지 않습니다.
    

    daily일일 노트를 작성·표시합니다. 본문을 넣는 경우에는 추가도 선택할 수 있습니다.Obsidian의 핵심 플러그인 “Daily notes”를 활성화합니다.
    

    open지정한 기존 노트를 표시합니다.노트가 존재함을 확인합니다.
    

    

    이 도구가 만드는 것은 Obsidian 공식 표준 URI입니다. Advanced URI 커뮤니티 플러그인 전용 obsidian://adv-uri은 만들지 않습니다. 기호·일본어·줄바꿈은 URI용으로 인코딩합니다. 본문을 넣으면 고정문인 URL이 됩니다. 단축키로 매번 다른 문장을 전달하려면 해당 변수를 URI 인코딩하여 content 파라미터에 포함시키는 설정이 별도로 필요합니다. 동작은 Obsidian의 설정 및 단말기에 따라 달라지므로, 먼저 개인 정보가 없는 짧은 문장으로 시도해 주세요. 출처：Obsidian 공식「Obsidian URI」.
    각 작업의 지정 및 일본어·기호 취급을 확인하려면, 공식 38 항목 입력 및 Linux의 58 관측을 지원한 URI 가이드도 참고하십시오.
    

    매번 단축키를 만들고 싶지 않은 경우
    

    이 도구는 URI를 한 번 만들기 위한 것입니다. iPhone에서 짧은 문장이나 음성을 반복하여 Obsidian에 남기려면, SimpleMemo의 설정 가이드에서 Files에서 선택한 보관함 폴더에 추가하는 방법과 저장을 확인하는 절차를 확인할 수 있습니다. 앱의 직접 쓰기에는 폴더 접근 권한이 필요하며, 정상적으로 작성되었는지는 저장처에서 확인해 주세요.
    

    iPhone 앱을 App Store에서 보기
    

    앱을 설치하지 않아도 이 URI 도구는 무료로 사용할 수 있습니다. 링크가 App Store로 이동합니다.
    

    구문과 고정 예제의 결과를 구분하여 읽기
    구문 OK는 query을 되돌릴 수 있다는 의미입니다. 임의의 값에 대한 Vault 등록, 파일 존재, 저장 대상, OS 연관, 단말기의 성공을 확인한 것이 아닙니다. 고정값만 58 기록과 대조하고, 동일한 daily/unique 입력의 최초 미작성 및 별도 계획 저장을 모두 표시합니다. 생 #에 의한 누락 등 14 부족을 성공으로 바꾸지 않았습니다.

    자주 묻는 질문
    일본어와 공백, #, &를 먼저 인코딩하시겠습니까?
    그대로 입력해 주세요. 이 도구는 입력 값을 한 번 인코딩하고, 공백을 %20, 슬래시를 %2F, #를 %23 등으로 변환합니다. 이미 %20이라고 적힌 문자열은 문자 형태의 %를 %25로 변환하기 위해 %2520가 됩니다. 본문의 줄바꿈도 값으로 유지합니다.
    구문 확인이 괜찮다면, Obsidian으로 반드시 성공합니까?
    구문 확인은 query의 읽기 되돌림과 입력값이 일치합니다. Vault 등록, 파일 존재, 저장 폴더, Core 플러그인, OS의 URI 연관은 검사하지 않았습니다. 고정된 Linux 입력값과 일치하는 경우에만 별도의 열에 원본 실결과와 실패·전제를 표시합니다. 임의의 입력을 실기 성공으로 승격시키지 않습니다.
    Daily와 Unique가 생성되지 않을 경우는?
    원래의 최초 일일·고유 입력에서는 Markdown을 할 수 없었습니다. 저장 폴더 등을 마련한 다른 계획에서는 저장을 관측하고 있습니다. Daily notes 또는 Unique note creator를 활성화하고, 사용할 저장 대상 설정을 확인합니다. 전제 변경만을 원인으로 단정한 기록이 아닙니다.
    기존 노트에 추가하고 싶으시면?
    액션을 new으로, 대상을 상대 경로로, 동작을 append로 지정하고, 추가할 본문을 입력합니다. 원래의 고정 예에서는 기존 본문을 유지하고 추가했습니다. overwrite 단독은 교체이며, append와 overwrite의 동시 지정에서는 추가된 별도 기록이 있습니다. 이 도구는 동작을 하나 선택하는 형태입니다.
    절대 패스, callback, Hook도 생성할 수 있습니까?
    기존 노트를 여는 open의 절대 Linux 경로를 처리합니다. new의 절대 path는 원래의 무경합 입력이라도 6초 후에 생성을 관측할 수 없으며, 대응 대상에 포함되지 않습니다. Callback와 Hook의 반송·출력도 아직 도달하지 못했습니다. daily의 name/file/path 지정은 설정된 날짜 파일로 이동했기 때문에 입력란에 포함되지 않았습니다.
    입력 내용은 전송·저장됩니까?
    생성 및 대조는 브라우저 내에서 수행합니다. 입력 전송 API 및 저장, 입력 측정은 추가하지 않았습니다. 기존 페이지 조회 및 App Store 링크의 측정은 유지합니다. 이 화면은 복사만 가능하며, URI를 자동이든 수동이든 실행하지 않습니다. 공유된 URI에는 본문이 포함됩니다.
