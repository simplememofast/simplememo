먼저 OG와 DB 버전을 구분합니다

공식 리포지토리에서는 파일 그래프가 Logseq OG로 구분되어 있습니다. 2026년 7월 13일에 공개된 2.0.1는 DB 버전의 베타입니다. 구버전 파일 저장·Org·플러그인 설명을 DB 버전에 그대로 적용하지 않도록 합니다.

일일 메모와 Quick add로 시작합니다

Logseq은(는) 항목 블록이나 참조로 사고를 구성하는 도구입니다. 처음부터 모든 것에 링크를 달 필요는 없으며, 일일 메모에 짧은 기록을 작성한 후 사용 상황에서 연관됩니다.

DB 버전에는 현재 저널에 보낼 내장 Quick add가 공식적으로 안내되고 있습니다。「 '퀵 입력에는 반드시 플러그인이 필요하다'는 설명은 적절하지 않습니다. 사용하는 기기에서 입구를 열고, 입력·저장·재표시까지 시도합니다.

공식: Quick add 설명

동기화와 백업을 별도로 준비합니다

공식 README는 DB 버전을 베타로, 새로운 모바일 버전과 RTC를 알파로 설명하고, 데이터 손실 가능성과 백업을 안내하고 있습니다. 동기화를 활성화하는 것만으로는 실수로 삭제하거나 데이터 손실을 방지할 수 있는 것은 아닙니다. 먼저 본편의 내용을 포함하지 않는 작은 그래프로 시험해 보겠습니다.

파일 버전과 DB 버전의 동기화 설정을 섞지 않고, 사용 중인 버전의 안내를 확인합니다. 동기화 대상에서 기록을 찾을 수 있는지, 독립된 복사본을 다시 읽을 수 있는지는 별도의 확인입니다.

공식: 개발 단계와 시험용 그래프 안내

DB 백업과 Markdown 내보내기를 구분하여 사용합니다

DB 버전의 Export graph에서는 DB와 첨부 파일을 통합하는 “Export both SQLite DB and assets”를 선택할 수 있습니다. 표준 Markdown 내보내기는 읽기 쉬운 텍스트를 꺼내는 용도이지만, 모든 속성 및 타임스탬프를 보유하지 않습니다. 마이그레이션용 Markdown만을 유일한 백업으로 만들지 않도록 합니다.

원래 그래프를 그대로 두고, 새로운 별도 그래프에서 Import → SQLite + assets (.zip)를 시도하여 필요한 내용이 열리는지 확인합니다. 구 파일 그래프를 DB로 변환하는 경우, Org 비지원, 작업 상태 변환, 다중 쿼리 및 임베드의 가져오기 제한도 확인해 주세요.

운용을 변경하시기 전의 5 절차

  1. 사용하고 있는 Logseq의 버전과 저장 방식을 기록하고, 원본 그래프를 독립된 위치에 백업합니다.
  2. 중요하지 않은 작은 테스트 그래프에 본문·작업·첨부·링크를 각각 1건 준비합니다.
  3. 위의 6 항목을 확인하고, 필요한 내보내기를 별도의 그래프에 가져와 엽니다.
  4. 와 함께 사용하고 싶다면 짧은 메모를 하나 만들고, 최종 Logseq의 저장처에서 찾을 수 있는지 확인하십시오.
  5. 불일치하거나 부족한 기능을 기록한 후, 본판 데이터의 취급을 판단합니다.

SimpleMemo를 병용하는 경우

보통 메일 수신함을 다시 확인한다면, 거기에 짧은 문장을 남기고 필요한 것만 Logseq의 일일 메모에 전사하는 방법이 있습니다. 복사한 시점에 본문과 반환 대상을 알 수 있는지 확인합니다. 메일 도착과 Logseq에 저장하는 것은 별개의 작업이며, 자동 추가를 전제로 하지 않습니다.

입력의 입구로 시도한다면 SimpleMemo의 목적지를 설정하고, 1건의 도착부터 확인할 수 있습니다. 그래프의 교체 및 이동에는 사용하지 않습니다.

첫 번째 메일을 보내는 절차와, 과거 파일 버전 비교도 참고해 주세요.

자주 묻는 질문

Logseq을 모두 Markdown 파일로 저장합니까?

아니요. 기존 파일 버전은 Logseq OG로 구분되고, DB 버전은 SQLite 데이터베이스를 사용합니다. DB 버전의 Markdown 내보내기는 모든 속성 및 타임스탬프를 유지하는 형식이 아닙니다.

DB 버전을 기존 그래프로 시험하기 전에 무엇을 하시겠습니까?

원본 그래프의 독립된 복사본을 남겨두고, 중요하지 않은 작은 테스트 그래프로 테스트합니다. SQLite뿐만 아니라 첨부도 필요한 경우, SQLite DB와 assets를 포함하는 내보내기를 선택하고, 별도의 그래프에 대한 가져오기를 확인합니다.

DB 버전에서 이전 플러그인을 그대로 사용할 수 있습니까?

호환성을 개별적으로 확인합니다. 공식 마켓플레이스의 “Supports DB?” DB 지원 표시를 확인하고, 사용할 플러그인이 DB 그래프를 지원하는지 확인해 주세요.

Logseq의 빠른 입력은 플러그인 필수인가요?

DB 버전의 공식 자료에는 짧은 메모를 현재 저널에 전송하는 내장 “Quick add”가 있습니다. 버전과 단말기에 따라 진입점이 다르므로, 추가 플러그인을 찾기 전에 현재 앱에서 확인해 주세요.

공식 동기화를 사용하면 데이터 손실이 없어지나요?

동기화는 백업을 대신할 수 없습니다. 공식 README는 DB 버전을 베타로, 새 모바일 버전과 RTC를 알파로 하여 데이터 손실 가능성과 독립적인 백업을 안내하고 있습니다. 사용하는 버전과 동기화 경로를 확인합니다.

SimpleMemo를 사용하면 Logseq에 자동으로 추가됩니까?

이 페이지의 병용 예시는 메일 수신함에 도착한 문장을 필요에 따라 Logseq에 전재하는 방법입니다. Logseq의 DB 및 그래프에 자동으로 쓰는 기능이나 그래프 전체를 마이그레이션하는 기능을 제공하지 않습니다.
