更正後測量的東西4個 — 方法v2

統計物件是現存記錄中最早的首次啟動時間位於統計期間內的裝置。這不代表使用者一生中的首次使用人數，也不是下載量。我們排除能夠識別的開發裝置、首次啟動記錄重複的裝置，以及存在更早儲存記錄的裝置，並記錄排除數量及其侷限。統計期間包含開始時刻，不包含結束時刻。

指標定義和極限
1 第一個觀測儲存的輸入標籤每個目標終端選擇最初的儲存記錄1件，計算記錄的輸入方法。 未記錄、未知的值作為“不明”留在分母中。 無法測量混合了語音和手動輸入的備忘錄的字數比例，以及僅用語音建立的比率
2 首次接收日的字數分佈在首次啟動記錄的日期和日本時間的日曆日，計算儲存成功收到的記錄。 0 / 1〜10 / 11〜50 / 51〜200 / 201+ / 不明的區分。 不是從第一次開始24小時的統計，也不計算出平均字數
3 儲存記錄的接收時間段期間內的儲存記錄到達伺服器的時間以日本時間進行統計。 不一定是實際說話的時間或製作時間。 同時記下事件數、貢獻終端數、日語區域的比例和不明數
4 Obsidian有效狀態的觀測比例物件終端中，在期間內收到過一次以上連線有效的記錄的比例。 分為只有無效記錄的終端和無法確認狀態的終端。 不是資料夾儲存確認、同步成功、持續使用的比率

儲存包括郵件API的受理成功和Obsidian單獨的本地儲存，不新增首次的追加記錄和測試傳送。 可以識別相同的傳送時，除重複外，也會留下無法識別的記錄數量。 不是確認郵件收件箱到達和同步到其他終端的統計。

8月20日提前公開的舊定義v1（結果未刊登・不用於現行統計）

舊規格以最近90日・視窗內的新安裝為物件。 將下表作為變更記錄留下。 根據實際記錄可以證明的範圍，在9月6日更正了上述v2。

指標定義
1 首次傳送的輸入方法比例新安裝首次傳送備忘錄時的輸入方法（語音/鍵盤/其他）的分佈。 以安裝為單位只計算最初的1件。 透過沒有輸入方法標籤的舊版本作為“不明”留在分母中（排除後比例不好看）
2 第一天的備忘錄文字數分佈安裝當天（以日本時間計算日期）傳送的備忘錄的字數桶的分佈。 桶是0 / 1~10 / 11~50 / 51~200 / 201+ 文字的5階段，因為應用程式只記錄這個粒度，所以無法計算出像平均字數這樣的細小值（按照設計）
3 傳送的時間段分佈傳送事件的發生時間（將伺服器受理時間轉換為日本時間）的0~23時分佈。 在腳註中同時記錄日語的外號比例
4 Obsidian並用率視窗內新安裝中，Obsidian配合（指定保管庫資料夾）設定的比例

測量方法 — 不使用本文進行統計

明確用於統計的記錄、排除方法、可以再次確認結果的範圍。

  • 這個調查不使用備忘錄正文。 統計使用事件的輸入方法、字數區分等，不取出正文和收件人。 包括本文在內的產品整體的資料路徑在另外的資料中說明（資料路徑的整體圖）。
  • 用於統計的只有允許的後設資料。 統計區分終端的ID和許可列表制的活動（輸入方法、字數桶、Obsidian的狀態等）。 在排除內部終端時，也會使用現有的傳送關聯和內部賬戶的雜湊進行核對。 公開的只是統計，不公開ID、雜湊、收件人。
  • 字數只存在於桶中。 0 / 1〜10 / 11〜50 / 51〜200 / 201+的5階段在終端端四舍五進後傳送，所以運營方也不知道確切的字數。
  • 排除內部賬戶。 除已知的開發者、測試終端外，同時記下排除數。 相關記錄的保留時間有限，不能保證能夠辨別所有內部終端。
  • 留下統計步驟。 統計步驟和變更記錄進行版管理。 由於記錄的追加、保留期間的刪除，重新獲取結果可能會發生變化，所以保留獲取時間點和定義版。
