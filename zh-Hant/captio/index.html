要點

Captio式（Captio-style）是指在想到的瞬間用1行短拋，之後總結清書、整理的前提下設計的重視連續性的筆記術。 起源於同名的iOS應用程式“Captio”（2024年10月1日停止服務）一鍵備忘錄→傳送郵件的工作流程。 本頁面是備忘錄術的解說。 Captio尋找替代應用程式的人請參考/captio-alternative/。

Captio公式的定義（3行）

Captio式是指在想到的瞬間只“短拋（1行筆記）”，之後總結“清書・整理”的前提下設計的筆記術。
因為不想當場寫得完美，所以即使在移動中也能減少溢位，繼續整理。
在清書的末尾加上“下一個動作”，思考日誌就會直接變成行動。

3分鐘知道的要點

1行備忘錄不是“資訊”而是“鉤子”
1行備忘錄的作用不是完美的記錄。 這是稍後清書時的“回憶鉤子”。 所以短一點就好。
清書比起“每次都完美”“整理粗糙”
每1封不用清書OK。 1在一天結束或週末總結回看，粗略地整理一下就足夠了。
清書的最後“下一個動作”
整理完就結束了太可惜了。“ 所以，接下來要做什麼？” 只要寫1行，備忘錄就會變成任務。
猶豫的話就用模板
“不知道該寫什麼”是最大的敵人。 使用模板的話，可以毫不猶豫地扔出去。看模板集 →

Captio式有效的理由

降低認知負荷
當場想得太多了。“ 先扔”可以釋放工作記憶，集中精力進行眼前的工作。
減少記錄的摩擦
啟動、寫、傳送馬上就結束了。 不需要資料夾選擇和標記。 所以在電車裡，邊走邊也能記筆記。
留下可以以後判斷的材料
1行備忘錄積聚在收件箱中=思考的日誌自然積累。 清書的時候知道了“當時在想什麼”。
與行動相連
在清書的末尾加上“下一個動作”的習慣，筆記不是“讀完”而是“做完”。

常見的失敗（以及對策）

  • 當場想寫長文就停了
    在移動中說“好好寫吧”的話，中途下了電車，或者被別的事情分心了，最後沒有記下。 Captio式的核心是“不寫得完美”。
    對策：1行，最大也是3行。 無視體裁。 以後以清書為前提扔。
  • 沒有時間清書而積攢
    1封一個仔細地清書，未處理的備忘錄堆積起來，受挫了。 完美主義是Captio式最大的敵人。
    對策：“彙總起來亂”即可。 每週1次，只有15分鐘。 扔掉不需要的東西，剩下的只需新增1行動作。
  • 清書滿足不任務化
    乾淨利落地總結的瞬間變得“做了”，沒有付諸實際行動的模式。 清書不是終點而是起點。
    對策：在清書的末尾一定要寫“接下來要做的事情：○○”1行。 如果沒有那個的話，清書還沒有完成。
  • 不知道在哪裡儲存，分散
    備忘錄應用程式、Notion、Slack草稿、Apple Notes......如果有多個儲存地址的話“那個寫在哪裡了？” 出現問題。
    對策：投擲目的地統一為1個（郵件收件箱）。 SimpleMemo的話，收件人是固定的，不會迷路。
  • 標籤、整理過於細緻而破產
    顏色區分、標籤、資料夾、專案繫結......雖然一開始很開心，但1周就變得麻煩了，全部放棄了。
    對策：整理只有“清書完成 or 未處理”的2分類。 Gmail的話只要存檔就可以了。

具體例子：1行備忘錄→清書→下一個動作

例1：工作（在Slack上說的委託）
1行備忘錄
田中先生 報價到週五為止
清書
田中先生有報價委託 物件：Q3的營銷措施 期限：週五17時 包含的專案：廣告費、製作費、運用費
下一個動作
週四上午製作電子表格，下午發給田中先生
例2：學習（在報道中讀到的內容）
1行備忘錄
OKR運用 每週簽到好像是關鍵
清書
OKR形骸化的原因是隻進行季度審查 每週只進行15分鐘的簽到就能提高達成率 即使不是全隊，只要OKR老闆就可以了
下一個動作
建議下週的例行OKR每週入住
例3：想法（散步中的靈感）
1行備忘錄
如果用公司內部FAQ bot的話，諮詢可能會減少
清書
假設：公司內部服務檯諮詢的60%應該可以透過FAQ解決 ChatGPT API + 連線公司內部Wiki的話好像可以bot化 成本：API月$20左右，工時2天可以試製
下一個動作
下週三30分試製。 順利的話分享給Slack

SimpleMemo的轉動方法

“投擲”的輸入很快
啟動0.4秒（iPhone 16e・warm啟動的實際測量）立即輸入。 既沒有主頁也沒有選單。 開啟的瞬間鍵盤就出來了，寫完就可以馬上傳送。
稍後可以一覽表清書
傳送的備忘錄在郵件收件箱中按時間順序排列。 週末一起開啟，只做清書+動作。
不會因為模板而迷茫
可以減少“不知道該寫什麼”。 工作、學習、生活的模板集後可以使用。
備忘錄→郵件統一化
備忘錄的儲存地址是自己的郵件收件箱。 無論是Gmail還是Outlook，都會送到平時使用的收件箱，所以不用找別的地方了。詳細看 →
