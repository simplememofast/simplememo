Obsidian 同步方法的比較

Obsidian在多個終端上同步4的方法

保管庫沒有特殊格式，只是Markdown資料夾。 所以同步方法不受Obsidian本身的束縛，可以自由選擇iCloud Drive等OS標準同步、付費官方Obsidian Sync、Git等版本管理、Syncthing等自託管型同步工具。 這裡透過費用、對應OS、衝突時的行為比較了4方式，Git和Syncthing實際碰撞了2臺的離線編輯，確認了破損方式。

一言以蔽之

如果僅用Apple產品完成的話iCloud Drive（預設執行，沒有額外費用）就足夠了。 Windows/Android也一樣，或者想要官方版本歷史和支援的話Obsidian Sync（收費）。 如果熟悉Git並想將變更履歷作為提交留下的話Git（免費・需要設定）。 如果想不透過雲運營商免費同步的話Syncthing（免費・需要設定。 iPhone・iPad官方不支援）。 實測發現的區別是“發生衝突（衝突編輯）時的破壞方式”，Git在筆記正文中直接插入衝突標記，需要手動解決，Syncthing自動保留一個，將另一個作為單獨的檔案儲存。

從iPhone用聲音說話留給Obsidian最短的方法，總結為4方式的比較（附帶不需要外掛的步驟）。

4個同步方法

無論哪個都做“在多個終端上整理保管庫資料夾的內容”的同樣的工作，但是結構不同。

☁️ iCloud驅動器
Apple純正的檔案同步。 只需將保管庫資料夾放在iCloud Drive內，Mac/iPhone/iPad之間無需追加設定即可齊全。 無法到達Windows/Android/Linux。設定步驟在另一頁中。
🔄 Obsidian Sync（官方・收費）
Obsidian開發者提供的官方服務。 擁有E2E加密・Version History功能，對應所有平臺。 費用是在另一篇報道中已實測在、Standard/Plus需要哪個也在另外的頁面上整理。
🌿 Git
將保管庫視為Git儲存庫，透過提交、push、pull進行同步的方式。 使用社群外掛（Obsidian Git等）也可以實現自動化。 所有變更都作為履歷留下的同時，解決衝突需要Git的知識。
🔁 同步
開源的自託管型檔案同步。 不透過雲企業，終端之間直接（P2P）同步。 免費，有面向電腦（Windows・Mac・Linux）的官方版。 Android官方應用程式的開發結束，使用社群版（Syncthing-Fork）。 iPhone・iPad在Obsidian的官方幫助中是“官方不支援”的處理，透過其他公司製造的應用程式（Synctrain等）迴避的形式。 在各個終端上安裝應用程式進行配對也很麻煩。

比較破損方式 — 實際發生了衝突

雖然經常看到同步方式的目錄式比較，但“同時用2臺編輯的話實際會怎麼樣”移動手確認的報道並不多。 在這裡，在這個驗證環境（Ubuntu 24.04・GitHub Actions）中實際設定了Git和Syncthing，在模仿2臺終端的資料夾中離線新增單獨的1行後重啟同步。 iCloud Drive和Obsidian Sync，因為這個環境下沒有macOS/iOS，所以實機無法再現，是基於官方幫助的記載。

實測 — Git

在筆記正文中直接插入碰撞標記

製作了1箇中央儲存庫，將2的clone分別視為不同的終端。 兩者都處於“離線”狀態，在同一筆記的末尾加上另一個1行並提交，按順序push。 

# デバイスAを先にpush → 成功
$ git push origin master
   ba48c62..f0be52e  master -> master

# デバイスBをpush → 拒否される
$ git push origin master
 ! [rejected]  master -> master (fetch first)

# デバイスBがpull（マージを試み、衝突）
$ git pull origin master --no-rebase
Auto-merging Daily Notes/2026-08-26.md
CONFLICT (content): Merge conflict in Daily Notes/2026-08-26.md

# ノートの中身（Obsidianで開くとこのまま見える）
# 2026-08-26

- 08:00 起床
<<<<<<< HEAD
- 09:15 買い物メモ
=======
- 09:00 会議メモ
>>>>>>> f0be52e...

資料不會丟失但是，帶有碰撞標記狀態的筆記本直接用Obsidian開啟。 如果不注意地閱讀的話，可能會誤讀自己的文章，為了解決，需要在理解<<<<<<< / ======= / >>>>>>>的意思後手動編輯，重新提交。 即使使用像Obsidian Git這樣的外掛，這個最終的衝突解決也是需要Git知識的工作。

實測 — Syncthing

留下一邊，把另一邊退到其他檔案

按照同樣的步驟（透過apt安裝的Syncthing v1.27.2啟動2例項，用本地TCP直接配對）嘗試的話，與Git的破壞方式完全不同。 

# 同期再開後のvault-a
Daily Notes/2026-08-26.md
Daily Notes/2026-08-26.sync-conflict-20260825-212901-P2RW67Y.md

# 2026-08-26.md（採用された側）
# 2026-08-26

- 08:00 起床
- 09:15 買い物メモ（デバイスBで追記）

# 2026-08-26.sync-conflict-....md（退避された側）
# 2026-08-26

- 08:00 起床
- 09:00 会議メモ（デバイスAで追記）

Syncthing自動將其中一個保留原檔名，將另一個儲存為名為*.sync-conflict-日時-デバイスID.md的另一個筆記。 正文中不會混入標記，也不需要Git知識。 但是不會自動合併，如果在沒有注意到被撤離的筆記的情況下放置的話，同一話題的筆記會分裂成2的檔案。 保管庫的搜尋結果中不熟悉的檔名增加，這可能會造成操作上的噪音。

官方資訊・未驗證 — iCloud Drive

Apple官方幫助上有編號的重複檔案

Apple官方的Mac幫助說明，在iCloud Drive上文件的版本衝突時，可以在衝突解決對話方塊中選擇並保留各個版本，如果保留多個版本，則像“Seven Wonders”“Seven Wonders 2”一樣末尾帶有編號的檔名。 但是這個對話方塊是針對Apple的檔案版本化API對應的應用程式（Pages等）的行為，像Obsidian一樣直接讀寫到檔案系統的應用程式不一定會出現相同的對話方塊。 這個環境中沒有macOS/iOS，Obsidian+iCloud Drive沒有進行實機驗證。

現有報道的“不進入每日筆記”章節中處理的同步延遲（即使寫入即時也需要幾秒鐘~數十秒才能反映），與這種競爭是不同的現象。 瞭解兩者的話，透過iCloud的故障分類會更快。

官方資訊・未驗證 — Obsidian Sync

衝突的解決演算法不公開。 可以依靠的是Version History

官方幫助（obsidian.md/help/sync，2026年8月26日獲取）中，沒有同時編輯時採用哪個版本的具體演算法記載。 另一方面“Obsidian Sync與Dropbox、Google Drive、OneDrive等其他雲端儲存同時使用的話，可能會發生同步衝突（sync conflicts），請備份保管庫”的官方注意事項，Obsidian Sync也存在競爭的概念本身。 作為恢復手段明確說明的是Version History功能，可以以筆記為單位從列表中選擇過去的版本進行恢復。 保留期限為Standard計劃1個月，Plus計劃12個月，附件不分計劃2周。

在這個環境下，因為需要付款，所以無法建立Obsidian Sync的賬戶，無法再現實際的競爭。

共同的教訓

4方式中，實測的Git・Syncthing都沒有丟失資料。 破壞方法的區別在於“標記是否混入正文”和“是否分裂成其他檔案”，兩者如果不注意就會安靜地放置這一點是共同的。 1的保管庫不要以多個同步方式進行雙重同步（Obsidian公式明確提醒這一點）是最可靠的預防措施。

選擇方法的基準

🍎 僅使用Apple產品
iCloud Drive就足夠了。 已經開啟了，不需要額外的費用和設定。
🖥️ Windows/Android也一樣
如果想在沒有技術知識的情況下獲得官方支援和版本履歷的話，Obsidian Sync。 如果免費的話，Syncthing是對手。
🌿 習慣了Git
如果想要將保管庫的變化本身作為提交履歷留下的話，Git。 前提是能夠自己解決衝突。
🔒 不想透過雲企業
4中，終端之間直接同步的只有Syncthing。 雖然是免費的，但iPhone・iPad在Obsidian的官方幫助中作為“官方不支援”的處理，各個終端的設定也是自己進行的。

無論哪種同步方式，保管庫都只是資料夾

選擇哪種同步方式，只是決定保管庫資料夾的“排列方法”而已。 SimpleMemo將傳送的備忘錄留在自己的郵件中，直接在iCloud Drive上的保管庫資料夾的每日筆記中進行補充。 以iCloud Drive同步的保管庫為物件，僅透過Git和Syncthing操作（不透過iCloud Drive）的保管庫資料夾，目前不在物件之列。

無論哪種同步方式，到達目的地都是同一個資料夾

下載免費。 只需選擇一次iCloud Drive上的保管庫資料夾即可完成設定。

常見問題

最終選哪個好呢？
如果只用Apple產品的話，已經開啟的iCloud Drive是最省事的。 也使用Windows/Android，或者官方要求版本歷史和支援的話，付費的Obsidian Sync。 熟悉Git，如果想作為提交履歷留下保管庫的變化的話，Git。 如果不想免費透過雲企業的話，就選擇Syncthing（iPhone・iPad在Obsidian的官方幫助中“官方不支援”的處理）。
不使用Obsidian Sync可以在多個終端上同步嗎？
可以。 保管庫只是沒有特殊格式的Markdown檔案的集合，所以iCloud Drive・Dropbox・Google Drive等OS標準的檔案同步，以及Git和Syncthing等通用的同步工具可以直接使用。 Obsidian Sync是同步方法的選擇之一，不是必須的。
同時用2臺編輯會怎麼樣？
根據方式不同，破損方式也不同。 在本報道中實際測量後，Git將衝突標記（<<<<<<<）直接寫入同一檔案中，需要手動解決。 Syncthing自動採用一邊，一邊將另一個作為名為“sync-conflict”的單獨檔案儲存，資料沒有丟失。 iCloud Drive和Obsidian Sync在這個環境下（沒有Linux・macOS/iOS）無法實機驗證。
可以同時使用多種同步方法嗎？
Obsidian官方幫助建議將Obsidian Sync與Dropbox、Google Drive、OneDrive等其他雲端儲存同時使用時會發生同步衝突（sync conflicts），建議備份保管庫。 避免將雙重同步結構疊加在同一資料夾中，在1個保管庫中使用1個同步方法比較安全。
用Obsidian Sync覆蓋錯誤的話可以恢復嗎？
根據官方幫助，透過Version History功能可以瀏覽、恢復每個筆記的過去版本。 保留期限為Standard計劃1個月，Plus計劃12個月，附件為2周（2026年8月26日在官方幫助中確認）。 恢復選擇檔案，從“Open version history”開始。
驗證環境和驗證範圍

驗證日期：2026年8月26日/環境：Linux桌面（Ubuntu 24.04・GitHub Actions執行環境）。 實測（在這個會話中實際移動確認）: Git 2.x — 中央儲存庫1個和2個clone離線同時編輯→push的拒絕→pull時的合併衝突→再現插入正文的衝突標記。 Syncthing v1.27.2（透過apt安裝）—在本地TCP中直接配對的2例項之間再現相同的場景，確認sync-conflict-*.md檔案的生成。 基於官方資訊的記載（未驗證）：Obsidian Sync版本履歷的保留期限・其他雲同時使用時的注意事項（obsidian.md/help/sync從本會話直接獲取・2026年8月26日）、iCloud Drive上檔案衝突時的帶編號檔名（Apple官方Mac幫助）、Syncthing的對應終端（obsidian.md/help/sync-notes和Syncthing的文件・2026年10月1日確認）。 在這個環境下無法驗證的事情：iCloud Drive和Obsidian組合的實際競爭行為（沒有macOS/iOS），Obsidian Sync的實際競爭再現（因為是收費服務，所以未簽約）。 Obsidian的版本和各工具的行為在未來可能會發生變化，所以最新資訊請在各官方網站上確認。
