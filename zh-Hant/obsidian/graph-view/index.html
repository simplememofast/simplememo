使用Obsidian的圖形檢視縮小
顯示範圍，確認連線

開啟圖表後，先選擇想看的筆記範圍。 透過資料夾、標籤搜尋、孤立筆記的顯示、顏色組、本地圖表的深度，在小作者製作的保管庫中確認了。

作者: SimpleMemo Developer · 實際操作確認: 2026年10月1日（日本時間） · Linux版Obsidian 1.13.7

根據想看的範圍，選擇整體和附近的筆記本

檢視整個保管庫時使用全域性圖表進行搜尋，檢視開啟的筆記本週圍時選擇本地圖表的深度。 顏色組是區分符合所選條件的筆記的顯示。 開啟筆記本確認是否儲存了正文和內部連結。

新增筆記的前後資料夾和標籤孤立筆記顏色組本地深度練習用檔案

例的筆記名、文章、標籤是作者製作的。 研究和生活的真實記錄，不是從使用者的保管庫中獲取的。 顯示位置是佈局，不是表示所需時間或理解程度的值。

自己排列卡片表示關係的步驟，請參考在Canvas中建立、連線、移動、重新顯示的例項。

這個例子的儲存內容和顯示條件

首先準備了六個Markdown。“ “研究”的三個筆記是入口→假設→驗證，“生活”的兩個筆記是購物→吃飯和內部連結，孤立筆記沒有其他筆記的連結。 可以區分兩個連線成分和一個孤立筆記的練習用構成。

研究/入口.md → 研究/仮説.md → 研究/検証.md
生活/買い物.md → 生活/食事.md
孤立.md

後からGUIで追加: 追加メモ.md → 研究/入口.md

最初的六個檔案是在應用程式啟動前準備的，只有第七個是用實際的編輯器製作的。“ 研究”資料夾的三本筆記和附加筆記上寫著#研究，生活中的二本上寫著#生活。

全域性圖的第一個條件是Search files空白、Tags OFF、Attachments OFF、Existing files only OFF、Orphans ON。 沒有未解決的連結。 之後的比較中，只切換了說明的搜尋、Orphans、顏色組。

1。 新增筆記，比較儲存內容和圖表

從左邊的絲帶開啟Open graph view。 一開始是六筆記、三連結。 接下來用Ctrl＋N製作“追加備忘錄”，將名字和正文輸入到實際編輯器中。 儲存的全文是以下92 bytes。

# 追加メモ

GUIで追加する著者作成ノートです。 [[研究/入口]]

#研究

等待自動儲存後開啟圖表，變成了七筆記、四連結。 從附加備忘錄到研究/入口的1個增加了，已儲存的Markdown和內部連結的解決結果也一致。

設定面板覆蓋了一部分節點。 這兩個影象的件數是從實際的Graph renderer讀取節點名稱和連結端點後確認的數值。 不是在影象中可以看到所有圓圈的計數方法。 影象保持原樣儲存。

最後從檔案一覽表中重新開啟附加備忘錄，閱讀了正文和標籤。 新增時、重新顯示後、應用程式正常結束後的儲存Markdown是相同的內容。

2。 在資料夾和標籤中，選擇不同的範圍

Graph settings的Filters → Search files中輸入搜尋字串。 選擇資料夾內的筆記的例子是path:"研究/"，選擇包含標籤的筆記的例子是tag:#研究。 這次的結果有如下不同。

輸入的條件物件筆記確認的結構
path:"研究/"研究 資料夾的入口・假設・驗證3筆記本/2連結
tag:#研究上述三本筆記和保管庫正下方的附加備忘錄4筆記本/3連結
清空搜尋字串這次的七個筆記全部7筆記本/4連結

因為附加備忘錄就在保管庫的正下方，所以不符合研究 資料夾的通行證條件。 因為擁有#研究，所以符合標籤條件。 這裡沒有嘗試將Tags的切換保持關閉狀態，將標籤本身顯示為節點的操作。

縮小範圍時，將Search files清空。 這次，搜尋候選與操作重合時，用Esc關閉後，點選了下一個切換。 資料夾名和標籤名，根據自己的儲存內容。

3。 如果也看孤立筆記的話，請開啟Orphans

在清空搜尋字串的狀態下，關閉Filters的Orphans後，孤立.md會消失，變成了六筆記、四連結。 回到ON後，回到了包括孤立.md在內的七筆記・四連結。 無論哪個連結端點都一樣。

在這個例子中，因為已經儲存的孤立筆記沒有內部連結，所以切換時顯示物件發生了變化。 看不到筆記時，會分別確認當前圖表的搜尋、顯示條件，看看是否儲存了正文。 不是嘗試未解決的連結和所有過濾器組合的結果。

4。 透過顏色組，辨別符合條件的筆記本

Groups → New group中新增組，第一個輸入path:"研究/"，第二個輸入tag:#生活。 點選組的顏色圓圈，在Linux的顏色選擇畫面中將第一個更改為RGB 30 / 140 / 220（#1e8cdc）。 第二個分配的顏色是#d6ad5c。

研究 資料夾 中的三則筆記變為藍色，帶有生活標籤的兩則筆記變為金色。儲存庫根目錄下新增的筆記和 孤立.md 不符合這兩個條件，因此沒有顯示群組顏色。我們也核對了節點名稱和顏色的讀取結果；整體仍為七則筆記、四條連結。

原始影象是實際的顏色選擇畫面，GUI輸入使用了現有的X11滑鼠、鍵盤輔助。 在應用程式API和DOM的值代入中沒有設定顏色。 沒有嘗試過顏色組的重複、重新排列、其他顏色和OS的選擇畫面。

5。 根據本地圖表的深度，選擇附近的筆記

檔案一覽表中開啟研究/入口.md，選擇了筆記的More options → Open linked view → Open local graph。 本地圖形的Filters有Depth滑塊。 這次的條件是Incoming links ON、Outgoing links ON、Neighbor links OFF。

深度入口周邊的筆記確認的結構
1入口，從入口參考的假設，參考入口的附加備忘錄3筆記本/2連結
2在上述中，增加了從假設中參考的驗證4筆記本/3連結

Depth透過實際的滑塊操作從1改為2，確認了節點名稱和連結端點。 生活二筆記本和孤立.md沒有連線到入口，所以沒有進入這兩個深度。

第二張圖片是選擇設定後關閉面板拍攝的原始圖片。 這是以入口為物件的深度1・2的記錄。 開啟另一個筆記的話，連結的本地圖表的物件也會改變。 深度3~5和Incoming/Outgoing/Neighbor links的其他組合沒有嘗試過。

常見問題

圖表上看不到筆記時，要確認什麼？
在這次的例子中，Search files的搜尋字串和Orphans的ON/OFF改變了物件。 開啟目標筆記確認儲存內容，清空搜尋字串，同時確認孤立筆記時開啟Orphans。 Tags、Attachments、Existing files only等條件也可以在官方幫助中確認。 沒有嘗試所有設定的組合。
全域性圖和本地圖有什麼不同？
全域性圖表以保管庫的整個筆記為物件，本地圖表以連線開啟的筆記的範圍為物件。 在這次的入口筆記中，開啟Incoming links和Outgoing links，關閉Neighbor links，深度1是3筆記・2連結，深度2是4筆記・3連結。 不包括其他連線成分和孤立筆記。
Tags的切換和tag:搜尋是同一個操作嗎？
官方幫助的Tags是為了在圖表上顯示標籤而進行的切換。 Tag：搜尋是縮小包含指定標籤的筆記的搜尋。 這次Tags在OFF狀態下，用tag:#研究顯示了4筆記。 這個例子沒有嘗試過將標籤本身顯示為節點的操作。
節點和線多的話，可以判斷知識和生產力高嗎？
在這篇文章中確認的是，儲存的筆記、內部連結、指定顯示條件的結構差異。 沒有衡量知識的正確性、理解的深度、生產力和速度。 本文中確認連結理由的練習，在Zettelkasten的筆記和連結的實踐指南中介紹。

驗證環境和確認範圍

  • 實際應用：Linux版Obsidian 1.13.7，安裝程式1.13.7。 沒有社群外掛，作者製作的小型日語保管庫。
  • 實GUI：開啟圖表，新建筆記、輸入、儲存、搜尋輸入、Orphans切換、組建立和顏色選擇、從檔案列表和選單開啟本地圖表、Depth滑塊、重新顯示、General設定、正常結束。
  • 輔助：啟動前準備初期六Markdown，讀取了儲存檔案、內部連結的解決結果、renderer的節點名/線數/顏色、設定。 新增筆記和更改顯示條件是實GUI。
  • 圖片：未加工實際畫面的原始PNG刊登。 設定面板和狹窄的顯示區域覆蓋了部分節點的記錄，件數是按照註明的API讀數進行核對的。
  • 未驗證：iOS/Android/Windows/macOS、Sync、SimpleMemo配合、別終端、大保管庫、所有搜尋、顯示設定、速度、學習、生產力、流入效果。
