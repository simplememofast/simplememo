是委託託管，還是自己管理生成物

Publish是Web公開筆記的官方託管服務。 Quartz是從Markdown生成網站的工具，另外選擇生成物的傳送目的地。 GitHub Pages是其傳送目的地之一。 結合Quartz和GitHub Pages時，處理生成和傳送兩個角色。

選擇想要公開的筆記，如果想要將網站的託管委託給服務的話，請確認Publish的條件。 如果能自己執行命令、更改設定、管理傳送目的地的話，用小筆記嘗試Quartz等靜態生成。 如果只儲存的筆記不需要在Web上公開的話，在選擇公開用的附加服務之前決定目的。

角色的比較費用確認實際構建的輸入生成步驟畫面和連結練習用檔案

Publish・Quartz・GitHub Pages，負責的範圍不同

選擇角色和自己要做的事情這次確認
Obsidian Publish官方的雲託管。 準備賬戶和Publish合同，管理公開的筆記和網站。用固定來源確認官方Introduction/Set up。 合同、Publish實際操作、實際公開未實施。
石英從Markdown等生成網站的工具。 自己處理Node/npm、設定、輸入檔案、生成物。v4分支的固定commit，在package 4.5.2中實際npm ci・本地構建・瀏覽器顯示。
GitHub 頁從儲存庫傳送靜態網站的服務。 管理儲存庫、公開來源、workflow、公開/非公開和計劃條件。用固定來源確認官方資料。 未實施新儲存庫的製作、設定、部署、實際釋出。

這個表不是比較所有功能的排名。 用Quartz構建，並不意味著與Publish相同的服務功能，以及GitHub Pages的釋出成功。

費用，將合同、傳送地址、運用分開確認

Publish的現行金額，在這次的環境下尚未再次確認。 最新的金額和年付、月付的申請期限請在Obsidian官方費用上確認。 從這個實際構建的成功來看，沒有得到Publish免費的結果。

固定的Quartz源是MIT許可證。 這是軟體的使用條件，並不是傳送地址、獨立域名、更新工作等費用一律為零的條件。 這次的執行費用也不清楚。

固定的GitHub官方資料，在GitHub Free和麵向組織的GitHub Free中可以在公開儲存庫中使用Pages，在Pro/Team/Enterprise的條件下對應公開・非公開儲存庫。 確認實際選擇的賬戶的計劃、公開範圍、限制和合同條件。 這邊這次也沒有改變賬戶和託管的設定。

現有費用一覽表是2026年9月9日確認官方標識的報道。 這次不將其作為現行費用的獨立確認，將最新的購買條件作為需要官方確認的資訊進行劃分。 Publish和終端之間同步的Sync也是另外的服務。

# 著者作成の公開前メモ

これはローカルビルドのための架空の短文です。利用者の記録ではありません。

次は [[手順/確認|確認ノート]] を開きます。

![[assets/fixture-diagram.svg]]

展開固定源，確認依賴和設定後構建

  1. 確認了官方Quartz的v4分支，在scratch中展開了commit d25a6eabf96751ffca56f8a8139272def7a65041的源檔案。
  2. 確認了README、MIT許可證、package.json、package-lock.json、CLI的構建處理。 Package version是4.5.2，必要版本是Node 22以上・npm 10.9.2以上。 實際環境是Node 24.19.0・npm 11.9.0。
  3. 用固定的lockfile執行了npm ci。 安裝了491 packages，exit 0。 lockfile的597 entries是包含對應OS等依賴的記錄，與安裝顯示件數的意思不一樣。 原lockfile的bytes沒有變化。
  4. 更改了私人設定，以三個筆記為物件用Quartz CLI生成。 接下來說明設定變更和第一次失敗。

執行的命令形式如下。 例子的輸入輸出資料夾，指定自己準備的地方。

npm ci --no-audit --no-fund
node quartz/bootstrap-cli.mjs build   --directory /path/to/fixture   --output /path/to/generated   --concurrency 1

在執行日誌中留下了scratch內的絕對路徑和隔離的npm cache指定。 這裡顯示的path是說明用的替換。 省略了audit的命令，並不意味著透過了依賴的安全審計。 報道不是執行到公開伺服器的部署程式的記錄。

在這個本地例子中更改的設定

專案這次的設定和確認範圍
顯示・連線地址日語locale，作者製作標題，localhost base URL，analytics null，不使用外部font的system font。
日期frontmatter/檔案屬性優先。 使用源檔案，沒有將Git履歷作為日期的證據。
任意OG生成CustomOgImages emitter失效。 Quartz的獨自OG生成尚未驗證。
數式第一次標準Latex要求外部KaTeX CSS/JS，在環境方面被遮蔽了。 用沒有數學公式的相同fixture，使未使用的Latex失效後重新構建了。

兩次的構建都生成了exit 0，每個20檔案。 保留首次生成物和失敗的瀏覽器記錄，在另一個資料夾中確認設定變更後的生成物。 不會擴大標準Quartz不進行外部通訊的結論和數式的相容性。

生成的HTML，wiki連結，實際開啟附件

在本地伺服器上開啟生成物，確認了320/390/768/1440 px的四幅。 閱讀title、日語正文、驗證標籤、SVG，入口→確認→參考→入口在各個寬度上實際點選。 總共12點選的有限確認。

生成HTML三件、CSS、JS二件、contentIndex、SVG共八件，localhost的實HTTP響應和生成原件的bytes/SHA256一致。 附加的SVG也與輸入原件的內容相同。 設定變更後的四幅沒有橫向突出和該頁面的console/page/resource錯誤。

雖然顯示了影象中的圖表和反向連結widget，但其全部功能都沒有嘗試過。 因為在fixture中也寫了正文標題，所以和Quartz那邊的報道標題重疊顯示。 現行費用確認、SEO效能、大Vault、Web公開的證明不計入。

常見問題

要在網上公開Obsidian的筆記，必須有Publish的合同嗎？
使用Publish時，官方指南中需要Obsidian賬戶和有效的Publish合同。 另一種方法是，在Quartz中將Markdown生成的網站放在自己選擇的傳送目的地。 這次確認了Quartz的本地生成，沒有嘗試Publish合同和外部發布。
Quartz和GitHub Pages是同一種類的服務嗎？
Quartz是將Markdown轉換為HTML、CSS、JavaScript等的工具，GitHub Pages是從儲存庫傳送靜態網站的服務。 將用Quartz製作的產物放在GitHub Pages等的構成。 GitHub Pages的設定、部署、實際釋出這次沒有進行。
Publish和替代方法的費用，應該在哪裡確認呢？
Publish的最新金額和請求期限將在官方費用頁面確認。 在這次的環境下無法重新獲得現行費用頁面，現行金額尚未確認。 Quartz的固定來源是MIT許可證，但傳送地址、域名、運用費用另行確認。 GitHub Pages的公開、非公開儲存庫的計劃條件也參考官方資料。
僅透過這次Quartz確認，就能判斷Web公開和所有功能的相容性嗎？
無法判斷。 關於三個作者製作的Markdown和一個SVG，確認了固定commit的本地構建、四畫面寬度、內部連結和生成檔案。 有使未使用的Latex和任意OG生成無效等設定變更。 數式、大保管庫、全Obsidian功能、外部傳送、同步、SimpleMemo配合、速度和生產率尚未驗證。

固定來源和確認的範圍

實際構建・瀏覽器確認的UTC日是2026年9月30日，日本時間是2026年10月1日。 Node/npm/Quartz的實版、source/lock、設定差異、首次失敗、儲存原件彙總到驗證記錄中。 首次瀏覽器的語言期望值錯誤和失敗JSON一件因覆蓋而缺失也明確說明了。

  • 執行確認：私人CLI的npm ci和二構建，設定變更後的本地四幅・內部連結・附加・HTTP原件核對。 實際沒有進行Obsidian GUI輸入。
  • 官方說明：Publish introduction/setup、Quartz source/docs、GitHub Pages角色・計劃條件透過固定commit確認。
  • 未確認：Publish現行金額・合同・實際操作，GitHub Pages/其他傳送目的地的部署和配送，數式・任意Quartz OG・全部功能，iOS/Sync/SimpleMemo，全環境・速度・生產力・流入效果。
