隱私政策

最後更新日期：2026年10月7日

YURIKA, K.K.（以下簡稱“本公司”）對“SimpleMemo”（以下簡稱“本服務”）中使用者資訊的處理，規定如下隱私政策。

1。 獲取的資訊

本公司可能會獲取以下資訊。

(A) 使用者輸入、設定的資訊

  • 收件人郵箱地址（To）
  • 標題設定（Subject）・簽名設定（Signature）
  • 備忘錄正文（傳送郵件所需的範圍）

(B) 關於終端、使用的資訊

  • 終端資訊（OS/終端種類等一般資訊）
  • 傳送處理所需的日誌（傳送日期、結果狀態等）
  • 使用事件（畫面顯示、操作、傳送結果）、終端單位的隨機識別符號、會話ID、傳送ID、啟動完成情況等診斷資訊
  • 用於防止濫用和限制請求頻率的技術資訊，例如 IP 地址、請求資訊等

使用活動中不包含郵箱地址和備忘錄正文，但透過傳送ID可以與傳送記錄的收件人郵箱地址的雜湊關聯。 因此，這些事件、終端識別符號、診斷資訊被當作與使用者聯絡起來的資訊。 終端識別符號的儲存位置和刪除應用程式後的處理情況記載在以下12中。

(C) 從Apple收到的訂閱、退款通知

為了掌握訂閱的運用情況和支付失敗，驗證從Apple收到的簽名通知，記錄訂閱開始、更新、自動更新設定變更、更新失敗、過期、退款等。 儲存的專案是通知和交易的識別符號、訂閱商品的識別符號、通知的種類、區分、生產或測試環境的區分、購買、有效期、取消、通知、接收等日期和時間，以及Apple通知的取消理由。 因為包含Apple側的識別符號，所以不作為完全匿名的資訊處理。 這個通知記錄不儲存郵箱地址、備忘錄正文、安裝識別符號，Apple的交易識別符號、安裝識別符號和收件人郵箱地址的對應表也不儲存。 以下（D）在處理中核對通知，製作其他分析記錄。 從僅基於郵箱地址的刪除請求中，無法確定原來的通知記錄。

(D) 訂閱狀態和持續使用的分析

在對應的應用程式中，如果這個分析有效，從終端接收帶有Apple簽名的購買、更新資訊，將驗證的訂閱狀態與終端單位的識別符號一起記錄下來，與持續使用的事件進行核對。 記錄的專案是訂閱商品、本人購買或家庭共享的區分、價格、貨幣、購買、有效期、取消、簽名、觀測、接收等日期和時間、自動更新的狀態、請求重新嘗試、寬限期、過期理由、生產或測試環境的區分，以及應用程式的執行環境。 處理中用Apple的交易識別符號核對上述（C）的通知，同時記錄當時確認的通知種類數量和最終日期。 Apple的交易識別符號和簽名資訊的原文，不會和這個分析記錄一起儲存。 雖然不包括郵箱地址和備忘錄正文，但終端識別符號、商品、日期、價格等與使用資訊相關聯，所以不視為匿名資訊。

這個分析記錄從收到開始超過90天的定期刪除。 從對應的應用程式刪除時，會刪除終端保留的刪除用資訊對應的分析記錄，即使刪除的資訊延遲重新傳送也不會儲存。 此操作不會一次性刪除上述（C）的原始Apple通知記錄、其他終端的記錄或外部分析服務的記錄。 丟失終端刪除用資訊等情況，可能無法確定物件。

(E) 對應應用程式版的使用情況分析選擇

在設定中提供“使用情況分析”選項的應用版本中，常規應用內使用事件及來自裝置的訂閱狀態分析預設關閉。只有使用者選擇“同意並開啟”後才開始收集；未選擇則不會開始。這項選擇獨立於郵件提醒的同意，也不同於 Apple 裝置的 App Analytics 共享設定。在應用內撤回同意後，我們會停止新的收集，並嘗試刪除裝置上尚未傳送的事件。若無法確認刪除，介面會顯示提示；之前同意期間生成的事件，不會在日後重新同意時再次傳送。已經開始傳輸的請求可能仍會完成，撤回本身不會刪除我們已經收到的記錄。內部驗證用 Capture 測試中，操作順序和傳送結果等測量也屬於使用情況分析與質量改進的目的。但參與測試還需要另行同意，屆時會說明測試範圍和期間。僅開啟此選項不會報名參加測試。撤回此選項後，新的測試測量也會停止。若需刪除已儲存的測試記錄，請使用測試的退出及刪除操作。沒有此選項的應用程式版本，會隨應用程式運作傳送下述 12 的使用事件及上述 (D) 的訂閱狀態分析。我們撤銷自 2026 年 9 月 28 日起實施的、不儲存舊方式請求的伺服器端限制，接收舊方式及提供此選項的版本雙方的分析請求。不會追溯補齊先前未能收集的事件。保留此選項的版本仍按應用程式內設定開始或停止收集。AppsFlyer SDK 的獲客與使用情況測量見下述 12。

這個選擇並不同意AppsFlyer的獲取測量。 在設定中有“知道應用程式的路徑測量”的版本中，只有在以下（F）的其他選擇和iPhone的跟蹤許可都同時存在的情況下，才會啟動AppsFlyer SDK。 在沒有其他選擇的使用情況分析對應版中，SDK會停止。 沒有選擇畫面的應用程式版的處理在以下12中記載。

(F) 對應APP版的獲取測量選擇

“知道應用程式的路徑的測量”是任意的，初始狀態是關閉的。 同意此選擇和iPhone的追蹤許可同時，為了掌握下載連結的獲取情況，向AppsFlyer傳送應用程式的啟動、獲取來源、活動資訊、廣告識別符號、IP地址、終端型號、OS、應用程式版本等技術資訊。 雖然使用SDK固有的識別符號，但是不會將本公司的使用情況分析的識別符號作為Customer User ID傳遞。 為此目的，不傳送備忘錄正文、郵箱地址、購買活動、普通的應用內使用活動，與廣告合作伙伴共享和廣告的個別最佳化無效。 SKAdNetwork、IDFV和Apple Ads的測量也在這個路徑上無效。 因為包含識別符號，所以不作為匿名資訊處理。

即使不同意也可以使用應用程式。 在設定中撤回的話，會停止新的測量，刪除終端內獲得來源的確認記錄。 通訊中的請求可能會完成，AppsFlyer已經收到的資料的刪除和iPhone的追蹤設定的更改，不包含在這個操作中。 同意使用情況分析、同意郵件提醒、Apple的App Analytics共享設定是獨立的選擇。

2。 使用目的

獲取的資訊，用於以下目的。

  • 提供郵件傳送功能（傳送、未傳送管理/重新傳送、歷史顯示）
  • 本服務的運用、維護、故障應對、質量改善
  • 將內部測試終端排除在使用統計之外，設定好的Obsidian功能的指南不要重複
  • 防止非法使用、確保安全（限制短時間連續傳送、伺服器端速率限制等）
  • 諮詢對應
  • 遵守法令

3。 根據計劃的差異

本服務的資訊處理與Free/Premium基本相同。 Premium以使傳送次數限制無效（解除Free的“每天3則”限制）為目的而提供，但為了安全和傳送基礎保護的限制（冷卻等），無論Free/Premium如何，都有適用的情況。

4。 備忘錄內容的處理（重要）

  • 備忘錄正文透過使用者的操作傳送郵件。
  • 為了傳送處理，備忘錄正文及收件人資訊可能會透過本公司使用的傳送基礎（包括外部服務）。
  • 除履行法律要求、防止濫用、處理服務故障等正當必要情形外，我們不以長期儲存或檢視筆記內容為目的。

5。 郵件提醒功能（任意）

本服務為了支援傳送備忘錄的習慣化，提供向希望的使用者傳送提醒郵件的任意功能。

(A) 獲得同意

  • 本功能預設無效，只有在認證畫面或設定畫面上使用者明確啟用時才會傳送。
  • 即使尚未啟用提醒，如果您已驗證郵件地址，且一段時間沒有傳送筆記（參考：距上次傳送約 72 小時），我們也可能傳送僅 1 次的邀請郵件，詢問您是否願意接收提醒。除非您選擇接收，否則不會傳送提醒。
  • 啟用後，也可以在設定畫面點選1停止。 各個提醒郵件末尾的解除連結也可以停止。

(B)獲取、儲存的資訊

  • 郵箱地址的雜湊值（SHA-256）—儲存在本公司伺服器（Cloudflare D1）。
  • 同意狀態（有效/無效）、最終備忘錄傳送日期、累計傳送次數。
  • 提醒傳送記錄（傳送日期、傳送/開啟/點選/彈跳等活動）。
  • 我們的伺服器不儲存原始電子郵件地址。原始地址僅由郵件傳送平臺（Resend）的聯絡人 API 儲存。

(C) 傳送頻率

  • 從最終備忘錄傳送開始，24小時/72小時/7天 經過的時機，每個1傳送。
  • 每個1使用者設定了每1每週最多2封，整個服務設定了1每天最多80封的上限。

(D) 自動解除

  • 郵件傳送時出現彈跳、投訴時，立即停止向該地址傳送，同意狀態無效。

(E) 受委託的服務提供商

提醒郵件傳送及聯絡人管理委託給美國的 Resend, Inc.。該公司遵守 Data Processing Agreement 及國際郵件傳送法規，包括 CAN-SPAM、GDPR 和日本《特定電子郵件法》等。

6。 第三方提供

除以下情況外，本公司不會向第三方提供個人資訊。

  • 如果使用者同意的話
  • 根據法令的情況
  • 需要保護人命、財產等時
  • 在業務所需範圍內向受委託的服務提供商提供資訊時（見下一節）

7。 委託（郵件傳送等）

我們可能將郵件傳送、運維和分析等業務委託給外部服務提供商，並對受委託方進行適當監督。

8。 安全管理

本公司為了防止資訊洩露、滅失、損毀等，採取合理的安全對策。

9。 保管期限

我們努力避免將資訊儲存超過實現使用目的所需的期限。使用事件及上述 1(D) 中的訂閱狀態分析記錄超過 90 天后，會定期刪除；傳送 ID 與收件人雜湊值的對應記錄超過 35 天后，也會定期刪除。Apple 的訂閱與退款通知原始記錄在接收超過 180 天后，由每日任務刪除。由於每次處理數量有上限，如待刪除記錄較多，會在次日及之後繼續處理。其他日誌等可能因防止濫用或運營需要，在必要範圍內儲存一定時間。

10。 修訂

本公司根據需要修改本政策。 修改後會在本服務或本公司網站等上公佈。

12。 關於加密的技術資訊（參考）

本服務為了保護使用者的隱私，採取了以下技術對策。 這些與其說是“安全”，不如說是為了“資料最小化”和“終端內保護”的實施。

  • 裝置內儲存空間：離線待傳送訊息（Outbox）和傳送歷史記錄使用 Apple 原生 CryptoKit 提供的 AES-GCM-256 加密，儲存在裝置上（檔案保護類別：completeFileProtectionUntilFirstUserAuthentication）。
  • 金鑰管理：256-bit 對稱金鑰存放在Apple Keychain Services（kSecClassGenericPassword），重啟後首次解鎖後可以使用，使用不轉移到其他終端的保護類。 應用程式在加密、解密時讀取金鑰。 備份中包含的金鑰副本由終端固有的金鑰保護，在其他終端無法使用（Apple的說明）。 在更換機型之前，請確認必要的備忘錄是否已送達郵件或Obsidian等儲存地址。
  • 通訊路：API通訊由TLS（HTTPS）保護。 傳送備忘錄用的URLSessionConfiguration.ephemeral是將該會話的快取、Cookie、認證資訊不永久儲存在磁碟上的構成。 與使用分析的儲存、傳送和外部SDK的通訊說明區分開來。
  • 郵件正文：為了傳送處理，透過本公司的Relay API（Cloudflare Workers）和外部傳送基礎（Resend），但不會進行持續儲存。 日誌也不記錄（開發時的DEBUG構建除外）。
  • 郵件地址的伺服器儲存：將傳送ID和收件人郵件地址的雜湊（從SHA-256生成）的對應儲存在Cloudflare D1中。 無論選擇加入提醒，都會建立這個對應記錄。 提醒用的聯絡人由Resend的Contact API進行管理。
  • 加密、保管、通訊路的依賴關係：備忘錄正文的加密（CryptoKit）、鑰匙保管（Keychain Services）、通訊（URLSession / Network.framework）全部用Apple純正框架完成，不透過第三方SDK。
  • 登入和防止非法使用的SDK：作為任意的入職縮短功能，從Google賬戶匯入郵箱地址時，使用GoogleSignIn-iOS SDK和Firebase Authentication SDK。 Firebase App Check SDK在啟動時初始化，使用Apple App Attest防止後端API的非法訪問。
  • 本公司的使用分析：為了改善質量和掌握使用情況，向本公司的/v1/analytics/event傳送事件。 專案包括隨機安裝識別符號、會話識別符號、事件種類、識別符號、時間、應用程式的版本、構建、語言、傳送結果等允許的屬性。 雖然設計不直接包含郵箱地址、備忘錄正文、驗證碼，但可以透過傳送ID與收件人郵箱地址的雜湊聯絡起來。 這個安裝識別符號儲存在終端的鑰匙鏈中。 在iOS的構造上，鑰匙鏈的專案即使刪除應用程式也會留在終端上，在這種情況下，重新安裝後也會使用相同的識別符號（以下的舊版AppsFlyer合作中，Customer User ID也使用相同的識別符號）。
  • 透過AppsFlyer獲得、使用分析：在沒有上述1（E）選擇畫面的應用程式版中，啟動AppsFlyer SDK，將首次備忘錄傳送成功、認證成功、收費畫面顯示、方案選擇、購買成功作為事件傳送。 從應用程式設定的屬性，在適用的情況下，包括購買金額、貨幣、訂閱期間、畫面的區分。 因為將與本公司分析相同的安裝識別符號設定為AppsFlyer的Customer User ID，所以可以將獲得的資訊和使用記錄聯絡起來。 從應用程式設定的活動專案中不直接包含郵箱地址、備忘錄正文、驗證碼。 這裡列舉的專案是應用程式明確設定的，並不是列出SDK獲取的技術資訊的所有專案。 識別符號和可關聯的記錄不會被視為完全匿名的資訊。 在有使用情況分析選擇的版本中，停止SDK，僅限於對應上述（F）的版本，在有其他目的的同意和iPhone的追蹤許可的情況下，只開始獲取測量。

注意：本服務不提供End-to-End加密（E2EE）。 為了在收件人使用者自己的郵件客戶端上正常閱讀正文，郵件正文將透過標準的SMTP協議傳送。 對於需要E2EE的用途，請考慮Standard Notes、Signal、ProtonMail等專用服務。

本節的內容，作為面向Obsidian使用者的“資料通道”的圖解，重新整理在隱私設計頁面。

13。 本公司網站的訪問分析

我們的網站（simplememofast.com）為了掌握瀏覽情況並改善內容，使用了以下訪問分析。 與上述應用程式（本服務）的使用資料是不同的。

(A) Google 分析（Google LLC・美國）

  • 在Cookie（第一方Cookie“_ga”等）中，儲存每個瀏覽器的隨機識別符號，區分使用者數和會話。
  • 收集的資訊包括瀏覽的頁面、參考來源、大致的地區、瀏覽器和終端的種類、頁面上的操作（App Store的連結顯示和點選等）等。 Google說明，Google分析4不會記錄、儲存IP地址。
  • 收集到的資訊由Google處理。 Google的使用方法請看“從使用Google服務的網站和應用程式收集的資訊由Google使用”。
  • 如果想要脫離統計物件，請使用Google分析選擇退出附加元件，或者在瀏覽器設定中禁用Cookie。

(B) Ahrefs Web Analytics（Ahrefs Pte. 有限公司 ・新加坡）

  • 用於瀏覽數等的統計。 Ahrefs說明，這個工具不使用Cookie，不直接儲存IP地址。
