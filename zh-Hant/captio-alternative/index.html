立即恢復與Captio相同的操作感

Captio的“開啟→備忘錄→立即郵件→消失”的肌肉記憶，只要稍微調整一下設定就可以直接再現。 滿足下一個4的話，從第一天開始就能恢復到“平時的Captio”的手感。

  1. 將收件人郵件設定為與Captio相同的地址 → 與過去的Captio備忘錄相同的收件箱中彙總。
  2. 在主頁的“Captio所在的同一位置”放置圖示 → 拇指的動作沒有變化，啟動是無意識的。
  3. 在鎖定畫面/主頁上新增小部件（iOS 17以後）→1點選開啟應用程式（iOS 26以後的對應機型、語言的話，可以直接開始語音備忘錄）。
  4. “寫→一鍵傳送→自動清除”1度嘗試→身體想起了Captio的流程。

更詳細的轉移步驟和功能對應表、本頁的5步驟轉移也請看。

Captio發生了什麼 — 完全時間線

Captio是iOS的“給自己傳送郵件”應用程式中最受歡迎的應用程式1。 得到了使用GTD實踐者、記者、收件箱作為收集工具的人們的熱烈支援。 這裡按時間順序整理從2010年左右釋出到2024年服務結束的經過。

2010年左右 — 釋出
荷蘭的Boonbits/Tupil（開發者Ben Lenarts）在App Store上作為搶購應用程式釋出。“ 只有“開啟應用程式→打→傳送”的極簡設計成為話題。 其特點是沒有資料夾、類別和工具欄，徹底的削掉。
2014〜2019年 — 黃金期
在Lifehacker、The Sweet Setup、MacStories等主要生產力媒體上被介紹。 在日本也有多個博主（teineini.net・growrichslowly.net・danshihack.com等）介紹，深入GTD使用者・博主・秘書層。
2021年6月 — 最後的更新
在這個時間點最後，應用程式本體的更新停止了。
2022年左右 — 從App Store撤軍
根據開發商的通知，Captio在雲服務終止通知的大約2年前退出了App Store。 面向現有使用者的雲服務，之後也在繼續。
2024年3月左右 — “無法傳送”的報告
note等，Captio接連收到“傳送失敗”“無法送達”的報告。
2024年10月1日 — 雲服務結束
正如開發者在captio.co上通知的那樣，面向現有使用者的雲服務已經結束。 通知的理由是，為了保持應用程式的穩定性和安全性，無法繼續花費精力。
結束後 — 尋找替代的應用程式
通知是，如果尋找替代品的話，在App Store上搜尋“email yourself”的話，會找到類似功能的應用程式。 迄今為止收到的備忘錄，在收件人郵件賬戶的儲存期限和可用性範圍內保留在收件箱中。
2026年 — 獨立的替代應用程式，SimpleMemo
YURIKA, K.K.釋出了SimpleMemo，一鍵將備忘錄傳送到自己的郵件中。 具備離線Outbox和終端內的加密（AES-GCM）。 沒有與Captio及其開發者合作，也沒有受到推薦，是獨立開發的替代應用程式。
確認出處：Captio的官方終止通知，要求終止的理由，以及保持穩定性和安全性的必要資源。 不是因為Gmail、OAuth、外部郵件API的方針變更。

結論：從Captio的操作感中獲得靈感的替代

SimpleMemo得到了Captio重視的3個體驗要素——啟動即輸入、傳送後消失、零多餘的東西――的靈感。 郵件的傳送使用外部服務Cloudflare Workers和Resend API。 離線時，Outbox會保留未傳送的備忘錄，連線恢復後重新傳送。 Outbox和傳送記錄在終端內透過AES-GCM進行加密。 這些功能並不能保證服務和傳送不會中斷。

選擇 SimpleMemo 作為 Captio 替代方案的 3 個理由

1。 同樣的操作感
啟動後會開啟輸入畫面，點選一下即可傳送。 傳送後輸入欄會消失。 雖然是習慣的“給自己發郵件”的流程，但是設定和傳送的行為因應用程式而異。
2。 郵箱的OAuth沒有連線傳送
SimpleMemo透過Cloudflare Workers和Resend API傳送。 只需設定收件人的郵箱地址，就不需要用OAuth連線郵箱。 Cloudflare和Resend是外部服務，所以取決於其可用性和方針。 傳送也取決於收件人的郵件服務。
3。 離線對應+終端內加密
用Outbox架構將離線備忘錄在終端內AES-GCM-256加密儲存。 恢復線上時自動重新傳送。 傳送記錄也同樣在終端內進行加密。

SimpleMemo的郵件傳送機制

SimpleMemo是“給自己發郵件”使用方法的選擇1。 這個頁面是開發者寫的。 以下是動作說明，不是第三方的排名或測量速度的比較。

記錄和傳送是兩回事
啟動後會開啟輸入畫面，一鍵傳送到預先設定的收件人。 啟動所需的時間取決於終端和應用程式的狀態，到達收件箱的時間也取決於網路和郵件服務。 點選或進入Outbox並不能證明已經送達。 這個頁面沒有聲稱SimpleMemo比其他應用程式快。
終端內的AES-GCM加密
AES-GCM保護儲存在終端上的Outbox和傳送記錄。 郵件的傳送是另外的處理，Cloudflare Workers和Resend為了傳送處理正文。 即使對終端內的儲存進行加密，普通郵件也不會被E2E加密。
離線也能寫
開發源的產品頁面，Captio在離線時也可以將備忘錄暫時儲存在終端上。 SimpleMemo也會在離線時傳送的備忘錄在終端內加密儲存，連線恢復後自動重新傳送。 重要的備忘錄請確認傳送情況。 Outbox裡的備忘錄還沒有收到郵件。
收件箱是保管場所
和Captio一樣，SimpleMemo將郵件的收件箱作為保管場所。 備忘錄可以在郵件軟體上搜尋，郵件的服務端也會保留，只要是能看到郵件的終端，就可以在任何地方閱讀。 沒有必要從自己的資料庫中匯出。 即使停止使用SimpleMemo，收到的備忘錄也會留在收件箱裡。

從Captio到SimpleMemo的過渡步驟（5步驟）

Captio是“傳送專用應用程式”，所以過去的備忘錄已經留在你的郵件收件箱裡了。 不需要資料轉移工作。 按照下面的5步驟完成。

  1. 從App Store安裝“SimpleMemo” — 在App Store中搜尋“SimpleMemo”或“SimpleMemo”，或者從本頁面的下載連結直接安裝。 應用程式本體是免費的，Free計劃是每天最多3則免費的（沒有使用期限限制）。
  2. 設定在Captio中使用的收件人郵箱地址 — 首次傳送備忘錄時（或設定的“收件人”），輸入與Captio相同的收件人郵箱地址進行認證。 只有這樣，新的備忘錄就會和過去的Captio備忘錄到達同一個收件箱，可以按時間順序進行統一管理。 Gmail、Outlook、iCloud、Yahoo!、公司郵件等，任何提供商都可以。
  3. 傳送測試備忘錄確認接收 — 寫簡短的測試備忘錄，一鍵傳送。 確認幾秒鐘內到達收件箱。 傳送後，和Captio一樣，畫面會自動清除，馬上回到可以寫下一個備忘錄的狀態。
  4. （任意）新增主頁小部件 — 長按主頁，從新增小部件中選擇“SimpleMemo”（顯示因iOS版本不同）。 點選小部件（iOS 17以後）就會開啟應用程式。 iOS 26以後的對應機型、語言的話，可以直接用聲音開始記筆記。
  5. （任意）在Gmail上設定自動分配標籤 — 透過Gmail的過濾功能在“From: noreply@mail.simplememofast.com”的郵件中自動賦予“SimpleMemo”標籤。 透過搜尋區分過去的Captio備忘錄（傳送地址不同）和新的備忘錄，在同一收件箱中可以進行時間序列管理。
小知識：使用Gmail時，Captio的過去備忘錄透過傳送方（發件人）地址進行過濾後，可以一次性收集。 Captio時代的郵件中包含發件人您自己的Gmail地址，所以在搜尋中輸入“from:您的地址”就會全部出現。

常見問題

Captio為什麼不見了？

開發來源在captio.co上通知雲服務結束（2024年10月1日）。 根據公告，Captio在大約2年前退出了App Store，終止的理由是無法繼續為保持應用程式的穩定性和安全性而付出努力。

2026年現在最接近Captio的替代應用程式是什麼？

根據使用方法不同，適合的應用程式會有所不同。 SimpleMemo是從Captio的工作流程（啟動即輸入、一鍵傳送、傳送後自動清除）中獲得靈感的獨立選擇，具備終端內加密的Outbox和傳送記錄。 Note To Self Mail（類似於Captio的UI）和Note to Email（免費・多個收件人）也是選擇。 這個頁面是SimpleMemo的開發者寫的，Captio及其開發者不推薦SimpleMemo。

Captio的資料（過去的備忘錄）可以轉移嗎？

Captio是“傳送專用”的應用程式，備忘錄沒有儲存在應用程式內，全部到達了你的郵件收件箱。 也就是說，不需要“轉移工作”本身。 安裝SimpleMemo後，只需將Captio使用的相同郵箱地址設定為收件人即可。 新的備忘錄也會收到同樣的收件箱，可以和過去的Captio備忘錄一起按時間順序進行管理。

SimpleMemo將來也不會突然結束嗎？

沒有可以保證能一直使用的應用程式。 SimpleMemo因為使用Cloudflare Workers和Resend API，所以依賴於外部基礎設施。 免費套餐和付費套餐是根據使用量而制定的，並不能保證服務在未來也能持續下去。 成功傳送的備忘錄，在收件人郵件賬戶的可用性和儲存期限範圍內保留在收件箱中。 Outbox中剩餘的未傳送的備忘錄，還沒有到達收件箱。

Gmail以外的郵箱地址也可以使用嗎？

是的。 Gmail、Outlook、雅虎！ 可以將郵件、iCloud郵件、公司郵件、獨立域名等設定為收件人。 SimpleMemo透過Cloudflare Workers和Resend API傳送，因此不需要OAuth訪問收件人的郵箱。 傳送取決於收件人郵件服務的過濾器和可用性。

可以免費使用嗎？ 費用是多少？

是的。 Free套餐的話每天最多3則，沒有使用期限限制，可以免費使用（無需註冊信用卡）。 Premium計劃是每月500日元或年費5,000日元無限傳送+全部功能解放。 Captio是買斷的應用程式，但SimpleMemo提供免費計劃和訂閱的付費計劃。

Captioo（在詞尾新增o的應用程式）是Captio的繼承者嗎？

不。 Captioo（808 inc. 制）雖然名字和UI與本家Captio（Tupil制）相似，但是是其他開發商的其他應用程式，沒有後續和官方關係。 根據App Store的說明，支援影象的傳送和小部件。 SimpleMemo以“從Captio的工作流程中獲得靈感的體驗，在獨立基礎上重建”的設計思想進行開發。

有安卓版嗎？

現在SimpleMemo只有iOS（iOS 16以後）。 因為Captio也是iOS專用的，所以使用層是重疊的。 沒有安卓版。 Android使用者中想要使用“給自己發郵件”系統的人，請考慮Note to Email和Email Me等替代，或者透過PC瀏覽器Google Keep→Gmail自動轉發。

可以傳送附件和圖片嗎？

不。 SimpleMemo是文字專用的（Captio也支援附加照片等）。 這不是限制，而是設計判斷，透過省略附加功能，以立即傳送文字為中心使用。 如果您想傳送影象或檔案，iOS標準的共享表或郵件應用程式是合適的。

和attnoel中介紹的Note To Self Mail / Note to Email有什麼不同？

Note To Self Mail是連線自己的郵件伺服器或郵件提供商傳送的方式，有多個收件人、存檔，附件是付費版（不是Gmail專用）。 Note to Email是免費的，收件人是2件，可以傳送多張照片，但不支援貼上。 SimpleMemo只需設定收件人的郵箱地址，不需要郵箱的OAuth連線。 Outbox和傳送記錄在終端內用AES-GCM加密，離線時從Outbox重新傳送。 在選擇之前，請確認現在商店的說明，並嘗試是否實際送達。

Captio使用者的轉移指南

從Captio換乘時在意的要點，從資料轉移、工作流程、功能的3的角度詳細解說。 綜上所述，對於Captio使用者來說，轉移的麻煩很小，還可以使用加密的Outbox和傳送記錄等功能。

資料轉移：其實什麼都不用做OK
用Captio傳送的備忘錄，已經到達你的郵件收件箱了。 Captio不是將備忘錄儲存在應用程式內，而是作為郵件傳送的應用程式，所以沒有從收件箱中刪除的過去的備忘錄會留在郵件中。 也就是說，資料轉移的工作本身是不需要的。 安裝SimpleMemo後，只需將Captio中使用的相同郵箱地址設定為收件人即可。 僅憑這一點，新的備忘錄就會到達同一個收件箱，可以和過去的Captio備忘錄一起按時間順序進行管理。 沒有任何匯出和匯入的麻煩。
工作流程比較：用相同的3步驟傳送
Captio的工作流程是“開啟應用程式→輸入文字→點選傳送按鈕”的3步驟。 SimpleMemo也是“開啟應用程式→輸入→一鍵傳送”的3步驟。 從主頁和鎖屏的小部件（iOS 17以後）點選開啟應用程式，iOS 26以後的對應機型、語言可以直接用聲音開始記筆記。 也支援離線（Captio也有將覆蓋範圍外寫的備忘錄暫時儲存在終端的功能）。 在地鐵裡、飛機裡、訊號無法到達的地方也可以寫筆記並按下傳送按鈕。 備忘錄被加密儲存在Outbox中，在網路恢復時自動傳送。
功能奇偶校驗清單
與Captio相同的點：一鍵傳送、郵件傳送、極簡的UI、傳送後自動清除、不需要多餘的設定的簡單性。 這些基本流程在SimpleMemo上也是一樣。 SimpleMemo的主要功能：終端內AES-GCM-256加密（離線傳送等待的Outbox和傳送記錄在終端內加密，鑰匙在Apple Keychain中保管。 通訊受到TLS的保護，郵件正文不會經常儲存在本公司伺服器上）、離線佇列（透過Outbox架構自動重新傳送）、傳送記錄（可以在應用程式內確認過去傳送的備忘錄一覽表）、黑暗模式（根據iOS的設定切換）。

Captio結束的理由：開發者所說的

關於Captio的終止，作為第一資訊的是開發者的終止通知。 從通知中可以看出，服務結束日期和維護的費力的限制，不知道具體的API問題和詳細的財務原因。

1。 維護的資源的極限
開發者Ben Lenarts表示，為了保持Captio的穩定性和安全性，不能再投入必要的資源了。 根據通知，應用程式從App Store撤出後，面向現有使用者的雲服務仍在繼續。 這是作為服務終止的理由所陳述的。
2。 不推測未確認的技術原因
通知不是因為Gmail、OAuth的規則、API的方針變更、特定的收費模式。 不應該把這樣的解釋當作確定的事實來對待。 選擇替代應用程式時，請確認當前的功能、隱私條件、依賴的服務、費用。 無論哪種商業模式，都不能保證服務會一直持續下去。
