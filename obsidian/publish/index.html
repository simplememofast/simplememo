ホスティングを任せるか、生成物を自分で管理するか

PublishはノートをWeb公開する公式のホスティングサービスです。QuartzはMarkdownからサイトを生成するツールで、生成物の配信先を別に選びます。GitHub Pagesは、その配信先の一つです。QuartzとGitHub Pagesを組み合わせる場合、生成と配信の二つの役割を扱います。

公開したいノートを選び、サイトのホスティングをサービスへ任せたい場合はPublishの条件を確認します。コマンド実行や設定変更、配信先の管理を自分で行える場合は、Quartzなどの静的生成を小さなノートで試します。保存しただけのノートをWeb公開する必要がなければ、公開用の追加サービスを選ぶ前に目的を決めます。

Publish・Quartz・GitHub Pagesで、担当する範囲が違う

選択肢役割と自分が行うこと今回の確認
Obsidian Publish公式のクラウドホスティング。アカウントとPublish契約を用意し、公開するノートとサイトを管理する。公式Introduction/Set upを固定ソースで確認。契約・Publish実操作・実公開は未実施。
QuartzMarkdownなどからサイトを生成するツール。Node/npm、設定、入力ファイル、生成物を自分で扱う。v4ブランチの固定commit、package 4.5.2で実npm ci・ローカルビルド・ブラウザー表示。
GitHub Pagesリポジトリから静的サイトを配信するサービス。リポジトリ、公開元・workflow、公開/非公開とプラン条件を管理する。公式資料を固定ソースで確認。新規リポジトリ作成・設定・デプロイ・実配信は未実施。

この表は機能のすべてを比較するランキングではありません。Quartzでビルドできたことは、Publishと同じサービス機能や、GitHub Pagesからの配信成功を意味しません。

料金は、契約・配信先・運用を分けて確認する

Publishの現行金額は、今回の環境では未再確認です。最新の金額と年払い・月払いの請求期間はObsidian公式料金で確認してください。この実ビルドの成功から、Publishが無料になるという結果は得ていません。

固定したQuartzソースはMITライセンスでした。これはソフトウェアの利用条件で、配信先、独自ドメイン、更新作業まで費用が一律ゼロになるという条件ではありません。今回の実行費用も不明です。

固定したGitHub公式資料は、GitHub Freeと組織向けGitHub Freeでは公開リポジトリでPagesを利用でき、Pro/Team/Enterpriseの条件では公開・非公開リポジトリに対応すると案内しています。実際に選ぶアカウントのプラン、公開範囲、制限と契約条件を確認します。こちらも今回、アカウントやホスティングの設定を変えていません。

既存の料金一覧は2026年9月9日に公式表示を確認した記事です。今回それを現行料金の独立確認として扱わず、最新の購入条件は公式確認を要する情報として分けます。Publishと端末間同期のSyncも別サービスです。

# 著者作成の公開前メモ

これはローカルビルドのための架空の短文です。利用者の記録ではありません。

次は [[手順/確認|確認ノート]] を開きます。

![[assets/fixture-diagram.svg]]

固定ソースを展開し、依存と設定を確認してビルドする

  1. 公式Quartzのv4ブランチを確認し、commit d25a6eabf96751ffca56f8a8139272def7a65041のソースアーカイブをscratch内に展開しました。
  2. README、MITライセンス、package.json、package-lock.json、CLIのビルド処理を確認しました。package versionは4.5.2、必要版はNode 22以上・npm 10.9.2以上です。実際の環境はNode 24.19.0・npm 11.9.0でした。
  3. 固定したlockfileでnpm ciを実行しました。491 packagesがインストールされ、exit 0。lockfileの597 entriesは対応OSなどの依存も含む記録で、インストール表示件数と同じ意味ではありません。元lockfileのbytesは変わっていません。
  4. 私的設定を変え、三ノートを対象にQuartz CLIで生成しました。設定変更と初回の失敗を次に説明します。

実行したコマンドの形は次のとおりです。例の入出力フォルダは、自分が用意した場所を指定します。

npm ci --no-audit --no-fund
node quartz/bootstrap-cli.mjs build   --directory /path/to/fixture   --output /path/to/generated   --concurrency 1

実行ログにはscratch内の絶対パスと隔離したnpm cache指定を残しています。ここで示したpathは説明用の置き換えです。auditを省いたコマンドで、依存のセキュリティ監査を通過したという意味ではありません。記事は公開サーバーへのデプロイ手順を実行した記録ではありません。

よくある質問

ObsidianのノートをWebで公開するには、Publishの契約が必須ですか？
Publishを使う場合は、公式の案内ではObsidianアカウントと有効なPublish契約が必要です。別の方法として、QuartzでMarkdownから生成したサイトを、自分で選んだ配信先に置く構成があります。今回はQuartzのローカル生成まで確認し、Publish契約や外部配信は試していません。
QuartzとGitHub Pagesは、同じ種類のサービスですか？
QuartzはMarkdownをHTML・CSS・JavaScriptなどへ変換するツールで、GitHub Pagesはリポジトリから静的サイトを配信するサービスです。Quartzで作った生成物をGitHub Pagesなどへ置く構成になります。GitHub Pagesへの設定・デプロイ・実配信は今回行っていません。
Publishや代替方法の料金は、どこで確認すればよいですか？
Publishの最新金額と請求期間は公式料金ページで確認します。今回の環境では現行料金ページを再取得できず、現行金額は未確認です。Quartzの固定ソースはMITライセンスでしたが、配信先、ドメイン、運用の費用は別に確認します。GitHub Pagesの公開・非公開リポジトリのプラン条件も公式資料を参照します。
今回のQuartz確認だけで、Web公開や全機能の互換性を判断できますか？
判断できません。三つの著者作成Markdownと一つのSVGについて、固定commitのローカルビルド、四画面幅、内部リンクと生成ファイルを確認しました。未使用のLatexと任意OG生成を無効にするなどの設定変更があります。数式、大きな保管庫、全Obsidian機能、外部配信、同期、SimpleMemo連携、速度や生産性は未検証です。

固定ソースと、確認できた範囲

実ビルド・ブラウザー確認のUTC日は2026年9月30日、日本時間は2026年10月1日です。Node/npm/Quartzの実版、source/lock、設定差分、初回失敗、保存原本は検証記録にまとめます。初回ブラウザーの言語期待値誤りと、失敗JSON一件の上書きによる欠落も明記しています。
