Obsidian · 日次と週次のノート

デイリーノートを強化するプラグイン — Calendar/Periodic Notes

日付や週番号から、振り返りたいノートを開く入口を用意します。CalendarとPeriodic Notesを組み合わせ、日誌と週誌を作成・保存し、同じアプリ内で再び開いた実例です。

検証日: 2026年9月30日（UTC） · Linux版 Obsidian 1.13.7

二つの役割を分けると、設定しやすい

Calendarは「いつのノートを開くか」の入口、Periodic Notesは「どこへ、どんな名前と本文で作るか」の設定です。 今回は日次の2026-09-30と週次の2026-W40を作り、テンプレートの本文に著者の確認文を加えて保存しました。

Obsidian標準のDaily notesや、iPhoneから日誌へメモを追記するルートはデイリーノートの親記事で扱っています。この記事はデスクトップのカレンダー操作と日次・週次の設定に絞ります。

機能役割この例で確認した範囲
Core Daily notesObsidian標準の日次ノート機能。実GUIで有効化。標準機能だけを使った日次作成とは分けて、以下の二つを組み合わせました。
Calendar 1.5.10日付と週番号からノートに進むサイドバー。日付30、週番号40、作成確認、前月と当月の移動。
Periodic Notes 0.0.17Daily/Weeklyの保存先、書式、テンプレート。日誌と週誌の設定、実際の作成本文、保存、同じアプリ内での再オープン。

ここで使った版は、公式の非betaタグから選んだCalendar 1.5.10とPeriodic Notes 0.0.17です。最新・現在の推奨版や、他の版で同じ結果になることを保証する記録ではありません。操作したUIの版も、下の元画面で確認しています。

版と有効化設定値日誌を作る週誌を作るつまずきとFAQ次の手順

検証した版を用意し、有効にする

この実例では、公式リリースのファイルを隔離した著者Vaultへ手動配置し、その後の有効化と操作をGUIから行いました。Community pluginsのBrowse → Installをクリックして導入した検証ではありません。

  1. 練習用のVaultに、空の日誌、週誌、テンプレートフォルダを用意します。この例の入力は下のMarkdownを使っています。
  2. Calendar 1.5.10の公式リリースと、Periodic Notes 0.0.17の公式リリースから、この例で使ったファイルを確認できます。手動配置の構成は下に示します。
  3. Settings → Core pluginsでDaily notesをONにします。今回の操作ではCommand paletteもON、Quick switcherはONの状態を確認しました。
  4. 自分で用意したVaultのTrust確認後、Settings → Community pluginsでPeriodic NotesとCalendarをONにします。以下の元画面は、この二つを実際に有効にした後の表示です。
  5. 右サイドバーを開き、Calendarのタブを選びます。Backlinksなどの別タブのままでは、日付の画面は見えません。

日誌と週誌の保存先を、先に揃える

Settings → Periodic NotesでDaily NotesとWeekly NotesをONにし、次の値を入力します。フォルダとテンプレートは、あらかじめVault内へ用意します。今回の設定入力は実GUIの表示と保存JSONを照合しました。

設定Daily NotesWeekly Notes
FormatYYYY-MM-DDgggg-[W]ww
Note Folder日誌週誌
Note Templateテンプレート/日テンプレート/週

Settings → CalendarではShow week numberとConfirm before creating new noteをONにしました。今回の週開始日はLocale default（Sunday）、アプリのロケールはen、環境のタイムゾーンはUTCです。全ての週境界やロケールの組み合わせを検証した結果ではありません。

つまずいたときの確認とFAQ

CalendarとPeriodic Notesは、どちらも必要ですか？
日付を選ぶ入口と、日次・週次ノートの設定を組み合わせたいときに、この例の二つを使います。Calendarはカレンダーの入口、Periodic NotesはDaily/Weeklyのフォルダ・書式・テンプレートを設定する側です。日次だけの標準設定を知りたい場合は、親記事のデイリーノート解説から始められます。
週番号が表示されないときは？
今回のCalendar1.5.10では、SettingsのCalendarにあるShow week numberをONにすると、左端に週番号の列が表示されました。右サイドバーを開くだけではBacklinksなどの別タブが選ばれていることがあるため、Calendarタブを選んでください。
日付をクリックしても本文に移れないときは？
今回、New Daily NoteとNew Weekly Noteの作成確認は、メイン画面ではなく開いていたSettingsの別ウィンドウに表示されました。両方の画面を見て、対象ファイル名を確認し、その確認画面のCreateを選びます。確認前に同じ日付を何度も押した結果は検証していません。
週次の書式はYYYYとggggのどちらですか？
この固定例で使った値はgggg-[W]wwで、2026-09-30の環境では2026-W40を作成しました。週の年を表す書式と日付の年は境界で一致しない場合があるため、形式を混ぜず、アプリの週開始日とロケールも確認します。全ての年境界・ロケール・タイムゾーンの結果は未検証です。
テンプレート変数やTemplaterも使っていますか？
日次入力にはObsidianのネイティブな{{date:YYYY-MM-DD}}を使い、実作成で2026-09-30への置換を確認しました。週次は著者の静的な本文です。Templater、JavaScript、任意の変数や全ての書式トークンの実行は、この例に含めていません。
iPhone、SimpleMemo、同期でも同じように動きますか？
実操作を確認したのはLinux版Obsidian1.13.7の著者Vaultです。iOS、Android、他OS、Obsidian Sync、SimpleMemoとの連携、端末間同期、速度・生産性・流入の効果は、この記録では検証していません。iPhoneから日誌へ追記するルートは、別のデイリーノート記事を参照してください。

実際に確認した範囲と公式資料

  • 公式Linux版Obsidian 1.13.7／Installer 1.13.7、英語UI。Calendar 1.5.10／Periodic Notes 0.0.17の実バージョン表示。
  • 著者Vaultでの実GUI設定、日次と週次のそれぞれ一つの作成確認・本文・保存・同じアプリ内での再オープン。月移動は別の固定試行で確認しました。
  • プラグインの公式release assetsは手動配置。補助コードは初期環境の用意と状態・保存ファイルの読み取り、原本コピーへ使用しました。ノートの作成・編集・保存・再オープンをAPIで代替していません。
  • 公開するPNGとMarkdownは元ファイルのbytesを保っています。iOS、他OS、SimpleMemo、Sync、全日付・週・月・時刻・タイムゾーン、生産性・流入への効果は未検証です。

準備段階の起動停止、beta版の画面と保存設定の不一致、非表示タブへのクリック、別ウィンドウの確認画面を見落とした失敗は、元の失敗として残しています。この記事の作成・保存例は別の固定試行に基づきます。Ctrl+OではQuick switcher画面を観測できず、同じ保存先のファイル一覧からの実クリックで初めて開き直しました。詳細と元ファイルの対応は検証記録へまとめます。
