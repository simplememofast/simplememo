「ローカル対応」という一語だけでは、プラグイン全体の送信先は決まりません。モデルへ渡すノートの抜粋、索引を作る場所、Web検索や文書変換のサービス、診断・更新確認を分けて確認します。

Copilot：モデルを選んでも、追加機能の経路は別に残る

固定版のガイドは、hosted・Cloud BYOK・Local BYOK・opencode・Claude・Codexの処理先を分けています。たとえばLocal BYOKのモデルはlocal endpointという説明でも、使うSkillやproject contextによって別のサービスが関わる場合があります。 Q03

ノートの参照とMiyoの索引を分ける

資料には、agentがノートを読み、必要な部分を選択モデルのpromptに入れる説明があります。「Agent Chatを開いただけでVault全体をuploadする」挙動とは説明されていません。Miyoはlocal接続とremote server接続があり、索引・検索先を別に選びます。検索で見つけた抜粋はモデルの文脈にも入ります。localの索引を使うことだけで、抜粋がモデルproviderへ渡らないとは言えません。 Q03 / Q05

文書処理も一律ではありません。資料上、Agent ChatのMiyo処理はlocal CLI、Quick Chatは接続先Miyo serviceを使用し、remoteならそのserverで処理します。Web・YouTube・binary fileを使うsaved project contextはhosted project serviceを使う場合があり、Miyoの選択とは別の経路です。 Q03

Self-Host Modeを通信遮断の保証にしない

ガイドはSelf-Host Modeでもcloudが無効になるわけではないと明記しています。選んだClaude・Codex・cloud modelや検索providerなどへ送る経路は残ります。使いたい機能と許容する処理先が一致するかを、機能ごとに確認するための設定です。 Q04

キーのgetter、初期定数、診断の方針は、それぞれの根拠で読む

確認したKeychainServiceの範囲は、app.secretStorageの有無を確かめ、なければエラーを出すgetterです。実際にキーを保存した結果や、OSの暗号化を検証した記録ではありません。enableMiyo=false、enableMiyoSearchSkill=false、activeBackend=opencode、debugFullFrames=trueはソース内の初期値であり、移行済み設定や読者のGUIの値を示しません。 Q07 / Q08 / Q09

READMEはhosted requestのランダムUUIDと、読者が選んでuploadする診断ZIPを説明しています。ZIPの60日後削除、hosted requestの一時処理・非保持・非学習は提供元が説明する方針です。ここでbackendの運用を監査したわけではありません。debugFullFrames=trueだけから診断ZIPが自動で送信されると判断することもできません。 Q02

Smart Connections：local embeddingの説明と、全通信の有無を分ける

READMEは、組み込みlocal modelがVaultをindexし、API keyを必要としないと説明しています。関連するノートを見つける仕組みの案内として読めますが、この比較ではモデルを起動して実索引や通信を観測していません。READMEの「private」「offline」やmobileに関する説明も、提供元の主張として扱います。 Q10 / Q11

一方、自前のsrc/main.jsには、initialize後の更新確認からGitHub latest-releaseへのGETを予約するコードがあります。初回ユーザーのStoryModalにはsmartconnections.appのURLが渡されます。これは通信に関わるコード経路の確認です。StoryModalの実装は依存側にあり、実際にURLが読み込まれたか、どんなpayloadが渡るかは未確認です。 Q12 / Q13

model・settings・HTTPなどの一部はSmart Environment/jsbrains関連の外部packageを参照しています。この範囲だけで「すべての機能が端末内」「telemetryがない」「ノートが必ず送られる」と断定できません。ローカル索引の説明、更新確認のコード、未確認の依存・実通信を分けると、追加で調べる対象が分かります。 Q14

Text Generator：文脈の候補と、キー保存の分岐を確認する

クリップボードを取得できる設定と、実promptは別

固定版の初期設定にはincludeClipboard=trueがあり、context builderはその値がtrueならclipboardを取得できる分岐を持ちます。一方、引用した初期templateにあるのはtitle、starredBlocks、tg_selectionで、clipboard placeholderではありません。 Q15 / Q17

template、frontmatter、context options、選択範囲によって、解決される値は変わります。利用可能な値の一覧と、実リクエストに入った値を同じものとして扱わないでください。このコード確認は「clipboardが必ず送られる」「Vault全部が常に送られる」という結果ではありません。 Q17 / Q18

plain key欄の空文字は、暗号化の証拠にならない

初期値はencrypt_keys=falseです。保存時にplain key欄を空にする処理と、別のsecret関連フィールドを用意する処理があります。getEncryptedKeyは暗号化が利用不可、またはencrypt_keysが無効のとき、固定prefixと入力keyをつないだ値を返します。フィールド名にencrypted/hashedが含まれていても、それだけで暗号化されたbytesとは判断できません。 Q15 / Q19 / Q20 / Q21 / Q22

キーは入力していないため、実保存の内容やこの端末のsafeStorage動作は未確認です。キーを含む設定ファイルや診断記録を共有する前は、plain欄だけでなく、保存される他の値にも目を向ける必要があります。

初期providerとlocal対応を分けて選ぶ

ソースの初期providerはOpenAI Chat (Langchain)、endpointはhttps://api.openai.com/v1です。Ollama providerは設定したbasePathを受け取る実装があります。local対応providerがあるという事実だけで、他の機能の処理先や全通信なしまで証明されるわけではありません。 Q15 / Q23 / Q24

添付request、automatic suggestions、slash suggestions、JavaScript実行は引用した初期値ではOFFです。これらも現行GUIの実測値ではありません。使うtemplateと保存済み設定を、自分の環境で確認してください。 Q15 / Q16

よくある質問

ローカルモデルを選べば、プラグインは一切通信しませんか？
モデルの処理先と、索引・Web検索・文書変換・更新確認は別の経路です。Copilotの資料は追加機能の経路を区別し、Smart Connectionsの自前コードにはGitHub更新確認GETがあります。今回の資料確認で、全機能が通信しないことや実際の送信内容は確認していません。
Smart Connectionsはノートを外部へ送りますか？
固定版READMEは、組み込みのローカルモデルでembeddingと索引を作ると説明しています。これは提供元の説明です。自前ソースに更新確認と初回案内のURLがあり、モデル・設定などは一部が外部依存です。実際のノート送信や全通信の有無は、この比較では測定していません。
Text GeneratorのincludeClipboard=trueは、クリップボードを必ず送る意味ですか？
ソースでは、その設定がtrueのときcontext builderがクリップボードを取得できる分岐があります。一方、掲載した初期テンプレートはtitle、starredBlocks、tg_selectionを使い、clipboardの指定はありません。利用可能な値と、実際に組み立てられたリクエストの内容は別です。実payloadは未測定です。
保存データのapi_keyが空なら、キーは暗号化済みですか？
空のキー欄だけでは判断できません。Text Generator 0.8.7ではplain key欄を空にする保存処理と別の保存フィールドがあり、暗号化が利用できない場合またはencrypt_keysが無効の場合は、固定prefixと入力キーを返す分岐があります。実際のキー保存やプラットフォームの暗号化動作は試していません。
この記事は、AIの回答品質や料金、iPhone動作を比較していますか？
比較対象は、固定した3版の公式資料とコードに示されるデータ経路と設定です。プラグインのインストール、設定画面の実操作、モデル生成、課金、実通信、iPhoneを含む端末の動作、提供元の保存・非学習方針の遵守は確認していません。
