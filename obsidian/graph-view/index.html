Obsidianのグラフビューを使う
表示範囲を絞り、つながりを確かめる

グラフを開いたら、見たいノートの範囲を先に選びます。フォルダ・タグによる検索、孤立ノートの表示、色グループ、ローカルグラフの深さを、小さな著者作成の保管庫で確かめました。

著者: シンプルメモ開発者 · 実操作確認: 2026年10月1日（日本時間） · Linux版Obsidian 1.13.7

見たい範囲に合わせて、全体と近くのノートを選ぶ

保管庫全体を見るときはグローバルグラフで検索を使い、開いたノートの周辺を見るときはローカルグラフの深さを選びます。色グループは、選んだ条件に合うノートを見分ける表示です。本文や内部リンクが保存されたことは、ノートを開いて確かめます。

ノート追加の前後フォルダとタグ孤立ノート色グループローカルの深さ練習用ファイル

例のノート名・文章・タグは著者が作ったものです。研究や生活の実記録、利用者の保管庫から採ったものではありません。表示位置はレイアウトで、所要時間や理解の程度を示す値ではありません。

カードを自分で並べて関係を示す手順は、Canvasで作成・接続・移動・再表示する実例を参照してください。

この例の保存内容と表示条件

最初に六つのMarkdownを用意しました。「研究」の三ノートは入口→仮説→検証、「生活」の二ノートは買い物→食事と内部リンクでつながり、孤立ノートには他のノートへのリンクがありません。二つの連結成分と一つの孤立ノートを区別できる練習用の構成です。

研究/入口.md → 研究/仮説.md → 研究/検証.md
生活/買い物.md → 生活/食事.md
孤立.md

後からGUIで追加: 追加メモ.md → 研究/入口.md

最初の六ファイルはアプリ起動前に用意し、七つ目だけを実際のエディターで作りました。「研究」フォルダの三ノートと追加メモには#研究、生活の二ノートには#生活を書いています。

グローバルグラフの最初の条件は、Search files空欄、Tags OFF、Attachments OFF、Existing files only OFF、Orphans ONです。未解決のリンクはありませんでした。以後の比較では、説明した検索・Orphans・色グループだけを切り替えています。

1. ノートを追加して、保存内容とグラフを比べる

左のリボンからOpen graph viewを開きます。最初は六ノート・三リンクでした。次にCtrl＋Nで「追加メモ」を作り、名前と本文を実エディターへ入力しました。保存した全文は次の92 bytesです。

# 追加メモ

GUIで追加する著者作成ノートです。 [[研究/入口]]

#研究

自動保存を待ってグラフを開くと、七ノート・四リンクになりました。追加メモから研究/入口への一本が増え、保存済みMarkdownと内部リンクの解決結果も一致していました。

設定パネルが一部のノードを覆っています。この二画像の件数は、実際のGraph rendererからノード名とリンク端点を読み取って確認した値です。画像内にすべての丸が見えるという数え方ではありません。画像はそのまま保全しています。

最後にファイル一覧から追加メモを開き直し、本文とタグを読みました。追加時・再表示後・アプリ正常終了後の保存Markdownは同じ内容でした。

2. フォルダとタグで、違う範囲を選ぶ

Graph settingsのFilters → Search filesに検索文字列を入力します。フォルダ内のノートを選ぶ例はpath:"研究/"、タグを含むノートを選ぶ例はtag:#研究です。今回の結果は次のように違いました。

入力した条件対象ノート確認した構造
path:"研究/"研究フォルダの入口・仮説・検証3ノート / 2リンク
tag:#研究上記三ノートと、保管庫直下の追加メモ4ノート / 3リンク
検索文字列を空にする今回の七ノート全部7ノート / 4リンク

追加メモは保管庫直下にあるため、研究フォルダのパス条件には入りません。#研究を持つため、タグ条件には入ります。ここではTagsの切替をOFFのままにし、タグ自体をノードとして表示する操作は試していません。

絞り込みを終えるときはSearch filesを空にします。今回、検索候補が操作に重なったときはEscで閉じてから、次の切替をクリックしました。フォルダ名やタグ名は、自分の保存内容に合わせます。

3. 孤立ノートも見るならOrphansをONにする

検索文字列を空にした状態で、FiltersのOrphansをOFFにすると孤立.mdが消え、六ノート・四リンクになりました。ONに戻すと、孤立.mdを含む七ノート・四リンクへ戻りました。どちらもリンク端点は同じです。

この例では、保存済みの孤立ノートに内部リンクがなかったため、切替で表示対象が変わりました。ノートが見えないときは、本文が保存されているかと、今のグラフの検索・表示条件をそれぞれ確認します。未解決リンクやすべてのフィルターの組み合わせを試した結果ではありません。

4. 色グループで、条件に合うノートを見分ける

Groups → New groupでグループを追加し、一つ目にpath:"研究/"、二つ目にtag:#生活を入力しました。グループの色の丸をクリックし、Linuxの色選択画面で一つ目をRGB 30 / 140 / 220（#1e8cdc）へ変更しています。二つ目の割り当て色は#d6ad5cでした。

研究フォルダの三ノートは青、生活タグの二ノートは金色になりました。保管庫直下の追加メモと孤立.mdは、この二条件には入らないため、グループの色が付きませんでした。ノード名・色の読み取りも照合し、全体の七ノート・四リンクは変わっていません。

原画像は実際の色選択画面で、GUI入力には既存のX11マウス・キーボード補助を使いました。アプリAPIやDOMの値代入で色を設定していません。色グループの重複、並べ替え、他の色やOSの選択画面は試していません。

5. ローカルグラフの深さで、近くのノートを選ぶ

ファイル一覧から研究/入口.mdを開き、ノートのMore options → Open linked view → Open local graphを選びました。ローカルグラフのFiltersにはDepthスライダーがあります。今回の条件はIncoming links ON、Outgoing links ON、Neighbor links OFFです。

Depth入口の周辺に含まれたノート確認した構造
1入口、入口から参照する仮説、入口を参照する追加メモ3ノート / 2リンク
2上記に、仮説から参照する検証が加わる4ノート / 3リンク

Depthを実際のスライダー操作で1から2へ変え、ノード名とリンク端点を確かめました。生活の二ノートと孤立.mdは、入口につながっていないため、この二つの深さには入りませんでした。

二画像は、設定を選んだ後にパネルを閉じて撮った原画像です。入口を対象とした深さ1・2の記録です。別のノートを開くと、リンクしたローカルグラフの対象も変わります。深さ3〜5や、Incoming/Outgoing/Neighbor linksの他の組み合わせは試していません。

練習用の七つのMarkdownをダウンロードする

七ファイルは、GUI追加後に保存したMarkdownの原本と同じbytesです。ZIPはこの記事の準備時に作った配布用パッケージで、七つの本文と相対パスを保っています。個別ダウンロードでは、表のフォルダ名とファイル名を合わせて配置します。

七ファイルをまとめて保存する（ZIP）

保管庫内の相対パス元Markdown
孤立.md孤立.mdを保存
生活/買い物.md買い物.mdを保存
生活/食事.md食事.mdを保存
研究/仮説.md仮説.mdを保存
研究/入口.md入口.mdを保存
研究/検証.md検証.mdを保存
追加メモ.md追加メモ.mdを保存

ZIPを展開した七ファイルの相対パス・本文のSHA256を原本と照合しました。読者側でのZIP取り込み、他の保管庫への配置、公開サーバーからの配送は、実アプリの検証に含まれていません。

よくある質問

グラフにノートが見えないとき、何を確認しますか？
今回の例では、Search filesの検索文字列とOrphansのON/OFFで対象が変わりました。対象ノートを開いて保存内容を確認し、検索文字列を空にして、孤立ノートも確認する場合はOrphansをONにします。Tags、Attachments、Existing files onlyなどの条件も公式ヘルプで確認できます。すべての設定の組み合わせは試していません。
グローバルグラフとローカルグラフはどう違いますか？
グローバルグラフは保管庫のノート全体を対象にし、ローカルグラフは開いたノートにつながる範囲を対象にします。今回の入口ノートでは、Incoming linksとOutgoing linksをON、Neighbor linksをOFFにし、深さ1で3ノート・2リンク、深さ2で4ノート・3リンクでした。別の連結成分や孤立ノートは含まれませんでした。
Tagsの切替とtag:検索は同じ操作ですか？
公式ヘルプのTagsは、タグをグラフに表示するための切替です。tag:検索は、指定したタグを含むノートを絞る検索です。今回TagsはOFFのまま、tag:#研究で4ノートを表示しました。タグ自体をノードとして表示する操作は、この例では試していません。
ノードや線が多ければ、知識や生産性が高いと判断できますか？
この記事で確認したのは、保存したノート、内部リンク、指定した表示条件による構造の違いです。知識の正しさ、理解の深さ、生産性や速度は測っていません。本文でリンクの理由を確認する練習は、Zettelkastenのノートとリンクの実践ガイドで紹介しています。
