Codifique tanto el # en el cuerpo como el # en el título como un valor

El texto oficial explica que el espacio en blanco es %20 y la barra es %2F. En I:N1, que convirtió el texto del autor mezclado con japonés, saltos de línea y # & ? + % / = por valor, el Markdown guardado coincidía con la entrada. Si convierte todo el URL a la vez, el separador también cambiará, por lo que los valores de vault, file y content se tratarán individualmente .

const vault = encodeURIComponent('練習Vault');
const file = encodeURIComponent('ノート/日本語 メモ');
const content = encodeURIComponent('本文 # & ? + % / =\n二行目');
const uri = `obsidian://new?vault=${vault}&file=${file}&content=${content}`;

Lo anterior es un código para explicar cómo ensamblar. No incluye la ejecución de guardar en el cuaderno en el terminal. Practica Vault y reemplaza el destino guardado con tu nombre.

La segunda mitad cayó en la entrada que dejó el crudo #

En I:W1, solo se dejó sin codificar el # dentro de content. Se guardó únicamente la frase inicial; el resto del texto no estaba en el archivo. Este caso no demuestra que Obsidian eliminara texto por su cuenta: es el resultado de una entrada que mezclaba delimitadores y valores del URI.

Separar nueva creación, añadir y sobrescribir

En new, name indica el nombre de la nota nueva y deja su destino en manos del ajuste Default location for new notes de Obsidian. file incluye el destino relativo a la raíz de la Vault. La documentación indica que file tiene prioridad sobre name; en I:N2 también se guardó en el destino de file. S:N01 usó solo name y guardó en la carpeta predeterminada previamente configurada.

obsidian://new?vault=Practice&file=Inbox%2FURI-test&content=Hello%20World

Para añadir texto sin borrar el existente, pasa append=true. I:N3 conservó el texto original y añadió el nuevo. overwrite=true sirve para sustituir el texto existente; I:N5 cuenta con un registro separado del original y del resultado guardado. La documentación indica que overwrite solo se aplica cuando append no está activado, y S:N03, con ambos parámetros, añadió el texto. No es necesario combinar una opción de sobrescritura al añadir texto en el uso cotidiano.

obsidian://new?vault=Practice&file=Inbox%2FURI-test&content=Another%20line&append=true

I:N4, con silent=true, creó el archivo sin cambiar la nota que se mostraba. Con clipboard=true, S:C01/C02/C03 guardaron el texto del autor de la pantalla dedicada mediante new/daily/unique. Preguntas frecuentes

¿Cuál es la diferencia entre obsidian:// y Web URL normal?

obsidian:// es el URI único que recibe Obsidian. No es URL para obtener la página web. Compruebe la asociación en el lado del terminal y la operación de la nota después de ir a Obsidian por separado. La medición real de este artículo es después de recibir el URI de la aplicación Linux.

¿Cómo se escribe en japonés, en blanco y #?

Codifica cada valor como URI. Un espacio se representa con %20, # con %23 y / con %2F. También debes codificar el # de un encabezado o bloque dentro del valor de file. En el ejemplo del autor que dejó un # sin codificar en el texto, no se guardó el contenido posterior a #.

¿Se usa open para añadir contenido a una nota existente?

El ejemplo verificado de adición de texto pasa file, content y append=true a new. La sección de open también menciona append/prepend, pero no enumera content; en las entradas exploratorias de esta prueba, el texto no cambió.

¿Puedo cambiar el destino pasando file o name a daily?

La versión fijada de la documentación oficial indica que daily acepta los mismos parámetros que new. Sin embargo, en esta prueba en Linux no se crearon los destinos indicados mediante name, file y path; el contenido se añadió a la nota fechada definida en los ajustes de Daily notes. Comprueba el destino con los ajustes reales y los archivos guardados.

Si especifico x-success, ¿ha confirmado la devolución?

No. En algunos casos de new, daily y unique se observó el guardado, pero no llegó ninguna respuesta al receptor HTTP controlado por el autor. Que la aplicación reciba el URI o que la CLI termine con código 0 no demuestra que la respuesta haya llegado a la aplicación que la invocó. No se comprobaron Hook, la transferencia de control del sistema operativo ni la aplicación de origen real.

¿El resultado es el mismo con iPhone?

Este artículo no ejecuta los accesos directos físicos iPhone, iOS y SimpleMemo. Este es el resultado de Vault solo para el autor de Linux Obsidian1.13.7. Para síntomas específicos de iPhone, consulte la guía de manejo de accesos directos existente y compruébalo en el terminal.
