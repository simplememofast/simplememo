# GSC エクスポート手順（所要 約5分 / 週1回）

> **この手順は BigQuery 一括エクスポートに置き換わります。**
> 設定は `growth/BIGQUERY_SETUP.md`（一度きり・15分）。
> 移行後はこの5分が不要になり、さらに以下が改善します:
>
> - **クエリ1,000行の上限が外れる** — 下記の手作業エクスポートは上位1,000件で
>   打ち切られ、2026-08-09 の回では実際の813クリックのうち257件しか見えていません
> - **手順3（クエリ×ページ）が自動で入る** — 「面倒なら飛ばして構いません」と
>   書いてある手順で、実際に毎回飛ばされており、カニバリ検知は一度も
>   データに対して動いたことがありません
>
> ただし一括エクスポートは**過去に遡りません**。28日ぶんの履歴が溜まるまでは
> この手順を続けてください。残り日数は `node growth/scripts/bq-preflight.mjs`
> が毎回表示します。

以下は、その移行が済むまでの手順です。Search Console は鍵なしでは自動取得できないため、
ここだけ手作業が残ります。逆に言えば、これさえ置けば
機会抽出・CTRギャップ・衰退検知・カニバリ検知・実験評価は全部自動で回ります。

所要時間を5分以内に収めるため、**判断を一切求めない手順**にしてあります。
考えることはありません。押す場所だけ書いてあります。

---

## 手順

### 1. 期間を選ぶ（30秒）

[Search Console → 検索パフォーマンス](https://search.google.com/search-console)

上部の **日付** を押して **過去28日間** を選択。

> 28日固定にする理由: スナップショット同士を比較して衰退を検知するので、
> 期間の長さが毎回違うと差分が「実際の変化」なのか「期間が違うだけ」なのか
> 区別できなくなります。**毎回28日**にしてください。

### 2. エクスポート（1分）

右上の **エクスポート** → **CSV をダウンロード** を押す。

ZIPが1つ落ちてきます（`クエリ.csv` `ページ.csv` `国.csv` `デバイス.csv` `日付.csv` 等）。
**中身を開いたり整理したりする必要はありません。**

### 3. クエリ×ページも取る（2分・カニバリ検知に必要）

手順2のZIPには「どのクエリがどのページに着地したか」が入っていません。
これがないとカニバリ検知だけ動きません。

1. 検索パフォーマンス画面で **＋ 新規** → **ページ** を選ぶ
2. 対象ページのURLを入れる（例: `/blog/line-keep-alternative`）
3. 下のタブで **クエリ** を選ぶ
4. **エクスポート** → CSV

これを**上位3〜5ページ分**やって、ファイル名を `query-pages-1.csv` のように
連番にして保存してください。

> 面倒なら**この手順3は飛ばして構いません。** 他の分析はすべて動きます。
> カニバリ検知だけが「データがないので実行しない」と表示されます。

### 4. 置く（30秒）

ZIPを解凍して、中身を**そのまま**このディレクトリへ:

```
growth/input/
```

ファイル名は変えなくて構いません。日本語のままで大丈夫です
（`クエリ.csv` `ページ.csv` のまま読めます）。

### 5. 取り込む（30秒）

```sh
node growth/scripts/ingest-gsc.mjs --label 2026-08-09 --period 2026-07-12..2026-08-08
```

- `--label` … スナップショットの名前。**エクスポートした日**を入れる
- `--period` … 検索パフォーマンス画面の日付範囲。省略可だが入れると比較が正確になる

これで `growth/data/gsc/2026-08-09/` にJSONが書き出され、以降すべての分析が使えます。

### 6. 読む（1分）

```sh
node growth/scripts/weekly-report.mjs --write
```

`growth/reports/YYYY-MM-DD-weekly.md` が生成されます。**見るのはこれだけで十分です。**

## 取り込み後の検算

取り込み直後に出る合計値が、Search Console 画面の数字と一致するか確認してください。
一致しなければ期間の選び間違いか、ファイルの入れ忘れです。

参考として、オーナー報告による**直近3ヶ月**の値:

```
Clicks:       1,501
Impressions: 67,100
CTR:            2.2%
Avg Position:   8.9
```

28日エクスポートなら、この概ね 1/3 前後（クリック 450〜550 程度）になるはずです。
桁が違う場合は期間かファイルを確認してください。

## 手順3（クエリ×ページ）を優先すべきページ

カニバリ検知の価値が高い順。上から3つ取れば十分です。

1. `/blog/line-keep-alternative` — 同一クラスタに4URLあり、カニバリの本命
2. `/blog/best-memo-apps-2026` — AI検索からの着地が集中している
3. `/obsidian/` — Tier 1（課金）に最も近いクラスタのピラー
4. `/vs/capacities/` — 表示回数の割にクリックが取れていない
5. `/apple-watch/` — Siri/音声クラスタとの重複が疑われる
