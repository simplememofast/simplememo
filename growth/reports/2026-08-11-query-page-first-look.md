## 1. 一番大きい発見: line-keep は「取れない」

`/blog/line-keep-alternative` に実際に着地しているクエリ:

| imp | clicks | CTR | 順位 | クエリ |

| **710** | **1** | **0.14%** | 9.4 | line keepメモ 終了 |

| 167 | 1 | 0.60% | 9.4 | line メモ代わり |

| 48 | 0 | 0.00% | 8.6 | ラインキープメモ |
| 38 | 0 | 0.00% | 10.0 | line keep 終了 |

**上位12クエリで 1,869 imp / 7 クリック（CTR 0.37%）。**

このクラスタの中身は「LINE Keepメモは終了したのか」という**サービス終了の確認**である。
検索者が求めているのは LINE の公式アナウンスであって、他社メモアプリの乗り換え記事ではない。
9〜10位にいる第三者の記事がここでクリックを取るのは、順位を上げても難しい。

### これが意味すること

機会ランキングで `/blog/line-keep-alternative` は **+120クリック**の上振れ余地として
2位に出ていた。**この数字は実現しない。** 期待CTRに届く前提が成り立っていない。

サイト自身の Relevance モデルは既にこのクラスタを **0.3（情報のみ）** と評価しており、
その判断は正しかった。**表示回数が最大であることと、価値があることは別である**という
モデルの主張が、クエリ単位で裏付けられた。

### FAQ実験の位置づけも変わる

`faq-2026-08-09-line-keep-doko` が狙った「line keepメモ どこ」は、
台帳に **139 imp** と記録したが、実際にこのページへ着地しているのは **99 imp**。

そして同じページの最大クエリ「line keepメモ 終了」は **710 imp** で7倍ある。
**FAQは、はるかに大きく、同じく取れない問題の一角を狙っていた。**
実験自体は続けるが、成功しても効果は小さい。

## 2. カニバリ検知: 「該当なし」だが、答えが出たわけではない

3ページ間で重複するクエリは**2件だけ**（`google keep` 13 imp、`ライン keepメモ` 4 imp）で、
どちらも閾値の50 impに届かない。

**これは「カニバリが無い」ではなく「互いに競合しない3ページを取った」という意味である。**

疑っていた line-keep クラスタは**4URL**あり、そのうち**1つしかエクスポートしていない**。
同じクエリを別URLが取り合っているかは、**残り3URLを取らないと分からない**。

```
/blog/line-keep-alternative   ← 今回取得
/vs/line-keep-memo/           ← 未取得
/blog/line-keep-*             ← 未取得
```

## 4. 衰退検知は動かせなかった（意図的に止めた）

```
2026-08-09 スナップショット : 2026-07-11 .. 2026-08-07
2026-08-11 スナップショット : 2026-07-13 .. 2026-08-09
                              → 28日中26日が重複（93%）
```

**この2つを比べても衰退は見えない。** ほぼ全てのクリックが両方の合計に入っているので、
差分は端の2日ぶんとノイズにしかならない。

`analyze.mjs` に**重複率50%超なら衰退検知を出力しない**ガードを追加した。
注意書きを添えて数字を出すのではなく、**数字自体を出さない**。
注意書きは読まれないが、数字は読まれてしまうため。

```
── Decay (vs previous snapshot)
   withheld: 2026-08-09 (2026-07-11..2026-08-07) and 2026-08-11 (2026-07-13..2026-08-09)
   share 93% of their days. …
```

**衰退検知の初稼働は、1周期あけた次のエクスポート（2026-09-06以降）になる。**

## 5. 取り込みパイプラインの欠陥を1件修正

Search Console には「クエリ×ページ」のエクスポートが無い。**ページで絞ってクエリを
出す**しかなく、その絞り込み対象は `フィルタ.csv` にしか書かれていない。

修正前の `ingest-gsc.mjs` は:

- ディレクトリを再帰しない（エクスポートは7つとも同じファイル名なので衝突する）
- `フィルタ.csv` を読まないので、絞り込まれた `クエリ.csv` を**サイト全体のクエリとして混ぜる**
- 絞り込まれた `ページ.csv` `デバイス.csv` `国.csv` も**サイト合計に加算する**

3番目が特に危険で、**1ページ分の数字がサイト全体の集計に混入する**。
気づかないまま以降の分析が全部ずれる類の欠陥だった。

修正後は、`フィルタ.csv` にページ指定があるディレクトリからは**クエリだけを取り、
そのページに帰属させ、他の次元は捨てる**。

```
export-2/クエリ.csv → query-pages (/blog/line-keep-alternative): 157 rows
export-2/ページ.csv  skipped: filtered to /blog/line-keep-alternative, only its queries are used
```
