## 1. 実測

オーナーにGA4で `デバイスカテゴリ = desktop` かつ `イベント名 = app_store_click` を
出してもらった。

```
app_store_click 全体      60件 / 56ユーザー
  desktop                21件 / 18ユーザー   （35%）
  mobile + tablet        39件 / 38ユーザー   （65%）

参考・検索側（GSC）  PC 50.9% / モバイル 46.5% / タブレット 2.6%
```

**PCは訪問の51%を占めながらApp Storeクリックの35%しか生んでいない。**
訪問あたりに直すとモバイルはPCの約1.9倍。

### 前日の私の言い方を訂正する

前日、私はこれを「流入の約半分が行き止まり」と書いた。**過大だった。**

PCユーザーは「押しても入らない」ことを分かっていて元々あまり押していない。
自己選択が働いている。**実際の取りこぼしは月21クリック**であり、
「半分が無駄」ではない。

## 2. それでも塞ぐ理由

効果量ではなく、**判断に統計的検出力が要らない**ことが理由である。

これまでの施策（スニペット、CTA配置）はすべて「変えたら良くなるか？」という問いで、
1,600セッション/28日では倍近く動かないと判定できなかった。

今回は違う。**この21人は現に壁に当たっている。** 検証を待つ性質の問題ではない。

実装コストも低い。`/ai-tags/` に既に正しいパターンがあった:

```css
.ai-release__qr{display:none}
@media (min-width:900px){ .ai-release__qr{display:block} }
```

**パターンは存在していて、横展開されていなかっただけである。**

### 3-2. `/blog/obsidian-voice-input` に本文CTA

調査中に見つかった、QRより重い問題:

```
/blog/obsidian-voice-input  の配置内訳 = {"nav": 2}
```

**サイト最強のページ**（64クリック / CTR 10.9% / 5.3位 / Relevance 1.0）に、
**本文中のApp Store導線が1本も無かった。** ヘッダーとフッターのnavボタンだけ。

前日、このページは「サイト最強を実験台にしない」として中間CTAの対象から外した。
**この除外は誤りだったので撤回する。**

その規則は**タイトルやスニペットの実験からページを守るため**に書いたものだった。
本文の1段落は検索順位もSERPのCTRも動かさない——タイトルにもdescriptionにも
ファーストビューにも入らないからである。それを本文CTAにまで適用した結果、
**サイトで最も購買意欲に近い読者が、ヘッダーまでスクロールで戻る以外に
インストールへ進む道を持っていなかった。**

方法4（このアプリを説明している節）の直後に、文脈に沿った1文＋リンクを配置した。

**なおこのページには今も締めのCTAが無い。** 追加するかはデザイン判断なので
オーナーに委ねる。

## 4. 測れないことを先に書く

**QRはスキャンされても `app_store_click` が発火しない。** 指で押していないので。

```
GA4上の見え方 : app_store_click は増えない。PC分が減って見える可能性すらある
実際の効果    : App Store Connect のキャンペーン別インストールにしか出ない
```

`ct=*__qr` の集計は **オーナー作業**であり、`growth/data/appstore/` は空のままである。
**この施策は、現状の計測体制では効果を確認できない。** それを承知で入れている。

## 5. 未検証の1点（マージ前に確認してほしい）

QRの中身は、**エンコードした文字列を既存CTAのURLと突き合わせる形でしか検証していない。**
生成された画像を実際にスキャンしてはいない（この環境にデコーダが無い）。

**Ready にする前に、どれか1枚をスマホで読み取って App Store に飛ぶことを確認してほしい。**
5秒で済み、間違っていた場合の損害（9ページに壊れたQR）は大きい。
