# DL意図と課金意図を分ける — 2軸目を足すときに、足しすぎないための設計

`businessRelevance` は「インストールにどれだけ近いか」の1次元で、**DLと課金を
同じ数字で表していた。**手元のGSC分析がここを正しく突いていた（「メモアプリ 無料」＝
DL◎/課金△、「obsidian 音声入力」＝DL◎◎/課金◎◎）。2軸目を実装した記録。

---

## 1. 基準は値付けから引く。好みでは決めない

    Free     1日3通
    Premium  月500円 / 年5,000円 — 送信無制限

**Premium が売っているのは機能ではなく回数の上限。**したがって課金するのは
「毎日何度もキャプチャする習慣を持つ人」だけである。この軸が見ているのは
題材への関心ではなく **捕捉の頻度**。

「無料のメモアプリを探している人」をいくら集めても、ここは増えない。
DLの母数としては優秀でも、である。**この2つが割れることを、1つの数字では書けない。**

## 2. 最初に5段で書いたら、2軸目の大半が1軸目の写しになっていた

0.2 / 0.3 / 0.5 / 0.7 / 1.0 の5段で書き、実データに当てて確かめた。

    218ページ中 129ページ が businessRelevance との差 0.1〜0.2
    差 0.3 以上は 3ページだけ

**差が 0.1 の2つの手入力値に意味は無い。**「1軸目から少し引いた値」を
2軸目と呼んでいただけだった。段を3つに畳んだ。

| 段 | 根拠 |
|---|---|
| **1.0** | 使い方そのものが「1日に何度も」を含む。画面を見ないキャプチャ（音声/Watch/Siri/AirPods）、保管庫への日次追記、自分宛メールの流儀。VISION §3.2 の Tier 1 がそのままこの層 |
| **0.5** | 道具の常用者だが**頻度は分からない**。乗り換え検討・手法の実践・用途別ガイド。**ここを 0.6 や 0.7 に刻まない** — 刻めるだけの根拠が無い |
| **0.2** | 無料狙い、または一度きりの答え探し。無料/おすすめランキング、LINE Keep の行き先、用語集・規約類 |

畳んだ結果、差 0.3 以上が 13ページ（クリックの約1割）になり、**2軸目が実際に
何かを足している状態**になった。

## 3. この軸は宣言であって実測ではない — だから反証を1つ持たせた

`ct=` 別のインストール／課金は**このリポジトリには無い。**
`growth/data/appstore` は列名と合計しか持たず（公開リポジトリなので分類列ごとの
内訳を置かない方針）、`App Downloads Standard` の列も Source Type / Page Type までで
**Campaign が無い。**突合するなら生データを持つ simplememo-ios 側でやることになる。

手入力の重みを増やせば、**都合のよい物語をいくらでも作れる。**
そこで、今日から反証できる実測を1つ用意した。

**`freeSeekingShare`** — 「無料」「広告なし」「課金なし」等を含むクエリからの表示が、
その面の何割かをクエリ文字列から数える。実測（2026-08-24窓・可視クエリのみ）:

    /blog/free-memo-apps-ranking   表示1,606中 1,552 が無料狙い   95.6%
    それ以外の主要21ページ          ほぼすべて 0.0%

**無料狙いの流入はサイト全体に薄く広がっているのではなく、1ページに集中している。**
分析の「メモアプリ 無料はDL向きで課金向きではない」は、この1ページについては
実測で裏づけられた。

### 反証は片側にしか成立しない

GSC は下位クエリを匿名化して返す（2026-08-24窓では表示の約64%が匿名化）。
だから **0% は「無料狙いが無い」ではなく「可視スライスには無い」。**

- **高く宣言した面が無料狙いに寄っていたら → 宣言が間違い。CIで落とす。**
- 高く宣言した面が 0% でも → **矛盾ではない。**見えていないだけかもしれない。

この非対称を実装に落としてある。壊し方も観測済み（`data/check-selftests.json`）。

## 4. 実測が「低い宣言の根拠」を支えていない面がある

`--check` では落とさないが、黙らせもしない区分を1つ置いた。

`/blog/best-memo-apps-2026` は課金 0.2 と宣言しているが、**可視クエリの無料狙いは 0.0%。**
「無料狙いだから低い」という理由は、この面には当たっていない。
残る理由は「比較検討は一度きり」という**推測**である。

これは反証ではない（匿名化）。だが**実測の裏づけがある低い宣言と、無い低い宣言を
同じ見た目にしない。**現時点で実測に支えられている低い宣言は
`/blog/free-memo-apps*` の1族だけである。

## 6. 決めていないこと

- **段の中身そのものは検証されていない。**「Obsidianユーザーは手法の実践者より
  捕捉頻度が高い」といった順序は、値付けからは出てこない。出てくるのは
  「回数の上限を売っている」までである。
- **突合の場所。**ct= 別の課金を見るには simplememo-ios 側で
  ASC の生データと結ぶ必要がある。このリポジトリは公開なので、
  ここに内訳を持ち込む形にはしない。
- **既定 0.5 に落ちるページ。**`businessRelevance` 側の既定（クリックの約3割）は
  前回のPRで扱いを決めていない。2軸目も同じ既定を持つので、決めるなら両方同時に。

# 追記 2026-08-28 — 既定値に落ちていたページを詰めた

上の §6 で「決めていないこと」に挙げた**既定 0.5 に落ちるページ**を扱った記録。

## 何が起きていたか

`businessRelevance` / `monetizationRelevance` はどちらも、規則に当たらないページを
既定値へ落とす。既定は「中くらい」に見えるが、**実際には「誰も決めていない」**であり、
この2つは違う。2026-08-24窓では:

    DL軸が未宣言    64ページ / クリックの 27.9% / 表示の 39.5%
    課金軸が未宣言  65ページ / クリックの 25.7% / 表示の 30.1%

**そしてこの事実を、どの出力も報告していなかった。**

## 根拠のある族だけ規則を置いた

| 族 | DL | 課金 | 根拠 |
|---|---|---|---|
| 自分宛メール（`email-yourself` / `email-self-task` / `iphone-shortcuts-email-guide` / `send-email-to-yourself`） | 0.9 | 0.5 | 製品の中核機能そのもの。`/note-to-email/` と同じ検索意図に応えるので同じ値 |
| `email-to-obsidian` | 1.0 | 1.0 | Obsidianクラスタ。スラッグが `obsidian-` で始まらないため既存規則に当たっていなかった |
| 暗号化・セキュリティ・プライバシー比較 | 0.5（既存） | 0.5 | 道具を真剣に選んでいるが**捕捉の頻度は分からない** |
| カテゴリ比較・ランキング（`free-memo-apps` / `best-memo-apps` / `offline-memo-apps` ほか） | 0.7 | 0.2 | 「どのアプリにするか」を今決めているのでDLは `/vs/` と同じ。**課金は無料狙いが実測95.6%で 0.2** |

**最大の未宣言は `/en/iphone-shortcuts-email-guide/`（1,813表示）**だった。
自分宛メールという製品の原点にあたる族に、規則が1つも無かったことになる。

結果、未宣言クリックは **25.7% → 10.8%**。

## 決められなかった5ページは、決められないと書いた

`data/relevance-undecided.json` に理由つきで置いた。**載せることは免罪ではない** ——
未宣言の数には数え続ける。理由には「何が分かれば決められるか」を書いてある。

例: `/blog/meeting-memo-template`（436表示）は
**テンプレートが欲しいのか道具が欲しいのかが分からない。**前者ならDLに繋がらず、
後者なら 0.7 が妥当。流入クエリを見れば決まるが、可視分が162表示しかない。

## 門は流入で切る

ページ数を上限にすると、**記事を1本足すたびにCIが落ちる。**それでは読まれずに
上限だけが上がる。代わりに「**100表示以上を得たページは、宣言を持つか、
理由つきで台帳に載っているかのどちらか**」を守る。新しい記事は流入が付くまで素通りし、
**流入が付いた時点で判断を迫られる。**

台帳の古い行（宣言が付いた／流入が消えた）も同時に落とす。片方だけ直しても通らない。
