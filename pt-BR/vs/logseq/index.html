Primeiro distinguir entre as versões OG e DB

No repositório oficial, os grafos baseados em arquivos foram separados para o Logseq OG. A versão 2.0.1, publicada em 13 de 7 de 2026, é uma versão beta baseada em banco de dados. Não aplique automaticamente a ela as informações da versão antiga sobre armazenamento em arquivos, Org e plugins.

Comece com o memorando diário e a adição rápida

Logseq é uma ferramenta que reúne pensamentos com marcadores e referências. Não há necessidade de vincular tudo desde o início, escrever um pequeno registro no memorando diário e, em seguida, associá-lo à situação em que você o usa.

A versão DB orienta oficialmente o Quick add integrado para enviar para o diário atual. " A explicação de que "um plug-in é sempre necessário para entrada rápida" não é apropriada. Abra a entrada no terminal que você está usando e tente inserir, salvar e exibir novamente.

Prepare a sincronização e o backup separadamente

O README oficial explica a versão DB como uma versão beta, e a nova versão móvel e RTC como um alfa, e orienta a possibilidade de perda de dados e backup. Habilitar a sincronização por si só não impede a exclusão acidental e a perda de dados. Primeiro, tente com um pequeno gráfico que não inclua o conteúdo da produção.

Verifique a orientação da versão que você está usando sem misturar as configurações de sincronização da versão do arquivo e da versão do banco de dados. Se o registro pode ser encontrado no destino de sincronização ou se uma cópia independente pode ser lida é outra confirmação.

Oficial: Estágio de desenvolvimento e guia de gráfico de teste

Use backup do banco de dados e exportação Markdown separadamente

Na versão do banco de dados do gráfico de exportação, você pode selecionar "Exportar banco de dados SQLite e ativos" que resume o banco de dados e os anexos. A exportação padrão Markdown é usada para trazer texto fácil de ler, mas não retém todos os atributos ou carimbos de data/hora. Não faça apenas o Markdown para migração como o único backup.

Ao deixar o gráfico original, tente Importar → SQLite + ativos (.zip) em um novo gráfico separado para ver se o conteúdo necessário pode ser aberto. Ao converter gráficos de arquivos antigos em banco de dados, verifique também o não suporte da organização, a conversão do estado da tarefa e várias consultas e restrições de importação de incorporação.

5 procedimento antes de alterar a operação

  1. Registre a versão e o método de salvamento do Logseq que você está usando e faça backup do gráfico original em um local independente.
  2. Prepare o texto, a tarefa, o anexo e o link para cada 1 em um pequeno gráfico de teste que não é importante.
  3. Verifique o item 6 em e importe a exportação necessária para outro gráfico e abra-o.
  4. Se você quiser usá-lo juntos, faça uma breve anotação e verifique se consegue encontrá-lo no destino final de armazenamento Logseq.
  5. Depois de registrar funções inconsistentes ou ausentes, determine o manuseio dos dados de produção.

Perguntas Frequentes

Você deseja salvar todo o Logseq no arquivo Markdown?

Não. A versão anterior do arquivo é dividida em Logseq OG, e a versão do DB usa o banco de dados SQLite. A exportação Markdown da versão do banco de dados não está em um formato que retenha todas as propriedades e carimbos de data/hora.

O que você faz antes de tentar a versão do banco de dados com o gráfico existente?

Deixe uma cópia independente do gráfico original e tente com um gráfico de teste pequeno e sem importância. Se você precisar não apenas do SQLite, mas também de anexos, selecione a exportação, incluindo o banco de dados e os ativos do SQLite e verifique a importação em um gráfico separado.

Posso usar o plug-in anterior como está na versão do banco de dados?

Verifique a compatibilidade individualmente. "Suporta DB" do Mercado Oficial? Verifique se o plug-in que você está usando suporta o gráfico de banco de dados olhando para a tela compatível com o banco de dados.

É necessário um plug-in para a entrada rápida do Logseq?

O documento oficial da versão do banco de dados tem um "Quick add" integrado que envia notas curtas para o diário atual. A entrada é diferente para a versão e o terminal, portanto, verifique com o aplicativo atual antes de procurar plug-ins adicionais.

Não haverá perda de dados se eu usar a sincronização oficial?

A sincronização não é um substituto para o backup. O README oficial é um beta para a versão DB e o alfa para a nova versão móvel e RTC, orientando a possibilidade de perda de dados e backup independente. Verifique a versão e a rota de sincronização a ser usada.

Se eu usar o SimpleMemo, ele será adicionado automaticamente ao Logseq?

O exemplo de uso nesta página é como encaminhar o texto recebido na caixa de entrada de e-mail para Logseq, se necessário. Não mostra a função de gravação automática no banco de dados ou gráfico do Logseq, ou a capacidade de migrar o gráfico inteiro.
