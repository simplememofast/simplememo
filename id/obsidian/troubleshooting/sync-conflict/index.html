Tinggalkan teks asli dan pilih konten

Pertahankan teks asli
untuk memperbaiki konflik Git Obsidian, bandingkan dan simpan

Jika penanda yang bertentangan muncul dalam teks, biarkan kedua teks asli secara terpisah dan periksa konten mana yang akan digunakan. Dalam latihan kecil ini, kami memilih dua item konfirmasi dan menyimpannya di Obsidian, dan mengonfirmasi bahwa penggabungan Git lokal telah selesai dan ditampilkan kembali.

Urutan konfirmasi adalah teks asli, konten yang dipilih, dan hasil penyimpanan

Target kali ini adalah ketika penanda yang bersaing dimasukkan dalam teks Markdown yang sama dalam penggabungan Git. Saya mengedit salah satu catatan yang dibuat oleh penulis dengan dua cabang Git lokal, dan mengkonfirmasi kegagalan penggabungan yang sebenarnya, perbandingan teks asli, dan koreksi manual. Ini bukan hasil dari sinkronisasi dengan beberapa terminal.

  1. Tinggalkan kedua teks asli secara manualSiapkan salinan yang dapat membedakan konten mana itu
  2. Bandingkan perbedaannyaPeriksa garis yang tidak biasa dan bagian yang umum
  3. Memutuskan konten yang akan diadopsiContoh ini menempatkan dua item yang kompatibel ke dalam baris terpisah
  4. Edit dan simpanKonfirmasikan penyelesaian penggabungan pada teks dan sisi Git
  5. Tampilkan ulang dan konfirmasiMengkorelasikan konten yang dipilih dan menyimpan Markdown

Urutan ini adalah diagram yang mengatur latihan ini. Ini bukan diagram yang menunjukkan jaminan pemulihan otomatis dan pencegahan kerugian, dan prosedur operasi untuk setiap layanan sinkronisasi.

Pertama, periksa bentuk kompetisi Anda

Dalam contoh ini, penggabungan Git berhenti pada kode keluar 1, dan 作業メモ.md menjadi UU. Indeks Git memiliki versi asli yang umum dan dua versi yang diedit, dan <<<<<<< HEAD, =======, dan >>>>>>> draft-b disertakan dalam isi catatan.

Jika file konflik alias atau layar riwayat muncul di lingkungan Anda, silakan periksa sesuai dengan metode sinkronisasi. Pintu masuk untuk memeriksa metodenya adalah panduan metode sinkronisasi Obsidian. Hasil Git dalam artikel ini tidak dapat dibaca ke dalam perilaku Obsidian Sync atau iCloud.

Teks yang disimpan dalam keadaan kompetisi ini adalah sebagai berikut. Teks lengkap dari file yang sebenarnya, termasuk penanda, diposting.

1. Tinggalkan dua teks asli di tangan secara terpisah

Sebelum Anda mulai mengedit, simpan setiap versi di tangan secara terpisah dengan nama yang mengenali versi aslinya. Jika Anda hanya memiliki satu dari mereka di tangan, jangan memperlakukan yang lain sebagai dapat menyimpannya, dan periksa status Git dan riwayat metode yang Anda gunakan. Saya belum mencoba mengambil dari riwayat setiap layanan kali ini.

Jika Anda ingin memeriksa persiapan untuk kembali ke teks sebelumnya sebelum memperbaiki konflik, silakan lihat juga Git, Pemulihan File, dan contoh pemulihan salinan di luar toko.

Dalam latihan ini, penulis secara manual menyimpan salinan rencana A dan rencana B sebelum gabung. Sebagai perbandingan, saya juga meletakkan 原文の控え/案A.md dan 原文の控え/案B.md di ruang penyimpanan dan membukanya. Ini bukan salinan konflik yang dihasilkan secara otomatis oleh alat sinkronisasi.

versiItem konfirmasi yang diubahBagian umum
Draf APeriksa urutan judulJudul, penjelasan catatan latihan, judul untuk konfirmasi berikutnya
Rencana BPeriksa di mana untuk menyimpan tautan internalSama seperti Rencana A

Daripada menilai hanya berdasarkan waktu pembaruan, bacalah teks dan periksa informasi yang diperlukan. Karena keduanya kompatibel sebagai item konfirmasi terpisah kali ini, penulis memutuskan untuk mengadopsi kedua baris dalam urutan A dan B. Jika kalimat yang sebenarnya kontradiktif atau diduplikasi, Anda perlu memilih sesuai dengan isinya.

2. Edit konten yang telah Anda putuskan dengan Obsidian dan periksa penghematannya

Buka 作業メモ.md di editor Obsidian yang sebenarnya dan masukkan teks yang dipilih. Dalam contoh ini, kami meninggalkan penjelasan umum, menempatkan dua item ke dalam baris terpisah, dan menghapus penanda konflik. Tunggu penyimpanan otomatis dan konfirmasikan bahwa teks lengkap berikut telah disimpan dalam file yang sebenarnya.

# 作業メモ

ローカルの競合を確かめるために著者が作った練習用ノートです。

## 次の確認
- 確認する項目: 見出しの順番を確認する。
- 確認する項目: 内部リンクの保存先を確認する。

Di buku catatan saya, selain hilangnya penanda, saya akan membaca ulang konten yang dipilih, urutan baris, dan bagian umum yang saya putuskan untuk ditinggalkan. Keputusan untuk meringkas teks dan operasi untuk menyelesaikan penggabungan di sisi Git akan dikonfirmasi secara terpisah.

3. Periksa status Git yang belum terselesaikan dan selesaikan penggabungannya

Dalam latihan ini, bahkan setelah menyimpan teks dengan Obsidian, keadaan Git adalah UU. Setelah itu, saya secara eksplisit git add hanya dengan catatan target dan membuat komit gabungan secara lokal. Dua komit asli tetap sebagai induk, git ls-files -u kosong, dan keadaan Git bersih.

Berikut ini adalah contoh perintah untuk memeriksa file target di Git lokal. Periksa nama catatan dan repositori yang sebenarnya sebelum menggunakannya. Sebelum git add, silakan periksa teks yang akan diadopsi dan status kerja lainnya.

git status --short -- "作業メモ.md"
git ls-files -u -- "作業メモ.md"
# 採用する本文を確認した後、対象ノートをstageする
git add -- "作業メモ.md"
git commit
# merge完了後の未解決indexと状態を確認する
git ls-files -u
git status --short

Operasi Git dilakukan dengan perintah lokal. Obsidian Plug-in Git tidak digunakan, dan remote, push/pull, dan refleksi pada terminal lain belum dikonfirmasi. Fakta bahwa kondisinya bersih tidak membuktikan daya tahan cadangan atau pengiriman ke semua terminal.

4. Buka kembali buku catatan dan baca konten yang dipilih

Setelah membuat komit penggabungan, saya membuka kembali 作業メモ.md dari penjelajah file yang sebenarnya. Dua item ditampilkan dalam tampilan baca, dan tidak ada penanda konflik. Markdown sebelum dan sesudah tampilan ulang adalah SHA256 yang sama, dan salinan A/B asli dan teks dari setiap komit juga dipertahankan.

Hasil ini dikonfirmasi oleh catatan penulis ini dan satu pemulihan lokal. Ini bukan hasil yang menunjukkan bahwa informasi tidak akan hilang dalam semua konflik dan semua metode sinkronisasi.

Unduh teks asli, status konflik, dan hasil yang disimpan

Empat Markdown adalah A/B asli, keadaan kompetitif, dan asli dari hasil pelestarian akhir. Nama distribusi adalah alias untuk membedakan negara bagian, dan nama catatan kerja yang sebenarnya adalah 作業メモ.md. Dalam praktik membandingkan konten, simpan dengan nama yang berbeda dan periksa di tempat di mana Anda tidak menimpa file dengan nama yang sama di buku catatan Anda.

Pertanyaan umum

Apakah penanda konflik dan salinan teks yang saling bertentangan sama?
Apa yang saya periksa kali ini adalah penanda yang bersaing yang dimasukkan Git ke dalam teks Markdown yang sedang dikerjakan. Salinan teks asli dibuat secara manual oleh penulis. Perilaku metode sinkronisasi yang secara otomatis membuat file terpisah tidak diverifikasi dalam contoh pemulihan ini. Mohon periksa instruksi pada metode yang Anda gunakan.
Bisakah saya menyelesaikannya jika saya meninggalkan kedua kalimat?
Karena dua item konfirmasi dalam contoh ini kompatibel, penulis memutuskan untuk membiarkannya sebagai baris terpisah. Jika kontennya tidak konsisten atau penjelasan yang sama tumpang tindih, silakan periksa makna dan informasi yang diperlukan dan pilih kembali. Tidak selalu merupakan prosedur untuk menambahkan keduanya.
Jika saya menghapus dan menyimpan penanda konflik, apakah penggabungan Git akan selesai?
Dalam latihan ini, keadaan Git adalah UU bahkan setelah menyimpannya dengan Obsidian. Setelah memeriksa isinya, git menambahkan catatan target, dan membuat komit penggabungan, saya mengkonfirmasi bahwa indeks yang belum terselesaikan kosong dan status Git bersih. Harap pisahkan pengeditan teks dan penyelesaian sisi Git.
Apakah prosedur ini telah diverifikasi pada Obsidian Sync dan iCloud?
Versi Linux dari Obsidian 1.13.7 dan satu repositori Git lokal offline telah diverifikasi. Obsidian Sync, iCloud, layanan sinkronisasi lainnya, dua terminal, hubungan iPhone, SimpleMemo belum dicoba. Silakan periksa riwayat dan mekanisme konflik sesuai dengan metode yang sebenarnya.

Lingkungan verifikasi dan rentang konfirmasi

  • Aplikasi aktual: 2026 tahun 9 bulan 30 Linux versi Obsidian 1.13.7. Catatan Jepang yang dibuat oleh penulis, satu repositori Git lokal offline, tidak ada plug-in komunitas.
  • Hasil Git aktual: gabungkan kegagalan, UU, tiga tahap indeks yang belum terselesaikan, penanda konflik, gabungkan komit dengan tahap target eksplisit dan dua orang tua, indeks yang belum terselesaikan kosong, keadaan bersih.
  • GUI Asli:A Asli, catatan konflik, catatan pasca-simpan, operasi penjelajah file aktual, masukkan dan simpan teks yang dipilih di editor asli, lihat baca, periksa tampilan ulang catatan.
  • Bantuan: Catatan gabungan dan salinan teks asli disiapkan secara langsung sebagai sebuah file. Saya menggunakan aplikasi API untuk membagi kiri dan kanan, menampilkan B, bilah sisi, jendela pengaturan, dan membaca statusnya. Git adalah operasi shell lokal.
  • Tidak terverifikasi:Generasi salinan konflik otomatis, Obsidian Sync, iCloud, layanan sinkronisasi lainnya, jarak jauh, pengeditan simultan pada dua unit, iOS/Android/Mac, pengiriman SimpleMemo, cadangan jangka panjang, kecepatan, produktivitas, efek aliran masuk.

Gambar asli adalah layar Obsidian yang sebenarnya yang belum diproses, dan Markdown adalah yang asli dari file yang sebenarnya. Catatan verifikasi dan korespondensi asli menjelaskan operasi aktual, bantuan, dan batasan.
