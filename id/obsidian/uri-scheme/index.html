Panduan Lengkap Skema URI obsidian:// — Tindakan Lengkap dan Jebakan

obsidian:// adalah URI untuk membuka, membuat, dan mencari catatan Obsidian dari aplikasi atau peluncur lain. Pertama, pilih tindakan yang sesuai dengan tujuan dan menyandikan setiap nilai URI. Teks tambahan dapat dimulai dengan contoh new+append=true, yang telah dikonfirmasi untuk disimpan kali ini.

Jika Anda ingin memasukkan teks dan menyalin URI, lihat juga penghasil URI gratis yang memisahkan sintaks dan pengamatan Linux tetap.

Di sini kami menambahkan bagian Hook tersendiri pada daftar 6 tindakan dalam dokumentasi resmi, lalu menyusun 7 bagian dengan 38 entri parameter per tindakan. Kami menghubungkannya dengan 58 catatan masukan yang diberikan kepada Linux Obsidian1.13.7. Masukan yang tidak menghasilkan keluaran juga dicantumkan agar deskripsi spesifikasi dapat dibaca terpisah dari lokasi penyimpanan sebenarnya.

Rentang yang dikonfirmasi:Vault lokal untuk penulis, aplikasi Linux resmi 1.13.7, UI Bahasa Inggris, layar Xorg yang terisolasi. Saya meneruskan URI ke file yang dapat dieksekusi dan memeriksa operasi setelah aplikasi menerimanya. Asosiasi OS dari tautan browser, fisik iPhone, pintasan iOS, SimpleMemo, sinkronisasi belum diverifikasi. 58 tidak berarti garansi untuk semua nilai, semua kombinasi, dan semua terminal.

Enkodekan # dari badan dan # dari judul sebagai nilai

Teks resmi menjelaskan bahwa yang kosong harus %20 dan garis miring harus %2F. Dalam I:N1, yang mengubah teks penulis dicampur dengan bahasa Jepang, jeda baris, dan # & ? + % / = berdasarkan nilai, Markdown yang disimpan cocok dengan input. Jika Anda mengonversi seluruh URL sekaligus, pemisah juga akan berubah, sehingga nilai dari vault, file, dan content akan diperlakukan satu per satu .

const vault = encodeURIComponent('練習Vault');
const file = encodeURIComponent('ノート/日本語 メモ');
const content = encodeURIComponent('本文 # & ? + % / =\n二行目');
const uri = `obsidian://new?vault=${vault}&file=${file}&content=${content}`;

Di atas adalah kode untuk menjelaskan cara merakit. Itu tidak termasuk eksekusi penyimpanan ke buku catatan di terminal. Berlatih Vault dan ganti tujuan penyimpanan dengan nama Anda.

Paruh kedua jatuh di input yang meninggalkan # mentah

Di I:W1, hanya # di tengah content yang dibiarkan mentah. Hanya kalimat pertama yang disimpan, dan bagian kedua dari badan tidak ada dalam file. Kasus ini bukan bukti bahwa "Obsidian menghapus teks tanpa izin", tetapi hasil dari masukan yang mencampur pemisahan dan nilai URI.

Pisahkan kreasi baru, tambahkan, dan timpa

name dari new adalah nama catatan baru, dan tujuan penyimpanan dibiarkan ke "Lokasi default untuk catatan new" dari Obsidian. file adalah nilai yang mencakup tujuan dari rute Vault. Rumusnya menyatakan bahwa file lebih diutamakan daripada name, dan I:N2 juga menyimpannya ke tujuan yang ditentukan file. Di S:N01, hanya name yang disimpan dalam folder default yang telah ditetapkan sebelumnya.

obsidian://new?vault=Practice&file=Inbox%2FURI-test&content=Hello%20World

Jika Anda ingin meninggalkan dan menambahkan teks yang ada, lewati append=true. I:N3 mempertahankan teks yang ada dan menambahkannya. overwrite=true ditentukan untuk menggantikan teks yang ada, dan ada teks asli/catatan tersimpan terpisah di I:N5. Pernyataan resmi menyatakan bahwa "overwrite hanya jika append tidak diatur", dan telah ditambahkan di kedua sebutan S:N03. Tidak perlu mencampur spesifikasi penimpaan dengan tambahan teks harian.

obsidian://new?vault=Practice&file=Inbox%2FURI-test&content=Another%20line&append=true

silent=true's I:N4 mempertahankan catatan yang ditampilkan saat membuat file yang disimpan. S:C01/C02/C03 clipboard=true menyimpan teks penulis dari layar khusus di new/daily/unique. Pada saat yang sama, S:C04, yang juga menyerahkan content, menyimpan teks clipboard. Kumpulan hasil prioritas ini tidak dapat diperluas ke semua bentuk dari semua terminal.

Bendera tambahan open tidak dapat mengkonfirmasi efeknya kali ini.Ada append/prepend di bagian resmi open, tetapi content tidak terdaftar di bagian yang sama. Penciptaan baru mutlak dari path tidak termasuk dalam kisah sukses

Bagian resmi new menjelaskan path absolut secara global. S:N02 tidak dapat mengajukan dengan input yang diteruskan oleh vault/name/file yang bertentangan. Rencana lain T:P1 hanya memberikan path dan content ke file yang belum dibuat di penulis terdaftar Vault. Meski begitu, tidak ada file target setelah 6 detik, dan layar tetap diindeks. Ini adalah catatan dari satu aplikasi Linux yang menerima jalur, dan bukan hasil dari menegaskan penyebab atau masalah di seluruh lingkungan.

Masukkan ノート名#見出し dalam nilai file untuk judul dan ノート名#^block-id dalam blok dan kode nilainya. I:O5 mengkonfirmasi perpindahan ke judul catatan penulis. Hanya karakter bahasa Inggris, angka, dan tanda hubung yang digunakan untuk ID blok (aturan karakter untuk teks asli dari tautan Internal tetap).

Unduh teks lengkap T:B1 asli panjang Markdown

Singkatan obsidian://vault/Vault名/ノート名 dan obsidian:///絶対パス adalah singkatan untuk open. Setiap S:H01/H02 menampilkan catatan penulis. Periksa penanganan nilai dalam bahasa Jepang, spasi, dan pemisah dengan cara yang sama seperti parameter normal.

Catatan harian dan catatan nama yang tepat juga memeriksa plug-in dan tujuan penyimpanan

Secara resmi dinyatakan bahwa daily membutuhkan catatan harian dan unique membutuhkan plug-in inti pembuat catatan Unik. I:D1/U1 pertama tidak dapat membuat file dan meninggalkan catatan kegagalan sebagaimana adanya. Dalam rencana lain nanti, kami menyiapkan folder penyimpanan untuk penulis asli dan mengamati I:D2, yang membuat file harian dari indeks, dan I:U2, yang membuat file nama yang tepat. Kami tidak menentukan bahwa perubahan asumsi ini adalah satu-satunya penyebab kegagalan.

obsidian://daily?vault=Practice&content=Daily%20entry
obsidian://unique?vault=Practice&content=Unique%20entry

Teks resmi tetap menjelaskan bahwa daily menerima parameter yang sama dengan new. Namun, S:D01/D02/D03 tidak dapat menentukan name, file, dan path, dan telah ditambahkan ke 日次/2026-09-30.md dalam pengaturan catatan harian. Catatan baru yang ditentukan namanya adalah new, masukan ke dalam catatan tanggal adalah daily, dan tujuan penyimpanan akhir dapat dikonfirmasi dalam file aktual dari pengamatan ini.

S:D04 disimpan setiap hari sambil mempertahankan tampilan indeks di silent. S:D05 menentukan append dan overwrite untuk mempertahankan teks asli, tetapi daily tanpa bendera juga ditambahkan, sehingga kontribusi append saja dan operasi overwrite saja belum dikonfirmasi.

Pilih tujuan tampilan paneType

open/new/daily/unique mencatat input 12 dari paneType=tab, split, dan window masing-masing (S:P01〜P12). Secara resmi, window hanya untuk Desktop. Baca tab utama yang sebenarnya, grup tab, dan layar pop-out terpisah dan tinggalkan tangkapan layar. Karena metadata layar tertutup tetap ada, keberhasilan atau kegagalan tidak hanya ditentukan oleh jumlah total daun global.

x-success・x-error konfirmasi penerimaan di alamat pengembalian

Deskripsi resmi termasuk name (tanpa ekstensi), url (URI obsidian), dan file (file URI) di desktop untuk kembali ke x-success. Ini berbeda antara keberhasilan menabung dan fakta bahwa penelepon telah menerima pengembalian. S:X01/X02/X03 mengamati pelestarian catatan, tetapi tidak ada penerimaan di penerima localhost HTTP yang dimiliki oleh penulis. Adaptor BROWSER yang disiapkan belum dieksekusi, dan OS dan serah terima pemanggil belum dikonfirmasi.

hook-get-address untuk Hook secara resmi dinyatakan bahwa jika ada x-success, itu akan dikembalikan ke sana, dan jika dihilangkan, tautan Markdown di buku catatan saat ini akan disalin ke clipboard. Di S:K01, nomor penulis clipboard tidak berubah, dan S:X04 tidak mengembalikannya. Tubuh Hook tidak berjalan. S:X05 tidak ada Vault menampilkan dialog "Vault tidak ditemukan" yang sebenarnya, tetapi x-error tidak diterima. Jangan mengganti tampilan kesalahan dengan pengembalian yang berhasil atau kegagalan produk untuk semua panggilan balik.

Pertanyaan umum

Apa perbedaan antara obsidian:// dan Web URL biasa?

obsidian:// adalah URI unik yang diterima oleh Obsidian. Bukan URL untuk mendapatkan halaman web. Periksa asosiasi di sisi terminal dan operasi catatan setelah pergi ke Obsidian secara terpisah. Pengukuran sebenarnya dari artikel ini adalah setelah menerima URI dari aplikasi Linux.

Bagaimana cara menulis bahasa Jepang, spasi, dan #?

Enkode URI untuk setiap nilai. Ruang kosong adalah %20, # adalah %23, / adalah %2F. # dari judul dan spesifikasi blok juga dikodekan dalam nilai file. Dalam contoh penulis yang meninggalkan # mentah dari teks, # dan # berikutnya tidak disimpan.

Apakah Anda menggunakan open untuk menambah notebook Anda yang sudah ada?

Contoh yang dikonfirmasi dari teks postscript adalah bahwa file, content, append=true diteruskan ke new. Ada juga deskripsi append/prepend di bagian open, tetapi content tidak terdaftar di bagian yang sama, dan teksnya tidak berubah dalam masukan eksplorasi verifikasi ini.

Dapatkah saya mengubah tujuan penyimpanan jika saya meneruskan file atau name ke daily?

Teks resmi tetap menyatakan bahwa daily menerima parameter yang sama dengan new. Di sisi lain, dalam input Linux ini, saya tidak menentukan tujuan name, file, dan path, tetapi menambahkannya ke catatan tanggal dari pengaturan catatan harian. Silakan periksa pengaturan dan file yang sebenarnya untuk alamat penyimpanan.

Jika saya menentukan x-success, apakah Anda sudah mengonfirmasi pengembaliannya?

Tidak. Beberapa masukan diamati disimpan di new, daily, dan unique, tetapi tidak ada tanda terima di tujuan pengembalian HTTP. Menerima URI ke aplikasi atau mengakhiri CLI 0 bukanlah bukti pengembalian ke penelepon. Hook, OS handoff, dan aplikasi sumber panggilan yang sebenarnya belum dikonfirmasi.

Apakah hasilnya sama dengan iPhone?

Artikel ini tidak menjalankan pintasan fisik iPhone, iOS, dan SimpleMemo. Ini adalah hasil dari Vault hanya untuk penulis Linux Obsidian1.13.7. Untuk gejala khusus iPhone, silakan lihat panduan penanganan pintasan yang ada dan periksa di terminal.
