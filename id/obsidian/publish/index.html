Apakah Anda mempercayakan hosting atau mengelola produk sendiri?

Publish adalah layanan hosting resmi yang menerbitkan catatan di web. Quartz adalah alat yang menghasilkan situs dari Markdown, dan memilih tujuan pengiriman produk secara terpisah. GitHub Pages adalah salah satu tujuan pengiriman. Ketika menggabungkan Quartz dan GitHub Pages, itu berhubungan dengan dua peran: generasi dan pengiriman.

Jika Anda ingin memilih catatan yang ingin Anda publikasikan dan meninggalkan hosting situs ke layanan, silakan periksa kondisi Publikasi. Jika Anda dapat menjalankan perintah, mengubah pengaturan, dan mengelola tujuan pengiriman sendiri, coba generasi statis seperti Quartz dengan catatan kecil. Jika Anda tidak perlu mempublikasikan hanya catatan yang disimpan di web, tentukan tujuannya sebelum memilih layanan tambahan untuk publikasi.

Periksa harga secara terpisah dari kontrak, alamat pengiriman, dan operasi

Jumlah Publikasi saat ini belum dikonfirmasi ulang di lingkungan ini. Silakan periksa jumlah terbaru dan periode penagihan tahunan dan bulanan di biaya resmi Obsidian. Dari keberhasilan build nyata ini, kami tidak mendapatkan hasil bahwa Publish akan gratis.

Sumber Quartz tetap adalah lisensi MIT. Ini adalah syarat untuk penggunaan perangkat lunak, dan ini bukan syarat bahwa biaya tujuan distribusi, domain asli, dan pekerjaan pembaruan akan nol secara seragam. Biaya eksekusi ini juga tidak diketahui.

Dokumen resmi GitHub tetap dapat menggunakan Pages di repositori publik di GitHub Free dan GitHub Free untuk organisasi, dan di bawah kondisi Pro/Tim/Perusahaan, ini mendukung repositori publik dan pribadi. Periksa paket, cakupan publik, batasan, dan syarat dan ketentuan akun yang sebenarnya Anda pilih. Saya juga belum mengubah akun atau pengaturan hosting saya kali ini.

Daftar harga yang ada adalah artikel yang mengkonfirmasi tampilan resmi pada 2026 tahun 9 bulan 9. Kali ini, itu tidak akan diperlakukan sebagai konfirmasi independen dari biaya saat ini, dan kondisi pembelian terbaru akan dibagi menjadi informasi yang memerlukan konfirmasi resmi. Sinkronisasi antara Publikasi dan sinkronisasi antara terminal juga merupakan layanan terpisah.

# 著者作成の公開前メモ

これはローカルビルドのための架空の短文です。利用者の記録ではありません。

次は [[手順/確認|確認ノート]] を開きます。

![[assets/fixture-diagram.svg]]

Terapkan sumber tetap, periksa dependensi dan pengaturan, dan buat

  1. Saya memeriksa cabang v4 dari Quartz resmi dan menyebarkan arsip sumber komit d25a6eabf96751ffca56f8a8139272def7a65041 secara awal.
  2. Memeriksa proses pembuatan README, lisensi MIT, package.json, package-lock.json, dan CLI. Versi paket adalah 4.5.2, dan versi yang diperlukan adalah Node 22 atau lebih tinggi dan npm 10.9.2 atau lebih tinggi. Lingkungan yang sebenarnya adalah Node 24.19.0 dan npm 11.9.0.
  3. npm ci dieksekusi dengan file kunci tetap. Paket 491 diinstal dan keluar dari 0. Entri 597 dari lockfile adalah catatan yang mencakup dependensi seperti OS yang kompatibel, dan tidak berarti sama dengan jumlah tampilan instalasi. Byte dari file kunci asli tidak berubah.
  4. Saya mengubah pengaturan pribadi saya dan membuatnya dengan Quartz CLI untuk tiga catatan. Berikut ini akan menjelaskan perubahan pengaturan dan kegagalan pertama.

Format perintah yang dieksekusi adalah sebagai berikut. Folder input dan output dalam contoh menentukan lokasi yang telah Anda siapkan.

npm ci --no-audit --no-fund
node quartz/bootstrap-cli.mjs build   --directory /path/to/fixture   --output /path/to/generated   --concurrency 1

Log berjalan meninggalkan jalur absolut di awal dan spesifikasi cache npm yang terisolasi. Jalur yang ditampilkan di sini adalah pengganti penjelasan. Perintah yang menghilangkan Audit tidak berarti bahwa Anda telah lulus audit keamanan yang bergantung. Artikel ini bukan catatan prosedur penyebaran ke server publik.

Itu tidak meluas ke kesimpulan bahwa Quartz standar tidak berkomunikasi secara eksternal atau kompatibilitas formula.

Dihasilkan HTML, tautan wiki, sebenarnya buka lampiran

Saya membuka produk di server lokal dan memeriksa empat lebar 320/390/768/1440 px. Saya membaca judul, teks Jepang, tag verifikasi, dan SVG, dan benar-benar mengklik pintu masuk → konfirmasi → referensi → pintu masuk di setiap lebar. Ini adalah konfirmasi terbatas dari total klik 12.

Tiga HTML yang dihasilkan, dua CSS, dua JS, contentIndex, dan SVG, total delapan, respons HTTP aktual dari localhost dan byte asli/SHA256 dicocokkan. SVG terlampir sama dengan input aslinya. Dalam empat lebar setelah mengubah pengaturan, tidak ada kesalahan konsol/halaman/sumber daya pada halaman.

Grafik dan widget tautan balik dalam gambar ditampilkan, tetapi saya belum mencoba semua fungsinya. Karena judul tubuh juga ditulis di perlengkapan, itu tumpang tindih dengan judul artikel di sisi Quartz. Itu tidak dihitung sebagai bukti konfirmasi biaya saat ini, kinerja SEO, Vault besar, dan publikasi web.

Pertanyaan umum

Apakah saya memerlukan kontrak Publikasi untuk menerbitkan catatan Obsidian di web?
Jika Anda ingin menggunakan Publikasikan, panduan resmi memerlukan akun Obsidian dan kontrak Publikasi yang valid. Metode lain adalah dengan menempatkan situs yang dihasilkan dari Markdown di Quartz ke tujuan distribusi pilihan Anda sendiri. Kali ini, saya memeriksa generasi lokal Quartz dan tidak mencoba kontrak Publikasi atau distribusi eksternal.
Apakah Quartz dan GitHub Pages adalah jenis layanan yang sama?
Quartz adalah alat yang mengubah Markdown menjadi HTML, CSS, JavaScript, dll., dan GitHub Pages adalah layanan yang mendistribusikan situs statis dari repositori. Ini dikonfigurasi untuk menempatkan produk yang dibuat dengan Quartz di Halaman GitHub, dll. GitHub Kami belum menyiapkan, menyebarkan, atau benar-benar mendistribusikan ke Pages kali ini.
Di mana saya dapat memeriksa harga Publikasi dan metode alternatif?
Anda dapat memeriksa jumlah terbaru dan periode penagihan Publikasi di halaman harga resmi. Dalam lingkungan ini, halaman biaya saat ini tidak dapat diperoleh kembali, dan jumlah saat ini belum dikonfirmasi. Sumber tetap Quartz adalah lisensi MIT, tetapi tujuan pengiriman, domain, dan biaya operasi akan dikonfirmasi secara terpisah. Silakan juga merujuk ke dokumen resmi untuk kondisi rencana untuk repositori publik dan pribadi Halaman GitHub.
Dapatkah Anda menentukan kompatibilitas penerbitan web dan semua fungsi hanya dengan memeriksa Quartz kali ini?
Saya tidak bisa menilai. Untuk Markdown yang dibuat oleh tiga penulis dan satu SVG, kami memeriksa build lokal dari komitmen tetap, lebar empat layar, tautan internal, dan file yang dihasilkan. Ada perubahan pengaturan seperti menonaktifkan Lateks yang tidak digunakan dan generasi OG yang sewenang-wenang. Formula, penyimpanan besar, semua fungsi Obsidian, distribusi eksternal, sinkronisasi, kerja sama SimpleMemo, kecepatan dan produktivitas belum diverifikasi.

Sumber tetap dan jangkauan yang dapat dikonfirmasi

Tanggal build dan pemeriksaan browser dalam UTC adalah tanggal 30 bulan 9 tahun 2026, dan dalam waktu Jepang tanggal 1 bulan 10 tahun 2026. Versi Node/npm/Quartz yang benar-benar digunakan, source/lock, perbedaan pengaturan, kegagalan awal, dan bukti asli yang disimpan dirangkum dalam catatan verifikasi. Kami juga mencatat kesalahan ekspektasi bahasa pada pemeriksaan browser pertama serta hilangnya satu JSON kegagalan akibat ditimpa.

  • Konfirmasi eksekusi: Private CLI npm ci dan dua build, empat lebar lokal, tautan internal, lampiran, HTTP asli setelah pengaturan perubahan. GUI Obsidian yang sebenarnya tidak dimasukkan.

  • Belum dikonfirmasi: Publikasikan jumlah saat ini, kontrak, operasi aktual, Halaman GitHub/Penyebaran dan pengiriman ke tujuan pengiriman lainnya, rumus matematika・Kuarsa OG opsional・Semua fungsi, iOS/Sinkronisasi/SimpleMemo, semua lingkungan, kecepatan, produktivitas, efek aliran masuk.
