# 共通Captureへの統合 — PRD

作成日: 2026-09-05
状態: 実装中
対象リポジトリ: `simplememo-ios` / `simplememo-api`

2026-09-19再照合。9/5の案を現行mainへ接続する。新規のCapture型をもう一つ作る指示ではない。

## 0. 一行定義

既存のMemoCapture・MemoDeliveryと受付ID・保存指示を使い、全入口から同じ配送経路へ渡す。Routing試作をこの経路へ統合する。

## 1. なぜこの機能か

iOS main `17dcad9` の `SimpleMemo/NotionManager.swift` にMemoCaptureとCaptureDestination、
`SimpleMemo/ObsidianManager.swift` にMemoDeliveryがある。
`CaptureInstruction.swift` は受付時の宛先集合を保持し、
`docs/capture-nsm-measurement-contract.md` は全入口の非空保存要求の受付を計測境界にする。
ローカルRouting試作 `6ddc66a` の `Capture.swift` は判定入出力用で、既存配送の載せ替えは未完了と明記されている。
共通処理の不在を前提に作り直さず、既存実装と差分を統合する。

## 2. VISION §13 のチェック

1. **Capture Coverage / Zero-decision 率を上げるか**: 入口追加と保存先一致を支える基盤。実測の改善は未確認。
2. **整理するUIを増やしていないか**: 内部統合であり、新しい管理画面は作らない。
3. **Destinationを所有しようとしていないか**: 保存先の識別と配送だけを扱う。
4. **共通Capture Objectを通るか**: 既存MemoCaptureを基点に試作を統合し、IDと受付時刻を保持する。
5. **修正が学習資産になるか**: Routing側の端末内Correction記録へ接続する。本文を分析へ出さない。
6. **AIを前面に出していないか**: 内部構造の変更であり、AIの訴求は追加しない。

**Routing Level**: ここでは判定しない。Routing側はLevel 1→2。

## 3. 受入条件

- [ ] キーボード・音声・Siri/Shortcuts・Watch・画面Captureの現行受付境界を一覧化し、同じIDで共通経路へ渡す。
- [ ] サイドボタン試作の入口も共通経路を使い、入口専用の配送を増やさない。
- [ ] CaptureInstructionの受付時の保存先集合、操作区間、最初の全保存先到達を維持する。
- [ ] 既存の暗号化Outbox・履歴・旧形式を読め、再試行で本文・元宛先・取得時刻・IDを失わない。
- [ ] 本文・宛先名・パス・メールアドレスを分析へ送らず、同意と削除範囲を維持する。
- [ ] メモ本文の永続保持は既存の暗号化Outbox・履歴に限定する。Correctionなどの追加記録に本文を保存しない。位置情報は取得せず、権限を増やさない。
- [ ] 失敗・キャンセル・欠測・Watch引継ぎ・重複を含む回帰検証が通る。
- [ ] 同じ配布版の全入口・実配送を確認してから実機完了を記録する。実測は適格な同意済みコホートのみ。
