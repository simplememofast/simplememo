# 直前の Capture をワンタップで取り消す — PRD

作成日: 2026-08-26
状態: 設計案
対象リポジトリ: `simplememo-ios` / `simplememo-api`

---

## 0. 一行定義

送信直後の一定時間だけ、**直前に送った1件を取り消せる**（メール送信の中止と、
Obsidian へ追記した行の削除）。取り消し用の一覧画面は作らない。

## 1. なぜこの機能か

| 事実 | 出典 |
|---|---|
| ★5レビューで名指しの要望。「間違って入力したメモをワンタップで削除できると更に嬉しい」 | `../simplememo-ios/data/appstore/asc-metrics.json` reviews.rows（2026-07-07・JPN・rating 5） |
| 同じレビューが「もう手放せないほど毎日使いまくっています」と書いている | 同上。**毎日使う人が踏んでいる**ので、頻度は低くない |
| バックログに載っており、根拠の種類は `observed` | `data/feature-backlog.json` の `undo_last_capture` |
| 送信は Outbox 経由で、即時とは限らない | `../simplememo-ios/SimpleMemo/` の送信経路（`SendManager` / `Outbox`） |

`evidence_strength: observed` ——**観察はしたが数えていない。**
レビュー1件であって、何%が踏むかは測っていない。§7 の測り方はそこを前提にする。

## 2. VISION §13 のチェック

1. **Capture Coverage / Zero-decision 率を上げるか**:
   Zero-decision 側。**取り消せないと、ユーザーは「送る前に確認する」ようになる。**
   確認は Capture 前の判断であり、Zero-decision の反対方向。
   取り消せることは「まず送る」を安くする。
2. **整理するUIを増やしていないか**:
   増やさない。**一覧・履歴・ゴミ箱は作らない。**直前1件のみで、
   導線は送信直後のトースト内に閉じる。
3. **Destination を所有しようとしていないか**:
   していない。Obsidian 側は**自分が追記した行を消すだけ**で、
   保管庫の他の内容には触らない。メールは送信の中止であって受信箱の操作ではない。
4. **共通 Capture Object を通るか**:
   通る。取り消しは Capture Object の id を指すので、
   入口（アプリ / Watch / ショートカット）ごとの実装にはならない。
5. **ユーザーの修正が学習資産として記録されるか**:
   **取り消しは「この Capture は要らなかった」という強い信号**なので、
   Phase 2 の Correction Learning（VISION §5.1）に入れる価値がある。
   ただし**本文を残すかどうかは §6 の未決定**。
6. **AI を前面に出していないか**:
   出していない。AI は関与しない。

**Routing Level**: 触らない（Routing の判定には関与しない）

## 3. 受入条件

- [ ] 送信直後のトーストに「取り消す」が出る。**タップ1回で完了する**
- [ ] 取り消し可能な時間を過ぎたらトーストは消え、**取り消す導線も消える**（押せない導線を残さない）
- [ ] Outbox に残っている（未送信の）Capture は、メールが送られないこと
- [ ] 既に送信済みの Capture は、**メールを取り消せないと明示する**（嘘をつかない）
- [ ] Obsidian 連携が有効なら、追記した行が消える。**その行だけ**で、前後の行は変わらない
- [ ] Obsidian の保管庫にアクセスできないときは、**失敗したことを出す**（黙って成功にしない）
- [ ] 取り消しは直前の1件のみ。2件前は対象にならない
- [ ] 一覧画面・履歴画面を追加しない

## 4. UX

送信後に出る既存のトーストへ「取り消す」を足す。**新しい画面は作らない。**

- トーストの表示時間 = 取り消し可能時間。消えたら取り消せない
- 押すと即座に取り消し、トーストは「取り消しました」へ変わる
- 送信済みでメールが取り消せない場合は「Obsidian の行だけ消しました」と出す
  （**何が消えて何が消えていないかを言う**）

| 要素 | JA | EN |

## 6. 決めていないこと

- **取り消し可能な時間の長さ** — 決めるのは: オーナー。
  短いと間に合わず、長いとトーストが邪魔になる。実測が無いので提案しない
- **取り消した Capture の本文を残すか** — 決めるのは: オーナー。
  Correction Learning（§2-5）としては残したいが、
  **VISION §14「推論をどこで回すか」が未決定**のまま本文を保持する経路を足すことになる。
  ここは §14 を決めてから
- **無料 / Premium のどちらに置くか** — 決めるのは: オーナー。
  課金圧力に触るため（`../simplememo-ios/docs/obsidian-only-mode-design.md` と同じ論点）
- **既に送信済みのメールをどう扱うか** — 決めるのは: オーナー。
  Resend の取り消しは実質できないので、「できない」と出す以外の案は無いと考えているが、
  ユーザーへの見せ方は判断が要る

## 7. 測り方

`data/feature-outcomes.json` に以下を書く。**出したあと判定できる形で。**

- 取り消しが使われた回数 / Capture 総数（**分母を必ず持つ**）
- 取り消し可能時間を過ぎてから開こうとした回数（時間の長さが足りているか）
- D7 継続率の前後比較

**レビュー1件が根拠なので、「効いた」と言うには分母が要る。**
`evidence_strength: observed` のまま出荷し、出荷後に `measured_ours` へ上げる。
上がらないなら、その事実のほうを記録する。
