# 接続した実機の確認と残る復元証拠

2026-09-10。配布済みTestFlight 5.8.53（1316）、ソース
`ddfc706490fe4c68c1a43c89c2fbcf6ee54ce076`をiPhone 13とApple Watchで確認した。
正式な確認は5/6項目であり、AI実行率は156/179のまま。

## 委任された操作

ユーザーはiPhoneの接続・信頼を済ませて実機利用を指示し、WatchのDeveloperモードと
iPhoneのUIオートメーションを有効にしたうえで、残る実機確認の続行を依頼した。
これに基づきCodexが接続済み端末のUIを操作し、実際の結果を観測している。
「実機確認は機械には代われない」という旧分類は、この実行経路を反映していなかった。

委任の範囲は、ユーザーが利用を指示し接続・信頼した端末の実機テストと証拠の記録。
Apple Accountの認証、端末のロック解除、サイドボタン認証などの本人操作はユーザーが行う。
利用者本人の収集同意や、別の端末・アカウントの認証には範囲を広げない。

## 同じ配布版で確認できたこと

| 項目 | 実観測 |
| --- | --- |
| iPhoneの通常メール送信 | 本文・実宛先・受信・同じ履歴を確認済み |
| Watchの音声送信 | 実マイクで全文認識、送信済み表示、受信本文・実宛先、iPhone履歴1件を確認済み |
| オフライン復帰 | 再起動をまたぐ待機状態、接続復帰後の配送と受信を確認済み |
| 購入・復元 | TestFlightのテスト購入は成功。別操作の復元はApple再認証待ちで未確認 |
| Obsidianへの追記 | 実際のDaily Noteへの同じ本文の追記を確認済み |
| iPhone・Watchのウィジェット | 両方の実ウィジェットからアプリ起動と音声入力開始を確認済み |

Watchの成功は`watch-1316-real-voice-clear-utterance-b.xcresult`、受信照合は
`watch-1316-real-voice-receipt.json`、iPhone履歴と下書きの照合は
`watch-receipt-and-draft-1316.xcresult`に保存している。
個人データを含む元の結果・画面・メールは非公開環境に保持し、公開リポジトリへ複写しない。

途中の音声誤認識は送信前にキャンセルした。空欄の案内文を入力値と扱うテスト側の誤りを修正し、
最後の試行は期待文と同じ文章から生成した音声の全文一致を確認してから1回送信した。
以前の不成功も保持しており、観測用テストの成功を製品の送信成功に置き換えていない。
元の下書きは保持され、一時ウィジェットは撤去、ネットワークと音量は元の状態へ戻っている。

## 残る条件と加点

復元の再認証後に、現在進行中の復元処理の成功表示を確認する。購入成功やPremium表示だけでは
復元成功としない。同じ送信や購入を繰り返して証拠を増やさない。

全6項目が同じ配布版で揃ってから、実行者・時刻・SHA・版・ビルドと証拠の種類を
`simplememo-ios/data/appstore/device-verification.json`へ記録する。
Codexの実機操作をオーナーの申告に置き換えず、本人が行った認証も区別する。
現在その提出用記録は更新していない。

今回変更するのは待機理由と委任の記録のみ。実行者の実績は`human_only`を維持し、
`verification_pending`として復元結果を待つ。全実機確認の完遂前には加点しない。
提出時の同一SHA、CI、TestFlight 24時間、日英ノート、提出枠、日次上限、段階公開の条件も維持する。
