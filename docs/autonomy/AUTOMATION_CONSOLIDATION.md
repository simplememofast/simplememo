# Automation consolidation decisions

These decisions reuse the discovered systems. The complete machine/account inventory, historical records, source timestamps and gaps are private in `~/.config/simplememo/company-os/automation-registry.json`. A definition, a scheduled invocation and a verified business output are distinct evidence levels.

| Purpose | Canonical path and output mapping | Overlap decision / migration evidence |
|---|---|---|
| Daily autonomous business action | Native `obsidian` → existing selection, claim, stop, value contract, Autopilot ledger and CI → Company execution receipt | Keep the existing daily owner. GitHub dispatch is a fallback entry, not a second daily agent. Paused Codex backups and legacy Claude routines retain their current state. |

## Selection criteria

The existing native owner provides the broadest current execution coverage: one claim, permission checks, budget gates, implementation, CI and delivery. Its reliability must still be measured from actual original scheduled turns; configuration alone does not prove that it fired. Existing GitHub and local fallbacks supply complementary observability and recovery without granting extra action authority.

Reusing the exact collectors preserves output coverage, population semantics and maintenance ownership. Original-parser parity, source hashes, date/window checks, negative tests and retained receipts supply verification. Adding adapters to the existing owner avoids an additional model subscription or recurring model invocation. Monetary savings and model cost are unknown until observed; they are not estimated as zero.

Permission risk stays within the original readers and execution gates. Transient read failures have bounded retries; authorization failures do not trigger a new credential or a broader token. Existing stops, paused tasks, approval boundaries, one-action limits and external communications rules remain authoritative.

No old job was deleted or retired by this integration. Discovered overlap was either retained as an intentional fallback, left paused, or mapped into the existing owner. Remote scheduler surfaces that could not be authenticated remain explicit inventory gaps. Retiring any future candidate requires equivalent coverage, one successful replacement execution, output parity and a saved rollback configuration.

## Rollback

The full native owner configuration was saved privately before integration. Restore its prior prompt with the native automation update tool and revert the implementation through a normal reviewed PR. Keep all original collectors, report destinations, historical ledgers and experiment records. Installed Company skills carry an ownership marker and source hash, so their files can be identified without touching unrelated skills.
