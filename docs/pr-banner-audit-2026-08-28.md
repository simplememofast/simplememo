# プレスリリース・バナーの数値監査（2026-08-28）

**結果: 5つが実測と違う。うち4つは過小で、1つ —— 見出しの数字 —— が大幅に過大。**

## 174 と 91.5 はどこから来たか

**174 は古い分母。** `docs/pr-autopilot-2026-09-body.md` に世代が記録されている:

    61.5% → 65.8% ／ 174 → 203タスク ／ 13件 → 15件 ／ 51種 → 67種

**91.5% は測定値ではなく、反実仮想の上限に近い。** `docs/autonomy-95-gap.md` の

    境界を全部渡しても 160/174 = 92.0%   ← 人へ残した22件をすべてAIに渡した場合

これは「人に残した境界（お金を含む）を全部AIに渡したら」という仮定の天井で、
**達成値ではない。**しかも分母が古い174なので、203では同じ仮定でも数字が変わる。

つまりバナーの見出しは **「古い分母」×「反実仮想の天井」** を掛け合わせている。

## 91.5% は開発では届かない（算術）

総合自動化率 = (自律 + ゲート付き実行) / (総タスク − 意図的にやらない)
= 131 / 199 = 65.8%。

91.5% に要る numerator は **182**。いま 131 なので **+51**。
変換候補は 68 件で、その内訳:

| | 件数 | |
|---|---:|---|
| **コードでは埋まらない** | **29** | |
| policy_boundary | 9 | お金の境界（オーナーが人に残すと決めた） |
| physical_human | 8 | 物理的に人が要る |
| missing_source_document | 6 | 存在しない書類が要る（オーナーが作る） |
| external_credential | 3 | 外部の資格情報（オーナーが入れる） |
| statistical_power | 2 | 標本が足りない。**時間が要り、コードでは埋まらない** |
| human_consent | 1 | 本人の同意 |
| **実装で埋まりうる** | **39** | |
| not_started | 28 | |
| external_data | 10 | |
| structural | 1 | |

**実装で埋まりうる39件を1つ残らず全部やっても 170/199 = 85.4%。**
91.5% には **12件足りない**。その12件は上の29件からしか取れず、うち9件はお金の境界。

しかも 85.4% 自体が非現実的。2026-08-28 の監査（`docs/implementable-27-audit-2026-08-28.md`）は、
未着手27件のうち**この環境で完遂できたのは1件**と結論している。残りは iOS 実機・Mac・
外部データ・オーナー作業の壁。

**したがって「数日で 91.5% を実測にする」経路は無い。**

## 何をすべきか

**見出しの数字を差し替える。**デザインではなく数字だけの問題。

台帳が持っている見出しはそのまま使える:

> 本番15件は100%AI・運営全体では65.8%

残り4つは**上方修正**できる —— 13→15件 / 16→18日間 / 54→72種。
**バナーは自分を過小評価している。**

## この監査を残す理由

数字を追って辻褄を合わせるのが、この台帳がいちばん警戒している形だから。
`data/pr-claims.json` の `pass_threshold` も `scripts/check-pr-facts.mjs` も、
**外向きの原稿が台帳より先に走らないため**に置いてある。
バナーは画像なのでその検査を通らなかった —— **通らない経路が1つあった**という記録でもある。
