## 0. なぜ「RSI」と名乗らないか

AI研究でいう **RSI（Recursive Self-Improvement）は、AI自身が自分の知能・学習
アルゴリズムを再帰的に改善すること**を指す。ここで起きているのはそれではない。

起きているのは **アプリ事業の運営能力**が、自分の結果を見て改善されていくこと。
別物なので、対外表現は次の3つに限る（`check-pr-facts.mjs` が「RSI」「完全自動化」
「人間不要」を禁止語として落とす）。

- **Autonomous App Operations**
- **Closed-loop App Operations**
- **RSI-like Business Improvement Loop**（「-like」を落とさない）

```
  ①〜④ だけ        →  Autopilot
  ⑤ まで            →  Closed-loop Autonomy   ← **ここが現在地**
  ⑥⑦ まで          →  再帰的に運営能力が改善している
```

> **[2026-08-25 追記] ⑦の実例が1件できた。**`om-2026-08-25-asc-landed` —

**⑥は今日置いた。⑦は「置いた仕組みが効いた」ことでしか示せないので、
最短でも次に同じ種類の signal が来る日まで判定できない。**

## 2. ⑦がまだ言えない理由を、具体的に書く

⑦の証明には「**過去の学習があったから、今回の判断が変わった**」という
1本が要る。運転記憶の7件は、**すべて「学習を書いた」側**であって
「学習に従って判断が変わった」側ではない。

唯一それに近いのが `om-2026-08-25-shallow-rebuild`（発生時記録）で、

- 検査が `--rebuild` を名指しした → そのとおり実行 → **壊れた**
- 学習「検査が直し方を名指しするなら、前提条件も検査が持つ」
- 歯止め「浅いクローンを検出して throw／月の連続性を検査」

ここまでは⑥。**⑦になるのは、次に別の検査が「こう直せ」と言ってきたときに、
前提条件の有無を先に見る判断が働いたときで、それはまだ起きていない。**

> **配信原稿では「⑦まで到達した」と書かない。**
> 書けるのは「⑥まで実装し、⑦を判定する仕組みを持った」まで。

## 5. 海外勢との対比 — 主張してよい2点だけ

各社が**自ら明言している制約**（自社に不利な記述なので、伝聞でも比較的安全）。

> **PostHog**: "Nothing merges itself, and nothing ships on autopilot."
> エージェントは branch protection・CI・レビュー規則に従うが **merge はできない。**
>
> **AppDNA**: 変更は SDK と Feature Flag で配る —— **「ストア申請を待たずに」。**

| 主張してよい | 理由 |
|---|---|
| ✅ **人の merge を待たずに本番へ出る** | PostHog が自分で「できない」と書いている線 |
| ✅ **App Store の正規リリース工程まで含む** | AppDNA が「申請を待たない」と回避している工程 |
| ❌ 「世界初」「最先端」「他社より進んでいる」 | **PostHog は scout 由来のPRを直近30日で178本マージ**。throughput で負ける |
| ❌ 「AIがASO・広告を自律運用」を訴求の中心に | **AppTweak（ASO最大手）が2026年3月に出荷済み。**新規性が無い |
