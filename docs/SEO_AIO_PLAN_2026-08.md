これは AI Mode / AI Overview の **query fan-out**（ユーザーの1つの質問をLLMが複数の下位質問に
分解して検索する）の痕跡である。「です・ます」の完全文、「2026年に」という時点指定、
句点で終わる依頼形——人間の検索行動ではない。

**意味するところ:**

1. **平均順位6.8で fan-out の検討対象に入っている。** AIが答えを合成する材料として本サイトを読んでいる。
2. **クリック0は失敗ではない。** fan-out クエリにクリックは発生しない。**この面のKPIはクリックではない。**
3. **順位1.0が2件ある**（`最高のノートテイキングアプリは？` / `チームが共有ノートに…`）。
   fan-out の第一候補になっている。ここで引用されているかどうかは GSC では分からない。
4. しかし内容は**答えられていない**。`セキュリティとコラボレーションの両立`（54表示・順位4.7）は
   本アプリの弱点そのもの（共同編集機能はない）で、`チームで共同作業`も同様。
   **強いクエリで拾われているが、答えの中身で負けている可能性が高い。**

生成AI機能の露出は **6,947表示（全体の10.2%）・179ページ**。到達は十分広い。
（分母は `dates` 次元の総表示 68,214。ページ次元の合計 73,550 を分母にすると 9.4% になるが、`ingest-gsc.mjs` は `dates` を正準の総計として扱うため、そちらに揃える。）
問題は「出ているか」ではなく「**出たときに何と言われているか**」に移っている。

### 2-3.【エンゲージメント】240ページあって、1.21ページしか読まれていない

```
session_start   1,600 → page_view 1,938 = 1.21 ページ/セッション
90%スクロール到達  10.4%
新規率           81.6%
app_store_click  60件 / 28日 = 2.1件/日（セッションの3.8%）
```

内部リンクは足りていない**のではない**。実測すると1ページあたり
`line-keep-alternative` 52本 / `best-memo-apps-2026` 87本 / トップ 98本ある。
**リンクは大量にあり、そして使われていない。**

87本のリンクは「次に何を読むべきか」を伝えない。選択肢が多いことは、
選択肢が無いことと機能的に等価になる。これが 1.21 の正体である。

同時に、サイトには**インタラクティブな要素が1つもない**。240ページはすべて読み物で、
`/comparison/` も静的な表である。滞在・再訪・被リンク・記憶のどれを取っても、
「触れるもの」が1つも無いのは大きな空白である。

## 3. 戦略

> ### 面を絞り、深さで勝ち、ブランド検索を作る。

三段の論理：

1. **勝ち筋の面（CTR 7.41%）の表示を2倍にする方が、コモディティ面で同じクリックを取るより8倍安い。**
   - 勝ち筋を2倍 → 可視分で +206クリック / 四半期
   - 同じ +206 をコモディティ面（0.92%）で取るには **+22,400表示**が必要。実現不能。

2. **勝ち筋の面を深く掘る唯一の方法は、他が持っていない一次情報を出すこと。**
   AIOで強いページ（プライバシー・暗号化・オフライン・ベンチマーク）はすべて
   「測った」「実装した」「断定できる」ページである。これは競合が模倣できない。

3. **ブランド検索（現在7.7表示/日）が全部の天井。**
   検索エンジンにもLLMにも操作できない唯一の信号であり、
   CTR 13.5% という最良の変換率を持つ。**これをノーススターにする。**

### 指標の再定義

| | 旧 | 新 |
|---|---|---|
| ノーススター | サイト全体CTR | **ブランド検索の表示数**（月次） |
| SEO主指標 | クリック合計 | **★勝ち筋クラスタのクリック**（コモディティと分離集計） |
| AIO主指標 | （なし） | **生成AI機能の表示数** + 会話型クエリの平均順位 |
| エンゲージ主指標 | （なし） | **ページ/セッション**（現1.21）と90%到達率（現10.4%） |
| 事業指標 | app_store_click | 変更なし（60件/28日） |

**サイト全体CTRは今後、報告書に単独では書かない。** 性質の違う2事業の平均であり、
どちらが動いても解釈できないため。

### 9-3. 実装中に見つかった、放置すると壊れる2件

**(1) 生成AI機能のCSVが、通常のページCSVとして取り込まれるところだった。**
AIO版 `ページ.csv` の列は `page,impressions` の2つだけで、ファイル名も見出しも
通常のページエクスポートと同一。`ingest-gsc.mjs` の分類は `has('page')` で
判定していたため、**179行がそのまま `pages` に追記される**状態だった。
ページ行が二重になり、総計が膨らみ、AIO行が「順位0でクリック0のページ」として
CTRカーブに入り、サイト全体の期待CTRを押し下げる——しかもすべての数字が
もっともらしいままになる。`page` かつ `impressions` かつ `clicks` なし → `pages-aio` で分離した。

**(2) `decay()` に期間長のガードが無かった。**
クリック数は期間に比例するのに、`decay()` は連続する2スナップショットの生のクリック数を
そのまま比較していた。これまで全スナップショットが28日だったため露見していなかったが、
本書の3ヶ月エクスポートを取り込むと**全ページが3倍に増えたように見え、次の28日
スナップショットでサイト全体が崩壊したように見える**。期間差が3日を超えたら
比較不能と表示するようにした。

そのため、**本書の3ヶ月データはスナップショットとして取り込んでいない。**
28日運用の系列に3ヶ月の点を混ぜると、期間差ガードが出るだけで系列としては使えないため。
数値は本書に記録し、次の28日スナップショットから通常運用に戻す。
