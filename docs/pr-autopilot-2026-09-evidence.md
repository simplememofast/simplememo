1. **①②③の一部・④は証跡が強い。**特に「毎朝06:00に自分でネタを選び、記事を書き、

   一度も記事を出荷していない。**この12日間の出荷はすべて副系CCRによるもの。

## 1. 判定の凡例

| 記号 | 意味 |
|---|---|
| ✅ **実装・稼働中** | コードかワークフローが存在し、実行ログ・成果物が残っている |
| 🟡 **部分的** | 仕組みはあるが、一部が手動・停止中・未接続 |
| 🔵 **設計のみ** | 設計文書・調査レポートはあるが実装が無い |
| ❌ **証跡なし** | 3リポジトリを検索した範囲で該当する実装・文書が無い |

「❌ 証跡なし」は「やっていない」の証明ではない。**このセッションから検証できない**という意味で、
リポジトリ外（オーナーの別環境・SaaS管理画面）で動いている可能性は否定しない。
ただし**プレスリリースに書くなら、記者に見せられる証跡が要る**ので、同じ扱いにしてある。

#### この初出荷は、台帳に書かれないまま数時間放置された

**止まった指標は「変化が無い」と見分けがつかないぶん質が悪い。**

### 13-6. 改訂4で作ったもの — 契約条項の受け皿（⑦・**自動化率は動かしていない**）

オーナーから「ベンダー10社の契約条件をレビューした」との連絡があった（2026-08-23）。
**ただしこの時点で各社の判定は受け取っていない。**

#### なぜ「レビュー済み」と書かなかったか

`dpa_reviewed` を10社まとめて埋めれば、主張検査の「契約は人が承認」は
67% → 100% になり、原稿の残る2件が1件になる。**やっていない。**

この台帳は自分で「**`dpa_reviewed` が null は『問題なし』ではなく『見ていない』**」と
書いている。判定の中身を受け取らないまま「レビュー済み」の文字列だけを入れるのは、
その規律を最初に破る行為で、**しかも破ったことが検査に映らない**
（`check-vendors.mjs` は文字列の有無しか見ない）。

#### 代わりに作ったもの

| 追加 | 役割 |
|---|---|
| `data/vendor-register.json` の `contract_terms` | 10社 × 4条項（責任上限 / 知財 / 個人情報 / 準拠法）。**初期値は全40件 `unknown`** |
| `scripts/check-contract-terms.mjs` | 条項の検査。`--check` で exit 1 |
| `.github/workflows/seo-check.yml` | CI に「Contract terms」を追加 |
| `data/authority-matrix.json` | `required_ci_checks` に追加（19 → **20本**） |

**4条項は `data/automation-coverage.json` のタスク名がそのまま来ている**
（⑦「責任上限・知財・個人情報・準拠法の条項検査」）。検査項目を勝手に増やさない。

#### 設計上いちばん効く1行は `source` の必須化

`unknown` 以外の判定には「**何を読んでそう判断したか**」（規約URL・契約書名・
管理画面のページ）を必ず書かせ、無ければCIが落ちる。

**出典の無い「問題なし」は、見ていないのと区別がつかない。**ここを緩めると、
この検査は「レビュー済みという文字列があるか」を見るだけの装置になる。

あわせて `dpa_reviewed` と条項の整合も見る。**「レビュー済み」だけが入っていて
条項が1つも確認されていない状態を、検査が名指しする。**

#### `unknown` は失敗ではない

40件すべてが `unknown` で、検査は通る（`enforce_clause_review: false`）。
これは `data/credential-expiry.json` が期限未記入を「未把握」として別枠に出すのと
同じ扱いで、**数えて名指しはするが、ゼロや「問題なし」では埋めない。**

`enforce_clause_review` を true にすると、**個人データを渡している事業者に
未確認の条項があるだけで落ちる**（動作確認：true で exit 1、false で exit 0）。
`enforce_unreviewed` と同じく、**リスクの大きいところから順に強制する**
——全社を一度に必須にすると、埋まるまでCIが落ち続けて auto-merge が止まる。

#### 台帳の数字は動かしていない

| | 改訂4前 | 改訂4後 |
|---|---|---|
| ⑦`責任上限・知財・個人情報・準拠法の条項検査` | `nobody` | **`nobody` のまま** |
| ⑦ 法人経営 の総合自動化率 | 0.0% | **0.0% のまま** |
| 主張検査「契約は人が承認」 | 67% | **67% のまま** |

**器はできたが、中身は空。**動くのは判定が入ってからで、
**入れられるのは各条項について「何を読んでどう判断したか」を受け取ったとき**だけ。
