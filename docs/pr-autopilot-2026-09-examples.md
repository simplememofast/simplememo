## §1. 配信前に見る3点（内部）

### 1-1. 原稿の「費用超過」は1件だが、台帳には超過が複数ある

原稿は「8月23日に記事の1回上限2.00ドルに対して7.30ドル」だけを書いている。
台帳（`data/autopilot-cost.json`・`data/model-routing.json`）では:

    08-23  記事  $7.30  / 上限 $2.00（当時）  3.6倍  オーナー承認済（08-25）
    08-25  修理  $11.93 / 上限 $3.00          4.0倍  オーナー承認済（08-25）
    08-26  記事  $7.88  / 上限 $6.00（08-25 に引き上げ後） 1.3倍  ※機械の超過判定には出ていない。理由は未確認
    09-01  修理  $9.37  / 上限 $3.00          3.1倍  **未レビュー**
    09-02  修理  $13.57 / 上限 $3.00          4.5倍  **未レビュー**

9月は2日で $22.95（月上限 $40 の 57%）。修理の種別枠 $8.00 は枠切れ（警告のみ・主系は止まらない）。

**記者が `autopilot-cost.json` を開けば5行とも見える。**原稿の1件だけを書くより、
§2 の「上限を守った回は、失敗した回だけだった」の形で全部出すほうが強い。

### 1-2. 明朝 06:00 の主経路は「記事」として動く見込み。ただし修理が要る日は止まる

`autopilot-selfheal.mjs --json` は `lane_f_required: false`（未修理の故障なし）なので、
明朝の種別は article。`autopilot-budget.mjs --check-run-cap --task article` は exit 0 で通る。

一方 `--task repair` は exit 1（09-01 / 09-02 の超過が未レビュー）。
**明朝までに新しい故障が出て修理レーンになった場合、主経路はスキップされる**
（副経路 07:30 / 08:30 / 09:20 は別経路なので動く）。解除は人間のみ:

    node scripts/autopilot-budget.mjs --ack-overrun 33454414490 --why "…"
    node scripts/autopilot-budget.mjs --ack-overrun <09-02 の run_id> --why "…"

止まったまま出すのも原稿の主張（失敗を隠さない）と矛盾しないが、配信当日の 09:00 に
記者が `autopilot-status.json` を開く前提で、どちらにするか決めておく。

### 1-3. 「どの経路も動かなかった日は2日」は台帳定義どおり。ただし 8/30・31 も全経路が失敗

8/30・31 は着手して失敗（AI側の週間利用上限・HTTP 429）なので `no_run` ではなく `failed`。
「3日間止まっていたのでは」と聞かれたら、§2「AIの週間利用上限に当たって、AIが止まった」が
そのまま答えになる。

## §2. そのまま貼れる文（原稿の ■／・ 表記）

### 2-1. 「境界」の事例 — ■仕組み ／ ■次の目標 のあたりに

■ 止める権限はAIにもある。解除は人だけ

・自動運転を止めるスイッチは、AI自身が立てられます（自己修復が同じ故障で3回失敗したときなど）。しかし解除は人にしかできません。止める側の誤りは出荷が1日止まるだけですが、解除する側の誤りは、止めたかった事象を素通りさせるためです。
・止める仕組みは11種類。うち本番で実際に止まることを確かめたのは2件で、残りは手元での訓練までです。「実装した件数」を「確かめた件数」の代わりにしないと台帳に明記しています。
※出典: data/emergency-stop.json ／ data/stop-drills.json ／ docs/obsidian/AUTOPILOT_RUNBOOK.md §0-0

■ AIは自分の予算上限を上げられない

・月のAI実費の上限（現在40ドル）を上げるには承認記録が必要で、承認者にAIを書くとCIが落ちます。1回の変更幅は25%までで、それを超える変更は承認者が2人必要です。止めることはAIに許し、金額を上げることは許さない設計です。
※出典: data/spend-approvals.json ／ data/financial-policy.json

■ 上限を守った回は、失敗した回だけだった

・1回あたりの実費上限は、当初「失敗した1回（0.81ドル）」から外挿した値でした。実際に仕事をして本番へ出した回は、記事作成が7.30ドル（上限2.00ドル）、修理が11.93ドル（上限3.00ドル）と、どちらも上限を超えていました。上限を満たしていたのは、何も出さずに終わった回だけです。
・オーナーは支出そのものを妥当と判断して承認記録を残し、記事の上限を6.00ドルへ引き直しました（8月25日）。修理の上限は据え置きのため、9月1日（9.37ドル）と9月2日（13.57ドル）の修理が再び超過しています。未レビューの超過がある間、修理が必要な日の主経路は止まり、解除は人のコマンドでしか行えません。
※出典: data/autopilot-cost.json ／ data/model-routing.json ／ .github/workflows/obsidian-autopilot.yml

■ AIの週間利用上限に当たって、AIが止まった

・8月30日・31日は主経路も副経路も失敗しました。原因はAIサービス側の週間利用上限（HTTP 429）で、同じアカウントを使う副経路も代走になりませんでした。
・当時の切り分けはこれを「認証情報の失効」と書く形になっていました。9月1日のセッションが自分自身のセッション記録を読み直し、利用上限が原因だと訂正しています。訂正した本人の記録には「答えは同じファイルの数行上にあった」と残っています。
※出典: data/autopilot-runs.json（ap-20260830-actions ほか）／ PR #738, #741

■ macOSのテストを回すには合言葉が要る

・2026年7月31日、AIが足したテスト起動の設定が1日でmacOSテストを13回走らせ、GitHub Actionsの予算10ドルを使い切りました。予算が枯れるとTestFlight配信もApp Review申請も止まります。
・以後、macOSテストの起動には必須の合言葉入力を置き、人が名指しで指示したときだけ回します。手順書には「回さなかった損失は数分、回した損失は月の予算」と書いてあります。合言葉はリポジトリに書いてあるので錠前ではなく、塞いでいるのは「読まずに回す」ことです。
※出典: ../simplememo-ios/.github/workflows/qa-ios.yml ／ ../simplememo-ios/CLAUDE.md

■ AIに渡していない権限のうち、技術的に強制されているのは1つだけ

・AI開発ワークフローには、他のワークフローを起動する権限を与えていません。与えると、タグ作成からビルド、TestFlight、App Review提出までの連鎖を、人の実機確認なしに起動できてしまうためです。権限表19領域のうち、これが唯一の「技術的に強制された境界」で、残りは人間のルールです。
※出典: data/authority-matrix.json ／ ../simplememo-ios/.github/workflows/claude.yml

■ 自分の壊れたところを直す「修理レーン」には歯止めがある

・毎朝の実行は記事を書く前に運転記録を読み、未修理の故障があれば修理を優先します。ただし触ってよいファイルは17件に限定し、権限表と監査の憲章は自分で書き換えられません。必須の自動検証を1本でも消す変更や、自分の権限を広げる変更はCIが検出して落とします。
・同じ故障を3回直しても再発すれば、修理をやめて自分で停止を立て、人に上げます。
※出典: data/authority-matrix.json（self_repair）／ scripts/autopilot-selfheal.mjs

■ 監査AIは、何も直さない

・自律システムを別系統から見る監査の憲章を置きました。監査に使うモデルは修理に使うモデルと別にし（同じモデルは同じ盲点を共有するため）、所見は追記のみで消せません。監査AIに直す権限を持たせないのは、「直したことにして所見を閉じる」が最短経路になるからです。
・ただし週次の監査は、まだ一度も走らせていません。
※出典: data/audit-charter.json ／ data/audit-findings.json

### 2-2. 「外向きの発言を機械がする」事例 — 新設の ■ として

## §3. 使わない表現・数字（内部）

- **CIが落とす語**: 完全自動化／完全無人／無人経営／人間不要／世界初／AIが経営／RSI・再帰的自己改善／「予算に応じて最適配分」
- **台帳に無い率**: 95.3% など。自律率で使えるのは 66.8%（総合）・76.4%（AI実行率）・82.9%（到達可能上限）だけ
- **「AIが売上／集客を伸ばした」**: 対照群つきの増分効果は未測定。書けるのは「出荷され、人が中身に触ったのは0件」まで
- **議事録の件**: 会社法上の備置義務が未履行であることを自ら告知する形になる。台帳（公開）にはあるが原稿には書かない
