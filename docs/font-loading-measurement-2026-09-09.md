# 主要LPのフォント読み込み — 2026-09-09

## 変更の根拠

公開トップページのLighthouse 13.4.1・モバイル設定の初回測定は、Performance 72、Accessibility 100、Best Practices 100、SEO 100。FCP 3.1秒、LCP 6.0秒、TBT 30ms、CLS 0だった。これはMacのChromeで行ったラボ測定で、実ユーザーのCore Web Vitalsや検索順位の計測ではない。

追加のBold-extフォント約138KBが読み込まれていた。既存の差分フォントは110文字で、現在の主要LPの文字が不足していた。通常・太字とも148文字へ再生成し、従来含まれた「権級達」も保持した。字形は従来のextフォントから抽出し、font-display: optional と字形の適用順序を維持する。

日本語トップ、AIタグ、Apple WatchとObsidian、Obsidian案内では差分フォントの両ウエイトを早期読込する。英語トップでは日本語の会社名などに使う通常ウエイトだけを追加する。早期読込が無い場合、小さい差分フォントだけを更新してもextの取得が残ることをブラウザーで確認した。

## 検証

変更前後それぞれをローカルHTTPで配信し、キャッシュを共有しないChromeの新規ページで390px・1280pxを確認。日本語4ページのフォント本文転送量は458,260→206,176 bytes（約55%減）。これはフォントの合計であり、ページ全体の転送量ではない。表示内容、見出しの高さ、App Store URLと計測属性が同じで、ページの横はみ出しは無かった。スマホのトップ画面も比較した。英語トップは303,344→182,904 bytes。両ウエイト148文字それぞれの輪郭と送り幅が元のextフォントと一致することも検査した。

preflightは192件成功し、残るQR関連2件は新規worktreeの依存不足だった。既存のローカル依存を接続して、その2件も再実行で成功した。

再生成を2回行い、フォント・CSS・プリロードの出力が同一バイトであることを確認。HTMLの大部分の差分は共通CSSのキャッシュ版のみ。画像、本文、見出し、実験の期間と判定は変更していない。

公開後のLighthouseは別途測定し、単一回の点数差だけで実利用での改善とは扱わない。

## 更新手順

```sh
python3 scripts/build_font_delta.py
node scripts/check-css-version.mjs --write
node scripts/preflight.mjs
```

生成器は2つのCSS内の対応するfont-faceが各2件であることと、生成した各ウエイトの文字収録を検査し、範囲とコンテンツハッシュを更新する。必要なページの文字が増えた場合は再生成し、ブラウザーのフォント取得を確認する。
