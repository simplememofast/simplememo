# PR TIMES ヒーローバナーの仕様 —— G1 は「幅1200px」では読まない

**2026-09-04 制定。**根拠は `pr-banner-audit-2026-09-02.md`（PR⑥ の配信前日監査・実際に切って確かめている）と
`pr-discover-strategy-2026-09-04.md`（乗車/非乗車の必要条件）。

D-SCORE のゲート **G1「サムネ1200px超・場面が写る」** を、毎回同じ判定に落とすための仕様。
**G1 は2つのことを言っているのに、幅の1つしか見られていなかった。**

## 1. 一行で

    比率は 1.91:1 で作る。中央 1:1 に主要素を寄せる。写すのは数字ではなく場面。

## 2. なぜこの仕様が要るか（実測された失敗）

PR⑥ のバナーは **1536×1024（3:2）** だった。幅は 1200 を超えるので **G1 の字面は通る。**
通したうえで切れた（`pr-banner-audit-2026-09-02.md` §2・実際に中央トリミングして確認済み）:

    1.91:1 に切られる面（OGP / X / Facebook / PR TIMES 一覧）
      → 上下 110px ずつ落ちる
      → 上端「PRESS RELEASE」バッジが消える
      → 下段の実績4枚が**上半分だけ残って切れる**

    1:1 に切られる面（一部のモバイル一覧・埋め込み）
      → 左右 256px ずつ落ちる
      → 見出しが「リが、／育ち続ける。」
      → 「76.4%」が「4%」

**「4%」は誤情報として表示される。**切れ方によっては、正しい数字が嘘になる。

> **⚠ ただし、バナーが PR⑥ の非乗車の原因だとは言っていない。**
> 非乗車の説明は S2（見出しの固有名詞ゼロ）で足りている
> （`pr-discover-strategy-2026-09-04.md` §3-1）。**ここは別に直すべき欠陥**であって、
> 「バナーを直せば乗る」ではない。**辻褄が合う説明を原因に格上げしない。**

## 3. 仕様

### 3-1. 寸法と比率

| 項目 | 値 | 出所 |
|---|---|---|
| **制作比率** | **1.91:1** | PR TIMES のメイン画像推奨（1200×630 以上・1.91:1）。SNS のリンクカードと一覧サムネイルに使われる |
| 推奨実寸 | **1920×1005** または 1536×804 | 幅 1200 超（Discover の大画像要件）を余裕で満たす |
| 最低幅 | 1200px | Discover の大きな画像の要件。`max-image-preview:large` は PR TIMES のページ側が持つ |
| 容量 | 5MB 以内 | PR TIMES の上限 |

### 3-2. セーフエリア（**ここが本体**）

    ┌─────────────────── 1.91:1（制作サイズそのもの）───────────────────┐
    │                                                                   │
    │            ┌──── 中央 1:1 ────┐                                   │
    │            │                  │  ← 見出し・主要な数字・製品名は    │
    │            │   ここに主要素    │     すべてこの正方形の内側に置く   │
    │            │                  │                                   │
    │            └──────────────────┘                                   │
    │  ← この帯に置いてよいのは背景と装飾だけ（切られても意味が変わらないもの）→ │
    └───────────────────────────────────────────────────────────────────┘

- **見出し・製品名・数字は、中央 1:1 の内側に完結させる**
- 帯の左右に置いてよいのは**背景と装飾だけ**
- **数字は分割されない置き方にする**（`76.4%` が `4%` になる形にしない）

### 3-3. 何を写すか —— G1 の後半「場面が写る」

**数字パネルは「場面」ではない。**

| 写す | 写さない |
|---|---|
| 実機の画面（**実在する文言で**） | 率・件数を並べたダッシュボード風のパネル |
| 生活の場面（キッチン・診察券・通勤） | 抽象的なループ図・アーキテクチャ図 |
| 行き先アプリの見分けがつくもの（リマインダー／カレンダー／Obsidian） | ロゴだけの並び |

**実機の画面を合成するなら、文言は実在のものにする。**
PR⑥ のバナーは端末画面が生成画像で、プレースホルダ「何か、思いついたことを書いてください」は
**アプリに存在しない文言**だった（実在は `compose.placeholder_speak_or_write` =
「話すか、思いついたことを書くだけ」）。かなキーボードの配列も iOS の実配列と違っていた。
**記者が実機と見比べる面**なので、ここは実物に寄せる。

## 4. 配信日時 —— **台帳の中で食い違っている。これを正とする**

    平日（月曜を第一候補）08:40〜09:00 JST

### 食い違いの内容

| 出所 | 言っていること |
|---|---|
| D-1 の G4 | 「平日の朝」だけ。**時刻の幅を持たない** |
| 追記A-3（2026-08-20） | 「時刻は**月曜〜火曜10〜11時**に固定して変数から外す」 |
| 実測（乗車2本） | ② 月曜 **08:51** ／ ③ 月曜 **08:42** |

**追記A-3 の 10〜11時は、乗車した2本のどちらとも違う帯を指している。**
A-3 の目的は「変数から外す」ことで、どの帯が良いかを主張してはいない。しかも
A-3 は **A-5（火元が Discover と確定した節）より前**に書かれていて、
乗車の機構が分かる前の記述である。

**したがって、固定するなら乗車した2本が入っている帯にする。**これは
「08:40〜09:00 が効くと分かったから」ではない ——**無料の変数を動かしたままにしないため。**

### 曜日と時刻について言えること／言えないこと

| | 実測 |
|---|---|
| 乗車した2本 | どちらも**月曜**・08:42 / 08:51 |
| 非乗車の4本 | 月曜（④08:38）・火曜（⑤08:32）・木曜（⑥08:03）・金曜（①17:18） |
| **言えるか** | **言えない。**月曜でも非乗車がある（④）。朝の5本は時刻順と当落順が完全に一致するが、**S1/S2 の必要条件とも完全に一致していて、n=6 では分離できない**（`pr-discover-strategy-2026-09-04.md` §5） |

**時刻を因果として扱わない。**③（08:42・通算 10,434PV）と ④（08:38・通算 469PV）は
**4分差で22倍**で、4分が22倍を作る機構が説明できない。

## 5. 配信前の検算（**目視で1回、必ず切る**）

1. 制作画像を **1.91:1** と **1:1** で中央トリミングする
2. **両方で意味が通るか**を目で見る —— 見出しが読めるか・数字が割れていないか・製品名が残っているか
3. 通らなければ、**再生成する**（左右に同色の地を足す拡張は、内容は欠けないが無地の帯が出る次善策）

    # 例: ImageMagick で中央トリミングして目視する
    magick banner.png -gravity center -crop 1920x1005+0+0 +repage /tmp/check-1.91.png
    magick banner.png -gravity center -crop 1005x1005+0+0 +repage /tmp/check-1x1.png

**G1 を 0/1 で埋めるのは、この3手を踏んでから。**幅の数字だけで 1 を付けない。
