# 既存の会社サービス1件の実照合

2026-09-09、Codexが認証済み管理画面から法人の会計サービスの契約・請求・
領収書・カード明細・既存仕訳・現在の役務提供を読み、1件の照合を実行した。
結果は「現在時点の照合完了・例外あり」。実額、会社・カード・書類の識別情報、
認証情報、原本PDFはこの公開リポジトリに置かない。

## 実際に突き合わせたもの

契約中の購入済み契約と請求書は、供給者自身の契約番号で直接接続していた。
プラン、数量、年額、対象期間を比較した。領収書は請求番号と決済番号を持ち、
請求書・領収書・会計にあるカード明細の金額と日付が一致した。円建てのため
為替換算は不要だった。会計の全処理状態で同額を検索した結果は1件で、
支払先も一致した。その既存仕訳には会社の会計サービス使用料と記されていた。

同じ法人・契約プランの会計サービスから実際の明細と仕訳を取得できた。
これは前払期間中の現在のサービス提供の確認であり、年間すべての提供完了や
過去の連続稼働を証明するものではない。

供給者の画面にあるダウンロードリンクから原本領収書PDFを取得し、全1ページを
抽出・描画・目視した。年払い、対象期間、開始日の領収、請求・決済番号、
小計・税・総額を原本に照合した。書面の所在とSHA-256を非公開の実行記録に
残し、転記JSONのハッシュを原本ハッシュとして使わない。

実PDFと観測値に対する28項目の照合は成功した。公開用の検証結果と原本・観測
記録のハッシュは `data/service-reconciliation-execution.json` にある。
CIは公開台帳と証跡の構造・整合を検査する。認証済み原本の再取得や税務承認を
CIの成功に含めない。

## 例外と加算範囲

年払いの未経過分は前払継続中として残す。領収書の登録番号と既存仕訳の税区分は
要レビューとして記録し、税務判断や仕訳修正を行っていない。カード明細との
一致は日付・支払先・円建て金額によるもので、請求書の外部キー、カード発行会社
原本、銀行引落の突合完了を主張しない。会社の既存費用処理を読み取った範囲で、
SimpleMemo単体への配賦比率や月次決算は認定しない。

AIが行ったのは照合と例外の記録である。既存の手動仕訳や支払いをAIが実行した
ことにはしない。旧Anthropic取引に残る不足はこの別取引によって解消されない。

この実行1件により、既存task125だけを `nobody` から `ai_executes_gated` に
移す。常設の自動取得・全取引照合サービスが完成したとは書かない。タスク名・
一覧・計算式は維持し、分子と実施中分母をそれぞれ1増やす。AI実行率は
156/179＝87.2%、総合自動化率は156/199＝78.4%となる。

PR TIMES下書きは前回の検証済み保存値から3ポイント改善したときに同期する。
今回は未到達のため更新しない。99.9%未満で配信・予約は行わない。

## 出荷と撤回

公開前に台帳・権限・履歴・表示の整合とSEO Validationを検査する。検証した
コミットだけを既存の自動マージでmainへ送り、Pagesの本番ビルドとHTTP表示を
確認する。照合証拠の不一致、過大加算、機密情報の混入があれば当該変更を
revertし、155/178の直前状態へ戻す。会計データやアプリ配信への変更は含まない。
