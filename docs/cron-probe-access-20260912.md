# 9月12日の停止通知とcron監視の診断

23:00 JSTの経路停止通知は、PR #1270の `ai90-act-stop-20260912` 訓練が
原因。停止の復元は既存PR #1271で進行しており、この修正では停止設定を触らない。

オーナー待ちのIssue #1193は、9月9日のAI Visibility Probe
[定期実行34291656440](https://github.com/simplememofast/simplememo/actions/runs/34291656440)
の失敗を追跡している。5問ともClaude Codeの組織側のサブスクリプション利用制限が
返り、有効回答0件・実費0ドルだった。次の定期実行は週次なので、3日経過は
3回再試行したことを意味しない。

9月12日23:10 JSTに現行main・既存資格情報・既存予算ゲートで
[手動確認34698479441](https://github.com/simplememofast/simplememo/actions/runs/34698479441)
を行い、同じ制限・有効回答0件・実費0ドルを確認した。
トークンの失効や単なる使用量上限と断定できる証拠はない。

CLIはこの失敗にも `subtype=success` を返すため、従来の保存結果は
`status=unverified` と `error=success` が同居していた。今回、未検証の結果で
確認した組織制限を `subscription_access_disabled` として記録し、検索未検証・
プロセス失敗・モデルエラーと区別する。正常な検索回答に同じ文言が含まれるだけなら
失敗にはしない。CIログには質問IDごとの診断コードを出す。

対応待ちの台帳・日報用の表示にも、組織のClaude Code利用許可を確認するという
具体的な作業と確認runを記載した。Issueは未解決のまま維持する。
組織管理者による利用許可の確認・必要な変更後に再検証する。別の課金経路や
資格情報は追加しない。既存の復旧条件は、追跡中の全workflowで最新定期実行が
成功すること。手動成功だけで閉じる、過去24時間から消えたら閉じる、といった
条件への緩和は行わない。
