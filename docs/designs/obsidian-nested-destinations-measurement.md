# Obsidian階層保存の事前評価計画

宣言日: 2026-09-06。対象は `folder_pick_ux`。実装中の機能であり、出荷・改善達成の記録ではない。

## 観測と分母

公開した版・ビルドを出荷記録に固定し、最初の本番提供時刻から28日間をUTCで集計する。評価日は2026-10-18。そこまでに28日間がそろわなければ `undecidable` とし、結果を見て観測期間を延ばさない。再出荷や再評価は別の事前宣言を必要とする。

主指標は、受付時に固定した階層保存先への実ファイル書き込みについて、`obsidian_append_success / (obsidian_append_success + obsidian_append_failed)`。`method=file`、`write_stage=vault`、`obsidian_layout=nested` と対象の公開版・ビルドで絞る。同じ受付からの再試行は別の試行として数える。イベントの配送再送はevent_idで除重する。これは試行結果率であり、ユニークメモの最終保存率ではない。

件数に加え、成功・失敗それぞれのinstall_id数、両方を経験したinstall_id数を示す。計測に同意しイベントが届いたインストールだけを対象とするため、全利用者への外挿はしない。本文、相対パス、フォルダ名、ブックマークをイベントへ含めない。

分母から漏れるキュー読取・復号・受付永続化の失敗は、ファイル書き込み成功として扱わない。これらを別の診断で確認できない場合、主指標だけで正常性や最終保存の保証を主張しない。

## 比較と判定

既存の読み取り専用D1集計では、2026-08-09 00:00 UTC以上、2026-09-06 00:00 UTC未満に成功1,592件・失敗48件、合計1,640件、97.07%。成功は138インストール、失敗は15インストールで集合は重なる。階層属性のない過去データのため、この値は参考値に限る。

同じ公開版・期間の `obsidian_layout=flat` を観測上の比較対象とする。両群とも200試行・20インストール未満なら `undecidable`。群の利用者は無作為割付ではない。階層利用の自己選択と反復試行による相関があるので、イベントを独立な標本とした有意差や因果効果は報告しない。

十分な露出がある場合、階層群の成功率が参考値97.07%以上かつ同期間の直下群より1ポイントを超えて悪化していなければ、事前に定めた運用品質基準を満たしたとして `success`。その基準を満たさなければ `failure`。ここでいう成功は基準達成であり、改善の因果証明ではない。必要な属性や対象版が欠け、正しい分母を復元できなければ `measurement_failed`。

補助指標は、保存先設定完了イベント `obsidian_destination_changed` の発生後24時間以内に同イベントを再度記録したインストール数 / 最初の設定完了を記録したインストール数。観測末尾24時間の初回設定は分母から外す。固定ノート・日次配置・フォルダ選択を対象とし、再設定が修復だったか好みの変更だったかは推測しない。このイベントはまだ未接続で、公開前にiOS・APIへ実装し確認する。

## 公開を止める条件

データ消失、二重追記、選択Vault外への書き込みが確認されたら、件数にかかわらず公開拡大を止める。50試行・10インストール以上で階層群の失敗率が5%を超えた場合も拡大を停止し調査する。保留キューは維持し、別の保存先への無断再送や破棄を撤回手段にしない。

## 未完了の公開ゲート

- iOS・APIの属性許可とイベント発火を接続し、実際の受信まで検証する。
- 階層属性は受付時の保存先から導出し、後の設定変更で付け替えない。
- 対象版・ビルドと提供開始時刻を出荷時に記録する。
- 実機のFile Providerと画面の受入条件を満たす。
- 評価時に集計SQL・実測値・判定と学びを保存する。

この宣言だけで開発完了、出荷完了、改善サイクル完走、AI実行率の上昇とは扱わない。
