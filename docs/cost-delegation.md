# AI開発・運用費の判断委任

2026-09-07、所有者は過去5件の判断依頼をいずれも「AIで対応可能」と評価し、
「想定の5倍超えそうな時はエスカレほしいな、でも基本ai ok」と指示した。
対象はAI開発・運用費の判断。広告、契約、月次総額の増額への包括承認ではない。

作業開始前に想定費用と根拠、run ID、記録時刻を保存する。
この想定は途中で上書きしない。開始時刻も実際の実行記録から照合する。
追加の有料実行・再試行・方針変更の前に、既に使った額を含む総費用見込みを更新する。

```sh
node scripts/autopilot-budget.mjs --check-cost-forecast --expected-usd 10 --projected-usd 49
```

上記は使い方の例で、実行証拠ではない。5倍ちょうどは範囲内、5倍を超える見込みは
exit 1となる。後者は追加支出前に金額・増加理由・続行案を所有者へ上げる。
想定や見込みが不明なら検査は失敗する。まずAIが取得を試み、取得不能を0ドルや範囲内としない。
SDKの既存支出閾値、月次総額・種別枠、品質ゲートは維持する。
このCLIは呼出時の見込み検査であり、進行中の全請求を監視する仕組みではない。
Mac実行手順で追加実行前に呼ぶ。実費が観測できないCodexを金額で強制停止できるとは主張しない。

1回上限を超えたrunの費用をAIがレビューする場合、実費台帳の当該行に開始前の
`cost_expectation` が必要。実費の初回追記時に `--expectation-file <保存済みJSON>` で渡す。
形式は `run_id`、`expected_usd`、`recorded_at`、`started_at`、`evidence`。
根拠には開始前に保存したコミットや記録への参照を含め、時刻は実行証拠と照合する。
CLIの時刻整合検査だけでは根拠の真正性を保証しない。
再取り込みや `--enrich-missing` では想定を差し替えない。過去runの想定を後付けしない。

```sh
node scripts/autopilot-budget.mjs --ack-overrun RUN_ID --by ai --projected-usd TOTAL_FORECAST --why '開始前想定と実費、残作業を照合した判断根拠'
```

5倍超・不明・他runの想定・開始後の想定・実費を下回る見込みは拒否する。
所有者レビューは既存の `by: owner`、委任によるAIレビューは `by: ai` として区別する。
AI担当への分類は実行開始・完了を意味しない。

今回の5件の評価は `owner_needed=false` と人の回答を保存した。
月次レビュー依頼そのものへの評価であり、未追認20件の中身を追認した記録ではない。
過去の実行を「人手なしだった」と書き換えず、UMR/RAの実行証拠も変更しない。
