# 全サイト観測と記事別事前計測の共存方針

作成日: 2026-09-15。状態: **レビュー用の方針案。実行ゲートの変更・既存実験の移行は未実施。**
依頼: 「全サイト実験と記事別の事前計測を共存させるルールの整理」。

## 結論

全サイトの推移を読む**観測**と、変更の効果を評価する**介入実験**を分ける。
観測の対象が全サイトであることだけを理由に、すべての記事実験を永久に止める設計にはしない。
一方、「観測」と名前を変えただけで既存実験の保護を解除しない。

記事実験を自動で許可するのは、次の両方を満たす場合に限る。

1. 全サイト側が、記録された方針変更を経て非排他的な観測として明示されている。
2. 記事側が、対象範囲・実測baseline・比較方法・母数・評価日・停止条件を実装前に固定し、別の有効な介入実験と重ならない。

**指標名が違うだけでは共存を認めない。** 記事変更は検索流入、ブランド検索、回遊、獲得に同時に影響し得る。単純な前後比較で各変更の単独因果を主張しない。

C15の拒否はこの契約どおり。エラー修正としてglobal判定を削除する対象ではない。
`frozen`の実験や有効なfollow-upも保護対象で、評価日が来ただけでは自動解除しない。

## 共存の判定表

| 全サイト側 | 記事側の作業 | 判定と条件 |
|---|---|---|
| 既存の排他的実験が有効 | データを読むだけ | 許可。新しい介入や成果認定を作らない |
| 既存の排他的実験が有効 | 記事別の介入を新規登録 | 現行どおり停止。移行完了または既存実験の正式終了を待つ |
| 明示移行済みの非排他的観測 | 記事別の介入実験 | 条件付き許可。記事側の事前契約と干渉確認が必要 |
| 全サイトに適用する介入実験 | 同じ期間の関連する記事介入 | 原則停止。独立した割付・対照群など、分離可能な設計を事前レビューした場合だけ個別判断 |
| 任意 | 同じ記事・共有部品・同じ評価対象へ二つの介入 | 後発を停止。URLや指標を変えただけでは独立としない |
| 任意 | 明示依頼による公開や事実訂正 | 実施権限を確認し、影響範囲と公開時刻を記録。実験ゲート通過や自律運転成功へ読み替えない。既存の停止条件に該当するなら、その実験側も正式に処理する |

非排他的観測は「サイト全体がどう動いたか」を継続して読むためのもの。
その増減から、一つの記事やブランド統一施策の単独効果を認定しない。
観測への移行が許すのは重複判定上の共存であり、予算・品質・権限・対象ページの別実験・価値契約の免除ではない。

## 記事別の事前計測で固定するもの

- **変更の全範囲:** 記事URLだけでなく、ハブへのリンク、既存関連記事、共通CTA、テンプレートなど変更対象を列挙する。新しい記事だけを申告して既存ページの干渉を隠さない。
- **指標と出典:** GSC、GA4、AI観測などを混ぜず、期間・タイムゾーン・フィルター・集計単位・原本ハッシュを保持する。
- **比較設計:** 対照群または前後比較を明示。前後比較なら同時変更、季節性、検索更新等の限界も固定する。
- **母数と判断:** 必要母数、評価日、データ遅延、判断基準、ガードレール、停止条件を実装前に固定する。
- **再確認:** 選定時と実装確定時に、元台帳の最新状態と全変更範囲を照合する。後から実験が入ったら古い許可を使わない。

新規URLには変更前のページ実測が存在しない。欠測を0としてCTRの改善実験を作らない。
新規記事は公開後の初期値を観測として蓄積し、最初の改善介入の前にbaselineを固定する方法、または実際に取得できる別の事前指標・比較群を用いる方法を選ぶ。
後者も関連性と既存の適格性基準を満たす必要があり、都合のよい別指標へ置き換えて公開を通す用途には使わない。
既存の事前baseline要件を満たせない新規記事を、自律実験として通す変更は本案に含めない。

## 既存の全サイト記録を移行する場合

推奨は、ブランド・回遊の全サイト集計を今後も継続しつつ、将来の運用を非排他的な観測として明示すること。
ただし現在の停止条件を含む運用契約が変わるため、次の記録と検証をそろえた別の実装変更として扱う。

1. 元の実験ID、開始日、評価日、baseline、source、仮説、停止条件、既知の交絡をそのまま保存する。過去を観測だったことに書き換えない。
2. 移行元ID、決定者、決定日、発効時刻、変更前後の保護、理由を追記する。過去の所有期間へ遡って適用しない。
3. 既存の実験台帳内で、将来期間の役割・排他性・許容される結論を型として表す。二重の実験台帳や別の収集スケジュールを作らない。未指定の古い記録は排他的扱いを保つ。
4. 元の評価日を残して評価責任を維持する。移行前後と同時変更を区別し、分離できない結果を成功と断定しない。母数不足、原本欠測、因果分離不能を別の理由として記録する。
5. 選定、計測準備、実装確定、follow-up、重複監査が同じ判定を使うように変更する。一箇所だけ許可する抜け道を作らない。

現行スキーマは`planned/running/frozen/evaluated/cancelled`でライフサイクルを管理している。
未実装の`observation_only`等を今すぐ台帳へ書き足して運用可能とみなさない。
`evaluated`にするのは実際の評価完了時だけであり、ロック解除を目的に完了扱いにしない。

## 実装時の受け入れ条件

- 明示移行済みの非排他的観測と、条件を満たす記事実験は共存できる。
- 未移行global、frozen、稼働中follow-up、同記事、共通変更部品の競合は拒否される。
- 不明・壊れたスコープは許可にならない。サイト外の対象も消さない。
- 指標名の違い、候補名・URL末尾・routeの変更で拒否を回避できない。
- 移行の発効前や、選定後に所有状態が変わった場合は誤って許可されない。
- baseline欠測、母数不足、計測失敗を0または成功へ変換しない。
- 元の履歴・日付・指標定義・過去の失敗は不変。両方の成果台帳に同じ出荷や効果を二重計上しない。
- 自律運転での自然起動・選定・公開・後日の評価を別々に検証する。単体テスト成功だけで無人運転再開を宣言しない。
