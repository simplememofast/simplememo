# GitHub・Cloudflare障害時の代替の訂正

<!-- fact-check: internal -->

2026-09-07、定期運転をCodexの独立タスクに移した後の依存を確認した。
GitHubの代替として登録されていたCCRは停止済みで、Codexの主系・補完も
当日占有、PR検証、マージ、Git連携による出荷にはGitHubを使う。
起動する基盤が別であることは、GitHubが利用不能でも出荷できる証拠にならない。

旧 `dual_lane` 検査は、手順書・ワークフローの存在と、緊急停止台帳の
`ccr-` で始まるキーを数えるだけだった。予約の有効性も、GitHubへの依存も
確かめていなかったため削除した。旧probeを再び登録しても通らない回帰検査を追加した。

ベンダー台帳ではGitHubの代替を「未検証」とした。APIに到達できなければ
処理を止める検査と、外部接続が制限された場合の縮退検査は継続する。
実サービスの障害や復旧が発生したという記録は作らず、自律スコアも変更しない。

根拠は `docs/obsidian/AUTOPILOT_RUNBOOK.md` 冒頭の現行運転経路、
`scripts/check-degradation.mjs`、`scripts/autopilot-gate.mjs`。
将来代替を登録するには、障害対象に依存しない経路と、その対象を利用できない
条件で必要な処理が完了する実証が必要になる。

同じ確認で、Cloudflareの代替に数えられていた端末側Outboxも縮退手段へ訂正した。
Outboxは未送信データを保持するが、Relay API・サイト・サーバー保存を提供しない。
既存のdevice_outbox検査は維持し、端末への保管とバックエンドの代替を区別する。
この検査が確認するのはファイルの存在であり、実機上の復旧完了の証明ではない。
