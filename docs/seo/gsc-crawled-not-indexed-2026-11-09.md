### 2. 誤訳の訂正（6言語・11ページ・737単位）

方法:

- 対象ページの翻訳単位（原文・現在の訳・ページ内の位置）を全件取り出した。11ページで計1,721単位。
- 言語ごとに「誤りを見つけて直す担当」と「その訂正を反証する担当」の2段で判定した（前回 #2091 と同じ形）。
- 直すのは、意味の誤り・製品名やプラグイン名の翻訳・誤った用語・誤読される文法・検索結果に出る部分の主題のずれだけ。
  文体の好みでは直さず、原文に無い主張は足していない。

- 却下の主な理由:
  - 生成器が日付を自動で整形するため、提案どおりだとかえって悪くなるもの（反証担当が実行して確認）

  - 文体の好みにすぎないもの

- 機械的な追加検査（原文に無い数字の混入0件、製品名の欠落はすべて意図した訳語化）も行った。
- 検索結果に出る単位（title・h1・meta・構造化データ）の訂正は、全件を人の目（このセッション）で原文と照合した。

## 翻訳以外で見つかった問題（この PR では直していない）

レビューで次の問題が見つかった。どれも生成器やテンプレートの全言語にかかわるため、別の判断にする。

1. **インライン要素の境目で単語の間の空白が落ちる**（例「Artikel iniContoh」）。空白で区切る言語（en/es/pt-BR/id/tr）の生成ページで発生。
2. **構造化データの発行者名が翻訳される**（例「Simple Memo - 用於Obsidian」）。`alternateName` には日本語のカナが残る。
3. **`og:site_name` が日本語のまま**（「Obsidian連携シンプルメモ」）。
4. **CTA の App Store リンクが日本のストア（`/jp/`）向けで、価格が円表記。**
5. **コード例・配布テンプレート・フォルダ名が日本語のまま**で、その言語の読者が手順を再現しにくい。
6. ko の例文ブロックで改行が失われ、1行の長文になる（`white-space: pre-line` の扱い）。

## 意図的にやっていないこと

- **生ファイルを robots.txt でブロックすること。** 取得を止めると Google は noindex を読めない。
  リンクされた URL は「robots.txt によりブロックされました」へ移るだけで、検索から外れることは保証されない（Google: noindex の説明）。
- **動画ファイルへの noindex。** 動画ガイドラインに反する。
- **登録されなかった多言語ページの noindex・削除・統合。** 10-14 のオーナー判断（index のまま直す）と、上の判定データに従った。
  - Captio・LINE Keep・日報など地域との関連が薄い話題を追加で noindex にするかは、表示の実績を見て別に判断する。
  - ko・zh-Hant の Captio 記事は表示0。es は16、en は20ある。
- **日本語 `/vs/apple-notes/` の改題。**
