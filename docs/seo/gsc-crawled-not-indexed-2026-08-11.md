  一度も再クロールされていない**。GSCは前回クロール時の判定を保持し続ける。

  この期間で再クロールし切れる見込みはなく、**同じ状態でもう一度
  「検証」を押しても、また落ちる。**

→ 変種URLについては追加の実装余地がない。301は正しく、レポートの

## 副次的な事象の追跡調査（2026-08-11 追記・前回の記載を訂正）

前回このセクションに書いた2点を実測したところ、**どちらも記載が誤っていた**。

### 訂正1: 「meta description 欠落 17ページ」は誤り

欠落しているのは `compose.html` と `verify.html` の**2つだけ**で、どちらも
`_headers` で `X-Robots-Tag: noindex, nofollow` を付けた実務ページ。
説明文が無いのは意図通りで、直すべき箇所は無い。

誤検知の原因は調査側の正規表現。`/en/` 配下は属性順が逆の
`<meta content="…" name="description"/>` で書かれており、
`name="description"` が先に来る前提の検索では拾えなかった。
`scripts/seo-check.js` の `getMetaContent()` は属性順に依存しない実装なので
最初から正しく通っていた（CIが 0 errors だったのはそのため。
欠落は warning ではなく **error** 判定なので、本当に欠けていれば
CIは落ちていた）。

### 訂正2: 二言語DOMは「重複コンテンツ」ではない

前回は別URLとの重複であるかのように読める書き方をしたが、実測すると
二言語DOMを持つ159ページのうち **`/en/` の対URLが実在するのは1ページだけ**。
残り158ページでは inline の英語が**唯一の英語版**であり、剥がすと
英語コンテンツそのものが消える。

つまりこれは単一URLでの二言語配信であって、Googleが重複判定する
「同じ内容が2つのURLにある」状態ではない。撤去するなら158ページ分の
`/en/` を新設する必要があり、インデックス問題の対策ではなく
別立ての大規模プロジェクトになる。**今回は着手しない**。

## 本コミットで実施した修正

### hreflang チェックを「対URLが実在するときだけ」警告するよう変更

`scripts/seo-check.js` の hreflang 判定は無条件で、240ページ中**163ページ**を
警告していた。hreflang は「同じ文書が別アドレスにもある」と宣言するタグなので、
対が無いページには宣言すべきアドレスが存在せず、**この163件は永久に消せない**。

対が実在する71ページは既に ja / en / x-default の3点セットを正しく持っており、
この検査が本来捕まえるべき「対があるのに hreflang が無い」ケースは
実際にはゼロだった。つまり出力は全件ノイズで、本当の警告を埋めていた。

対URLの実在を条件に変更した結果、埋もれていた `[LANG]` 警告5件が浮上した。

### 浮上した5ページの残骸マークアップを除去

`/`、`/obsidian/`、`/ai-tags/`、`/apple-watch/`、`/blog/best-memo-apps-2026`
の5ページに、旧二言語DOM方式の名残である `data-lang` スパンが2〜5組ずつ
残っていた。

この5ページは既に**リンク型**の言語切替（`<a href="/en/obsidian/">`）に
移行済みで、対応する `/en/` ページも全て実在する。切替は遷移で行われるため
`lang.js` は不要であり、**壊れてはいない**。残っていた `data-lang="en"` 側は
CSSで隠されたまま何も表示に切り替えないため、永久に見えない死んだテキスト
だった。

英語版は各 `/en/` ページに存在するので、除去による情報の損失は無い。
`data-lang="ja"` 側は素のテキストにアンラップした。

結果、`seo-check` は **0 errors / 0 warnings** になった（従来は163警告）。
