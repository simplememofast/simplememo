## 巡回の効率（サイトマップ・lastmod・条件付き取得・生ファイル）

- **サイトマップに欠陥は無い。**掲載2,387件は index 可能な公開 HTML の全件で、検出509件も全件載っている。
  hreflang 26,050本のうち、サイトマップ外を指すものは0本。lastmod は CI（`generate_sitemap.py --check`）が毎回、内容の履歴と照合している。
- **lastmod は、全ページに効くテンプレートの変更で一斉に動く。**日本語250件中178件が 2026-10-17（#2100 の著者名の一括変更、2,496ファイル）。

  オリジンの ETag を外す（Cloudflare Docs「Using ETag Headers」）。Googlebot は、変わっていない HTML も毎回全体を取り直している。
  応答は速くエラーも無いので、約2,500ページの規模で巡回の上限になっている証拠は無いが、無駄ではある。`_headers` の「304 が返る」という説明も実態と違っていたので、注記した。

     書き換えの起きない `Accept: */*` でも ETag は無い。Functions は外していない（配布ファイルは Functions を通っても ETag が残る）。
   - Cloudflare Docs（Using ETag Headers）では、Automatic HTTPS Rewrites・Replace insecure JavaScript libraries・Email Obfuscation・Rocket Loader の
     どれかが有効だと、オリジンの ETag を外す（圧縮のときは弱い ETag に変え、それも外す）。このゾーンでは前の2つが有効
     （11-13 に API で読んだ。Email Obfuscation・Rocket Loader は無効。使っていない Server-side Excludes も有効）。
   - 取り戻すには、自動挿入をやめる（Cloudflare 側の訪問計測を手放すか、全ページに手動のスニペットを入れて約2,400ページの lastmod を動かす）うえに、
     この2つ（と Server-side Excludes）を外す必要がある。この規模で巡回の上限に当たっている証拠は無く（平均168 ms・ホストの状態は問題なし）、
     得るものが小さいので変えない。全ページを作り直す一括の公開（下の3）をするときに、手動のスニペットを同梱できるなら、そのときに改めて決める。
     ゾーンの設定を変える場合は、オーナーが操作する（Automatic HTTPS Rewrites は SSL/TLS の設定）。
3. **全ページに効く変更の出し方 → 1回のデプロイにまとめ、急がないものは見送る。**次のまとまりは12月上旬、次の「ページのインデックス登録」の一覧
