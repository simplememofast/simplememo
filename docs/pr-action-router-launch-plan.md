## 3. X / note でのプリテスト（**配信の前**）

追記D-3'' の手順 —— **候補を混ぜて使い、ユーザーが復唱した言い回しを採る。**
復唱されなかった言葉は、記者にも復唱されない。

### 3-1. ⚠ 台帳どうしが衝突している。**平語だけをテストする**

| 出所 | 言っていること |
|---|---|
| 追記D-3'' | 機能名候補に **「話し分け」（造語で所有可能）**「声わけ」を挙げている |
| `docs/story-seeds.md` §0 | **「造語を作らない。新しい呼び名を発明して概念を売らない」**（note / X / Reddit / IH の全媒体） |

**媒体側の規律が勝つ。**プリテストする候補は**平語だけ**に絞る:

    ○ おまかせ仕分け      「カメラのおまかせモード」「メール自動振り分け」の隣。説明ゼロ
    ○ 言うだけ仕分け      「置くだけ充電」系の「だけ」構文
    ✕ 話し分け / 声わけ   造語。story-seeds §0 に当たる

**命名で検索需要を作った実績（`captio式` / `obsidian連携`）も、勝ったのは英語ジャーゴンではなく
「◯◯式」「◯◯連携」という平語構文**だった（追記D-3'）。ここは実績と規律が一致している。

### 3-2. 何を見るか

1. 保存・引用の反応差
2. **引用RT・リプで、ユーザーがどの言葉を復唱するか**（← これが決定打）

### 3-3. 乗せる先

- **X** —— `x-engagement-simplememofast`（昼／夜の既存 Routine）
- **note** —— `note-simplememo-3days`。ネタは `docs/story-seeds.md` から
- **結果は実験台帳に記録する**（`growth/experiments/experiments.json`）

### 3-4. ⚠ プリテストで機能を予告しない

**「近日提供」を書かない。**テストするのは**言い回し**であって、機能の告知ではない。
予告してしまうと、配信日の S1（初出性）を自分で削ることになる ——
**ニュース面から見て「もう聞いた話」になる。**言い回しは、既存の機能や一般論の文脈で使う。
