# 失敗した実行の費用種別を取りこぼさない

2026-09-06、主系run [33996430959](https://github.com/simplememofast/simplememo/actions/runs/33996430959) の実費は $19.600872199999998、251ターン、結果failedとして記帳されていた。しかし `task_kind` が欠け、articleの1回上限 $10 と照合されていなかった。

旧同期処理は、運転台帳のlane/actionから種別を推定できるときだけ欠測を再取得していた。失敗した回にはlane/actionが無いため、「同期済み」と判定してAPI読取0回で見送っていた。00:21:38Zに実在するこの1件だけを切り出して再現した。本番台帳への手動補完はしていない。

## 変更

- 記帳済みでも実行種別が欠けていれば同期を閉じず、主系ジョブを読み直す。
- 運転結果のlane/actionを種別へ変換しない。モデル着手前に成功した「タスク種別とモデルの振り分け」stepの実noticeだけを読む。
- 一意なstep、成功状態、順序、開始・終了時刻を照合する。GitHubのstep時刻は秒単位なので、終了秒の小数部分は含めるが、モデルの開始以降は含めない。
- コマンドの表示、モデル出力、未知の種別、重複したnotice、矛盾するnoticeは証跡にしない。確認できない種別は未確認のまま再取得対象に残す。
- 種別の取得元としてrun ID、job ID、step番号、ログの時刻を保存する。これはAPIで読んだ出典の記録であり、第三者署名ではない。
- 既存費用はrun ID単位で、同じrunの再実行を区別できないため、jobのrun ID一致と初回実行（run_attempt=1）を要求する。再実行や実行回不明では別回の金額へ種別を補わず、未確認のまま残す。
- 既存の精密な実費・日付・経路・ターン数・結果・レビューを上書きしない。種別と出典の補完は一度だけ行う。
- 既存の実費がある回は、後日ログが読めなくても「実費が存在しない」の除外へ戻さない。
- 結果台帳にまだ無い実行の観測も、金額を回収しただけでは捨てず、種別の欠測が解消するまで保持する。
- 直近のAPI一覧や保存観測が無くなっていても、既存の実費行から種別の欠測を拾い直す。

新規の費用を0円と推測すること、既存の種別を再分類すること、超過レビューを自動承認することはしない。予算額・配点・集計式は変えていない。`usd_per_shipped`のv10は費用台帳の出典保存と検査の変更を記録するもので、指標の計算式の変更ではない。
