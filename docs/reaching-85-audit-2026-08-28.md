# 85.4% に到達できるか — 39件を「誰が・いつ動かせるか」で仕分けた

`docs/pr-banner-audit-2026-08-28.md` で「実装で埋まりうる39件を全部やっても
170/199 = 85.4%」と書いた。**その39件を1件ずつ当たった記録。**

## 結論を先に

**A（AIが今日できる）は 0件。**

| | 件数 | |
|---|---:|---|
| A AIが今日できる | **0** | |
| B オーナーの操作が要る | 17 | 権限付与・外部接続・判断・Mac |
| C 時間・事象を待つ | 9 | 28日窓・母数・初回昇格・返金の到来 |
| D コードでは動かない | 6 | アナログ5＋対象0件のQA1 |
| E **人に残すべき** | 7 | 下記 |

**そして 85.4% を目指すと、バナー自身の主張を壊す。**

E の7件にはこれが含まれる:

- ④ **App Review への提出**
- ④ **App Store への公開（審査通過後）**

バナーは `HUMAN APPROVAL / 公開・価格・広告・契約 人が承認` と書いてある。
**この2件をAIに渡すと、その一文が嘘になる。**85.4% はその2件を渡した前提の数字。

残る E も渡すべきではない:

- ⑬ 危機対応（個人情報事故・法的請求・重大障害・炎上）… 過去に決定済み
- ④ 本番で停止機構を実際に通す（訓練）… 過去に決定済み。AIが一度越えた行
- ④ Remote Feature Flag と緊急Kill Switch … kill を叩くのは人
- ③ SNS投稿（X日本語）… **Xアカウントが1回BANされた後**の停止。再開判断は人
- ⑨ オンボーディング改善（課金導線）… お金に近接

## E と D を人に残したままの上限

    131 + B(17) + C(9) = 157 / 199 = 78.9%

**これが「境界を壊さずに到達できる天井」。**しかもそこに届くには、
オーナー操作17件が全部済み、かつ時間待ち9件が全部解けている必要がある。

数日で動くのは C のうち初回昇格（8/29以降）と、B のうちオーナーが実際に
手を動かしたぶんだけ。**現実的には数日で 66〜70% 程度。**

## この監査の意味

「実装で埋まりうる39件」の *implementable* は**ブロッカーの分類名**であって、
「いま実装できる」という意味ではなかった。1件ずつ当たったら A が 0 件だった。

同じことを 8/28 に一度やっている（`docs/implementable-27-audit-2026-08-28.md`・
未着手27件のうちこの環境で完遂できたのは1件）。**分類名を能力の見積もりに
使うと、2回同じ結論に着く。**

## 提案

**目標を 85.4% から 78.9% へ置き換える。**それが境界を壊さない天井で、
到達には B の17件が要る。B は AI では動かないので、**数字はオーナーの
操作量で決まる** —— 実装量では決まらない。

バナーに載せる数字は、いま実測の 65.8% にする。台帳の規約は
「4つの率を必ず並べて出す」であって、低い数字を隠さなければ高い数字も出せる:

> 出荷物はすべてAIが書いている（100%）。運営業務全体で見ると、まだ65.8%

**この形なら、数日後に数字が動いても嘘にならない。**
