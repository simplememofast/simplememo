## 1. なぜこの弾か（1段落）

PR⑥（2026-09-03・D-SCORE 85）は Discover に乗らなかった。**採点が高かったのに落ちた**のではなく、
**採点した見出しと配信された見出しが別物**で、配信物を採り直すと45点だった。
そこから出た必要条件は2つで、**合計点では代替できない**:

    S1（Googleにとっての初出性）  >= 20
    S2（見出しの固有名詞の関心圏）>= 10

**台帳にある弾のうち、この2つを余裕で満たすのはこの弾だけ**（S1 20 / S2 20）。
乗車した2本（Obsidian連携 提供開始・Apple Watch初対応）と**同じ形**をしている ——
「**大きな固有名詞 × 提供開始/初対応**」。

## 2. 見出し（確定稿ではない。候補と、選び方）

### 型

    〈生活の場面名詞〉は〈国民級の固有名詞〉へ —— 〈アプリ名〉、〈ニュース動詞〉

この型を守るだけで S2（固有名詞）と S3（生活名詞）が同時に埋まる。

### 候補

**A（本命）**

    「明日、牛乳」はリマインダーへ。「金曜15時、歯医者」はカレンダーへ
    ——Obsidian連携シンプルメモ、話すだけの仕分けを提供開始

**B（動詞を前に出す）**

    言ったら、鳴る。——Obsidian連携シンプルメモ、話した用事をリマインダーとカレンダーへ
    自動で振り分ける機能を提供開始

**C（Obsidian を主語に残す）**

    思いつきはObsidianへ、用事はリマインダーへ、予定はカレンダーへ
    ——Obsidian連携シンプルメモ、話すだけの仕分けを提供開始

## 4. 本文に必ず書くこと

### 4-1. できることと、できないこと（同じ節に並べる）

PR⑥ で唯一よく効いた設計は「**できていないことを表で出す**」だった。それは残す。

| | 状態 |
|---|---|
| 話した内容から行き先の候補を出す | Level 1（提案）。**ユーザーが選ぶ** |
| 選んだらリマインダー／カレンダーへ入る | Level 2（ワンタップ） |
| 思いつきは今までどおり Obsidian へ | 変わらない |
| 完了状態が Obsidian へ戻る | **結果整合**。iOS は常駐できないので、アプリ起動時／バックグラウンド更新時に突き合わせる。**「即時反映」とは書かない** |
| 行き先をユーザーが直したことの学習 | 記録は取る（VISION §5.1）。**この版では推論に反映していない** |
| 行き先を全部おまかせにする | **未実装**。Level 3 は作っていない |

### 4-2. 所有していないものの明示

アプリの中に **Todo 管理画面もカレンダー UI も作っていない**（VISION §9）。
リマインダーとカレンダーは iOS 標準アプリのもので、そこへ書き込むだけである。
**この一文はブランディングそのもの**なので削らない。

### 4-3. プライバシー

判定は端末内で行い、この処理のためにメモ本文を外部サーバーへ送らない
（**実装がそうなっていることを確認してから書く**。VISION §14 の未決定論点に触れる）。
