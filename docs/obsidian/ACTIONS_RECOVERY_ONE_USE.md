## 試運転の日にしないこと（2026-10-21 追記）

- **試運転の日は、その日の定時 run が終わるまで、Obsidian Autopilot を手動起動（workflow_dispatch）も再実行もしない。**
  再実行は定時の1回目ではないので封じ込めを越えず、手動起動が同じ concurrency group に並ぶと
  待機中の定時 run が取り消されることがある（取り消された定時 run も `cancelled` の行として記帳されうる）。
- **publish ジョブだけを再実行しても回復にならない。**引き渡し（handoff）の artifact 名が
  `run_attempt` を含むので、「Re-run failed jobs」の2回目からは見つからない（`rejected_handoff_missing`）。
  publish が途中で落ちたら、再実行ではなく、残った当日ブランチ・PR を見てオーナーが次の手を決める。
- 公開運転表の点数は JST の日付で決まる。記帳（publish）と PR の SEO Validation が JST の日付をまたぐと、
  運転表が記帳時の日付のままになり、成果物の無い日でも価値契約が要る扱いで落ちる（`check-autopilot-page --check` も同じ境目で落ちる）。

## 依頼ファイルが無いときの再開（1回・2026-10-22 追加）

- 主の段（`id: claude`）の直後に、`$GITHUB_SHA` の `scripts/autopilot-publish.mjs --inspect-handoff` が2つのファイルを
  publish と同じ規則（大きさの上限・symlink 不可・JSON のオブジェクト）で確かめる。
- 主の段が success で、どちらかが無ければ、**同じセッションを1回だけ再開する**（`--resume <session_id>`。session_id は厳密な
  UUID の形のときだけ渡す）。主の段と同じ固定版の claude-code-action・同じモデル・読み取り専用の job token で、道具は Bash・Read・Write
  だけ（WebFetch/WebSearch は無い）、`--max-turns 12`、予算は「この run の上限（`--runtime-budget`）− 主セッションの実費」と $3 の小さい方

  主の段が failure の回は再開しない（publish は依頼を読まない push_only になり、上限で止まった回にさらに使わない）。
- ほかに再開しない回が2つある。
  - 手順0で終える日（終了コード `skipped_already_done` だけがあり、依頼は無い）。依頼は要らず、publish は何も公開しない。
  - 再開（8分）と、その外の段（Gate より前の checkout・再開より後の照合・梱包・upload に5分）がジョブ上限（90分）に

    引き渡しまで失う。時刻が読めない回も再開しない。

  出た result 行（段ごとに1つまで）を足す（ほかの段の行は足さない。同じ段に2行あれば読めない扱い）。再開の段が result 行を出さずに
  終わった回（時間切れ・取り消しなど）は、主セッション分だけを「再開分（最大 $3）を含まない」と注記して記帳する。
- 実行の要約はジョブ出力ではなく、引き渡しの `summary.json`（manifest に sha256）で publish へ渡す。主の段の後と再開の後に2つのファイルが
  あったか、再開したか・その結果・再開で拒否された道具の件数も入る（型付きの値だけ）。
- プロンプトの手順5・8 は「status JSON・LOG を含む最後のコミットの直後に依頼→終了コードを書き、読み戻してから終える。LOG に書くのは
  書いたことにならない」に改めた。
- オーナーが受け入れた残り: モデルが書き忘れた日は再開の予算ぶん（最大 $3）を使う。再開でも書かなければ、その日は何も公開されない（今までどおり）。
