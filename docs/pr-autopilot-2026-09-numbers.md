# ヒーローバナー（仮）の数字を、1つずつ出どころに当てる

<!-- fact-check: internal -->

> **用途:** 2026-08-22 に上がったヒーローバナー案の数字を、実装台帳と突き合わせる。
> **結論を先に書く: 12個の数字のうち、台帳に出どころがあるのは1個。**
> バナーは仮とのことなので、**差し替えに使える実測値も同じ表に並べた。**
>
> 台帳: `data/automation-coverage.json` `data/autopilot-runs.json` `data/autonomy-timeline.json`
> 集計: `node scripts/automation-rate.mjs` / `autopilot-runs.mjs` / `autonomy-timeline.mjs`

---

## 0. なぜこれを先に出すか

この原稿は「**証跡の無い主張を一切入れていない**」ことを売りにしています。
そして自社のCIには、**配信原稿に誇大表現が出たら落とす検査**（`scripts/check-pr-facts.mjs`）が
入っています。**出どころの無い数字をヒーローに置くと、原稿の主張そのものが自己矛盾します。**

記者が最初にやるのは、**バナーの数字1つを選んで「これはどう数えましたか」と聞くこと**です。

## 2. 95.3% は、台帳の定義では到達できない

「自律性が足りないところは数日で改修する」という前提でも、**この数字には届きません。**
理由は実装の速度ではなく、**分母の中身**です。

```
   現在（2026-08-22 の実装27件を反映）  90 / 172 タスク  =  52.3%
   未実装 22 件を全部埋めても                         →  65.1%
   提案どまり 41 件も実行へ上げたら                    →  89.0%  ← **人間専任19件を人間に残したままの理論上限**
   95.3% に必要なタスク数                              164 件（あと 74 件）
```

**89.0% が天井。**人間専任19件を人間に残す限り、AI実行に回せるのは最大153件（89.0%）。
95.3% には164件が要るので、**人間専任19件のうち11件をAIに渡さないと届かない** —
実機での事前確認・App Storeへの公開・価格変更・事故対応のどれかを渡すことになる。

**人間専任19タスクには、意図的に人間へ残したものが含まれます** —
実機での事前確認、App Storeへの公開、価格変更、事故・法的請求・炎上時の対応。
**これらをAIへ渡すと95.3%に近づきますが、原稿の売りである「境界」が消えます。**

つまり **95.3% は「まだ達成していない数字」ではなく、「この設計では目指していない数字」**です。

## 3. 「コード変更 98.8%」も、配信前に導出をやり直したほうがいい

既存原稿は「**231,315行中228,498行・56コミット中55件**」（2026-08-11〜08-22）としています。
**今回、同じ窓で計測し直したが再現できませんでした。**

| 計測 | コミット | 変更行 |
|---|---|---|
| simplememo 単体・マージ除く | 66 / 67（98.5%） | 37,866 / 40,683（93.1%） |
| 3リポジトリ・現ブランチ・マージ除く | 126 / 127（99.2%） | 51,516 / 54,333（94.8%） |
| 3リポジトリ・全ブランチ・マージ除く | 261 / 263（99.2%） | 73,606 / 76,647（**96.0%**） |

**どの数え方でも 231,315行 にならず、98.8% にもなりません。**
AI著者の定義は「author が Claude、または本文に `Co-Authored-By: Claude` を含む」で、
`git show --numstat` の追加+削除行を合計しています。

**再現できない数字は、記者に聞かれた瞬間にいちばん高くつきます。**
配信前にどちらかにしてください。

- 元の導出手順を復元して原稿に書く（どの範囲・どのオプションで数えたか）
- または**再現できる値に差し替える** — 素直に出すなら
  **「コミットの99%、変更行の96%がAI著者」**（3リポジトリ・全ブランチ・マージ除く）

## 4. 差し替えに使える実測値

**どれも台帳から出ていて、`--check` が現在値との一致を強制しています。**

| 使える数字 | 値 | 何を言えるか |
|---|---:|---|
| **成果物への人の介入** | **0件 / 0.0%** | 「出荷10件すべてAIが書き、人は中身に触っていない」。**バナーの主張にいちばん近い真実** |
| 成果物のAI自律率 | **100%** | 同上を率で言ったもの |
| コミットのAI著者率 | **99.2%** | 「コードは人がほぼ書いていない」 |
| 変更行のAI著者率 | **96.0%** | 同上（3リポジトリ・全ブランチ・マージ除く） |
| AI関与率 | **87.3%** | 「誰かがやっている業務の9割近くにAIが関わる」。**最も甘い数え方であることを併記する条件つき** |
| 自律度の推移 | **3.5% → 52.3%** | **ローンチから4か月で約15倍。**バナーを「率」ではなく「変化」に振るなら、これが最も強い |
| 権限表 | **15領域中10が承認制** | 「人は重要判断だけ」の裏づけ。**バナーのこの1行は正しい** |
| 自動検証 | **41種 / 必須32本** | 「検証を通ったコミットだけが本番へ出る」 |

### バナーを直すなら、いちばん短い直し方

**ヒーローの数字を「率」から「変化」に替える。**

> **運営の自律度、4か月で3.5% → 52.3%。**
> 人は重要判断だけ。／ 出荷物に人が手を入れた回数：**0**

**52.3% は、この原稿ではそれが効きます。**
「まだ半分」と自分から言う会社が、その横で「介入0件」と言うから信用が乗ります。
**95.3% は、その効き方を丸ごと捨てることになります。**

## 5. グラフの扱い（`data/autonomy-timeline.json`）

月次の系列は**再構成であって当時の実測ではありません。**
`scripts/autonomy-timeline.mjs` が持つ制約は3つで、**グラフに出すときは必ず併記します。**

1. 証跡ファイルの追加日 ≒ 稼働開始日（実際には数日〜数週のずれ）
2. **分母は現在の棚卸し（172タスク）を過去へ固定している。**当時は一覧自体が無かった
3. 出せるのは総合自動化率だけ。AI関与率とカバー率の系列は復元していない

**終点だけは実測**で、`--check` は終点が `automation-rate.mjs` の現在値と一致しない限り
**CIを落とします**。ずれた系列は、グラフとして存在してはいけないためです。
