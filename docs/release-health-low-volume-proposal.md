# 次期公開候補の低流量時の健康度判定案

この文書と `scripts/assess-release-health-evidence.mjs` は、次期版の安全判断に使う**読み取り専用の提案**。現行の `data/release-gate.json`、実行側のピン、100セッション条件、正式AI実行率は変更しない。既に公開した版を再公開したり、過去の業務を加点したりしない。

現行の同週100セッションずつは、流量の小さい版では到達しにくい。一方、100セッションでクラッシュが見えなくても、1ポイントの悪化を統計的に証明したことにはならない。将来の別版ポリシーでは、**母数不足を「異常なし」と呼ばず、個別の安全審査へ送る**。20件や30件などの恣意的な代替閾値は置かない。

判定材料は、公開中の版と直前に公開した版をASCの版履歴で確定し、両版について同じ確定WEEKLY期間の `App Sessions Standard` と `App Crashes` を使う。アプリID・iPhone/iPadの対象範囲・期間が一致し、24時間以内に読み戻した元報告であることを確認する。Expanded、別週、全版合計、90日ダッシュボードの数値は同週の分子・分母に混ぜない。Appleが `App Crashes` を生成していない状態は、クラッシュ0件の報告とは異なる。

診断器の結果は次の3段階に限る。

| 結果 | 意味 | 次の扱い |
|---|---|---|
| `hold` | 版別行、同週クラッシュ報告、範囲、鮮度などの材料が欠ける | 公開の安全合格とはしない。元取得と提供元の新根拠を待つ |
| `human_safety_review_required` | 両版の元報告は揃うが、どちらかが現行100セッション未満 | 対象候補と実証済み影響を明示した個別判断へ移管。恒常的な事前承認で代用しない |
| `evidence_ready_for_original_gate` | 両版の同週元報告と現行母数がある | 既存の悪化幅、CI、実機QA、対象SHA/ASC版、承認後6時間、kill後7日、段階公開、日次上限などを別途判定 |

この診断器は元報告の真正性や「直前公開版」の選定を自分では検証せず、公開APIも呼ばない。すべての結果で `automatic_release=false`、`formal_task_78_credit=false` を返す。将来この案を実行ゲートへ組み込む場合は、元材料の真正性を実行側で照合し、版付きポリシー・両リポジトリのピン・同一SHAのCI・段階公開の実適用と公開後読戻しを改めて確認する。既存版の事後認定は行わない。
