### 2026-09-09の名指し承認の反映

オーナーは「利用者本人の同意と未配信業務、承認するので権限も渡すので進めて」と明示した。
次回リリース `202609-autonomy-followup`（企業182412・下書き10）の配信操作は委任済みとして、
権限表の一律 `human_only` を今回1件のAI実行許可へ訂正した。既存の `evaluateDispatch` が
実測99.9%以上・品質審査・本文・宛先・日時・料金・未配信状態を確認する。追加承認を求めない。
委任と実行は分け、配信操作の `executor` は公開を実行・確認するまで変更しない。
配信前にはこの1件が非AIのため、他の全業務が完了しても198/199 = 99.497487%にとどまる。
この循環する前提を `circular_prerequisite` として記録し、到達可能な加点や計画の上限に加えない。
権限の追加や時間経過で解消する待機としても扱わない。

この承認は「99.9%になるまではプレスリリースは出しません」の撤回とは扱わない。
PR TIMESの下書き上書きは最後の検証済み保存から実測で3ポイント以上改善したときに限る。
99.9%到達時の配信直前に必要な最終同期は例外とし、保存完了の確認前に基準値を動かさない。

収集同意はApp Analyticsで各利用者が選ぶ共有オプトインである。
[Appleの説明](https://developer.apple.com/documentation/analytics-reports/app-store-opt-in)でも、
開発者への共有を選んだ利用者が対象とされている。オーナーの事業上の承認やご本人としての
承認を他の利用者の同意へ置き換えない。今回、端末の共有設定変更や共有状態の確認は行っていない。
この承認だけで収集同意の `executor` を変えず、`human_consent` と未完了の実績を保持する。

## 開始点と達成条件

main `79f8f81d` の実行148 / 実施中177 = **83.615819%**。
総合自動化率148/199 = **74.371859%**、AI関与率160/177 = **90.395480%**、
カバー率177/199 = **88.944724%**。既存203タスク、意図的な除外4件の定義を維持する。

既存の実施中業務をk件移管し、未着手からn件をAIが実行すると `(148+k+n)/(177+n)`。
99.9%以上には**既存実施中で残る29件すべての移管**が必要。
未着手22件を全部実施しても、非AI業務1件が残れば198/199 = 99.497487%で未達。
この粒度では99.9%以上は実質100%を要求する。表示の丸め、業務の削除・分割、
物理作業や本人同意の完了偽装で埋めない。現在の物理行為・本人同意の制約も未達の理由に含む。
公開済み9/3記事の76.4%は配信時点の記録として凍結する。

現行定義では本人の収集同意などAIが代行できない行も分母に含まれる。さらに未移管の
「PR TIMESへの配信操作」は配信実行後にのみ加点するため、今回の配信を99.9%達成の
先取り加点には使えない。この制約を率の定義変更で隠さず、未達のままなら配信を保留する。

完了には次のすべての現在の証拠が必要：

1. 同じ棚卸し定義で実行率99.9%以上。各移管行に対象・実行者・実行結果・日時・実体への参照。
2. 必要な改善がマージされ、実際の本番で動くこと。CI成功やコードの存在だけでは代用しない。
3. TestFlightは必要な改善をまとめて配信し、iPhone 13で確認する。既存配布・他タスクの実行と重複しない。
4. 実測99.9%以上を確認した後に新しいPR TIMES記事を配信し、公開URL・表示本文・日時・
   指標・配信状態を確認できること。当初の来週期限より達成条件を優先する。
5. 原稿の数値を配信前に更新し、その時点のスナップショットを凍結する。未達の99.9%を達成と書かない。
