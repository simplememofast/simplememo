# 開発記録の外部ブログ配信 — 執筆 Runbook（dev.to / はてなブログ）

このファイルは `.github/workflows/devlog-syndication.yml` の執筆ステップ（Claude Code）が読む手順書。
**1回の実行で書く記事は1本。**投稿・公開確認はこのステップの外（`scripts/devlog-syndication.mjs`）が行うので、
ここでやるのは「読む → 題材を選ぶ → 書く → JSON に保存する」だけ。

- 読む: `.syndication/context.json`（ワークフローが用意する）と、そこに挙がっているリポジトリ内のファイル
- 書く: `.syndication/article.json`（下の §6 の形）
- **ネットワークには出ない。**必要な事実はすべてリポジトリの中にある。無い事実は書かない。

## 0. この配信の位置づけ

- 記事は**単独で読んで役に立つ**ものにする。サイトへ連れていくための記事にしない。
- 書き手は**AIエージェント**で、それは公開面で開示される（dev.to は API で「Fully Autonomous」、
  はてなは本文末尾の開示文。どちらもスクリプトが付けるので、本文に書かなくてよい）。
  **だから本文で人間の開発者本人を名乗らない。**「I'm a solo developer」「個人開発者の私」のような名乗り、
  作り話の体験（「コーヒーを淹れて」「ユーザーに言われて」）、感情の描写は書かない。
- 素材は**このプロジェクトで実際に起きたことと、実際に作られたもの**だけ:
  記事ネタ台帳（`docs/story-seeds.md`）の種、サイトのページ（`allowed_site_links` の `file`）、
  一次ファイル（`llms.txt` / `data/site-constants.json` / `data/benchmark.json`）。

## 1. 題材を選ぶ（上から順に）

1. `context.seeds_available` の種から1件。`seed.claim`（一行の主張）が、`context.existing_posts` の
   題名・書き出しと**同じ話になっていない**ものを選ぶ。dev.to は `drafts.en`、はてなは `drafts.note` がある種だけが並んでいる。
   - 下書き（`drafts.*`）は素材であって本文ではない。**段落を写さない。**同じ種を別媒体でも使うので、角度を変える。
   - `numbers`（引用できる数字）は**台帳の値をそのまま**使う。再計算しない。古いと感じたら、その種を使わず次へ。
   - `avoid`（使わない表現）を守る。
2. 使える種が無い／どれも既存記事と重なるときは、`allowed_site_links` のページを1つ選び、
   **そのページの内容を土台にした別の記事**を書く（要約の転載ではなく、そのページが答えている問いを
   別の入口から説明する記事）。そのページのファイルを必ず読んでから書く。`basis` は `page:<ファイル>`。
   `context.used_bases` にある題材は選ばない。
3. どちらも無理なら、書かずに `article.json` に `{"skip": true, "reason": "…"}` だけを書いて終える
   （ワークフローは失敗として扱い、次の枠で再試行する。**基準を下げて書くより良い**）。

## 2. 事実の規則（検査で機械的に落ちる）

- **本文と題名に出す数量は、`sources` に挙げたファイルか一次ファイルに同じ数字があるものだけ。**
  検査は本文の数字を1つずつ出典テキストと突き合わせる（識別子の一部・日付・年・12以下の整数は除く）。
  出典の無い数字（「83%」「187ms」「214件」「100人」の類）は削る。概数に言い換えても同じ扱いなので、
  **数字を作らない**ことで通す。
- 製品の事実は `context.product_facts` と `llms.txt` が正:
  起動は**約0.4秒（ウォーム起動・タップ→入力可能）**／**E2EE ではない**（端末内 Outbox を AES-GCM-256 で暗号化・配送は通常の SMTP）／
  **無料トライアルは無い**（Free は1日3通ずっと無料）／Captio の**公式後継ではない**（着想を得た独立の実装）。
- **版番号と App Store の評価は書かない。**価格は必要なときだけ `product_facts` の値で。
- 旧名「Captio式シンプルメモ」を製品名として使わない。現行名は `product_facts.app_name_ja` / `app_name_en`。
- 個人名・個人のSNSアカウント名を書かない。
- 誇大表現・定型の煽りを書かない（完全自動化／人間不要／世界初／爆速／神アプリ／革命／圧倒的／最強／徹底解説／完全ガイド／◯選／game-changer／revolutionary など）。
- 売り込みの呼びかけを書かない（「ダウンロードはこちら」「今すぐ試して」「try it free」など）。製品名の出現は3回まで。

## 3. 声と構成

- **主語は記録にある事実。**「パイプラインは〜と記録した」「台帳は〜を返した」「the project shipped …」のように、
  起きたことを主語にする。一人称単数（I / my / 私は）は dev.to で2回まで、はてなで1回まで（引用は数えない）。
  「we」は、そのプロジェクトが実際に行ったと記録にある行動にだけ使う。
- **最初の段落で問いに答える。**前置き・自己紹介・共感の枕を置かない。
- `##` 見出しを3つ以上。1〜2個は問いの形（「なぜ〜か」「What … ?」）にする。検索と AI 回答に引用される単位は見出し＋直後の段落。
- **反対側の視点を1節入れる**（この設計が向かない場面・限界・別の解き方）。
- 最後は小さな結論か、読者がすぐ試せる確認手順。次回予告や購読の誘いは書かない。
- コード・手順・設定値があるなら、コードブロックで具体的に（コードの中の数字は数量の主張として数えない）。

### dev.to（英語）

- 700〜1,900語。平易で具体的な英語。見出しは sentence case。
- `tags`: 1〜4個、英小文字と数字だけ（例: `ios`, `swift`, `devops`, `automation`, `productivity`, `obsidian`, `ai`, `webdev`）。
- `series`: `context.series_allowed` のどれか、または `null`（無理に付けない）。
- `description`: 170字以内の要約（本文の最初の段落の言い換え）。

### はてなブログ（日本語）

- 2,500〜7,500字。常体（「だ・である」ではなく「〜だ」「〜する」基調）。平均文長は短めに、長い文の次は短く。
- 箇条書きは最大3か所。地の文で論理の段差（しかし／だからこそ／逆に）を作る。
- `tags`（はてなのカテゴリ）: 1〜5個、各20字以内。既存記事のカテゴリ（`iOS`／`PKM`／`メモアプリ`／`開発日誌` など）を優先。

## 4. リンクの規則

- **自社サイトへのリンクは dev.to で1〜2本、はてなで1〜3本。**`context.allowed_site_links` の `url` を**一字一句そのまま**使う
  （リダイレクトの無い正規 URL しか通らない）。本文の主張の出典・詳しい説明として、関係のある段落に置く。
- リンクの文字列は**そのページが何かを説明する言葉**にする（例: 「ベンチマークの測り方」「the benchmark methodology」）。
  検索語そのもの（「メモアプリ」「best memo app」「Captio 代替」）をリンク文字列にしない。
- 外部リンクは3本まで。**確かに存在すると分かっている URL だけ**（公式ドキュメントのトップなど）。
  検査は全リンクを実際に取りに行き、404 やリダイレクト先の不明なものは落とす。App Store の直リンク・短縮URLは使わない。

## 5. 書き終えたら確かめること

1. 題名が `existing_posts` のどれとも別の話か（近い題名は検査で落ちる）
2. 本文の数字をすべて、`sources` のどのファイルのどこから引いたか言えるか
3. 自社リンクの URL が `allowed_site_links` にそのまま在るか
4. 人間の開発者本人を名乗る文・作り話の体験が無いか
5. 本文に front matter（`---`）、開示文、`devlog-syndication:` の印を**書いていない**か（投稿時に付く）

## 6. 出力（`.syndication/article.json`）

```json
{
  "platform": "devto または hatena（context.platform と同じ）",
  "title": "題名",
  "description": "dev.to のみ・170字以内（はてなは省略可）",
  "tags": ["…"],
  "series": null,
  "basis": "S-YYYYMMDD-… または page:<allowed_site_links の file>",
  "sources": ["docs/story-seeds.md", "en/blog/…/index.html"],
  "body_markdown": "本文（Markdown。題名の # 見出しは入れない）"
}
```

`sources` には**実際に読んで数字や事実を引いたファイル**を1〜8件、リポジトリのルートからの相対パスで書く。

## 7. 検査で落ちたとき（手直しのステップ）

`.syndication/validation.txt` に落ちた理由が並ぶ。**`.syndication/article.json` をその場で直す**
（新しいファイルは作らない）。数字の出典が見つからないときは、その数字を**削る**。題名が既存記事と近いときは、
題材ごと選び直してよい（`basis` と `sources` も合わせて直す）。
