### 手で見つけた誤りを、機械に見つけさせる

上の12件は**読めば分かる**状態で数日残っていた。読む人が居ないと直らないものは
直らないので、同じ食い違いを CI が落とすようにした
（`scripts/check-coverage-authority.mjs`）。

**突き合わせるのは領域ではなく条項の文字列。**領域まるごとで照合すると
**部分的に渡した領域**が扱えない —— 「段階公開の撤回」は ai_may に
『ガードの判定が閾値を割ったときの kill』を、human_only に
『ガードの判定によらない kill（**手動・訓練を含む**）』を持っていて、
渡した側と残した側が同じ領域の中に並んでいる。

だから coverage の行に条項そのものを書かせる:

```
    "authority": { "domain": "…", "human_only": "…" }   境界は人の側にある
    "authority": { "domain": "…", "ai_may":     "…" }   境界は外れている
```

表からその条項が消えたら照合が落ちる。**両方向とも落ちる**のが要点で、
片方だけだと「境界を実装待ちに書く」（天井が高く出る）か
「渡されたものを境界に書く」（やれることを隠す）のどちらかが素通りする。

いま名指ししているのは16件（人の側13 / 渡した側3）。
表に領域が無い境界7件は `$authority_absent` に理由を書かせ、
**件数はラチェット**（`authority_absent_budget: 7`）にした ——
散文だけを根拠にした境界が黙って増えるのを防ぐ。

壊し11通りで落ちることを実測してある（`--selftest`・`data/check-selftests.json`）。
