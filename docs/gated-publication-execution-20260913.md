# 委任公開を実際の判定・実行へ接続する

2026-09-13。既存業務78（App Store公開）と142（課金導線改善）の実行を進めるため、
提出後の公開経路を修正した。AI実行率は159/179 = 88.826816%を維持する。
コード、承認、CI、過去の公開観測を新しい公開実行へ加算しない。

## 解消する問題

以前は委任による提出も`AFTER_APPROVAL`で、Appleの審査通過と同時に公開され、
独立した`evaluateRelease`を実行していなかった。5.8.54/1342の実機・公開確認は
既存の証拠として保持するが、事後の観測を事前ゲート通過へ読み替えない。

iOS [PR500](https://github.com/simplememofast/simplememo-ios/pull/500)は委任提出だけを
`MANUAL`に設定し、既存の公開要求スクリプトへ固定された公開ゲートを接続する。
審査・実機確認・ビルド・タグ由来メタデータ・段階公開を照合し、Appleへの公開要求は
一度だけ実行する。個別の公開指示に基づく既存経路も保持する。

承認待機の起点を版ID・版番号・ビルド番号・SHA・完了した審査ID・提出時刻へ結び付けた。
差替え、再審査、欠測では過去の時刻を引き継がない。対象版ごとの観測を非公開側へ保存し、
再実行時にも最新mainから前回観測を読み直す。提出時刻を承認時刻の代わりにはしない。

停止証拠の観測時刻と判定時刻はどちらも公開要求直前に60秒以内を求める。
公開版の比較ペアと審査IDも最終ASC読取りに一致する必要がある。
非公開の予約をSHA付きで保存・読戻ししてから実行し、不明な結果や未解決予約が残れば
別日・別版でも再送しない。明確に公開要求前で中止した場合だけ予約を終了する。

## 遠隔停止の実機準備

iPhone 13の5.8.56/1428で、終了状態の設定から再取得の試行時刻だけを除き、
通常起動による実サーバー設定の再取得を確認した。取得成功時刻が更新され、
フラグの値・Obsidian/Notion連携・宛先・件名・署名・下書きの保存設定は不変だった。
元設定・操作用設定・読戻し設定のハッシュと比較結果は非公開の端末証跡へ保存した。
これはテスト端末の再取得手段の確認であり、通常の24時間スロットルが短縮された証拠ではない。

iPhoneミラーリングではタップとアプリ起動は確認できたが、設定リストのスクロール入力が
反映されず、対象の案内行を画面で確認できていない。予定した`wp05_lock_visible`の
本番定義・kill・復元操作はまだ0件で、既存の`tf04_progress`停止も変更していない。
本番停止を始める前に表示・復元を観測できる操作経路を確立する。停止中に取得した端末は
次の正常取得まで停止を維持するため、24時間経過だけで復活すると扱わない。
業務82への加点は未実施である。
