```
                      初回   改訂1
  S1 新規性            26  →  28  / 30
  S2 エンティティ到達  12  →  17  / 20   ← 見出し方針の確定が効いた
  S3 具体名詞          13  →  15  / 15
  S4 変化              10  →  13  / 15
  S5 時流               3  →   3  / 10   ← Appleウィークに無関係弾。自分で引き受けたハンデ
  S6 ニュース動詞       2  →   4  / 5
  S7 ローンチ設計       0  →   0  / 5    ← 受け皿ページで +5
  ────────────────────────────────────
  合計                 66  →  80  / 100   （S7充足で 85・合格 60）
```

各軸の増減理由は `experiments.json` の `d_score_pre.score_rationale` に1軸ずつ書いてある。

**バックテストとの位置関係**（`node growth/scripts/d-score.mjs --backtest`）:

```
   21    469PV  非乗車 │
   40  1,347PV  非乗車 │  非乗車の最高 46
   46    217PV  非乗車 │
  ─────────────────────  合格ライン 60
   65 10,434PV  乗車   │  乗車の最低 65
   71 12,188PV  乗車   │
                       │  ← 今回 80（S7充足で85）
```

**80は乗車帯の上にある。**ただし n=5 の較正であり外挿の根拠にはならない。
とくにS5=3は乗車した2本（5と8）より低く、**ここが読み違いの本命**。

## 3. 配信前に潰しておくべき穴

### 3-1. 【オーナー】`docs/GROWTH_ROI_PLAN_2026-08-20.md` がリポジトリに無い

D-SCOREの較正根拠（n=5バックテスト・合格60の由来）が入っている文書が
**4箇所から参照されているのに存在しない**（`experiments.json:1198/1238` /
`growth/reports/2026-08-canonical-funnel-0815-0819.md:9` / `data/cpp-map.json:4`）。

**このリリースは「判断の根拠をファイルに落としてCIに監視させている」ことが売り。**
その根幹の文書が欠けている状態で「散文は手を挙げない」と書くのは、
記者に確認されたら崩れる。

> 緩和は済んでいる: `growth/scripts/d-score.mjs --backtest` が
> `annotations.json` から較正を**再現できる**ようになったので、文書が無くても
> 数字そのものは示せる。ただし「合格60をどう決めたか」の記述はまだ文書側にしかない。

### 3-2. 【オーナー・最優先】主系オートパイロットが11回連続で成果物ゼロ

| run | 日付 | 結果 | 原因 |

`additional_permissions` / `claude_args` のツール許可リストを確認してほしい。
毎朝ジョブが緑のまま推移するため最も気づきにくい。

> **配信との関係:** 原稿は改訂1でこの事実を**そのまま書く**方針に変えた
> （「主系・副系の二重化で維持している」＝冗長化が効いた実例）。

### 3-3. 【AI・8/24】受け皿ページ `/autopilot/` が無い（S7 = 0 の原因）

PR TIMESからの流入を受ける場所が無い。過去実績では
**被リンク獲得がPR TIMES単発配信に全面依存**しており
（`GROWTH-AUDIT-2026-08-09.md`）、受け皿の有無が転載後の資産化を左右する。

必要な要素:

- 1サイクルの図解（転載で単体使用される前提）
- **D-SCOREバックテスト表**（数字と結果が並ぶ表は引用されやすい）
- 実行ログの実物抜粋・「AIに与えていない権限」の該当箇所引用
- **`data/autopilot-status.json` と `data/autopilot-cost.json` へのリンク**
  — 生きている状態がその場で見えるのが最大の説得力
- できないことの一覧

**`content-graph.json` 登録とデスクトップQRが必須**（CIが強制する）。
実装規約は `AUTOPILOT_RUNBOOK.md` §3。

### 3-4. 【自動】原稿の数字は配信日時点で更新が必要

本文の「12日連続」「261ファイル」「13,195リンク」はすべて2026-08-22時点。
**実費は改訂1時点で n=1（$0.8149）しかない。**

→ 予算台帳が毎日積まれるようになったので、**配信日には2週間ぶんの実測が揃う**。
原稿の実費まわりの記述は配信-2日に差し替える。
**それまで金額の具体値を本文に書かない**（n=1を「1日あたり」と書かない）。
