## 2. 画像の仕様 — **3:2 は切れる**

PR TIMES のメイン画像は SNS のリンクカードと一覧のサムネイルに使われ、公式の推奨は
**1200×630 px 以上・縦横比 1.91:1**、容量 **5 MB 以内**（PR TIMES MAGAZINE / ヘルプセンター）。
Google Discover の大きな画像は **幅 1200 px 以上**＋ `max-image-preview:large`（Discover 側の要件。PR TIMES のページが満たす）。

いまのバナーは **1536×1024（3:2）**。幅は 1200 を超えるので G1 の字面は満たすが、**1.91:1 に中央で切られると**:

```
   1.91:1（OGP / X / Facebook / PR TIMES 一覧）   1536×804 を中央から → 上下 110 px ずつ落ちる
     ・上端「PRESS RELEASE」バッジ  … 切れる
     ・下段の実績4枚（15/15・0件・17日間・67種） … **上半分だけ残って切れる**
   1:1（一部のモバイル一覧・埋め込み）            1024×1024 を中央から → 左右 256 px ずつ落ちる
     ・見出し「アプリが、自ら育ち続ける。」 … 「リが、／育ち続ける。」
     ・「76.4%」 … 「4%」
```

（描画で確かめた。`thumb-1.91-ogp.png` / `thumb-1x1-square.png`。切り抜きは `pngcrop.py` による中央トリミング。）

**直し方は2つ。**

1. **再生成を 1.91:1 で**（例: 1920×1005 / 1536×804）。件数3つを現在値に差し替えるついでに比率も直す。
   文字は**中央 1.91:1 の帯の内側**に収める（正方形の切り抜きも見るなら中央 1:1 にも主要素を寄せる）。
2. 再生成できないなら、**左右に同色の地を足して 1.91:1 に拡張**する（`banner-padded-1200x630.png`。
   内容は1画素も欠けないが、左右に無地の帯が出る。件数は古いまま）。

**G1 を「幅 1200 px 超」だけで読むと通る。**通しても切れる。ゲートの字面ではなく、
一覧で何が見えるかで判断すること。
