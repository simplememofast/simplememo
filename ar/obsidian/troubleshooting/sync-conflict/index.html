ترتيب التأكيد هو النص الأصلي والمحتوى المحدد وحفظ النتائج

الهدف لهذه المرة هو عندما يتم تضمين علامة منافسة في نفس نص Markdown في دمج Git. لقد قمت بتحرير إحدى الملاحظات التي أنشأها المؤلف مع فرعين من Git المحلي، وأكدت فشل الدمج الفعلي، ومقارنة النص الأصلي، والتصحيح اليدوي. إنها ليست نتيجة التزامن مع محطات طرفية متعددة.

  1. اترك كلا النصين الأصليين يدوياقم بإعداد نسخة يمكنها التمييز بين المحتوى
  2. قارن الاختلافاتتحقق من الخط غير العادي والجزء المشترك
  3. قرر المحتوى الذي سيعتمدهيضع هذا المثال عنصرين متوافقين في أسطر منفصلة
  4. تحرير وحفظتأكيد اكتمال الدمج على النص وجانب Git
  5. إعادة العرض والتأكيدطوق المحتوى المحدد وحفظ Markdown

هذا الترتيب هو رسم تخطيطي ينظم هذا التمرين. إنه ليس رسما بيانيا يوضح ضمان الاستعادة التلقائية ومنع الخسائر، وإجراءات التشغيل لكل خدمة مزامنة.

أولا، تحقق من شكل منافستك

في هذا المثال، يتوقف دمج Git عند رمز النهاية 1، ويصبح 作業メモ.md UU. يحتوي فهرس Git على إصدار أصلي مشترك وإصدارين محررين، ويتم تضمين <<<<<<< HEAD و======= و>>>>>>> draft-b في نص المذكرة.

إذا ظهر ملف تعارض الاسم المستعار أو شاشة السجل في بيئتك، فيرجى التحقق وفقا لطريقة المزامنة. المدخل للتحقق من الطريقة هو دليل طريقة مزامنة Obsidian. لا يمكن قراءة نتائج Git في هذه المقالة في سلوك Obsidian Sync أو iCloud.

النص المحفوظ في حالة التعارض هذه هو كما يلي. يتم نشر النص الكامل للملف الفعلي، بما في ذلك العلامة.

1. اترك النصين الأصليين في متناول اليد بشكل منفصل

قبل البدء في التحرير، احفظ كل إصدار في متناول اليد بشكل منفصل باسم يعرض الإصدار الأصلي. إذا كان لديك واحد منهم فقط في متناول اليد، فلا تعامل الآخر على أنه قادر على حفظه، وتحقق من حالة Git وتاريخ الطريقة التي تستخدمها. لم أحاول الاسترداد من سجل كل خدمة هذه المرة.

إذا كنت ترغب في التحقق من الإعداد للعودة إلى النص السابق قبل إصلاح التعارض، فيرجى أيضا الرجوع إلى Git و File Recovery واسترداد النسخ الإضافية.

في هذا التمرين، احتفظ المؤلف يدويا بنسخة من الخطة أ والخطة ب قبل الدمج. للمقارنة، وضعت أيضا 原文の控え/案A.md و原文の控え/案B.md في غرفة التخزين وفتحتها. هذه ليست نسخا متضاربة يتم إنشاؤها تلقائيا بواسطة أداة المزامنة.

مشروع أتحقق من ترتيب العناوينالعنوان، شرح ملاحظات الممارسة، عنوان التأكيد التالي
الخطة بتحقق من مكان حفظ الرابط الداخلينفس الخطة أ

بدلا من الحكم فقط من خلال وقت التحديث، اقرأ النص وتحقق من المعلومات الضرورية. نظرا لأن الاثنين متوافقان كعناصر تأكيد منفصلة هذه المرة، فقد قرر المؤلف اعتماد كلا الخطين بترتيب A وB. إذا كانت الجملة الفعلية متناقضة أو مكررة، فأنت بحاجة إلى الاختيار وفقا للمحتوى.

2. قم بتحرير المحتوى الذي قررته باستخدام Obsidian وتحقق من التوفير

فتحت 作業メモ.md في محرر Obsidian الفعلي وأدخلت النص المحدد. في هذا المثال، تركنا تفسيرا مشتركا، ووضعنا العنصرين في أسطر منفصلة، وأزلنا علامات التعارض. انتظر الحفظ التلقائي وتأكد من حفظ النص الكامل التالي في الملف الفعلي.

# 作業メモ

ローカルの競合を確かめるために著者が作った練習用ノートです。

## 次の確認
- 確認する項目: 見出しの順番を確認する。
- 確認する項目: 内部リンクの保存先を確認する。

بالإضافة إلى حقيقة أن العلامة قد اختفت، سأعيد قراءة المحتوى المحدد وترتيب الخطوط والأجزاء المشتركة التي قررت تركها. سيتم تأكيد قرار تلخيص النص والعملية لإكمال الدمج على جانب Git بشكل منفصل.

3. تحقق من حالة Git التي لم يتم حلها وأكمل الدمج

في هذا التمرين، حتى بعد حفظ النص باستخدام Obsidian، كانت حالة Git UU. بعد ذلك، قمت صراحة ب git add مع الملاحظة المستهدفة فقط وأجرت التزاما بالدمج محليا. يبقى الالتزامان الأصليان كآباء، git ls-files -u فارغ، وحالة Git نظيفة.

فيما يلي مثال على الأمر للتحقق من الملف المستهدف في Git المحلي. تحقق من اسم الملاحظة الفعلي والمستودع قبل استخدامه. قبل git add، يرجى التحقق من النص الذي سيتم اعتماده وحالة العمل الأخرى.

git status --short -- "作業メモ.md"
git ls-files -u -- "作業メモ.md"
# 採用する本文を確認した後、対象ノートをstageする
git add -- "作業メモ.md"
git commit
# merge完了後の未解決indexと状態を確認する
git ls-files -u
git status --short

تم تنفيذ عملية Git باستخدام أمر محلي. لا يتم استخدام المكون الإضافي Obsidian Git، ولم يتم تأكيد جهاز التحكم عن بعد والدفع/السحب والانعكاس على المحطات الطرفية الأخرى. حقيقة أن الحالة نظيفة لا تثبت متانة النسخ الاحتياطي أو التسليم إلى جميع المحطات الطرفية.

4. أعد فتح دفتر الملاحظات واقرأ المحتوى المحدد

بعد إنشاء التزام دمج، قمت بإعادة فتح 作業メモ.md من مستكشف الملفات الفعلي. تم عرض عنصرين في عرض القراءة، ولم تكن هناك علامات تعارض. كان Markdown قبل وبعد إعادة العرض هو نفسه SHA256، كما تم الاحتفاظ بنسخة A / B الأصلية ونص كل التزام.

تم تأكيد هذه النتيجة من خلال ملاحظة هذا المؤلف واستعادة محلية واحدة. إنها ليست نتيجة تظهر أن المعلومات لن تضيع في جميع الصراعات وجميع طرق المزامنة.

قم بتنزيل النص الأصلي وحالة التعارض والنتائج المحفوظة

Markdown الأربعة هي A/B الأصلية، وحالة الصراع، والأصلية لنتيجة الحفظ النهائية. اسم التوزيع هو اسم مستعار للتمييز بين الدول، وكان اسم مذكرة العمل الفعلية 作業メモ.md. في ممارسة مقارنة المحتويات، احفظها بأسماء مختلفة وتحقق منها في مكان لا تقوم فيه بالكتابة فوق الملف الذي يحمل نفس الاسم في دفتر ملاحظاتك.

الحالةملف التوزيع
الأصل Aoriginal-a.md
الأصل Boriginal-b.md
حالة الخلافconflicted-note.md
النتائج المحفوظةresolved-note.md

لا يتم تضمين عملية الالتقاط والاستعادة على جانب القارئ من الملف الموزع في التحقق الفعلي من هذا التطبيق.

الأسئلة الشائعة

هل علامات الصراع في النص والنسخة المتضاربة هي نفسها؟
ما تحققنا منه هذه المرة هو العلامة المنافسة التي وضعها جيت في نص Markdown الذي يعمل عليه جيت. تم كتابة نسخة من النص الأصلي يدويا من قبل المؤلف. لا يتم التحقق من سلوك طريقة المزامنة تلقائيا لإنشاء ملف منفصل في مثال الاستعادة هذا. يرجى التحقق من التعليمات الخاصة بالطريقة التي تستخدمها.
هل يمكنني حلها إذا تركت كلتا الجملتين؟
عنصرا التأكيد في هذا المثال متوافقان، لذلك قرر المؤلف تركهما كخطوط منفصلة. إذا كان المحتوى غير متناسق أو تداخل نفس الشرح، فيرجى التحقق من المعنى والمعلومات الضرورية وإعادة الاختيار. ليس دائما إجراء لإضافة كليهما.
إذا قمت بمسح العلامة المتضاربة وحفظها، فهل سيكتمل دمج Git؟
في هذا التمرين، كانت حالة Git UU حتى بعد حفظها باستخدام Obsidian. بعد التحقق من المحتويات، وإضافة المذكرة المستهدفة، وإنشاء التزام دمج، أكدت أن الفهرس الذي لم يتم حله كان فارغا وكانت حالة جيت نظيفة. يرجى فصل تحرير النص وإكمال جانب Git.
هل تم التحقق من هذا الإجراء على Obsidian Sync وiCloud؟
تم التحقق من إصدار Linux من Obsidian 1.13.7 ومستودع Git محلي واحد غير متصل بالإنترنت. لم يتم تجربة Obsidian Sync، iCloud، خدمات المزامنة الأخرى، محطتان، iPhone، SimpleMemo الروابط. يرجى التحقق من التاريخ وآلية الصراع وفقا للطريقة الفعلية.

بيئة التحقق ونطاق التأكيد

  • التطبيق الفعلي: 2026 year 9 month 30 Linux version Obsidian 1.13.7. ملاحظات يابانية أنشأها المؤلف، مستودع Git محلي واحد غير متصل بالإنترنت، لا يوجد مكون إضافي للمجتمع.
  • نتائج Git الفعلية: دمج الفشل، UU، ثلاث مراحل من الفهرس الذي لم يتم حله، علامة الصراع، دمج الالتزام مع المرحلة المستهدفة الصريحة واثنين من الوالدين، الفهرس الذي لم يتم حله فارغ، حالة نظيفة.
  • واجهة المستخدم الرسومية الحقيقية: تحقق من عملية مستكشف الملفات الحقيقية للنص الأصلي A، وملاحظات التعارض والملاحظات المحفوظة، وإدخال النص المحدد وحفظه في المحرر الحقيقي، وقراءة العرض، وإعادة عرض الملاحظة.
  • مساعد: تم إعداد الملاحظة المركبة ونسخة النص الأصلي مباشرة كملفات. لقد استخدمت التطبيق API لتقسيم اليسار واليمين، وعرض B، والشريط الجانبي، وإعداد النافذة، وقراءة الحالة. Git هي عملية قذيفة محلية.
  • لم يتم التحقق منه:توليد النسخ المتضاربة التلقائي، Obsidian Sync، iCloud، خدمات المزامنة الأخرى، عن بعد، التحرير المتزامن على وحدتين، iOS/Android/Mac، تسليم SimpleMemo، النسخ الاحتياطي على المدى الطويل، السرعة، الإنتاجية، تأثير التدفق.

الصورة الأصلية هي شاشة Obsidian الفعلية التي لم تتم معالجتها، وMarkdown هي الأصل من الملف الفعلي. يصف سجل التحقق والمراسلات الأصلية العملية الفعلية والمساعدة والحدود.
