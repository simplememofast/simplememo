主题1：首次注册・第一印象

📥 注册、认证顺利的声音
“输入邮箱地址收到验证码很快，感觉门槛很低”“认证邮件很快就收到了”的声音。 最小化初始流的摩擦是设计上的首要事项，所以这里的评价符合设计意图。
⚡ “点击反应快”评价
收到了很多“操作感简单”“发送按钮反应快”这样的感想。 这是公称值的启动0.4秒（iPhone 16e・warm启动的实际测量）・一键发送这个数字，作为实际体验可以感受到。 采用UIKit的实施上的判断，在这里起作用。
🔑 “一键识别”的体验
收到了“特别是识别（认证）一键就能完成”的声音。 在打开应用程序的瞬间将笔记带到可以开始书写的状态——我意识到尽可能不给这个路径留下流程。
📥 “可以防止不写”“也可以用于邮件草稿”
收到了“可以防止备忘录被写掉”“也可以作为邮件的草稿用”“即使删除邮件也会留在应用程序内，所以很放心”的声音。 备忘录软件即使写字的瞬间很快，如果没有以后访问的路径，就会变成单纯的消费行为。 在本APP中，可以通过“自己的邮件收件箱”和“APP内履历”的2个路径进行回顾（在APP内履历中留下的，从新的到100件）。
🚀 “在注册周围没有犹豫，马上就开始使用了”
收到了“在注册周围没有犹豫，马上就能开始使用”“整体上使用方便”这样的感想。 发送第一个1之前的导线是最重视的UX判断之一。 因为每次增加设置画面的选择都会产生犹豫，所以当时的首次流程是缩小到“输入邮箱地址→输入验证码→备忘录画面”的3画面，文件夹制作和设置的同意按钮等，故意省略了后面返回的项目。“ 立刻开始使用”的反应，也是这种设计判断发挥作用的证据。 （现在的应用程序，第一次启动后会立即打开备忘录的画面，第一次发送备忘录时会询问收件人的邮箱地址。）
⏱ “从下载开始1分钟以内，自动输入验证码感动”
“下载应用程序→输入邮箱→接收验证码→通过应用程序输入→可以使用备忘录，没有错误1分钟”“对自动输入验证码感到感动”的报告。 认证码输入栏指定了iOS的AutoFill提示（textContentType: .oneTimeCode），所以iOS将邮件中收到的代码作为候选人时，可以从键盘上方点击输入（是否成为候选人取决于iOS和邮件应用程序）。 虽然很朴素，但是第一次体验“连复制粘贴都不需要”可以感受到差异相当大的部分。 用马克杯来说，虽然是把手的舒适感等细节，但通过测试人员的语言化，终于可以确信“这里有效”。
🖥️ “iPhone↔可以作为其他终端的文本桥”
使用方法的发现：“从iPhone到Windows PC等其他终端的文本复制粘贴环境很简单，有可以使用的场景”这样的感想。 在iPhone中备忘录→发送到自己的邮件→在PC的邮件中打开并复制文本，这种流程作为“剪贴板替代”加以利用的想法。
背景：Apple的Universal Clipboard只能在同一Apple ID下属的终端之间运行，所以Windows / Linux / ChromeOS之间有剪贴板的墙。 本软件代替了“写给自己的邮件”的简单性，邮件本身就具有跨平台性，所以最终“收到电子邮件的所有终端”成为复制目的地。 虽然在设计时没有这么明确地说明用途，但作为测试员独自发现的使用方法，很有价值。活用事例 上追加讨论中。
🌙 “晚上可以确认白天的想法，邮件基础的优点”
使用方法的发现：“因为有一定要检查邮箱的习惯，所以晚上睡觉前可以用邮件确认白天想到的事情”的声音。 即使有不打开备忘录软件的日子，每天都会看邮件 — 那个每天的动线搭载本身就是价值的场景。
与设计的联系：本应用程序将“写给自己的邮件”固定在输出目的地的理由之一，正是这个“叠加在已经通过的动线上”的想法。 不需要每天打开应用程序，相反，思考的碎片会流入已经通过的邮件的路径，所以不需要“回忆笔记的事实的成本”。活用事例集 也在考虑追加说明。
🔗 “从邮件回到应用程序输入验证码的按钮给人留下了好印象”
感想：“在注册周围没有犹豫的地方（用Google账号注册）”“从认证邮件开始回到应用程序输入验证码的按钮的好感度很高”的声音。
背景：初次流程中容易绊倒的是“邮件中收到的验证码，回到应用程序手动输入”的往返部分。 在本APP中，通过认证邮件内的按钮回到应用程序，直到输入代码，将画面的来回和复制粘贴最小化（与iOS的认证码自动输入一起减少第一次摩擦的设计）。“ 没有犹豫”这种反应，是尽可能消除这种往返的设计判断有效的证据。

主题2：注意到的点和对应

🔇 “有时候发送音不响”
报告：有按发送按钮也不会发出声音的情况。
确认：请确认终端的静音模式和应用程序的发送声音设置。
确认发送：仅凭有无声音无法判断邮件的到达。 请确认未发送的状态和收件人的收件箱。 声音设置是 FAQ“可以关闭发送声音吗？” 上注明了。
📜 “使用规则页面空白”
报告：打开使用规则页面的第一个显示是纯白的，在浏览器重新加载时显示的情况。
当时的情况：在iOS的WebView中首次读取时，有可能发生罕见的事件，正在确认再现。 已经确认通过重新读取恢复。 如果有需要注意的地方 咨询 告知。
🔍 “很难理解'只要搜索就可以随时返回'”
报告：初次欢迎时收到的备忘录上写着“搜索的话随时都可以回来”，但是搜索功能是应用程序端还是邮件端犹豫不决，在应用程序内搜索了。 此外，从邮件中收到的备忘录中没有返回应用程序的动线，也有人说发现邮件→应用程序没有导线。
当时的设计：“搜索”指的是邮件客户端（Gmail/Apple Mail等的搜索）。 本应用程序将角色缩小到“投入”，将“整理、搜索”交给平时习惯使用的邮件客户端的方针。
当时的对应：您指出表达容易引起误解，这一点是对的，正在考虑将首次介绍的文字明确表示为“在您使用的邮件客户端中搜索”的形式进行改善。 应用内履历一览也作为回顾过去备忘录的手段存在，但由于初次介绍的说明不足，所以也计划一起改善。（ 之后，在完成第一次设置时，不再自动发送引导的备忘录，最初的1通知是自己写好后发送的形式。 在现在的应用程序中，除了可以通过邮件应用程序的搜索来查找发送的备忘录外，在历史画面的列表向下拉出的搜索栏中，还可以通过关键词搜索历史记录中留下的最近的备忘录。 ）详情 常见问题 呀 邮件管理的诀窍 也请参考。
⌨️ “在注册画面中键盘上有时会隐藏输入栏”
报告：在注册画面上点击邮箱地址栏时，键盘上会隐藏输入栏的情况。 试了几次就看不见了，感觉显示位置不稳定。
原因：iOS的键盘回避逻辑（ScrollView的inset调整、SafeArea / keyboardLayoutGuide的约束）在对焦时不齐的原因。 活跃的输入栏还残留着潜入画面下方的案例。
当时的对应预定：计划在下一个次要更新中修复。 为了在对焦时对应的字段一定会在键盘上，明确地对齐滚动动作的方针。（ 在之后的更新中，包括键盘高度后来发生变化的情况在内，修改了输入栏不被隐藏。） 感谢您的报告。

主题3：要求・未来方向

📨 “如何整理积攒的备忘录”
问题：“把备忘录发到邮件里，1日10通·1月300通时整理的工具不是需要吗？” 这样的指出。 虽然投入得很快，但之后的整理是另外一个问题，确实如此。
当时的答案：“整理”特意放在应用程序方面，推荐Gmail过滤器、标签、搜索运算符、AI合作（Gemini/Apple Intelligence）等邮件客户端功能完成的设计。 这些具体的活用方法 博客：邮件管理的诀窍 和、相关的 活用事例集 请参考。
🔗 “发送到Obsidian等其他收件人”
要求：“如果连接到Obsidian的话，可以选择发送地址怎么样”的建议。
当时的想法：敢于维持“发送到自己的邮件”的选择。 理由是，如果增加选择的话，就会产生“考虑送到哪里的时间”，Captio本该丢弃的摩擦会回来。 另一方面，通过邮件导入Obsidian和Notion的运用是完全可以实现的，这 博客 呀 vs Obsidian的比较页面 中提到。 之后，对应了Obsidian的保管库的笔记的补充（发送地址的邮箱地址现在也是1）。
📋 “从履历中复制部分”
要求：不仅有履历一览表中的“全文复制”，还有“部分复制”，作为AI聊天的用途不是很方便吗？ 这样的暗示。
当时的情况：和旧Captio一样，只有全文的副本。 AI合作的使用案例是无法完全预想的，所以回答了加入路线图的讨论。（ 在现在的应用程序中，长按历史记录中已发送的备忘录，就会打开共享表，可以复制全文，也可以传递给其他应用程序。） 如果有具体的使用场景和希望的规格 咨询 开始分享。
💾 “不发邮件，留在应用程序内的Save按钮”
要求：“没有发送邮件，只有在应用程序内留下备忘录的功能，我会很高兴”的声音。 草稿和尚未确定发送对象、时机的备忘录，一旦可以保存在应用程序中，会更方便。
当时的想法：正如您所说，如果有Save按钮的动作的话，体验会扩大。 当时的“备忘录一定会通过邮件发送给自己”的设计是为了保护Captio的核心体验而做出的判断，但是增加“不发送的选项”应该不会矛盾。（ 之后，如果选择Premium的“只保存Obsidian”，就可以不发送邮件，只留在Obsidian的保管库中。） 回答了除了考虑路线图之外，还要考虑UI的嵌入方法。 如果有希望的具体移动方式（保留备忘录的图标位置、之后发送时的动线等） 咨询 开始告诉我。
✏️ “备忘录1行想用粗体将标题和正文从视觉上分开”
要求：“我知道邮件的标题和正文是通过换行分割的，但是如果在备忘录画面上1行用粗体的话，可以直观地知道标题到什么程度”的建议。
当时的行为：备忘录的1行会自动变成邮件的标题（Subject），2行以后会变成正文（Body）。 规格是常见问题和使用方法指南上记载了，但是画面上没有UI提示。
当时的方针：只提高1行的字体权重，或者加上“标题”“正文”的薄标签，作为附加成本低的改善方案很有力，回答会添加到路线图的讨论中。 一边写一边看到边界比较直观，这一点是对的。
💬 “把发送地址变成Slack的频道投稿用邮件会很有趣吧”
使用方法的建议：“如果将发送地址设为Slack的频道投稿用邮箱地址的话，Slack上会堆积备忘录，这样会比较好”这样的想法。
答案：收件人1是符合现在设计的使用方法，但我们没有尝试过。 在Slack的付费计划中，每个频道都可以创建专用的邮箱地址，然后将收到的邮件发布到频道。 如果将本应用程序的收件人定为那个地址，备忘录就会被投稿到那个频道。 但是，因为收件人是用确认码认证的，所以最初确认码的邮件也会到达那个渠道。 因为包括这个认证的步骤都没有确认动作，所以作为已经确认的使用方法没有介绍。“ 整理交给邮件客户端/其他工具”的设计（Theme 3的 发送地址设为Obsidian怎么样？ 相同的系统）应用于Slack的例子。
注意事项：这个Slack的功能可以在付费计划中使用，工作空间的所有者和管理员可能会限制可以使用的人。 设置方法 Slack的帮助 请确认。
🤖 “想要AI聊天的动线”
要求：“最近有写备忘录的话什么都放进AI的习惯，所以想要交给AI的动线。 那个是成为收费功能，还是以后会加入，从现状来看还不知道”这样的声音。
当时的答案：当时，本APP本身没有AI功能（从2026年7月开始，设置Obsidian联动的人打开“自动添加AI标签”时，终端内的AI会附加标题和标签）。 传递给AI的方法是“通过邮件转发、复制粘贴到AI客户端”或“从历史记录复制→粘贴到ChatGPT / Claude / Gemini”的外部合作。 这个 博客“AI和备忘录应用程序的区别” 呀 ChatGPT 合作工作流程 也总结了。
当时的方针：与Theme 3的另一张卡片“从履历中的部分复制”密切相关的要求，回答了AI合作的动线（从履历中一键传递给AI，通过共享表等）在路线图上进行讨论（收费还是免费也未定）。（ 在现在的应用程序中，长按历史记录中已发送的备忘录，就会打开共享表，从那里可以传递给其他应用程序。） 如果有具体的使用案例（想给哪个AI，什么怎么给） 咨询 开始告诉我。
🔎 “想要应用内的履历搜索功能”
要求：“发送的邮件作为履历留下，以后回过头来很珍贵。 如果能够通过搜索等简单搜索的话，使用起来的满意度就会提高”的声音。
当时的想法：最初是将“整理、搜索”委托给邮件客户端的设计（Gmail的搜索运算符非常强大）。 但是，在应用程序内，想要当场回顾“自己写的备忘录一览表”的需求作为另一个轴心，确实存在。 Theme 2的“很难理解'只要搜索就可以随时返回'”是welcome文言的故事，而这里是 添加in-app的搜索UI的要求。
当时的方针：回答是考虑在履历一览表中添加增量搜索（标题+正文）。（ 之后，在履历画面上添加了搜索栏。 向下拉列表就会出现，可以用关键词搜索记录中留下的最近的备忘录。） 如果有希望的具体规格（搜索范围、日期过滤器的有无等） 咨询 开始告诉我。
🧭 “重新考虑一下发送按钮和设置图标的配置？”
要求：收到了多位关于配置的指出。“ 发送按钮在键盘的正上方比右上角更容易按下（熟悉LINE和聊天类AI）“右上角放置设置，左上角只显示履历，这样很容易理解每个入口”“设置图标的位置瞬间会迷路”等，希望将操作导线简单整理好，这个方向的建议。
当时的想法：虽然仿着旧Captio培养的“右上角=发送”的心理模型，但近年来的聊天UI（Messenger、ChatGPT、Claude等）是 键盘正上方的发送按钮 是主流。 是根据用户世代和平时使用的应用程序来划分最佳解决方案的领域。 另一方面，很难找到设置图标的指出与配置是不同的问题，有提高可视性的余地。
当时的方针：（1）发送按钮位置的定制（右上角或键盘上），（2）左上角=履历/右上角=设置的作用在视觉上明确化，2点，在保持外观简单的情况下进行讨论。 如果有具体的喜好的话 咨询 开始告诉我。
📓 “也想用在日记：想要履历的编辑和模板”
感想・要求：“感觉是面向日记的”“想从履历内容开始编辑”“如果有模板就好了”的声音。 作为日常记录使用中，过去备忘录的重新编辑和，导出的模板的话，着手的手数会减少，这个建议。
当时的设计：本应用程序将角色缩小到“写好发送（投入）”，发送后的备忘录被设计为确定为邮件，所以没有预想在应用程序内重新编辑。 模板也没有实现。
当时的方针：我认为日志/日次日志是相配的用途，从（1）履历中复制、重新编辑，（2）常用的导出模板（日期标题、定型标题等）的2点，在不破坏简单性的情况下，以路线图进行讨论。 如果有具体的模板例子的话 咨询 开始告诉我。 相关：活用事例。
💴 “免费是每天3条。 收费使用的价值吗？” 直率的声音
指出：“免费的话，在每天最多3条这个限制中，有人付费使用吗？ 那么用其他备忘录软件可以吗，这是坦率的感想”，收到了触及价值核心的反馈。 非常感谢您的指出。
我们的想法：本应用程序的价值不是“备忘录应用程序之间的功能比较”，将备忘录作为“写给自己的邮件”输出本身。实际觉得有价值的用户，使用方式如下：
・发送到Gmail的话以后容易搜索（用强大的搜索运算符即时发掘过去的备忘录）
・Gmail的星/过滤器自动化ToDo管理（收件箱直接成为任务管理）
・即使终端坏了，备忘录也会留在云端=自动备份（Apple备忘录在iCloud上也一样，但是邮件是独立于应用程序的）
—这样的“备忘录单体应用程序”很难替代只有邮件基础才有的优点。反过来，不使用这些集成功能的用户往往用免费方案就足够了，我们也会如实说明。
当时的方针：这个“为什么是邮件/为什么是收费”第一次看到就没有传达的点被当作课题，首页和 活用事例・邮件管理的诀窍 中回答了加强具体优点的语言化。 非常感谢您的坦率反馈。
