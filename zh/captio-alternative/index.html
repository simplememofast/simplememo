立即恢复与Captio相同的操作感

Captio的“打开→备忘录→立即邮件→消失”的肌肉记忆，只要稍微调整一下设置就可以直接再现。 满足下一个4的话，从第一天开始就能恢复到“平时的Captio”的手感。

  1. 将收件人邮件设置为与Captio相同的地址 → 与过去的Captio备忘录相同的收件箱中汇总。
  2. 在主页的“Captio所在的同一位置”放置图标 → 拇指的动作没有变化，启动是无意识的。
  3. 在锁定画面/主页上添加小部件（iOS 17以后）→1点击打开应用程序（iOS 26以后的对应机型、语言的话，可以直接开始语音备忘录）。
  4. “写→一键发送→自动清除”1度尝试→身体想起了Captio的流程。

Captio发生了什么 — 完全时间线

Captio是iOS的“给自己发送邮件”应用程序中最受欢迎的应用程序1。 得到了使用GTD实践者、记者、收件箱作为收集工具的人们的热烈支持。 这里按时间顺序整理从2010年左右发布到2024年服务结束的经过。

2010年左右 — 发布
荷兰的Boonbits/Tupil（开发者Ben Lenarts）在App Store上作为抢购应用程序发布。“ 只有“打开应用程序→打→发送”的极简设计成为话题。 其特点是没有文件夹、类别和工具栏，彻底的削掉。
2014〜2019年 — 黄金期
在Lifehacker、The Sweet Setup、MacStories等主要生产力媒体上被介绍。 在日本也有多个博主（teineini.net・growrichslowly.net・danshihack.com等）介绍，深入GTD用户・博主・秘书层。
2021年6月 — 最后的更新
在这个时间点最后，应用程序本体的更新停止了。
2022年左右 — 从App Store撤军
根据开发商的通知，Captio在云服务终止通知的大约2年前退出了App Store。 面向现有用户的云服务，之后也在继续。
2024年3月左右 — “无法发送”的报告
note等，Captio接连收到“发送失败”“无法送达”的报告。
2024年10月1日 — 云服务结束
正如开发者在captio.co上通知的那样，面向现有用户的云服务已经结束。 通知的理由是，为了保持应用程序的稳定性和安全性，无法继续花费精力。
结束后 — 寻找替代的应用程序
通知是，如果寻找替代品的话，在App Store上搜索“email yourself”的话，会找到类似功能的应用程序。 迄今为止收到的备忘录，在收件人邮件账户的保存期限和可用性范围内保留在收件箱中。
2026年 — 独立的替代应用程序，SimpleMemo
YURIKA, K.K.发布了SimpleMemo，一键将备忘录发送到自己的邮件中。 具备离线Outbox和终端内的加密（AES-GCM）。 没有与Captio及其开发者合作，也没有受到推荐，是独立开发的替代应用程序。
确认出处：Captio的官方终止通知，要求终止的理由，以及保持稳定性和安全性的必要资源。 不是因为Gmail、OAuth、外部邮件API的方针变更。

结论：从Captio的操作感中获得灵感的替代

SimpleMemo得到了Captio重视的3个体验要素——启动即输入、发送后消失、零多余的东西――的灵感。 邮件的发送使用外部服务Cloudflare Workers和Resend API。 离线时，Outbox会保留未发送的备忘录，连接恢复后重新发送。 Outbox和发送记录在终端内通过AES-GCM进行加密。 这些功能并不能保证服务和发送不会中断。

选择 SimpleMemo 作为 Captio 替代方案的 3 个理由

1。 同样的操作感
启动后会打开输入画面，点击一下即可发送。 发送后输入栏会消失。 虽然是习惯的“给自己发邮件”的流程，但是设置和发送的行为因应用程序而异。
2。 邮箱的OAuth没有连接发送
SimpleMemo通过Cloudflare Workers和Resend API发送。 只需设置收件人的邮箱地址，就不需要用OAuth连接邮箱。 Cloudflare和Resend是外部服务，所以取决于其可用性和方针。 发送也取决于收件人的邮件服务。
3。 离线对应+终端内加密
用Outbox架构将离线备忘录在终端内AES-GCM-256加密保存。 恢复在线时自动重新发送。 发送记录也同样在终端内进行加密。

SimpleMemo的邮件发送机制

SimpleMemo是“给自己发邮件”使用方法的选择1。 这个页面是开发者写的。 以下是动作说明，不是第三方的排名或测量速度的比较。

记录和发送是两回事
启动后会打开输入画面，一键发送到预先设定的收件人。 启动所需的时间取决于终端和应用程序的状态，到达收件箱的时间也取决于网络和邮件服务。 点击或进入Outbox并不能证明已经送达。 这个页面没有声称SimpleMemo比其他应用程序快。
终端内的AES-GCM加密
AES-GCM保护保存在终端上的Outbox和发送记录。 邮件的发送是另外的处理，Cloudflare Workers和Resend为了发送处理正文。 即使对终端内的保存进行加密，普通邮件也不会被E2E加密。
离线也能写
开发源的产品页面，Captio在离线时也可以将备忘录暂时保存在终端上。 SimpleMemo也会在离线时发送的备忘录在终端内加密保存，连接恢复后自动重新发送。 重要的备忘录请确认发送情况。 Outbox里的备忘录还没有收到邮件。
收件箱是保管场所
和Captio一样，SimpleMemo将邮件的收件箱作为保管场所。 备忘录可以在邮件软件上搜索，邮件的服务端也会保留，只要是能看到邮件的终端，就可以在任何地方阅读。 没有必要从自己的数据库中导出。 即使停止使用SimpleMemo，收到的备忘录也会留在收件箱里。

从Captio到SimpleMemo的过渡步骤（5步骤）

Captio是“发送专用应用程序”，所以过去的备忘录已经留在你的邮件收件箱里了。 不需要数据转移工作。 按照下面的5步骤完成。

  1. 从App Store安装“SimpleMemo” — 在App Store中搜索“SimpleMemo”或“SimpleMemo”，或者从本页面的下载链接直接安装。 应用程序本体是免费的，Free计划是每天最多3条免费的（没有使用期限限制）。
  2. 设置在Captio中使用的收件人邮箱地址 — 首次发送备忘录时（或设置的“收件人”），输入与Captio相同的收件人邮箱地址进行认证。 只有这样，新的备忘录就会和过去的Captio备忘录到达同一个收件箱，可以按时间顺序进行统一管理。 Gmail、Outlook、iCloud、Yahoo!、公司邮件等，任何提供商都可以。
  3. 发送测试备忘录确认接收 — 写简短的测试备忘录，一键发送。 确认几秒钟内到达收件箱。 发送后，和Captio一样，画面会自动清除，马上回到可以写下一个备忘录的状态。
  4. （任意）添加主页小部件 — 长按主页，从添加小部件中选择“SimpleMemo”（显示因iOS版本不同）。 点击小部件（iOS 17以后）就会打开应用程序。 iOS 26以后的对应机型、语言的话，可以直接用声音开始记笔记。
  5. （任意）在Gmail上设置自动分配标签 — 通过Gmail的过滤功能在“From: noreply@mail.simplememofast.com”的邮件中自动赋予“SimpleMemo”标签。 通过搜索区分过去的Captio备忘录（发送地址不同）和新的备忘录，在同一收件箱中可以进行时间序列管理。
小知识：使用Gmail时，Captio的过去备忘录通过发送方（发件人）地址进行过滤后，可以一次性收集。 Captio时代的邮件中包含发件人您自己的Gmail地址，所以在搜索中输入“from:您的地址”就会全部出现。

常见问题

Captio为什么不见了？

开发来源在captio.co上通知云服务结束（2024年10月1日）。 根据公告，Captio在大约2年前退出了App Store，终止的理由是无法继续为保持应用程序的稳定性和安全性而付出努力。

2026年现在最接近Captio的替代应用程序是什么？

根据使用方法不同，适合的应用程序会有所不同。 SimpleMemo是从Captio的工作流程（启动即输入、一键发送、发送后自动清除）中获得灵感的独立选择，具备终端内加密的Outbox和发送记录。 Note To Self Mail（类似于Captio的UI）和Note to Email（免费・多个收件人）也是选择。 这个页面是SimpleMemo的开发者写的，Captio及其开发者不推荐SimpleMemo。

Captio的数据（过去的备忘录）可以转移吗？

Captio是“发送专用”的应用程序，备忘录没有保存在应用程序内，全部到达了你的邮件收件箱。 也就是说，不需要“转移工作”本身。 安装SimpleMemo后，只需将Captio使用的相同邮箱地址设置为收件人即可。 新的备忘录也会收到同样的收件箱，可以和过去的Captio备忘录一起按时间顺序进行管理。

SimpleMemo将来也不会突然结束吗？

没有可以保证能一直使用的应用程序。 SimpleMemo因为使用Cloudflare Workers和Resend API，所以依赖于外部基础设施。 免费套餐和付费套餐是根据使用量而制定的，并不能保证服务在未来也能持续下去。 成功发送的备忘录，在收件人邮件账户的可用性和保存期限范围内保留在收件箱中。 Outbox中剩余的未发送的备忘录，还没有到达收件箱。

Gmail以外的邮箱地址也可以使用吗？

是的。 Gmail、Outlook、雅虎！ 可以将邮件、iCloud邮件、公司邮件、独立域名等设置为收件人。 SimpleMemo通过Cloudflare Workers和Resend API发送，因此不需要OAuth访问收件人的邮箱。 发送取决于收件人邮件服务的过滤器和可用性。

可以免费使用吗？ 费用是多少？

是的。 Free套餐的话每天最多3条，没有使用期限限制，可以免费使用（无需注册信用卡）。 Premium计划是每月500日元或年费5,000日元无限发送+全部功能解放。 Captio是买断的应用程序，但SimpleMemo提供免费计划和订阅的付费计划。

Captioo（在词尾添加o的应用程序）是Captio的继承者吗？

不。 Captioo（808 inc. 制）虽然名字和UI与本家Captio（Tupil制）相似，但是是其他开发商的其他应用程序，没有后续和官方关系。 根据App Store的说明，支持图像的发送和小部件。 SimpleMemo以“从Captio的工作流程中获得灵感的体验，在独立基础上重建”的设计思想进行开发。

有安卓版吗？

现在SimpleMemo只有iOS（iOS 16以后）。 因为Captio也是iOS专用的，所以使用层是重叠的。 没有安卓版。 Android用户中想要使用“给自己发邮件”系统的人，请考虑Note to Email和Email Me等替代，或者通过PC浏览器Google Keep→Gmail自动转发。

可以发送附件和图片吗？

不。 SimpleMemo是文本专用的（Captio也支持附加照片等）。 这不是限制，而是设计判断，通过省略附加功能，以立即发送文本为中心使用。 如果您想发送图像或文件，iOS标准的共享表或邮件应用程序是合适的。

和attnoel中介绍的Note To Self Mail / Note to Email有什么不同？

Note To Self Mail是连接自己的邮件服务器或邮件提供商发送的方式，有多个收件人、存档，附件是付费版（不是Gmail专用）。 Note to Email是免费的，收件人是2件，可以发送多张照片，但不支持粘贴。 SimpleMemo只需设置收件人的邮箱地址，不需要邮箱的OAuth连接。 Outbox和发送记录在终端内用AES-GCM加密，离线时从Outbox重新发送。 在选择之前，请确认现在商店的说明，并尝试是否实际送达。

Captio用户的转移指南

从Captio换乘时在意的要点，从数据转移、工作流程、功能的3的角度详细解说。 综上所述，对于Captio用户来说，转移的麻烦很小，还可以使用加密的Outbox和发送记录等功能。

数据转移：其实什么都不用做OK
用Captio发送的备忘录，已经到达你的邮件收件箱了。 Captio不是将备忘录存储在应用程序内，而是作为邮件发送的应用程序，所以没有从收件箱中删除的过去的备忘录会留在邮件中。 也就是说，数据转移的工作本身是不需要的。 安装SimpleMemo后，只需将Captio中使用的相同邮箱地址设置为收件人即可。 仅凭这一点，新的备忘录就会到达同一个收件箱，可以和过去的Captio备忘录一起按时间顺序进行管理。 没有任何导出和导入的麻烦。
工作流程比较：用相同的3步骤发送
Captio的工作流程是“打开应用程序→输入文本→点击发送按钮”的3步骤。 SimpleMemo也是“打开应用程序→输入→一键发送”的3步骤。 从主页和锁屏的小部件（iOS 17以后）点击打开应用程序，iOS 26以后的对应机型、语言可以直接用声音开始记笔记。 也支持离线（Captio也有将覆盖范围外写的备忘录暂时保存在终端的功能）。 在地铁里、飞机里、信号无法到达的地方也可以写笔记并按下发送按钮。 备忘录被加密保存在Outbox中，在网络恢复时自动发送。
功能奇偶校验清单
与Captio相同的点：一键发送、邮件发送、极简的UI、发送后自动清除、不需要多余的设置的简单性。 这些基本流程在SimpleMemo上也是一样。 SimpleMemo的主要功能：终端内AES-GCM-256加密（离线发送等待的Outbox和发送记录在终端内加密，钥匙在Apple Keychain中保管。 通信受到TLS的保护，邮件正文不会经常保存在本公司服务器上）、离线队列（通过Outbox架构自动重新发送）、发送记录（可以在应用程序内确认过去发送的备忘录一览表）、黑暗模式（根据iOS的设置切换）。

Captio结束的理由：开发者所说的

关于Captio的终止，作为第一信息的是开发者的终止通知。 从通知中可以看出，服务结束日期和维护的费力的限制，不知道具体的API问题和详细的财务原因。

1。 维护的资源的极限
开发者Ben Lenarts表示，为了保持Captio的稳定性和安全性，不能再投入必要的资源了。 根据通知，应用程序从App Store撤出后，面向现有用户的云服务仍在继续。 这是作为服务终止的理由所陈述的。
2。 不推测未确认的技术原因
通知不是因为Gmail、OAuth的规则、API的方针变更、特定的收费模式。 不应该把这样的解释当作确定的事实来对待。 选择替代应用程序时，请确认当前的功能、隐私条件、依赖的服务、费用。 无论哪种商业模式，都不能保证服务会一直持续下去。
