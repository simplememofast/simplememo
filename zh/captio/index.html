Captio公式的定义（3行）

Captio式是指在想到的瞬间只“短抛（1行笔记）”，之后总结“清书・整理”的前提下设计的笔记术。
因为不想当场写得完美，所以即使在移动中也能减少溢出，继续整理。
在清书的末尾加上“下一个动作”，思考日志就会直接变成行动。

3分钟知道的要点

1行备忘录不是“信息”而是“钩子”
1行备忘录的作用不是完美的记录。 这是稍后清书时的“回忆钩子”。 所以短一点就好。
清书比起“每次都完美”“整理粗糙”
每1封不用清书OK。 1在一天结束或周末总结回看，粗略地整理一下就足够了。
清书的最后“下一个动作”
整理完就结束了太可惜了。“ 所以，接下来要做什么？” 只要写1行，备忘录就会变成任务。
犹豫的话就用模板
“不知道该写什么”是最大的敌人。 使用模板的话，可以毫不犹豫地扔出去。看模板集 →

Captio式有效的理由

降低认知负荷
当场想得太多了。“ 先扔”可以释放工作记忆，集中精力进行眼前的工作。
减少记录的摩擦
启动、写、发送马上就结束了。 不需要文件夹选择和标记。 所以在电车里，边走边也能记笔记。
留下可以以后判断的材料
1行备忘录积聚在收件箱中=思考的日志自然积累。 清书的时候知道了“当时在想什么”。
与行动相连
在清书的末尾加上“下一个动作”的习惯，笔记不是“读完”而是“做完”。

常见的失败（以及对策）

  • 当场想写长文就停了
    在移动中说“好好写吧”的话，中途下了电车，或者被别的事情分心了，最后没有记下。 Captio式的核心是“不写得完美”。
    对策：1行，最大也是3行。 无视体裁。 以后以清书为前提扔。
  • 没有时间清书而积攒
    1封一个仔细地清书，未处理的备忘录堆积起来，受挫了。 完美主义是Captio式最大的敌人。
    对策：“汇总起来乱”即可。 每周1次，只有15分钟。 扔掉不需要的东西，剩下的只需添加1行动作。
  • 清书满足不任务化
    干净利落地总结的瞬间变得“做了”，没有付诸实际行动的模式。 清书不是终点而是起点。
    对策：在清书的末尾一定要写“接下来要做的事情：○○”1行。 如果没有那个的话，清书还没有完成。
  • 不知道在哪里保存，分散
    备忘录应用程序、Notion、Slack草稿、Apple Notes......如果有多个保存地址的话“那个写在哪里了？” 出现问题。
    对策：投掷目的地统一为1个（邮件收件箱）。 SimpleMemo的话，收件人是固定的，不会迷路。
  • 标签、整理过于细致而破产
    颜色区分、标签、文件夹、项目绑定......虽然一开始很开心，但1周就变得麻烦了，全部放弃了。
    对策：整理只有“清书完成 or 未处理”的2分类。 Gmail的话只要存档就可以了。

具体例子：1行备忘录→清书→下一个动作

例1：工作（在Slack上说的委托）
1行备忘录
田中先生 报价到周五为止
清书
田中先生有报价委托 对象：Q3的营销措施 期限：周五17时 包含的项目：广告费、制作费、运用费
下一个动作
周四上午制作电子表格，下午发给田中先生
例2：学习（在报道中读到的内容）
1行备忘录
OKR运用 每周签到好像是关键
清书
OKR形骸化的原因是只进行季度审查 每周只进行15分钟的签到就能提高达成率 即使不是全队，只要OKR老板就可以了
下一个动作
建议下周的例行OKR每周入住
例3：想法（散步中的灵感）
1行备忘录
如果用公司内部FAQ bot的话，咨询可能会减少
清书
假设：公司内部服务台咨询的60%应该可以通过FAQ解决 ChatGPT API + 连接公司内部Wiki的话好像可以bot化 成本：API月$20左右，工时2天可以试制
下一个动作
下周三30分试制。 顺利的话分享给Slack

SimpleMemo的转动方法

“投掷”的输入很快
启动0.4秒（iPhone 16e・warm启动的实际测量）立即输入。 既没有主页也没有菜单。 打开的瞬间键盘就出来了，写完就可以马上发送。
稍后可以一览表清书
发送的备忘录在邮件收件箱中按时间顺序排列。 周末一起打开，只做清书+动作。
不会因为模板而迷茫
可以减少“不知道该写什么”。 工作、学习、生活的模板集后可以使用。
备忘录→邮件统一化
备忘录的保存地址是自己的邮件收件箱。 无论是Gmail还是Outlook，都会送到平时使用的收件箱，所以不用找别的地方了。详细看 →
