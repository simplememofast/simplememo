Obsidian · 转移笔记

Obsidian的过渡指南 — 从Notion/Evernote/Apple Notes开始

转移后容易困扰的是，比起笔记的数量，附件、链接、正文的显示方式。 在官方Importer中实际导入了Notion的HTML ZIP和Evernote的ENEX，将原始数据与保存的Markdown进行了比较。

验证日：2026年9月30日（UTC） · Linux版 Obsidian 1.13.7 · Importer 3.1.9

将导入的数量和没有留下的形状分开

Notion保存了4笔记本+5图像，Evernote保存了3笔记本。 但是，Notion的折叠和段落的缩进不会保持原样。 Apple Notes没有在Linux上验证实际导入。

输入是官方存储库固定commit中的测试用fixture。 这不是作者从自己的Notion/Evernote账户实际export的数据。 在这篇文章中，用这个小例子展示了什么还剩下，什么要修改。

转移来源选择的路线实际结果
NotionNotion → File import → HTML的ZIP4导入/5附件/0失败。 保存亲子页面和图片。 折叠和缩进是变化。
EvernoteEvernote（.enex）→ENEX 1件3导入/0附件/0失败。 3种代码示例的缩进和符号进行核对。
Apple Notes确认固定source的macOS条件实际导入未验证。 这不是在Mac上成功的结果。

用练习用Vault，确认Importer的版本和保存位置

首先准备空的练习用Vault，用少量的笔记本看输出。 Obsidian的导入和Vault的制作在下载和安装的家长指南中处理。

  1. 在Settings → Community plugins中激活Importer。 这个例子的实际画面是Importer v3.1.9。
  2. 用Ctrl+P打开Command palette，选择Importer: Import notes。
  3. 选择转移源的格式，确认输入文件和Output folder。 也读执行前的Preview。
  4. Start import，分别确认显示完成的笔记、附加、failed的件数和Vault中保存的文件。

这次的初期准备，将官方发布的main.js・manifest.json・styles.css手动配置到隔离Vault，激活后用实际GUI进行操作。 不是点击Community plugins的Browse → Install导入的验证。 选定的3.1.9以外的版本也会有相同的结果，这是未验证的。

Obsidian和Installer的实际版本画面

Notion将HTML的ZIP传递给File import

这个版本的Notion有两条路线。 这次选择了File import。 画面说明“不需要代币和网络连接”“不保留数据库”。 Notion account的数据库、数式的转移是另外的途径，这个验证没有执行。

  1. Notion选择后，选择File import。 实际画面介绍了HTML格式的export。 在自己的过渡中，按照官方的export程序准备文件。
  2. Choose file中选择ZIP。 验证时，在OS的文件选择画面中选择了官方fixture的notion-testspace.zip。 外部ZIP中还有另一个ZIP1件的构成，也直接读取了。
  3. Folders to import确认后Continue。 这次以选择所有对象的初始状态进行。
  4. Output folder是Notion，Attachment location是Vault folder，Save parent pages in subfolders是ON。 这是没有现有笔记本的空Vault的例子。 没有验证Update的覆盖、竞争处理。
  5. 在下一个画面中打开Save Notion ID，关闭Single line breaks，在未选择模板的初始状态下阅读Preview，选择Start import1次。

父页面是Notion/Notion-Testspace/Notion-Testspace.md，子页面进入了同一个下属。 Attachment Tests还在同名文件夹中。 父正文的3的链接，唯一对应这个Vault对应的子笔记本。

原始数据的形式保存的结果转移后的确认
折叠标题・toggle list隐藏的正文剩余，展开为普通的标题・列表。 原来的details/summary的折叠结构没有保留。确认是否可以阅读正文，必要时使用Obsidian侧的标题和列表的折叠。
带缩进的段落原HTML的嵌套indented段落，成为普通的独立段落。 缩进的层次的外观会发生变化。判断是否将想要保留层次的段落修改为标题、要点。
标题、块的单独链接例子的输出是[[Formatting Tests]]。 原HTML的href已经没有位置的锚了。同时查看原export和输出，重新添加到必要位置的链接。 没有判定是只有Importer的故障。

例如原HTML的折叠内的With a hidden text block.和…with hidden content!，也留在了保存的Markdown中。 但是是普通的标题、列表的正文。 不是完全复制原画面外观的结果。

Formatting Tests中的单独链接，即使显示字符串中有Notion的块ID，原HTML的href也只指向页面。 保存示例中的“Link to heading”和“Link to text block”都是页面链接。 从目录到标题的链接是另一个例子，在Markdown中生成了标题链接，但不是尝试所有链接的实际点击的结果。

另外，外部的Web图像URL保留在保存正文中。 因为这次验证停止了外部通信，所以那个外部图像的显示是未验证的。 正在和本地的5图像分开确认。

Evernote选择ENEX，比较代码的缩进

  1. Importer再次从Command palette打开，选择Evernote (.enex)。 实际画面介绍了每个笔记本的ENEX export。
  2. Choose files中选择ENEX。 在这个例子中，在OS的文件选择画面中传递了官方fixture的code-block-indentation.enex。
  3. Output folder是Evernote，Attachment location是Vault folder，模板未选择。 从Continue开始阅读Preview，选择了1次Start import。
  4. 完成显示是3 imported / 0 attachments / 0 failed。 保存的Evernote/code-block-indentation/有3笔记本。

空白的例子保留了4・8的缩进和空行。 NBSP的例子变成了普通的空白，但4、8个缩进是一致的。 包含反斜杠、*、_的字符串也作为代码块内的文字保留下来。

包含空白缩进的真实保存全文

```python
def f(x):
    if x:

        return 1
    return 0    # aligned
```

包含反斜杠和Markdown符号的实际保存全文

```bash
grep -o 'a\\*b' file \\
  | sed 's/_x_/*y*/'
```

这个3例子中没有生成的frontmatter。 制作、更新日期和标签等所有metadata、Evernote的附加、任意格式的保留尚未验证。

Apple Notes明确macOS条件和未验证

官方的固定source正在检查Platform.isMacOS和桌面环境。 这次运行的是Linux版Obsidian，所以没有尝试Apple Notes的实际导入。 从source中读取对应条件和在Mac上实际转移是不同的。

从Apple Notes转移时，请确认官方的Apple Notes的转移步骤和对象环境。 这个页面的Notion/Evernote的成功件数，不能作为Apple Notes的实机成功使用。

转移前后的确认和FAQ

在Notion中选择哪种导入方式？
这个验证是Notion → File import。 Notion account是使用令牌和通信的其他路径，没有执行。 实际画面说明了关于File import不保留数据库。 数据库、数学公式的完全转移超出了这个结果的范围。
Notion的ZIP要先解压吗？
这个官方fixture是ZIP中还有1个ZIP的构成，外面的ZIP可以直接选择Choose file。 带有4的ID的HTML成为笔记，没有ID的index.html没有成为笔记。 不是任意ZIP构成成功的证明。
0 failed的话，原来的外观也一样吗？
不一定相同。 在这个例子中，折叠的内容被展开为普通的标题、列表，带有缩进的段落变成了普通的段落。 0 failed是处理件数的显示。 分别确认外观、附件、链接。
Notion的标题和块的链接为什么会变成页面链接？
这次的原HTML即使显示字符串中有块ID，href中也没有锚，输出是[[Formatting Tests]]。 在原来的export中丢失的位置，仅靠Importer无法恢复。 转移前的export和输出都看。
Evernote的代码还有缩进吗？
在这个ENEX的3例子中，空白4・8个，空行，代码内的反斜杠和符号仍然存在。 NBSP变成了普通的空白，4、8个的缩进一致了。 不是尝试附件、所有格式、所有笔记的结果。
Apple Notes也可以在这个环境下导入吗？
检查这个固定source是否是macOS的桌面环境。 因为验证的环境是Linux，所以没有尝试Apple Notes的实际导入。 通过这个验证无法判断Mac的成功和完全转移。

确认范围和官方资料

  • Linux版Obsidian/Installer 1.13.7、Importer v3.1.9的实际画面。 通过手动配置官方release assets3件的隔离Vault从GUI激活了。
  • Notion File import和Evernote ENEX各1次，从实际的OS文件选择和Start import开始执行。 将保存的7笔记、5本地图像、有限的正文、链接、layout例子与原fixture进行了核对。
  • Notion的附加笔记和Evernote的空白代码笔记，从同一启动内的文件列表再次打开，确认bytes一致。 重启应用程序后重新打开是未验证的。
  • PNG・输入fixture・保存Markdown保持原bytes。 辅助代码用于准备和读取，导入和输出文件生成没有用plugin API代替。

保留了准备的profile ID错误、点击对象的selector等待失败、文件选择中仅靠第一个Return没有关闭的事实。 实际选择确定是通过OS画面的Open按钮进行的。 应用程序是GUI Close后的实际wait在exit 0，Xorg是所有process的SIGTERM和实际wait 0。 控制器在末尾的Xlib结束处理中退出了1，整体没有正常结束。 详细情况总结在验证记录中。

真实账户的export、Notion account/API・数据库・数式、Apple Notes的执行、全部metadata/全部layout/任意的大规模数据、其他OS、iOS、Sync、SimpleMemo、速度・安全性・生产力的效果尚未验证。
