Obsidian模板集 — 复制粘贴可以使用的实用10种

每日备忘录、会议、读书、调查等，可以选择想要使用的类型来复制正文。 用作者的Linux版Obsidian插入了全部10种，确认了标题、日期的替换、保存、在同一应用程序内重新打开。

验证日期：2026年10月1日（日本时间）·Obsidian 1.13.7

从现在的用途中选择一个

填补空白的最小框。 请根据自己的工作填写必要的项目。 这里分发的输入Markdown和应用后的例子，分别保留了原来的字节列。

  1. 01。 每日备忘录留下当天的目的、预定、注意
  2. 02。 会议备忘录议题、决定、负责人和期限分开
  3. 03。 读书笔记分类出处、要点、自己的问题
  4. 04。 项目决定目的、完成条件、下一步行动
  5. 05。 学习笔记留下主题、理解、练习、未解决
  6. 06。 想法构思・谁的课题・留下尝试的方法
  7. 07。 每周回顾完成的事情・困难的事情・分下周的一步
  8. 08。 调查备忘录调查的问题、出处、事实和解释分开

Core Templates的设置和插入

  1. 在练习用的Vault上准备Templates 文件夹，将选择的输入Markdown放在其中。 粘贴代码的Markdown也可以准备同样的输入。
  2. 在Settings → Core plugins中激活Templates。 不需要社区插件。
  3. 将Templates指定为Template folder location。 下面的原画面是实际设置的英语UI。
  4. 制作新的笔记，决定好标题后选择正文。 在这次的Linux操作中，用Ctrl+N制作了。
  5. 用Ctrl+P打开命令调色板，搜索Insert template。 选择Templates的候选，选择一个想要插入的模板。
  6. 确认正文后保存。 这次，对齐了Ctrl+S之后的保存文件和编辑器的字节列，关闭了目标笔记，从同一个应用程序内重新打开。

这个例子的输入是用Source mode准备的。 在官方说明中，请注意，在Live Preview中编辑包含Properties的模板时，可能会覆盖没有引号的变量。 这次10输入没有使用Properties的YAML。

三个变量，在插入时替换

  • {{title}}：实际打开的笔记本的标题。
  • {{date:YYYY-MM-DD}}：这次是2026-10-01。
  • {{time:HH:mm}}：这次是04:29。

输入文件名是各种类型的识别用。 保存例的标题是“適用01-日次メモ”等，是给用GUI创建的笔记起的名字。 执行环境的时区是Asia/Tokyo。 不是验证所有格式代币和时区组合的记录。

常见问题

Templates和Templater有什么不同？
这篇报道中使用的Templates是Obsidian的核心插件。 实例中使用的变量是标题、日期、时间三个。 Templater是另一个社区插件，不是在这里激活、执行的。
日期、时间是什么时候的值？
这次使用了插入模板时的应用程序的时钟。 Linux的验证环境是Asia/Tokyo，所有10例的保存值是2026-10-01和04:29。 之后打开时保存的值会被重新计算，这次重新打开没有确认。
模板文件名和制作的笔记名需要相同吗？
这次，输入的是Templates 文件夹的01-日次メモ.md等，制作的笔记是適用01-日次メモ.md等。{{ Title}}被替换为实际打开的笔记标题，而不是输入文件名。
字符串的{{date:YYYY-MM-DD}}保持原样的时候呢？
只是复制Markdown打开的话，这个变量是正常的字符串。 请设置Templates 文件夹，在本文的光标位置选择Templates的Insert template进行插入，请确认步骤。 这篇报道的实例是，通过这个实际GUI操作确认替换。
如果将ZIP直接展开到Vault的话，会有同样的动作吗？
ZIP的Templates中输入10件，Applied中保存结果的例子10件。 在Templates设置中指定输入的文件夹的构成。 将ZIP导入读者的保管库的操作尚未验证，请先在自己练习用的保管库中尝试一个。
与iPhone和SimpleMemo的合作也验证了吗？
这个10件的实际操作只由Linux版Obsidian1.13.7的作者Vault进行。 iOS、Android、Windows、macOS、Obsidian Sync、SimpleMemo、终端间同步、对速度和生产力的效果，在这个记录中没有验证。

实际确认的范围

  • Linux官方Obsidian1.13.7，安装程序1.13.7，英语UI。 作者制作的小Vault，没有社区插件。
  • Core Templates的激活、文件夹指定、固定10输入的命令插入、标题、日期的替换、实际保存、在同一过程中重新打开笔记。
  • 输入的是作者直接制作的Markdown。 插入和输出笔记的制作是从GUI进行的，辅助代码用于准备初期环境和读取、证据复制。
  • 保留全部10件的原始画面和保存Markdown。 刊登的PNG没有加工、再生成。 应用程序整体重启，读取器导入Vault，其他OS，iOS，Sync，SimpleMemo，速度、生产力、流入效果尚未验证。

准备阶段的启动失败和选择命令候选的脚本失败仍然存在。 这篇报道的适用结果不是成功处理它们，而是基于其他固定10件的实际操作。 原件的对应和经过汇总到验证记录中。
