Obsidian和Anytype的比较 — 本地优先的2个解释

连接手边的Markdown的使用方法和组装自己的数据模型的使用方法。 将Obsidian的实际保存例子、Anytype的官方说明和Linux启动画面分开，整理选择的轴心。

确认日期：2026年9月30日（UTC）·Linux版的作者验证

选择的轴是文件和数据模型

如果重视将保存的文章作为Markdown文件处理的话，这次的Obsidian实例可以作为判断材料。 如果想用独特的数据模型组装信息的种类和显示，Anytype的官方说明是讨论的入口。 无论哪个都只是提出“本地”，并不是相同的保存形式、同步条件。

在这篇报道中，用实际作者Vault确认了Obsidian的四个保存文件和链接显示。 Anytype实际启动了官方Linux版，观测了welcome画面。 因为从保存、编辑到同一课题都不是在两个APP上进行的比较，所以在表中注明依据的种类。

# 索引

この例で扱うテーマは、メモを書く段階と、関連を残す段階を分けること。

- [[20260930-01 入力と整理を分ける]] — 書き留める内容と整理する内容を分ける例。
- [[20260930-02 関係に理由を添える]] — 関連ノートへ進む理由を添える例。

在这个例子中，本文的wikilink表示与其他笔记的关系。 添加链接之前是三注・零链接，添加相关理由后是三注・一链接，添加索引后是四注・三链接。 图表以另一种方式显示这个保存内容。

Markdown可以作为文件读取，可以从这个小的实际保存例子中确认。 是解释其他应用程序相同的wikilink记号，还是再现附加功能是另外的条件。 详细的链接、反向链接、读取画面的实际操作总结在Zettelkasten的作者实例中。

Anytype的官方说明：组装自己的数据模型

固定在v0.57.3标签上的官方README，将Anytype解释为personal knowledge base，制作页面、任务、wiki、日志等，定义自己的数据模型介绍使用方法。 此外，还列举了文本、数据库、看板、日历、custom Types的composable blocks。 这不是从这次welcome观察到的功能，而是基于官方source的说明。

“先离线，本地存储，可选点对点同步。”

“可组合块：文本、数据库、看板、日历和自定义类型。”

Anytype v0.57.3的固定commit・官方README

同样的README也记载了end-to-end-encrypted、zero-knowledge encryption powered by any-sync。 可以读作本地存储、任意P2P同步、加密的设计说明，但这次启动观测没有测量内部保存形式、与同步对象的通信、加密实施、密钥的管理、恢复。

因此，Obsidian的Markdown保存例和Anytype的设计说明，依据的深度不同。 可用于判断是否想以文件为单位处理正文，是否想用数据模型设计信息的种类和显示。 两者的安全性、同步的确定性、导出后的再现性的排名，无法从这个记录中得出。

用自己的笔记本，决定重视的条件

  1. 想以文件为单位保存文章:阅读下面的Markdown例子，可以具体确认用Obsidian保存的正文和链接记号。 包括附加功能的依赖，另外掌握必要的状态。
  2. 想按种类和显示整理相同的信息： Anytype的官方数据模型说明可以成为考虑的入口。 实际使用的版本操作和必要数据的出入，是与保存例子不同的确认事项。
  3. 想在多个终端上使用:选择保存地址、同步、恢复、备份作为不同的条件。“ 本地第一”这个词不能作为保证智能手机和同步结果的比较。

在查看实际应用程序的启动画面和保存的正文后，决定每天处理的信息是以文章为主，还是有种类和显示的信息，比较起来会更容易。

常见问题

Obsidian和Anytype，都是本地优先吗？
虽然重视本地的点是共同的，但这次可以展示的依据是不同的。 在Obsidian中，作者Vault的Markdown正文用实际GUI编辑、保存，重新打开并核对。 Anytype官方README说明了本地存储和任意P2P同步。 这次的Linux实际操作是启动和welcome画面的观测。
Anytype是直接管理Markdown文件的应用程序吗？
固定版本的官方 README 介绍了其自身的数据模型，以及文本、数据库、看板、日历和 custom Types。本次没有测量 Anytype 的内部保存格式，也没有测量 Markdown 的导入导出。这不是证明 Obsidian 提供的 Markdown 文件可以在 Anytype 中无损往返的比较结果。
在Anytype的启动画面上，确认到什么程度了？
启动了一次官方Linux AppImage 0.57.3，两次观测了I am new here和I already have a Key的welcome画面。 没有点击按钮。 另一个拥有的窗口是空白的New tab，不是登录后的工作空间。 屏幕上的应用程序版也未确认。
加密的话，总是比较安全吗？
从这个记录中无法得出安全性的排名。 Anytype的end-to-end encryption和zero-knowledge是固定公式README的描述。 实施、密钥的管理、恢复、同步通信的加密尚未测量。 用Markdown读取Obsidian的保存例子，也不能保证加密和备份。
分发ZIP是Anytype的出口吗？
分发的是Obsidian的独立作者验证保存的四个Markdown。 将原来的日语文件名保留在ZIP内，包括索引的链接。 不是从Anytype导出的数据，读者的导入操作也未验证。
连智能手机和同步的易用性都比较了吗？
确认的实际应用程序是Linux的Anytype启动画面和另一个Linux Obsidian作者Vault。 iOS、Android、终端间同步、Anytype的对象操作、与SimpleMemo的配合、速度、生产力、流入的效果没有比较测量。 选择同步或外部备份时，请另外确认使用的版本和保存地址的条件。

资料和验证范围

  • Anytype是官方Linux AppImage v0.57.3的一次启动，两次读取观测。 刊登了welcome的原始PNG。 实际GUI的点击和账户操作为零。
  • Obsidian是另一个Linux作者Vault的实际GUI编辑、保存、重新打开和实际文件。 通过验证记录区分了三个事前输入、Settings和布局的辅助API、状态读取和使用原件复制的路径。
  • Anytype结束是向所有进程发送SIGTERM，app和Xorg的实wait0和确认释放的记录。 不是点击GUI的Close的结果。
  • 原PNG和分发Markdown的bytes和SHA256进行核对。 Anytype的官方source使用与固定标签绑定的保存正文，这次没有进行额外的source获取。
