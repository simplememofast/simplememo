属性是处理笔记开头的YAML的UI

在Properties中输入的名称和值会保存在笔记开头的frontmatter中。 例如，如果准备好status: 進行中，就可以在Dataview的WHERE条件下选择“进行中”的笔记。 和本文中写的普通文章的处理方式不同。

首先，决定要比较什么，然后使用少数项目。 在这个例子中，状态为status，优先度为priority，完成为done，期限为due，分类为tags。 作者制作的虚构记录，不是使用者的数据。

用GUI输入保存YAML表・列表变更和结果练习用原件

按顺序决定名称、类型、值

  1. 打开笔记，从Add property或官方的Ctrl/Cmd+;中添加项目。 在实机例子中，点击Add property添加了priority。
  2. 按项目名旁边的类型图标，打开Property type选择类型。 在实机上选择Number，输入3保存。
  3. 现有的status选择了Text，从“未着手”变更为“进行中”。 检查、Date输入、Tags输入也通过实际的UI进行变更，确认会反映在保存YAML中。
  4. Tags不只是输入文字就结束了，而是通过聚焦的输入按Enter进行确定。 这次的辅助操作也无法确定一次，再次通过Enter和焦点移动确认了保存。
名字这个例子的类型和值在实机上做过的事情
状态Text / 進行中Text选择，未着手→進行中
优先级编号/3添加项目，选择Number，输入3

在官方资料中，同名的型号在整个保管库中是通用的。 在将相同的名称用于其他含义的值之前，先确认类型和用途。 List和Date & time等，这里没有处理的类型不包含在这次的动作确认中。

# 調査A

著者が検証用に作成した架空の記録です。顧客データではありません。

在官方资料中，frontmatter用---包围文件开头，以名前: 値的YAML格式进行描述。 属性名称不会在一个笔记中重复。 这个例子的数值3和检查true分别保存为数值和boolean。 Date是保存这个值的确认，不是验证所有日期格式和输入的正确性的结果。

将相同的值作为TABLE和LIST的条件

在实机中，将官方Dataview稳定发布的三个文件事先复制到隔离的保管库中，通过实际的信任确认激活了插件。 这不是验证Browse/Install的画面操作的记录。 插件为了执行第三方代码，确认分发来源和使用条件后进行选择。

发布名称是0.5.70，分发manifest和实际画面的显示版是0.5.68。 需要的Obsidian最小版是manifest上的0.13.11，实际运行的Obsidian是1.13.7。 DataviewJS设置是false，将下一个DQL输入到实际编辑器中，在Reading view中显示。

文件夹名記録、项目名、状态字符串一致。 调查A/B正在进行中，C已完成。

# Properties接続検証

著者が作成した架空の3件だけを表示します。

## 進行中の表

```dataview
TABLE status AS "状態", priority AS "優先度", done AS "完了", due AS "期限"
FROM "記録"
WHERE status = "進行中"
SORT file.name ASC
```

## 未完了の一覧

```dataview
LIST
FROM "記録"
WHERE done = false
SORT file.name ASC
```

## 保留の該当なし

```dataview
LIST
FROM "記録"
WHERE status = "保留"
SORT file.name ASC
```

TABLE将正在进行的两件列为表，LIST将done将false的笔记列为列表。 最后的LIST选择了保留的笔记，也确认了没有对象的情况下的实际显示。 DQL的全部功能、内联字段、DataviewJS没有在这里尝试。

更改完成检查后，未完成列表从2件到1件

done = false的LIST调查A・C / 2件调查C / 1件
status = 保留的LIST不适用不适用

变更前的TABLE两件用实际Reading DOM确认了，当时的PNG从表向下滚动。 上面的变更后，在PNG中可以看到表两件和未完成一览一件。 没有重新制作并替换显示位置和图像。

从文件一览表中再次打开调查A和一览表笔记，也确认了保存Markdown的bytes和SHA256相同。 同一应用程序启动中重新显示，不是整个应用程序的重启或确认其他终端。 在这次的条件下，数值反映在显示上，没有测量工作速度和生产力提高的因果关系。

常见问题

Obsidian的属性和frontmatter是不同的数据吗？
属性是操作笔记结构化值的UI，值作为文件开头的YAML frontmatter保存。 在这次的实机中，用GUI操作了status、tags、done、due、priority，与保存的Markdown的值进行了核对。
属性的类型是按笔记设置的吗？
在官方资料中，同一属性名称在整个保管库中使用相同的类型。 从名字旁边的类型图标打开Property type，选择类型。 在这次的实机中，在priority中选择了Number，保存了3。 并不是所有的类型和日期输入都进行了验证。
在Dataview中列出属性的基本形式是什么？
在dataview代码块上写TABLE或LIST、FROM和WHERE。 在这次的三件中，以FROM "記録"为对象的文件夹，status = "進行中"的TABLE是2件，done = false的LIST是完成检查变更前两件，变更后一件。
下载的例子是什么状态？
这是在GUI中将调查A的done更改为true后的保存原件。 記録 文件夹内调查A・B・C，显示了将一覧.md放在同一保管库正下方的构成。 这次的实机结果是TABLE两件，未完成LIST是调查C一件，保留不适用。 读者导入保管库和其他环境的动作尚未验证。
