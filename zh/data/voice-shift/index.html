更正后测量的东西4个 — 方法v2

统计对象是现存记录中最早的首次启动时间位于统计期间内的设备。这不代表用户一生中的首次使用人数，也不是下载量。我们排除能够识别的开发设备、首次启动记录重复的设备，以及存在更早保存记录的设备，并记录排除数量及其局限。统计期间包含开始时刻，不包含结束时刻。

指标定义和极限
1 第一个观测保存的输入标签每个目标终端选择最初的保存记录1件，计算记录的输入方法。 未记录、未知的值作为“不明”留在分母中。 无法测量混合了语音和手动输入的备忘录的字数比例，以及仅用语音创建的比率
2 首次接收日的字数分布在首次启动记录的日期和日本时间的日历日，计算保存成功收到的记录。 0 / 1〜10 / 11〜50 / 51〜200 / 201+ / 不明的区分。 不是从第一次开始24小时的统计，也不计算出平均字数
3 保存记录的接收时间段期间内的保存记录到达服务器的时间以日本时间进行统计。 不一定是实际说话的时间或制作时间。 同时记下事件数、贡献终端数、日语区域的比例和不明数
4 Obsidian有效状态的观测比例对象终端中，在期间内收到过一次以上连接有效的记录的比例。 分为只有无效记录的终端和无法确认状态的终端。 不是文件夹保存确认、同步成功、持续使用的比率

保存包括邮件API的受理成功和Obsidian单独的本地保存，不添加首次的追加记录和测试发送。 可以识别相同的发送时，除重复外，也会留下无法识别的记录数量。 不是确认邮件收件箱到达和同步到其他终端的统计。

8月20日提前公开的旧定义v1（结果未刊登・不用于现行统计）

旧规格以最近90日・窗口内的新安装为对象。 将下表作为变更记录留下。 根据实际记录可以证明的范围，在9月6日更正了上述v2。

指标定义
1 首次发送的输入方法比例新安装首次发送备忘录时的输入方法（语音/键盘/其他）的分布。 以安装为单位只计算最初的1件。 通过没有输入方法标签的旧版本作为“不明”留在分母中（排除后比例不好看）
2 第一天的备忘录文字数分布安装当天（以日本时间计算日期）发送的备忘录的字数桶的分布。 桶是0 / 1~10 / 11~50 / 51~200 / 201+ 文字的5阶段，因为应用程序只记录这个粒度，所以无法计算出像平均字数这样的细小值（按照设计）
3 发送的时间段分布发送事件的发生时间（将服务器受理时间转换为日本时间）的0~23时分布。 在脚注中同时记录日语的外号比例
4 Obsidian并用率窗口内新安装中，Obsidian配合（指定保管库文件夹）设定的比例

测量方法 — 不使用本文进行统计

明确用于统计的记录、排除方法、可以再次确认结果的范围。

  • 这个调查不使用备忘录正文。 统计使用事件的输入方法、字数区分等，不取出正文和收件人。 包括本文在内的产品整体的数据路径在另外的资料中说明（数据路径的整体图）。
  • 用于统计的只有允许的元数据。 统计区分终端的ID和许可列表制的活动（输入方法、字数桶、Obsidian的状态等）。 在排除内部终端时，也会使用现有的发送关联和内部账户的散列进行核对。 公开的只是统计，不公开ID、散列、收件人。
  • 字数只存在于桶中。 0 / 1〜10 / 11〜50 / 51〜200 / 201+的5阶段在终端端四舍五进后发送，所以运营方也不知道确切的字数。
  • 排除内部账户。 除已知的开发者、测试终端外，同时记下排除数。 相关记录的保留时间有限，不能保证能够辨别所有内部终端。
  • 留下统计步骤。 统计步骤和变更记录进行版管理。 由于记录的追加、保留期间的删除，重新获取结果可能会发生变化，所以保留获取时间点和定义版。
