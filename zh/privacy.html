隐私政策

最后更新日期：2026年10月7日

YURIKA, K.K.（以下简称“本公司”）对“SimpleMemo”（以下简称“本服务”）中用户信息的处理，规定如下隐私政策。

1。 获取的信息

本公司可能会获取以下信息。

(A) 用户输入、设置的信息

  • 收件人邮箱地址（To）
  • 标题设置（Subject）・签名设置（Signature）
  • 备忘录正文（发送邮件所需的范围）

(B) 关于终端、使用的信息

  • 终端信息（OS/终端种类等一般信息）
  • 发送处理所需的日志（发送日期、结果状态等）
  • 使用事件（画面显示、操作、发送结果）、终端单位的随机标识符、会话ID、发送ID、启动完成情况等诊断信息
  • 用于防止滥用和限制请求频率的技术信息，例如 IP 地址、请求信息等

使用活动中不包含邮箱地址和备忘录正文，但通过发送ID可以与发送记录的收件人邮箱地址的哈希关联。 因此，这些事件、终端标识符、诊断信息被当作与用户联系起来的信息。 终端标识符的保存位置和删除应用程序后的处理情况记载在以下12中。

(C) 从Apple收到的订阅、退款通知

为了掌握订阅的运用情况和支付失败，验证从Apple收到的签名通知，记录订阅开始、更新、自动更新设置变更、更新失败、过期、退款等。 保存的项目是通知和交易的标识符、订阅商品的标识符、通知的种类、区分、生产或测试环境的区分、购买、有效期、取消、通知、接收等日期和时间，以及Apple通知的取消理由。 因为包含Apple侧的标识符，所以不作为完全匿名的信息处理。 这个通知记录不保存邮箱地址、备忘录正文、安装标识符，Apple的交易标识符、安装标识符和收件人邮箱地址的对应表也不保存。 以下（D）在处理中核对通知，制作其他分析记录。 从仅基于邮箱地址的删除请求中，无法确定原来的通知记录。

(D) 订阅状态和持续使用的分析

在对应的应用程序中，如果这个分析有效，从终端接收带有Apple签名的购买、更新信息，将验证的订阅状态与终端单位的标识符一起记录下来，与持续使用的事件进行核对。 记录的项目是订阅商品、本人购买或家庭共享的区分、价格、货币、购买、有效期、取消、签名、观测、接收等日期和时间、自动更新的状态、请求重新尝试、宽限期、过期理由、生产或测试环境的区分，以及应用程序的运行环境。 处理中用Apple的交易标识符核对上述（C）的通知，同时记录当时确认的通知种类数量和最终日期。 Apple的交易标识符和签名信息的原文，不会和这个分析记录一起保存。 虽然不包括邮箱地址和备忘录正文，但终端标识符、商品、日期、价格等与使用信息相关联，所以不视为匿名信息。

这个分析记录从收到开始超过90天的定期删除。 从对应的应用程序删除时，会删除终端保留的删除用信息对应的分析记录，即使删除的信息延迟重新发送也不会保存。 此操作不会一次性删除上述（C）的原始Apple通知记录、其他终端的记录或外部分析服务的记录。 丢失终端删除用信息等情况，可能无法确定对象。

(E) 对应应用程序版的使用情况分析选择

在设置中提供“使用情况分析”选项的应用版本中，常规应用内使用事件及来自设备的订阅状态分析默认关闭。只有用户选择“同意并开启”后才开始收集；未选择则不会开始。这项选择独立于邮件提醒的同意，也不同于 Apple 设备的 App Analytics 共享设置。在应用内撤回同意后，我们会停止新的收集，并尝试删除设备上尚未发送的事件。若无法确认删除，界面会显示提示；之前同意期间生成的事件，不会在日后重新同意时再次发送。已经开始传输的请求可能仍会完成，撤回本身不会删除我们已经收到的记录。内部验证用 Capture 测试中，操作顺序和发送结果等测量也属于使用情况分析与质量改进的目的。但参与测试还需要另行同意，届时会说明测试范围和期间。仅开启此选项不会报名参加测试。撤回此选项后，新的测试测量也会停止。若需删除已保存的测试记录，请使用测试的退出及删除操作。没有此选项的应用版本，会随应用运行发送下述 12 的使用事件及上述 (D) 的订阅状态分析。我们撤销自 2026 年 9 月 28 日起实施的、不保存旧方式请求的服务器端限制，接收旧方式及提供此选项的版本双方的分析请求。不会追溯补齐此前未能收集的事件。保留此选项的版本仍按应用内设置开始或停止收集。AppsFlyer SDK 的获客与使用情况测量见下述 12。

这个选择并不同意AppsFlyer的获取测量。 在设置中有“知道应用程序的路径测量”的版本中，只有在以下（F）的其他选择和iPhone的跟踪许可都同时存在的情况下，才会启动AppsFlyer SDK。 在没有其他选择的使用情况分析对应版中，SDK会停止。 没有选择画面的应用程序版的处理在以下12中记载。

(F) 对应APP版的获取测量选择

“知道应用程序的路径的测量”是任意的，初始状态是关闭的。 同意此选择和iPhone的追踪许可同时，为了掌握下载链接的获取情况，向AppsFlyer发送应用程序的启动、获取来源、活动信息、广告标识符、IP地址、终端型号、OS、应用程序版本等技术信息。 虽然使用SDK固有的标识符，但是不会将本公司的使用情况分析的标识符作为Customer User ID传递。 为此目的，不发送备忘录正文、邮箱地址、购买活动、普通的应用内使用活动，与广告合作伙伴共享和广告的个别优化无效。 SKAdNetwork、IDFV和Apple Ads的测量也在这个路径上无效。 因为包含标识符，所以不作为匿名信息处理。

即使不同意也可以使用应用程序。 在设置中撤回的话，会停止新的测量，删除终端内获得来源的确认记录。 通信中的请求可能会完成，AppsFlyer已经收到的数据的删除和iPhone的追踪设置的更改，不包含在这个操作中。 同意使用情况分析、同意邮件提醒、Apple的App Analytics共享设置是独立的选择。

2。 使用目的

获取的信息，用于以下目的。

  • 提供邮件发送功能（发送、未发送管理/重新发送、历史显示）
  • 本服务的运用、维护、故障应对、质量改善
  • 将内部测试终端排除在使用统计之外，设置好的Obsidian功能的指南不要重复
  • 防止非法使用、确保安全（限制短时间连续发送、服务器端速率限制等）
  • 咨询对应
  • 遵守法令

3。 根据计划的差异

本服务的信息处理与Free/Premium基本相同。 Premium以使发送次数限制无效（解除Free的“每天3条”限制）为目的而提供，但为了安全和发送基础保护的限制（冷却等），无论Free/Premium如何，都有适用的情况。

4。 备忘录内容的处理（重要）

  • 备忘录正文通过用户的操作发送邮件。
  • 为了发送处理，备忘录正文及收件人信息可能会通过本公司使用的发送基础（包括外部服务）。
  • 除履行法律要求、防止滥用、处理服务故障等正当必要情形外，我们不以长期保存或查看笔记内容为目的。

5。 邮件提醒功能（任意）

本服务为了支持发送备忘录的习惯化，提供向希望的用户发送提醒邮件的任意功能。

(A) 获得同意

  • 本功能默认无效，只有在认证画面或设置画面上用户明确激活时才会发送。
  • 即使尚未启用提醒，如果您已验证邮件地址，且一段时间没有发送笔记（参考：距上次发送约 72 小时），我们也可能发送仅 1 次的邀请邮件，询问您是否愿意接收提醒。除非您选择接收，否则不会发送提醒。
  • 激活后，也可以在设置画面点击1停止。 各个提醒邮件末尾的解除链接也可以停止。

(B)获取、保存的信息

  • 邮箱地址的散列值（SHA-256）—保存在本公司服务器（Cloudflare D1）。
  • 同意状态（有效/无效）、最终备忘录发送日期、累计发送次数。
  • 提醒发送记录（发送日期、发送/打开/点击/弹跳等活动）。
  • 我们的服务器不保存原始电子邮件地址。原始地址仅由邮件发送平台（Resend）的联系人 API 保存。

(C) 发送频率

  • 从最终备忘录发送开始，24小时/72小时/7天 经过的时机，每个1发送。
  • 每个1用户设置了每1每周最多2封，整个服务设置了1每天最多80封的上限。

(D) 自动解除

  • 邮件发送时出现弹跳、投诉时，立即停止向该地址发送，同意状态无效。

(E) 受委托的服务提供商

提醒邮件发送及联系人管理委托给美国的 Resend, Inc.。该公司遵守 Data Processing Agreement 及国际邮件发送法规，包括 CAN-SPAM、GDPR 和日本《特定电子邮件法》等。

6。 第三方提供

除以下情况外，本公司不会向第三方提供个人信息。

  • 如果用户同意的话
  • 根据法令的情况
  • 需要保护人命、财产等时
  • 在业务所需范围内向受委托的服务提供商提供信息时（见下一节）

7。 委托（邮件发送等）

我们可能将邮件发送、运维和分析等业务委托给外部服务提供商，并对受委托方进行适当监督。

8。 安全管理

本公司为了防止信息泄露、灭失、损毁等，采取合理的安全对策。

9。 保管期限

我们努力避免将信息保存超过实现使用目的所需的期限。使用事件及上述 1(D) 中的订阅状态分析记录超过 90 天后，会定期删除；发送 ID 与收件人哈希值的对应记录超过 35 天后，也会定期删除。Apple 的订阅与退款通知原始记录在接收超过 180 天后，由每日任务删除。由于每次处理数量有上限，如待删除记录较多，会在次日及之后继续处理。其他日志等可能因防止滥用或运营需要，在必要范围内保存一定时间。

10。 修订

本公司根据需要修改本政策。 修改后会在本服务或本公司网站等上公布。

12。 关于加密的技术信息（参考）

本服务为了保护用户的隐私，采取了以下技术对策。 这些与其说是“安全”，不如说是为了“数据最小化”和“终端内保护”的实施。

  • 设备内存储空间：离线待发送消息（Outbox）和发送历史记录使用 Apple 原生 CryptoKit 提供的 AES-GCM-256 加密，保存在设备上（文件保护类别：completeFileProtectionUntilFirstUserAuthentication）。
  • 密钥管理：256-bit 对称密钥存放在Apple Keychain Services（kSecClassGenericPassword），重启后首次解锁后可以使用，使用不转移到其他终端的保护类。 应用程序在加密、解密时读取密钥。 备份中包含的密钥副本由终端固有的密钥保护，在其他终端无法使用（Apple的说明）。 在更换机型之前，请确认必要的备忘录是否已送达邮件或Obsidian等保存地址。
  • 通信路：API通信由TLS（HTTPS）保护。 发送备忘录用的URLSessionConfiguration.ephemeral是将该会话的缓存、Cookie、认证信息不永久保存在磁盘上的构成。 与使用分析的保存、发送和外部SDK的通信说明区分开来。
  • 邮件正文：为了发送处理，通过本公司的Relay API（Cloudflare Workers）和外部发送基础（Resend），但不会进行持续保存。 日志也不记录（开发时的DEBUG构建除外）。
  • 邮件地址的服务器保存：将发送ID和收件人邮件地址的哈希（从SHA-256生成）的对应保存在Cloudflare D1中。 无论选择加入提醒，都会创建这个对应记录。 提醒用的联系人由Resend的Contact API进行管理。
  • 加密、保管、通信路的依赖关系：备忘录正文的加密（CryptoKit）、钥匙保管（Keychain Services）、通信（URLSession / Network.framework）全部用Apple纯正框架完成，不通过第三方SDK。
  • 登录和防止非法使用的SDK：作为任意的入职缩短功能，从Google账户导入邮箱地址时，使用GoogleSignIn-iOS SDK和Firebase Authentication SDK。 Firebase App Check SDK在启动时初始化，使用Apple App Attest防止后端API的非法访问。
  • 本公司的使用分析：为了改善质量和掌握使用情况，向本公司的/v1/analytics/event发送事件。 项目包括随机安装标识符、会话标识符、事件种类、标识符、时间、应用程序的版本、构建、语言、发送结果等允许的属性。 虽然设计不直接包含邮箱地址、备忘录正文、验证码，但可以通过发送ID与收件人邮箱地址的散列联系起来。 这个安装标识符保存在终端的钥匙链中。 在iOS的构造上，钥匙链的项目即使删除应用程序也会留在终端上，在这种情况下，重新安装后也会使用相同的标识符（以下的旧版AppsFlyer合作中，Customer User ID也使用相同的标识符）。
  • 通过AppsFlyer获得、使用分析：在没有上述1（E）选择画面的应用程序版中，启动AppsFlyer SDK，将首次备忘录发送成功、认证成功、收费画面显示、方案选择、购买成功作为事件发送。 从应用程序设置的属性，在适用的情况下，包括购买金额、货币、订阅期间、画面的区分。 因为将与本公司分析相同的安装标识符设置为AppsFlyer的Customer User ID，所以可以将获得的信息和使用记录联系起来。 从应用程序设置的活动项目中不直接包含邮箱地址、备忘录正文、验证码。 这里列举的项目是应用程序明确设置的，并不是列出SDK获取的技术信息的所有项目。 标识符和可关联的记录不会被视为完全匿名的信息。 在有使用情况分析选择的版本中，停止SDK，仅限于对应上述（F）的版本，在有其他目的的同意和iPhone的追踪许可的情况下，只开始获取测量。

注意：本服务不提供End-to-End加密（E2EE）。 为了在收件人用户自己的邮件客户端上正常阅读正文，邮件正文将通过标准的SMTP协议发送。 对于需要E2EE的用途，请考虑Standard Notes、Signal、ProtonMail等专用服务。

本节的内容，作为面向Obsidian用户的“数据通道”的图解，重新整理在隐私设计页面。

13。 本公司网站的访问分析

我们的网站（simplememofast.com）为了掌握浏览情况并改善内容，使用了以下访问分析。 与上述应用程序（本服务）的使用数据是不同的。

(A) Google 分析（Google LLC・美国）

  • 在Cookie（第一方Cookie“_ga”等）中，保存每个浏览器的随机标识符，区分用户数和会话。
  • 收集的信息包括浏览的页面、参考来源、大致的地区、浏览器和终端的种类、页面上的操作（App Store的链接显示和点击等）等。 Google说明，Google分析4不会记录、保存IP地址。
  • 收集到的信息由Google处理。 Google的使用方法请看“从使用Google服务的网站和应用程序收集的信息由Google使用”。
  • 如果想要脱离统计对象，请使用Google分析选择退出附加组件，或者在浏览器设置中禁用Cookie。

(B) Ahrefs Web Analytics（Ahrefs Pte. 有限公司 ・新加坡）

  • 用于浏览数等的统计。 Ahrefs说明，这个工具不使用Cookie，不直接保存IP地址。
